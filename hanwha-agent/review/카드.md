# 복습 카드

폰으로 볼 회상 카드다. `python review/만들기.py` 가 이 파일과 `concepts/` 를 읽어
`review/복습.html` 한 장으로 묶는다.

형식은 셋뿐이다.

```markdown
## <노트 파일 이름 (확장자 없이)>
### <질문 한 줄>
<답. 여러 줄·코드블록·표 다 된다>
```

`##` 이름이 `concepts/` 의 노트와 안 맞으면 만들 때 경고가 뜬다.
카드 id 는 질문 글자에서 만든다 — **답을 고치면 진도가 유지되고, 질문을 고치면
새 카드가 된다.** 순서를 바꾸거나 사이에 끼워 넣어도 진도는 밀리지 않는다.

---

## 01_개발환경설정

### 가상환경(venv)을 프로젝트마다 따로 만드는 이유는?
프로젝트마다 필요한 패키지 버전이 다르다. 전역에 깔면 A 프로젝트를 고치다 B 가 깨진다.

활성화되면 프롬프트 앞에 `(.venv)` 가 붙는다.

## 02_Git과_GitHub

### Git 과 GitHub 의 관계를 한 줄로?
Git 은 내 컴퓨터에 설치하는 **버전 관리 프로그램**, GitHub 는 그 저장소를 올려 두는 **온라인 서비스**.

GitHub 가 없어도 로컬 git 은 그대로 동작한다. 원격 백업·공유만 안 된다.

## 03_Pydantic

### 설정을 읽는 곳을 한 군데로 모으는 이유는?
여러 곳에서 `os.environ` 을 직접 읽으면 기본값과 검증이 흩어진다.
`Settings` 하나를 두면 **어떤 값이 필요한지가 한 파일에 다 적힌다.**

### `.env` 와 `.env.example` 을 같이 두는 이유는?
`.env` 는 커밋하지 않는다(키가 들어 있다). `.env.example` 에 **키 이름만** 적어 두면
받는 사람이 무엇을 채워야 하는지 안다.

### Pydantic 에서 기본값을 "안전한 쪽"으로 잡는다는 게 무슨 뜻인가?
설정을 빠뜨렸을 때 사고가 나지 않는 쪽. 관측·외부 호출 같은 것은 기본을 꺼짐으로,
검증·차단은 기본을 켜짐으로 둔다.

## 04_레이어드_아키텍처

### 계층 규칙을 문서가 아니라 테스트로 강제하는 이유는?
문서는 어겨도 아무 일이 안 일어난다. 테스트로 두면 **어긴 순간 빨간불이 뜬다.**

예: 라우터가 리포지토리를 import 하면 실패하는 테스트.

### 계층 import 테스트가 못 잡는 구멍은?
함수 안에서 하는 **지연 import**. 파일 맨 위가 아니라 함수 안에 있으면
정적 검사에 안 걸린다.

## 05_예외_계층_설계

### 예외를 계층으로 설계하면 뭐가 좋은가?
부르는 쪽이 **원하는 넓이로 잡을 수 있다.** 최상위 하나만 잡으면 전부,
하위를 지정하면 그것만 잡힌다.

### `raise ... from ...` 을 쓰는 이유는?
원인을 잃어버리지 않기 위해서. `from` 없이 새 예외를 던지면
진짜 원인이 트레이스백에서 사라진다.

## 06_로깅

### 로깅 설정(`basicConfig`)을 앱 전체에서 한 번만 해야 하는 이유는?
두 번째부터는 무시된다. 여러 모듈이 각자 부르면 **먼저 부른 쪽 설정만 살아남아**
왜 포맷이 안 바뀌는지 알 수 없게 된다.

### WARNING 과 ERROR 를 가르는 기준은?
WARNING 은 지금은 도는데 앞으로 문제가 될 수 있는 것(임계치 근접, 재시도 발생),
ERROR 는 이미 실패한 것(LLM 요청 실패, 500).

## 07_pytest

### pytest 에서 테스트가 "등록"되는 방법은?
이름 규칙. 파일은 `test_`, 함수도 `test_` 로 시작해야 수집된다.

안 붙으면 **에러 없이 그냥 실행되지 않는다** — 통과한 것처럼 보인다.

### `__init__.py` 가 있고 없고가 왜 문제가 되나?
pytest 가 `sys.path` 에 넣는 폴더가 달라진다. import 경로가 바뀌어
어제 되던 테스트가 오늘 모듈을 못 찾는다.

### 수집 단계에서 에러가 나면 어떻게 되나?
`Interrupted` 로 중단되어 **나머지 테스트도 안 돌아간다.** 한 파일의 import 실패가
전체를 멈춘다.

## 08_네트워크와_인터넷_기초

### IP 주소만으로는 왜 부족한가?
프로그램을 구분할 수 없다. 한 기계에 서버가 여럿 떠 있으므로
**포트**가 있어야 어느 프로그램인지 정해진다.

## 09_HTTP와_URI

### GET 과 POST 의 데이터 전송 위치 차이는?
GET 은 URI 의 쿼리스트링, POST 는 본문(body).

그래서 GET 으로 비밀번호를 보내면 주소창과 로그에 남는다.

### HTTP/3 가 이전 버전과 다른 점 한 가지는?
전송 계층이 TCP 가 아니라 UDP 다. (HTTP/1.1·2 는 TCP)

## 10_FastAPI

### FastAPI 와 Uvicorn 의 역할 차이는?
Uvicorn 이 포트를 열어 HTTP 요청을 받고, FastAPI 가 그 요청을 처리한다.
프레임워크와 서버는 다른 물건이다.

### `--app-dir` 옵션은 무엇을 정하나?
모듈을 찾기 시작할 위치. `uvicorn app.main:app --app-dir backend` 는
`backend/` 안에서 `app.main` 을 찾는다.

## 11_SQLAlchemy

### Engine · Session · Model 은 각각 무엇인가?
Engine 은 DB 로 가는 통로, Session 은 실제로 작업하는 공간, Model 은 테이블을
표현하는 파이썬 클래스.

### SQLite 파일 경로가 실행 위치에 따라 달라지는 이유는?
상대 경로가 **현재 작업 디렉터리(cwd)** 기준이라서. 노트북에서 돌릴 때와
루트에서 돌릴 때 다른 파일을 연다.

## 12_리포지토리_패턴

### 라우터에서 직접 SQL 을 조립하면 생기는 문제 둘은?
1. 문자열로 SQL 을 만들면 **보안에 취약하다.**
2. 같은 조회를 다른 곳에서 또 쓸 수 없고 테스트·DB 이관이 어렵다.

### `scalars().all()` 과 `scalar_one_or_none()` 을 언제 나눠 쓰나?
여러 건이 나올 수 있으면 `.all()`(없으면 빈 리스트).
조건상 0건 또는 1건만 나와야 확신할 때 `scalar_one_or_none()` — 2건이면 에러를 낸다.

### 지연 로딩(lazy)과 즉시 로딩(eager)의 차이는?
지연은 연관 객체를 쓸 때 쿼리를 한 번 더 친다. 목록에서 N건을 돌면 N번 친다(N+1).
즉시는 처음 조회에 같이 가져온다.

## 13_서비스_계층

### 서비스 함수 하나가 곧 무엇의 단위인가?
트랜잭션 하나. 여기서 커밋·롤백 경계가 정해진다.

라우터나 리포지토리가 아니라 서비스가 그 경계를 쥔다.

## 14_문서_업로드_API

### DB 모델을 응답에 그대로 쓰면 안 되는 이유는?
안 보여줘야 할 컬럼까지 나간다. 스키마를 따로 두면
**응답에 들어갈 것을 명시적으로 고른다.**

### 파일 업로드가 JSON 이 아니라 멀티파트인 이유는?
JSON 은 텍스트 형식이라 바이너리를 그대로 못 싣는다.
base64 로 바꾸면 크기가 약 33% 늘어난다.

## 15_비동기_asyncio

### 코루틴 함수를 호출하면 무슨 일이 일어나나?
**바로 실행되지 않는다.** 코루틴 객체가 만들어질 뿐이고,
`await` 하거나 이벤트 루프에 넘겨야 돈다.

### 코루틴 안에서 동기 함수(`time.sleep`, 동기 HTTP)를 부르면?
이벤트 루프가 통째로 멈춘다. 그 시간 동안 다른 작업이 하나도 못 돈다.

### FastAPI 에서 `def` 와 `async def` 의 차이는?
`def` 로 만든 라우터는 스레드풀에서 돌고, `async def` 는 이벤트 루프에서 돈다.
`async def` 안에서 동기 블로킹을 하면 서버 전체가 느려진다.

## 16_Streamlit

### Streamlit 의 재실행 모델을 한 줄로?
화면에서 이벤트가 일어날 때마다 **스크립트를 처음부터 끝까지 다시 실행한다.**

그래서 값을 유지하려면 `session_state` 에 넣어야 한다.

## 17_비밀번호_해싱_bcrypt

### 비밀번호를 그대로 저장하면 안 되는 이유는?
DB 가 새면 전부 털린다. 사람들이 같은 비밀번호를 여러 서비스에 쓰기 때문에
피해가 그 서비스에서 끝나지 않는다.

### bcrypt 실습에서 확인한 뜻밖의 사실은?
**서로 다른 문자열인데 둘 다 검증에 통과한다** — bcrypt 는 입력을 72바이트까지만 본다.
그 뒤가 달라도 같은 값으로 취급된다.

### `create_all()` 이 컬럼 추가를 반영하지 못하는 이유는?
"표가 없으면 만들고 이미 있으면 아무것도 하지 않는다"가 전부다.
이미 있는 표에 컬럼을 더하지는 않는다. 그래서 마이그레이션이 필요하다.

## 18_로그인과_인증

### 사번이 없는 경우와 비밀번호가 틀린 경우를 같은 예외로 묶는 이유는?
나눠서 알려 주면 **어느 사번이 존재하는지**를 알려 주는 셈이 된다.
둘 다 같은 `AuthFailed` 로 던진다.

### 로그인 실패를 예외 상황으로 보지 않는 이유는?
사번이 없는 것은 시스템 오류가 아니라 **정상적인 결과**다.
서버 에러(500)가 아니라 인증 실패(401)로 답해야 한다.

## 19_문서_목록_화면과_API_연동

### 백엔드 호출을 전부 `api_client` 한 곳으로 모으는 이유는?
주소·타임아웃·예외 변환이 화면마다 흩어지지 않는다.
엔드포인트가 바뀌면 **그 파일 한 줄만** 고친다.

### Streamlit 화면이 백엔드를 부를 때, 요청은 어디서 나가나?
브라우저가 아니라 **Streamlit 서버의 파이썬 코드**에서 나간다.
그래서 백엔드가 사내망에만 있어도 된다.

## 20_Docker와_PostgreSQL

### `pgvector/pgvector:pg16` 이미지를 쓰는 이유는?
PostgreSQL 에 pgvector 확장이 미리 들어 있다. 벡터를 저장하려면 그 확장이 필요하다.

### compose 의 환경변수(`POSTGRES_DB` 등)가 안 먹는 것처럼 보일 때는?
**처음 만들어질 때만** 반영된다. 볼륨이 이미 있으면 무시되므로,
바꾸려면 볼륨을 지우고 다시 만들어야 한다.

### `(healthy)` 인데 접속이 안 되는 이유는?
healthcheck 가 **컨테이너 안에서** 도는 검사라서. 안에서 잘 뜬 것과
바깥에서 포트로 닿는 것은 다른 문제다.

## 21_Alembic_마이그레이션

### `create_all()` 대신 Alembic 을 쓰는 이유는?
`create_all()` 은 이미 있는 표를 바꾸지 못한다. Alembic 은
**어디까지 적용했는지**를 `alembic_version` 표에 기록하고 차이만 적용한다.

### `alembic.ini` 에 DB URL 을 적으면 안 되는 이유는?
비밀번호가 파일에 남아 커밋된다. `env.py` 에서 설정을 읽어 넣는다.

### 첫 마이그레이션에서 `upgrade head` 가 아니라 `stamp head` 를 쓴 이유는?
표는 이미 `create_all()` 로 만들어져 있었다. `stamp` 는 실행하지 않고
"여기까지 적용됨"만 기록한다.

### `env.py` 에서 모델을 import 하지 않으면?
Alembic 이 "표가 하나도 없다"고 판단해 **전부 삭제하는 마이그레이션**을 만든다.

## 22_AI_Native_애플리케이션

### AI Native 애플리케이션의 정의는?
핵심 기능의 일부를 **같은 입력에 같은 출력을 보장하지 않는 구성요소(LLM)** 에 맡기고,
그 전제 위에서 설계된 애플리케이션.

### 그 전제에서 따라오는 설계 원칙은?
답을 만드는 부분과 **그 답을 검증·제한하는 부분을 따로** 둔다.
모델이 시킨 대로 바로 실행하지 않는다.

### API 키를 화면·로그에 찍지 않으려면?
`mask` 를 거쳐 앞뒤 몇 글자만 남긴다. 키는 `.env` 에만 두고 코드에는 이름만 적는다.

## 23_포트와_어댑터

### 포트·어댑터를 쓰지 않으면 뭐가 문제인가?
모드 분기(`if mock: ... else: ...`)가 기능마다 퍼진다.
모드가 하나 늘면 **고칠 자리가 기능 수만큼** 늘어난다.

### `typing.Protocol` 과 ABC 의 차이는?
ABC 는 상속해야 한다. Protocol 은 **약속한 메서드를 갖고 있으면** 통과한다
— 상속하지 않은 클래스도 맞는다.

### `runtime_checkable` 의 한계는?
메서드 **이름만** 본다. 인자 개수·타입·반환형은 검사하지 않는다.
`isinstance` 를 통과해도 부르면 터질 수 있다.

### `LLMResult` 가 `text` 만 담지 않는 이유는?
호출 한 번마다 돈과 시간이 든다. 토큰 수·모델명을 같이 받아 두어야
나중에 원가를 집계할 수 있다 — "나중에 최적화"가 안 통하는 자리다.

## 24_API_토큰과_과금

### 과금 단위는 무엇인가?
요청 수가 아니라 **토큰 수**. 그래서 한 번 부르더라도 긴 문서를 붙이면 비싸진다.

### 토큰은 글자인가 단어인가?
둘 다 아니다. 정확한 수는 응답의 `usage` 로만 알 수 있다.

한국어는 글자 수가 영어의 절반인데 토큰은 더 많이 나온다.

### 입력과 출력 중 어느 쪽이 비싼가?
출력이 입력보다 약 5배 비싸다. 그래서 답을 길게 뽑는 설계는 값이 크게 뛴다.

## 25_Claude_API_호출

### Claude API 에서 `max_tokens` 가 특별한 이유는?
**필수 파라미터**다. 빼면 호출이 안 된다.

### 같은 질문을 두 번 보내면?
출력 길이도 문장도 달라진다. 입력이 한 글자도 안 바뀌어도 그렇고,
따라서 **비용도 매번 달라진다.**

### 예외를 `except Exception` 으로 잡으면 안 되는 이유는?
내 코드의 버그까지 API 실패로 둔갑한다. `except anthropic.APIError` 로 좁게 잡는다.

## 26_프롬프트_설계와_컨텍스트

### 프롬프트를 코드에 박으면 생기는 문제는?
같은 지시를 여러 곳에서 고쳐야 하고, 로그에 남은 응답과
**프롬프트 버전을 이을 수 없다.**

### system 과 user 의 역할 분담은?
system 은 역할·규칙·출력 형식처럼 매번 같은 것, user 는 이번 질문과 근거처럼 매번 바뀌는 것.

### 프롬프트 파일을 못 찾았을 때 빈 문자열을 돌려주면 왜 위험한가?
규칙이 통째로 빠진 채 모델이 돌아간다. 에러가 안 나서 아무도 모른다.

## 27_구조화_출력

### 구조화 출력의 원칙을 한 줄로?
출력은 스키마로 강제하고 파싱·검증한다. **자연어를 그대로 다음 단계로 넘기지 않는다.**

### "JSON 만 보내라"고 해도 모델이 코드펜스를 붙이면?
받는 쪽에서 벗겨낸다. 프롬프트로 100% 막을 수 없으므로 `_extract_json` 이 필요하다.

### `doc_id` 를 `Literal` 로 막을 때 주의할 점은?
문서 목록이 따로 관리되는 값이라, 문서가 늘면 `Literal` 도 같이 고쳐야 한다.
안 고치면 **모델이 맞게 답해도 검증이 실패한다.**

## 28_가드와_재시도_폴백

### 가드·재시도·폴백의 순서와 역할은?
보내기 전에 **가드**로 거르고, 응답이 규칙을 어기면 **재시도**하고,
끝내 안 되면 **폴백**으로 정해 둔 답을 낸다.

### 재시도하면 안 되는 실패는?
다시 해도 같은 결과가 나오는 것 — 인증 실패, 잘못된 파라미터, 한도 초과.
재시도는 돈과 시간만 쓴다.

### `AskOut` 에 `fallback_used` 필드를 둔 이유는?
폴백으로 답한 것과 진짜 답한 것이 화면에서 똑같이 보이기 때문.
구분할 수 있게 필드로 남긴다.

## 29_골든셋_회귀테스트

### LLM 테스트가 기존 테스트와 다른 점은?
같은 입력에 같은 출력이 안 나온다. 그래서 정답 문자열 비교가 아니라
**지켜야 할 조건**을 본다.

### 골든셋 문항 수의 기준은?
단일 이슈를 보는 골든셋은 10문항 규모가 정석이다. 대신 각 유형이 최소 한 건은 있게 짠다.

### 골든셋을 가짜 어댑터로 도는 이유는?
모델을 부르면 돈이 들고 매번 답이 달라진다. 판정 로직을 먼저 확실히 하려면
모델을 빼고 돌려야 한다.

### 통과율만 볼 때 놓치는 것은?
어떤 유형에서 떨어졌는지. 90% 라도 "근거 없을 때 모른다고 답하기"가
전부 틀렸다면 제일 중요한 게 깨진 것이다.

## 30_LLM_프레임워크_개요

### LangChain 과 LangGraph 를 가르는 기준은?
한 줄로 흐르면 LangChain, **되돌아오는 화살표**가 있으면(재시도·분기·상태 유지)
LangGraph.

### 관측 도구가 필요한 이유는?
다시 부르면 다른 답이 온다. 그때 무슨 프롬프트로 무슨 답이 왔는지
**실행 기록이 없으면 재현할 수 없다.**

## 31_관측과_실행_기록

### 관측 어댑터에서 가장 중요한 규칙은?
**관측이 실패해도 답변은 나가야 한다.** 부가 기능이 본 기능을 막으면 안 된다.

### Langfuse 를 셀프 호스팅할 때 compose 가 안 해 주는 것은?
`DATABASE_URL` 에 적힌 데이터베이스를 만들어 주지 않는다. 직접 만들어야 한다.

### 컨테이너끼리 부를 때 호스트 이름은?
`localhost` 가 아니라 서비스 이름(`postgres`). 각 컨테이너의 `localhost` 는 자기 자신이다.

## 32_사용량과_원가_기록

### 사용량을 검증 **전에** 기록하는 이유는?
검증에 실패해도 호출은 이미 일어났고 돈은 나갔다.
검증 뒤에 기록하면 실패한 호출이 장부에서 빠진다.

### 원가를 계산해서 저장해 두는 이유는?
단가는 나중에 바뀐다. 그때 계산하면 과거 비용이 틀어지므로
**그때 이렇게 됐다는 스냅샷**으로 남긴다.

### 컬럼 이름을 바꿀 때 autogenerate 를 쓰면 안 되는 이유는?
Alembic 은 이름 변경을 알아보지 못하고 **지우고 새로 만드는** 마이그레이션을 만든다.
데이터가 날아간다.

## 33_RAG_개요

### RAG 가 없애려는 문제는?
모델이 모르는 것을 그럴듯하게 지어내는 것. 이건 **모델을 바꾸거나 프롬프트를 다듬는 것으로는
없앨 수 없다.**

### RAG 11단계에서 ①~⑤와 ⑥~⑪은 어떻게 다른가?
**다른 시간에 돈다.** ①~⑤(로딩·파싱·청킹·임베딩·적재)는 문서를 올릴 때 한 번,
⑥~⑪(질의·검색·필터·프롬프트·LLM·답변)은 질문할 때마다.

이 경계를 놓치면 질문할 때마다 PDF 를 파싱하는 구조가 된다.

### 청크 크기를 정할 때의 상충 관계는?
크면 관계없는 내용까지 프롬프트에 실려 비싸지고, 작으면 문맥이 끊긴다.

## 34_LangChain_기초

### `ChatAnthropic` 에 키를 직접 넘겨야 하는 이유는?
`pydantic-settings` 는 `.env` 를 읽어 `Settings` 객체에만 담고
**`os.environ` 에는 넣지 않는다.** 라이브러리가 환경변수를 찾아도 없다.

### LLM 을 부르면 돌려받는 것은 문자열인가?
아니다. `AIMessage` 객체다. 토큰 사용량 등이 같이 들어 있어서,
문자열이 필요하면 `StrOutputParser` 로 꺼낸다.

### LCEL 파이프(`|`)로 잇는 이유는?
부품이 모두 `Runnable` 이라 같은 방식으로 실행된다. 흐름이 한 줄로 보인다.

## 35_체인_합성

### `assign` 이 하는 일은?
원본을 잃지 않고 키를 더한다. 그냥 매핑하면 `question` 이 사라지는데
`assign` 은 살려 둔다.

### 파이프에서 모든 함수를 `RunnableLambda` 로 감싸야 하나?
아니다. **사슬의 첫 고리만 Runnable 이면** 된다.
왼쪽 객체의 `__or__` 가 오른쪽을 알아서 감싼다.

### `RunnableParallel` 은 언제 쓰나?
갈래를 동시에 돌리고 결과를 딕셔너리로 모을 때.

## 36_체인을_앱에_붙이기

### `ChatPromptTemplate` 에 `("system", 내용)` 튜플을 쓸 때의 함정은?
**중괄호가 변수로 읽힌다.** "JSON 으로 답하라"는 프롬프트에 JSON 예시를 넣는 건
자연스러운 일인데, 그 순간 템플릿이 변수를 찾다가 터진다.

포맷팅이 필요 없는 자리는 `SystemMessage` 로 둔다.

### 우리 `LLMPort` 를 체인에 넣으려면?
그대로는 파이프에 안 들어간다. `RunnableLambda` 로 감싸야 한다.

### `PydanticOutputParser` 를 쓰면 무엇이 체인 안으로 들어오나?
검증. 파싱만 하는 게 아니라 스키마에 안 맞으면 거기서 걸린다.

## 37_비동기와_스트리밍

### 주피터에서 `asyncio.run` 을 쓸 수 없는 이유는?
주피터가 **이미 이벤트 루프를 돌리고 있다.** 루프 안에서 루프를 또 돌릴 수 없다.
셀에서는 `await` 를 바로 쓴다.

### `ainvoke` 가 된다고 해서 진짜 비동기인가?
아니다. 안에서 동기 함수를 그대로 부르면 **그 자리는 진짜로 비동기가 아니다.**
메서드 이름만 `a` 로 시작할 뿐이다.

### 체인 중간의 `RunnableLambda` 하나가 스트리밍을 끊는 이유는?
평범한 함수는 결과를 다 만든 뒤 한 번에 돌려준다.
조각을 흘려보내려면 **제너레이터**로 감싸야 한다.

## 38_동시_실행과_재시도_폴백

### `abatch` 와 `asyncio.gather` 는 언제 나눠 쓰나?
`abatch` 는 **같은 체인·같은 모양**일 때. 서로 다른 체인을 동시에 돌리려면 `gather`.

### `with_retry(stop_after_attempt=3)` 은 몇 번 더 시도하나?
2번 더. `stop_after_attempt` 는 재시도 횟수가 아니라 **총 호출 횟수**다.

### `with_fallbacks` 가 스트리밍에서 다르게 동작하는 이유는?
이미 내보낸 조각은 못 거둔다. 앞부분이 나간 뒤 실패하면 폴백으로 갈아탈 수 없다.

### 재시도를 체인과 서비스 양쪽에 걸면?
곱해진다. 3 × 3 = 9번 호출이 될 수 있다. 한 겹만 남겨야 한다.

## 39_문서_파싱

### 파싱 실패 중 가장 위험한 것은 어떤 종류인가?
에러가 나지 않는 실패. 파일이 안 열리면 바로 알지만, **빈 문자열이나 잘린 내용이
성공처럼 돌아오면** 그대로 다음 단계로 흘러간다.

그래서 `parse_local` 은 결과가 비면 성공으로 넘기지 않고 예외를 올린다.

### `pypdf` 로 PDF 를 읽을 때 못 가져오는 것은?
표. 페이지 단위 텍스트만 나오고 표의 행·열 구조가 사라진다.
표를 꺼내려면 `pdfplumber` 가 따로 필요하다.

### `python-docx` 에서 `doc.paragraphs` 와 `doc.tables` 를 따로 읽으면 안 되는 이유는?
**문서 순서가 무너진다.** 문단을 다 모은 뒤 표를 다 모으면, 원래 3번째 문단과
5번째 문단 사이에 있던 표가 맨 뒤로 간다.

`doc.element.body` 의 자식을 순서대로 훑으면서 태그가 `p` 인지 `tbl` 인지로
갈라야 원래 순서가 산다.

## 40_표_추출과_마크다운

### 표를 마크다운 문자열로 바꿔서 저장하는 이유는?
블록 하나가 문자열 하나라는 규칙을 지키기 위해서다. 표만 다른 자료구조로 두면
청킹·임베딩·프롬프트까지 전부 표 전용 분기를 달아야 한다.

마크다운이면 LLM 이 표라는 것도 알아본다.

### `pdfplumber` 가 찾아낸 표 33개를 9개로 줄인 기준은?
행 3개 이상, 열 2개 이상, 빈칸 40% 이하.

`pdfplumber` 는 선으로 표를 찾기 때문에 **줄 긋기만 한 자리도 표로 잡는다.**

## 41_기술_스택_지도

### 도구를 고르는 순서는?
요구가 먼저다. 도구를 먼저 고르고 거기에 요구를 맞추지 않는다.

"문서가 밖으로 나가면 안 된다" 같은 조건이 후보를 자르고, 남은 것 중에서 잰다.

## 42_임베딩_모델_받기

### 임베딩을 API 대신 로컬 모델로 하기로 한 결정적 이유는?
문서가 밖으로 나가는지 여부. 사내 규정에 대외비 등급이 섞여 있어서
**기술 선택이 아니라 보안 결정**이다.

덧붙여 임베딩은 문서를 올릴 때 전부 한 번씩 도니까 호출 수가 문서 수에 비례한다.

### 받은 모델 파일의 크기를 바이트까지 대조하는 이유는?
받다가 끊겨도 파일은 남기 때문. 이름만 보면 다 있는 것 같은데 내용이 잘려 있다.

```text
크기다름: pytorch_model.bin (1,402,653,184 B · 기대 2,271,145,830 B)
```

### `HF_HUB_DOWNLOAD_TIMEOUT` 을 언제 설정해야 하나?
`import` 하기 전에. 라이브러리가 불려 올 때 이 값을 읽는다.

기본값 10초라 GB 단위 파일에서는 끊긴다.

### `bge-m3` 저장소를 통째로 받으면 안 되는 이유는?
`onnx/` 에 같은 가중치 사본이 또 있다(2.27GB). 쓰지도 않는 걸 두 배로 받는다.
`allow_patterns` 로 필요한 것만 집는다.

### `.safetensors` 와 `.bin` 의 차이는?
`.bin` 은 파이썬 객체를 그대로 저장한 형식이라 **여는 것만으로 코드가 실행될 수 있다.**
`safetensors` 는 그게 불가능하도록 만든 형식이다.

`bge-m3` (`.bin`) 를 열려면 torch 2.6 이상이 필요한 것도 이 때문이다.

## 43_HWPX_파싱

### HWPX 파일은 실제로 어떤 형식인가?
ZIP 안에 XML. `zipfile` 로 열고 `ElementTree` 로 읽는다.

한글 전용 라이브러리가 필요 없다.

### HWPX 를 읽을 때 `findall` 과 `iter` 를 나눠 쓰는 이유는?
`findall` 은 바로 아래 자식만 본다 — 문단·표 같은 **구조**를 셀 때 쓴다.
`iter` 는 깊이 상관없이 전부 훑는다 — 글자를 다 긁어모을 때 쓴다.

## 44_파일_형식_분기와_차단

### 확장자로 분기하지 않고 폴더를 통째로 훑으면 무슨 일이 생기나?
못 읽는 파일이 **조용히 빠진다.** 24건 중 20건만 읽히고 4건이 말없이 사라졌다.

에러가 아니라서 아무도 모른다.

### 못 여는 형식(.hwp, .doc)을 만났을 때 `None` 대신 예외를 올리는 이유는?
`None` 은 "없음"과 "실패"를 구별 못 한다. 올린 사람은 성공한 줄 안다.

막을 거면 **올리는 자리에서** 막고 이유를 말해 줘야 한다 — "한글에서 열고 hwpx 로 저장하세요".

## 45_채팅_화면

### Streamlit 에서 대화 이력을 `st.session_state` 에 두는 이유는?
입력이 들어올 때마다 스크립트가 처음부터 다시 돈다. `chat = []` 을 그냥 두면
매번 빈 목록이 되어 한 마디도 안 쌓인다.

`if 'chat' not in st.session_state` 로 감싸서 없을 때만 만든다.

### 대화 이력을 `{"role": ..., "content": ...}` 로 두면 뭐가 좋은가?
Anthropic SDK 의 `messages` 와 같은 모양이다. LangChain 의 `SystemMessage` 도
이걸 객체로 감싼 것이다.

나중에 이력을 모델에 넘겨 이어 대화할 때 변환이 거의 없다.

### 화면이 답변을 받아온 뒤 실패하면 무엇이 남나?
질문만 남는다. `st.error` 는 그 실행에서만 그려지고 `session_state` 에 안 남으니,
다음 재실행에서 **답이 안 온 질문 하나**만 보이고 이유는 사라진다.

user 메시지는 이미 쌓였는데 `return` 으로 assistant 메시지를 안 쌓은 탓이다.

### 백엔드가 주는 `AskOut` 중 화면이 안 쓰는 것 가운데 제일 아쉬운 것은?
`sources`. RAG 11단계의 ⑪ Citation 자리인데 비어 있다.

출처 없이 답만 보여주면 사용자가 답을 확인할 방법이 없고, 규정 답변에서는 그게 전부다.

## 46_블록과_청크

### 블록과 청크는 어떻게 다른가?
| | 무엇 | 누가 정하나 |
| --- | --- | --- |
| 블록 | 파서가 보는 단위 — 문단 하나, 표 하나 | 문서와 파서 |
| 청크 | 검색이 쓸 단위 — 조 하나, 표 하나 | 우리 |

블록은 주어진 것이고 청크는 정하는 것이다.

### 답이 들어 있는 블록 하나만 검색해서 넘기면 뭐가 빠지나?
출처. 실제로 재 보면 이렇다.

```text
고른 블록 : ② 광역시 지역의 숙박비는 1박당 70,000원을 상한으로 한다.
  이 블록 안에 조 표시가 있나 : False
```

"제14조(숙박비)" 는 30번 블록에 9자짜리로 따로 떨어져 있다. 근거를 대려면
조 단위로 묶어야 한다.

### 여비 규정 233개 블록 중 30자도 안 되는 것이 몇 개였나?
131개. 절 제목·조 제목·문서번호 같은 것들이라, 하나씩 검색 단위로 만들면
**뜻이 없는 조각이 결과의 절반**을 차지한다.

### 파서를 고쳐서 블록을 크게 만들지 않는 이유는?
파서는 문서 구조를 그대로 옮기는 일만 하게 두어야 **같은 파서 출력으로
청킹 방식을 여러 개 시험**할 수 있다.

## 47_벡터와_코사인_유사도

### 낱말 비교(LIKE, 자카드)의 한계를 한 줄로?
쓴 사람과 찾는 사람이 같은 단어를 써야만 맞는다.

```text
LIKE '%숙박비%'      → 27건
LIKE '%잠자리%'      → 0건
```

### 코사인 유사도가 거리가 아니라 각도를 보는 이유는?
문장이 길면 벡터가 커진다. 내적만 쓰면 긴 문서가 이긴다.

```text
# 내적만 : d1 0.900  vs  d2 3.000   → d2 승
# 코사인 : d1 0.994  vs  d2 0.707   → d1 승
```

### 코사인 값 +1 / 0 / −1 은 각각 무슨 뜻인가?
+1 같다 · 0 아무 상관 없다 · −1 정반대.

### 정규화한 벡터끼리는 왜 내적만 하면 되나?
크기가 둘 다 1이라 코사인의 분모가 1이 된다.

```text
dot(û, v̂) = 0.960000   cosine(u, v) = 0.960000
```

적재할 때 정규화해 두면 검색은 내적만으로 끝난다.

### 차원이 다른 벡터를 `zip` 으로 비교하면?
예외가 안 난다. 짧은 쪽에서 멈추고 **틀린 값이 그대로 나온다.**

```text
1024차원 vs 768차원 코사인 : 0.8660   ← 1.0 이어야 하는 값
```

### `pgvector` 에서 저장 가능 차원과 색인 가능 차원이 다른 이유가 왜 중요한가?
담기는 16,000, 색인은 2,000. **2,000을 넘기면 저장은 되는데 색인이 안 걸려
검색할 때마다 전부 훑는다.**

데이터가 적을 때는 티가 안 나고 쌓인 뒤에 느려지므로, 차원은 적재 전에 정한다.

## 48_임베딩_모델_비교

### `HF_HUB_OFFLINE` 을 언제 설정해야 먹나?
`import` 보다 먼저. 라이브러리가 불려 올 때 값을 읽는다.

그래서 `embed_compare.py` 는 `sentence_transformers` 를 **함수 안에서** import 한다.

### 모델을 돌리기 전에 문장쌍에 사람이 답을 적어 두는 이유는?
점수만 보면 잘한 것처럼 보인다. 무엇이 나와야 하는지를 먼저 고정해야
결과를 판정할 수 있다.

### 실측에서 두 모델이 공통으로 실패한 것은?
**먼 쌍이 가까운 쌍보다 높게 나왔다.**

| | 가까운 쌍 최저 | 먼 쌍 최고 |
| --- | --- | --- |
| KURE-v1 | 0.6585 | 0.7216 |
| bge-m3 | 0.6573 | 0.7626 |

순서가 뒤집혀 있으니 임계값을 어디에 두어도 옳게 가를 수 없다.

### 그 실패를 모델 탓으로 보지 않은 이유는?
문제의 쌍이 `출장 신청서를 낸다 / 재택근무를 신청한다` 인데 **둘 다 사내 절차를
신청하는 문장**이다. 0.72 가 틀렸다고 보기 어렵다.

거르는 건 ⑧ 필터·리랭킹이 할 일이고 ④ 임베딩이 할 일이 아니다.
즉 문장쌍 6개로는 모델을 평가할 수 없다는 뜻이다.

### 임베딩이 실제로 해낸 것은?
자카드 0.154, `LIKE` 0건이던 `광역시 숙박비 상한 / 잠자리 비용 한도` 가
**0.6585** 로 올라왔다. 글자가 안 겹쳐도 뜻으로 찾는다.

## 49_임베딩_모델_고르기

### 희소(Sparse) 벡터와 밀집(Dense) 벡터의 차이는?
| | 희소 | 밀집 |
| --- | --- | --- |
| 차원 | 어휘 사전 크기 | 1024 고정 |
| 값 | 대부분 0 | 거의 다 0 이 아니다 |
| 한 칸 | 특정 단어 하나 | 대응 단어 없음 |
| 예 | BM25 · `LIKE` | KURE-v1 · bge-m3 |

### bge-m3 의 "Dense + 멀티 벡터"에서 멀티 벡터란?
토큰마다 벡터를 하나씩 내놓는 방식(N×1024). 문장을 하나로 뭉개지 않아
긴 글에서 세부가 덜 죽는다.

대가는 저장량이다 — 조 단위 청크 평균이 65토큰이라 Dense 31.25MB 가 2.00GB 가 된다.

### 우리가 bge-m3 의 멀티 벡터를 쓰고 있나?
아니다. `modules.json` 이 `Transformer → Pooling(CLS) → Normalize` 하나뿐이라
sentence-transformers 로 열면 Dense 만 나온다.

sparse·멀티 벡터를 쓰려면 `FlagEmbedding` 으로 따로 불러야 한다.

### 모델 후보를 자르는 순서는?
조건이 먼저, 측정이 나중.

"문서가 밖으로 나가면 안 된다"가 API 를 자르고, 라이선스·차원이 더 자른 뒤
남은 둘을 잰다. 반대로 하면 못 쓸 모델을 재느라 시간을 쓴다.

### 차원과 벡터 개수 중 저장량을 더 크게 흔드는 것은?
벡터 개수. 차원을 4배(1024→4096)로 올리면 4배지만,
멀티 벡터로 바꾸면 토큰 수만큼 — 실측 65배다.

## 50_청킹_규칙

### 글자 수로만 자르면 표에 무슨 일이 생기나?
머리행과 본문이 갈린다. 1,200자로 끊어 보니 표 7개 중 2개가 두 조각이 됐다.

```text
앞 조각에 머리행이 있나 : True
뒤 조각에 머리행이 있나 : False
```

뒤 조각에는 열 이름이 없어서 `| 국내선 항공 | 일반석 | 실비 |` 만 검색되면 뜻을 알 수 없다.

### `RecursiveCharacterTextSplitter` 를 쓰면 표가 안 갈리나?
갈린다. 같은 표 2개가 그대로 갈렸다.

**줄 경계는 알아도 표라는 것은 모른다.** 한도를 넘으면 줄 사이 어디든 끊는다.
문서 구조를 아는 쪽이 먼저 갈라 주어야 한다.

### "표는 자르지 않는다"는 규칙의 비용은?
0이다. 가장 긴 표가 378자로 한도(1,200)의 3분의 1이라, 통째로 둬도 청크가 커지지 않는다.

### `re.split` 에서 조 제목 패턴을 괄호로 감싸야 하는 이유는?
안 감싸면 **조 제목이 결과에서 사라져** 출처를 못 적는다.

```text
캡처 ()    ['', '제1조(목적)', ' 이 규정은…', '제8조(일비)', ' 일비는…']
비캡처 (?:) ['', ' 이 규정은…', ' 일비는…']        ← 제목이 없다
```

안쪽까지 감싸면 그룹이 셋이 되어 홀짝으로 짝짓는 규칙이 깨진다.

### `TOC_BODY_MIN` 이 왜 필요한가?
목차 줄을 거르기 위해서다. 문서 앞쪽 목차가 조 제목과 똑같이 생겨서 본문처럼 잡힌다.

```text
('제1조(목적)', '제1조(목적)')   ← 본문이 없다
```

실제로 46개가 이렇게 잡혔다. 거르지 않으면 청크가 53개에서 99개로 늘고
평균 글자 수가 156자에서 83자로 떨어진다.

### `_hard_wrap` 의 `separators` 에 `"다. "` 가 들어 있는 이유는?
한국어 규정 문장이 `~한다.` 로 끝나므로 거기서 문장 경계가 잡힌다.
`keep_separator="end"` 로 그 `"다. "` 를 앞 조각 끝에 남겨 문장이 온전히 끝나게 한다.

### 문장 안의 상호참조가 조 제목으로 잡히는 것을 어떻게 막았나?
괄호 제목을 선택(`?`)이 아니라 **필수**로 바꿨다.

```python
_ARTICLE = re.compile(r"^[ 	]*(제\s*\d+\s*조(?:의\s*\d+)?\s*\([^)
]{1,30}\))", re.M)
```

`제32조 에 따라 반환한다` 는 괄호 제목이 없어서 안 걸린다. 조각이 101개에서 74개로 줄었다.

대가는 `제5조` 처럼 제목 없이 번호만 있는 조를 못 잡는 것이다.

### `chunk()` 가 표를 만나면 `flush()` 를 먼저 부르는 이유는?
본문 순서를 지키기 위해서다. 안 그러면 표가 앞서 나오고 앞에 쌓인 본문이 뒤로 밀린다.

본문을 `buffer` 에 모으는 것은 **조 하나가 여러 블록에 걸칠 수 있어서**다.

### 장·절 제목 정규식의 끝을 `$` 로 막는 이유는?
줄 전체가 제목인 줄만 잡기 위해서다.

```python
_HEADING = re.compile(r"^[ \t]*(?:(제\s*\d+\s*장)|(제\s*\d+\s*절)|(부\s*칙))(?:[ \t]+[^\n]{1,30})?[ \t]*$")
```

안 막으면 `④ … 제4장의 특례를 적용한다` 같은 문장이 장 제목으로 잡힌다.

### 장이 바뀔 때 절을 비우는 이유는?
안 비우면 앞 장의 절이 다음 장에 따라붙는다.

`제3장 제3절` 다음에 `제4장` 이 오면 `제4장 제3절` 이 되어 버린다.

### `where` 를 `chunk()` 가 만들어 `flush()` 사이에 돌려 쓰는 이유는?
표를 만날 때마다 `flush()` 가 돈다. 그때마다 위치가 초기화되면
**표 뒤에 오는 조들이 장 정보를 잃는다.**

여비 규정은 표가 7개라 `flush()` 가 8번 돈다.

### 장 제목 줄은 본문에서 빼는데 `[별표2]` 줄은 남기는 이유는?
장 제목은 locator 로 올라가므로 본문에 남으면 같은 정보가 두 번 실린다.
반면 `[별표2]` 는 **그 줄 자체가 별표의 시작**이라 내용의 일부다.

별표·서식은 장 밖이므로 장·절 정보는 버리고 별표 이름만 위치로 쓴다.

### 조 하나가 쪼개졌을 때 어느 조의 몇 번째인지 어떻게 남기나?
locator 뒤에 `(1/2)` 를 붙인다.

```python
suffix = f' ({i + 1}/{len(pieces)})' if len(pieces) > 1 else ''
```

### 완성된 chunker 가 여비 규정 하나를 몇 청크로 만드나?
53개다.

```text
조항 단위 46 + 표 단위 7 = 53 청크
청크 글자 수 : 최대 653 · 최소 17 · 평균 156.4
```

조항 46개 중 35개가 장 정보를 갖고, 남은 11개는 장이 없는 게 맞는 것들이다
— 문서 머리말, 부칙, 별표·서식.

### locator 가 `제1장 제2조(정의) · 별표2` 까지 나오는 게 왜 중요한가?
장, 조, 그 조가 가리키는 별표가 한 줄에 다 들어간다.
[[45_채팅_화면]]에서 비어 있던 ⑪ Citation 에 그대로 적을 수 있다.

## 51_청킹_테스트와_형식_차이

### 청킹 테스트 셋이 실제 파일을 열지 않고 `ParsedDoc` 를 손으로 만드는 이유는?
파서를 지나지 않고 **청킹만** 재기 위해서다. 실제 파일로 재면 문서가 바뀔 때
청킹이 멀쩡한데도 테스트가 깨진다.

조 하나가 블록 셋에 걸친 상황도 세 줄로 만들 수 있다.

### "표는 길이를 무시한다"를 실문서로 확인할 수 없는 이유는?
가장 긴 표가 378자로 한도(1,200)에 한참 못 미친다. 그냥 돌리면
**규칙이 작동한 건지 길이가 짧아서 안 걸린 건지 구별이 안 된다.**

그래서 120행짜리 표를 만들어 한도를 확실히 넘긴 뒤 잰다.

### `summarize(a) == '조항 단위 46 + 표 단위 7 = 53 청크'` 처럼 숫자를 박아 두는 이유는?
모르는 사이에 53이 99가 되는 것을 막는다. 규칙을 고치면 이 단언도 고쳐야 하는데,
**고칠 때 왜 달라졌는지 설명할 수 있어야 한다**는 것이 목적이다.

### 같은 규정을 세 형식으로 청킹하면?
HWPX 와 DOCX 는 완전히 같고 PDF 만 다르다.

```text
[hwpx] blocks=233 tables=7 → 조항 46 + 표 7 = 53 청크
[docx] blocks=233 tables=7 → 조항 46 + 표 7 = 53 청크
[pdf ] blocks= 16 tables=0 → 조항 45 + 표 0 = 45 청크
```

### HWPX 와 DOCX 결과가 같아야 하는 이유는?
같지 않으면 **같은 규정을 hwpx 로 올린 사람과 docx 로 올린 사람이 다른 답을 받는다.**

파서 코드는 전혀 다르다(ZIP+XML vs python-docx). 그래도 같은 `ParsedDoc` 을 만들어야
한다는 계약이라 테스트로 고정했다.

### PDF 에서 표가 어디로 가나?
사라지지 않고 **조항 청크 안의 평문**이 된다.

```text
docx  표 | 표2        ← 마크다운 표
pdf   조항 | 별표1      ← 평문
```

숫자는 들어 있지만 어느 열의 값인지가 없다. 마크다운 표 기호 `|` 가 docx 323개, pdf 0개다.

### 청킹 규칙과 파서의 관계를 한 줄로?
**"표는 자르지 않는다"는 파서가 표라고 알려 줬을 때만 작동한다.**

PDF 에는 `kind == '표'` 인 블록이 없으니 이 규칙은 한 번도 실행되지 않는다.
조 규칙은 조 제목이 글자로 남아 있어서 PDF 에서도 돈다.

### PDF 표를 살리려면 어디를 고쳐야 하나?
파서다. `pdfplumber` 를 `parse_pdf` 에 넣으면 PDF 도 `표` 블록을 갖게 되고
**청킹 규칙은 손대지 않아도 된다.**

### 재료 파일이 없을 때 실패가 아니라 `pytest.skip` 을 쓰는 이유는?
파일이 빠진 것과 청킹이 틀린 것은 다른 문제다. 섞어 놓으면
빨간불의 원인을 찾느라 시간을 쓴다.

## 52_파서_진입점과_형식_확장

### `.txt` 가 `parse_local` 에서 막히는 게 왜 이상한가?
**글자가 이미 다 있는데 파서를 찾다가 막혔다.**

```text
[그냥 읽으면]  71자      ← 읽히긴 읽힌다
[parse_local 에 넣으면]  ValidationFailed: 지원하지 않는 형식입니다: .txt
```

`.txt`·`.md` 는 파싱할 것이 없고 `.xlsx`·`.pptx` 는 전용 라이브러리가 필요하다.
같은 "못 읽음" 이 아니라서 처리도 달라야 한다 — 그래서 진입점을 따로 뒀다.

### `parser.parse()` 의 분기 순서는?
1. `.txt`·`.md` → `_parse_plain`
2. `.html`·`.htm` → `_parse_html`
3. `use_upstage` 가 참이고 `_LOCAL_ONLY` 가 아니면 → 상용 API
4. 나머지 → `parse_local`

### `_LOCAL_ONLY` 가 상용 API 조건 **뒤**에 오는 이유는?
한글 문서는 **스위치를 켜도 밖으로 보내지 않는다.**

```text
…v2.0.hwpx  -> parse_local  (그대로)
sample_table.xlsx -> upstage  (바뀐다)
```

보안 결정이라 설정으로 뒤집지 않는다.

### `_parse_plain` 이 `errors="replace"` 를 쓰는 이유는?
인코딩이 틀린 글자를 `?` 로 바꿔 넣는다. 예외를 올리는 대신 읽히는 만큼 읽어서,
**메모 한 줄 때문에 적재 전체가 멈추지 않게** 한다.

### 마크다운을 `\n\n` 으로 자르면 뭐가 문제인가?
제목이 독립 블록이 된다.

```text
[2] 8자 : ## 1. 신청
[4] 8자 : ## 2. 승인
```

제목만 있고 내용이 없는 조각이 검색 단위가 된다([[46_블록과_청크]]).
제목을 다음 문단에 붙여야 하는데 아직 안 했다.

### HTML 에서 태그를 한 번에 지우면?
전부 한 줄이 되고 **표가 본문에 녹는다.**

```text
… 날짜 당직자 연락처 10/03 김민준 내선 2201 10/04 이서연 내선 2202
블록 1개
```

어디가 열 이름이고 어디가 값인지 알 수 없다.

### HTML 파서의 순서는?
**표를 먼저 떼어내고** 본문을 정리한다.

```python
tables = re.findall('<table.*?</table>', raw, flags=re.S|re.I)   # 모아 두고
body = re.sub('<table.*?</table>', ' ', raw, flags=re.S|re.I)    # 본문에서 뺀다
```

`<script>`·`<style>` 을 먼저 지우는 것은 그 안의 글자가 본문이 아니기 때문이다.
자바스크립트 코드가 규정 문장처럼 검색되면 안 된다.

### `<(script|style)[^>]*>.*?</\1>` 의 `\1` 은 무엇인가?
앞에서 잡은 태그 이름을 다시 쓰는 역참조다.
`<script>` 를 `</style>` 로 닫는 짝이 생기지 않게 한다.

### `parse_xlsx` 에서 `data_only=True` 가 필요한 이유는?
수식이 아니라 **계산된 값**을 가져온다. 끄면 `=SUM(B2:B4)` 가 그대로 나와서
검색에 쓸 수 없다.

### XLSX 의 `locator` 로 시트 이름을 쓰는 이유는?
출처가 `출장비 집계` 가 된다. 파일명보다 어디서 왔는지가 분명하다.
표 변환은 [[40_표_추출과_마크다운]]의 `_table_to_markdown` 을 그대로 재사용한다.

### 엑셀에서 첫 행을 머리행으로 쓰는 것의 한계는?
엑셀에 머리행이라는 개념이 따로 없다. **첫 행이 머리행이라고 정한 것**이고,
그렇지 않은 시트에서는 어긋난다.

### `_parse_html` 이 표를 튜플로 넣으면 어떻게 되나?
노트북에서 블록 수·글자 수만 찍으면 멀쩡해 보인다. 튜플도 `len()` 이 되기 때문이다.
그런데 `.kind` 를 보는 쪽에서 무너진다.

```text
AttributeError: 'tuple' object has no attribute 'kind'
```

`chunk()` 가 블록마다 `block.kind == "표"` 를 보므로 청킹에서 바로 터진다.
`ParsedBlock` 으로 감싸야 한다.
