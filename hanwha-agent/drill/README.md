# drill — 스스로 코드를 쓰게 하는 연습 도구

강사님 코드를 따라 치는 대신, **요구사항만 보고 백지에서 짜 보는** 연습장입니다.
맞았는지는 사람이 아니라 `pytest` 가 판정합니다.

지금 문제 9개가 있습니다 (개념 노트 03~28).

---

## 1. 시작하기

터미널을 열고 **`hanwha-agent` 폴더에서** 아래를 차례로 칩니다.

### ① 어떤 문제가 있는지 본다

```bash
python drill/run.py 목록
```

```text
문제               상태     제목
--------------------------------------------------------------------
03_스키마                  요청·응답 스키마 — 제약을 타입에 박아 넣는다
05_예외계층                 예외 계층 — 한 번 잡아서 HTTP 로 번역한다
...
24_원가계산                 원가 계산 — 출력이 입력보다 다섯 배 비싸다
...
```

### ② 문제를 하나 받는다

처음이라면 **`24_원가계산`** 으로 시작하세요. 제일 작습니다.

```bash
python drill/run.py 풀기 24_원가계산
```

```text
24_원가계산 — 원가 계산 — 출력이 입력보다 다섯 배 비싸다
  요구사항 : ...\drill\problems\24_원가계산\요구사항.md
  답안 파일 : ...\drill\작업\24_원가계산\시작.py  (새로 받았습니다)

다 쓰면 :  python drill/run.py 채점 24_원가계산
```

**경로가 둘 찍힙니다. 앞의 것을 읽고, 뒤의 것을 고칩니다.**

### ③ 다 쓰면 채점한다

```bash
python drill/run.py 채점 24_원가계산
```

## 2. 어디서 푸나

```text
drill/
├── problems/           문제. 읽기만 합니다
│   └── 24_원가계산/
│       ├── 요구사항.md    ← ① 이걸 읽고
│       ├── test_문제.py   ← ② 이걸 봐도 됩니다 (채점 기준)
│       ├── 시작.py         빈 서식 (건드리지 않습니다)
│       └── 문제.json       메타
│
└── 작업/               ← ③ 여기서 씁니다
    └── 24_원가계산/
        └── 시작.py        ★ 고칠 파일은 이것 하나
```

`풀기` 를 하면 `drill/작업/<문제>/시작.py` 가 생깁니다. **고칠 파일은 그것 하나입니다.**

파일을 열면 이런 구분선이 있습니다.

```python
# ══════ 여기부터 직접 채운다 ══════
```

위쪽은 준비물(import·이미 만들어 둔 예외 클래스 등)이니 그대로 두고 **아래에만** 씁니다.

> `drill/작업/` 은 `.gitignore` 에 있습니다. 답안은 커밋되지 않으니 마음껏 고쳐도 됩니다.

## 3. 한 문제, 처음부터 끝까지

### 채점 — 아직 아무것도 안 썼을 때

```text
FAILED test_문제.py::test_단가표와_환율이_이름으로_있다 - AttributeError: module '시작' ...
FAILED test_문제.py::test_토큰이_없으면_0원 - AttributeError: module '시작' has ...
6 failed in 0.10s

아직입니다. 위 실패 사유를 보고 고쳐서 다시 채점하세요.
```

실패한 테스트 이름이 곧 할 일 목록입니다. `단가표와_환율이_이름으로_있다` → 상수 두 개부터 만들면 됩니다.

### 채점 — 통과했을 때

```text
......                                                                   [100%]
6 passed in 0.03s

통과했습니다. 이제 원본과 대봅니다 — 통과가 곧 잘 쓴 코드는 아닙니다.

--------------------------------------------------------------------
--- estimate_cost_krw (내 답안)
+++ estimate_cost_krw (원본)
@@ -1,3 +1,5 @@
+# 호출 한 번의 비용을 원화로 어림 잡아 계산
+# - 캐시 쓰기/읽기 단가는 아직 반영하지 않는다 (입력은 전부 input 단가로 계산한다)
 def estimate_cost_krw(input_tok: int, output_tok: int) -> float:
-    비용 = input_tok * PRICING["input"] + output_tok * PRICING["output"]
-    return round(비용 / 1_000_000 * USD_KRW, 1)
+    usd = input_tok / 1000000 * PRICING['input'] + output_tok / 1000000 * PRICING['output']
+    return round(usd * USD_KRW, 1)
--------------------------------------------------------------------
개념 노트 : concepts/2_AI-Native_아키텍처_테스트/24_API_토큰과_과금.md
```

**여기가 이 도구의 핵심입니다.** `-` 가 내 답안, `+` 가 원본입니다.

테스트는 통과했는데 원본에는 주석이 붙어 있습니다 — *왜 캐시 단가를 아직 안 넣었는지*. 테스트로는 절대 안 잡히는 것이고, 대보지 않으면 모르고 지나갑니다.

마지막 줄의 개념 노트를 열어 그날 정리를 다시 읽으면 한 바퀴가 끝납니다.

## 4. 명령어

| 명령 | 하는 일 |
| --- | --- |
| `python drill/run.py 목록` | 문제 전부. 푸는 중인 것은 `작업중` 으로 표시 |
| `python drill/run.py 풀기 <문제>` | 답안 파일을 깔아준다. **이미 있으면 안 건드린다** |
| `python drill/run.py 풀기 <문제> --다시` | 답안을 버리고 처음 상태로 되돌린다 |
| `python drill/run.py 채점 <문제>` | pytest → 통과하면 원본과 diff |
| `python drill/run.py 검증` | 문제 자체가 멀쩡한지 확인 (7절 참고) |

## 6. 막혔을 때

**무엇을 만들어야 하는지 모르겠다**
`problems/<문제>/요구사항.md` 를 다시 읽습니다. "만들 것" 표에 이름·인자·반환이 다 적혀 있습니다.

**요구사항은 알겠는데 조건이 애매하다**
`problems/<문제>/test_문제.py` 를 열어 봐도 됩니다. **숨기지 않습니다.** 실무에서도 요구사항은 주어집니다 — 모르는 건 구현이지 조건이 아닙니다.

**에러 메시지가 뭘 말하는지 모르겠다**
`AttributeError: module '시작' has no attribute 'xxx'` 는 *아직 `xxx` 를 안 만들었다* 는 뜻입니다.

**개념이 가물가물하다**
개념 노트를 먼저 읽습니다. 문제마다 `문제.json` 에 노트 경로가 적혀 있고, 통과하면 마지막 줄에도 찍힙니다.

**그래도 안 되면**
`문제.json` 의 `정답.파일` 을 열면 원본이 있습니다. 보고 나면 며칠 뒤에 `--다시` 로 한 번 더 푸는 걸 권합니다.

## 7. 설계 — 왜 이렇게 만들었나

### 채점은 pytest 가 한다. LLM 이 아니다

LLM 채점은 돈이 들고, 채팅에서 물어보는 것과 같고, 무엇보다 **애매하게 맞았다고 해줍니다.** pytest 는 안 봐줍니다.

이 저장소엔 이미 채점기가 있었습니다.

| 파일 | 줄 | 무엇을 보는가 |
| --- | --- | --- |
| [test_layers.py](../backend/tests/test_layers.py) | 119 | 계층 구조가 무너졌는지 |
| [test_chat_golden.py](../backend/tests/test_chat_golden.py) | 129 | 응답이 조건을 만족하는지 |
| [test_guards.py](../backend/tests/test_guards.py) | 29 | 가드가 막아야 할 걸 막는지 |
| [test_exceptions.py](../backend/tests/test_exceptions.py) | 49 | 예외가 HTTP 로 옳게 번역되는지 |

문제의 채점기는 여기서 가져오거나 같은 방식으로 새로 쓴 것입니다.

### 문제를 파일 하나로 좁힌다

`backend/tests` 의 테스트는 `from app.services import chat_service` 로 **진짜 패키지**를 부릅니다. 그대로 쓰면 내가 쓴 코드가 아니라 원본을 채점하게 됩니다.

| 방법 | 결과 |
| --- | --- |
| 원본을 답안으로 덮어쓴다 | 원본이 날아간다 |
| `app` 을 통째로 복사하고 한 파일만 바꾼다 | 느리고 DB 설정까지 딸려온다 |
| **문제를 파일 하나로 좁힌다** | 제약이 생긴다 — 그리고 그 제약이 맞다 |

그래서 "`chat_service` 를 짜라"가 아니라 "재시도 힌트와 폴백을 짜라"입니다. `ask()` 는 가드·팩토리·관측·DB·재시도가 한자리에 모인 함수라 통째로는 연습 문제가 안 됩니다. **한 번에 하나만 생각합니다.**

### 정답 파일은 두지 않는다

폴더에 `정답.py` 가 있으면 편집기 탭에서 그냥 보입니다. 대신 `문제.json` 에 **위치만** 적습니다.

```json
"정답": {
  "파일": "backend/app/core/guards.py",
  "함수": ["MIN_QUESTION_LEN", "ALLOWED_MODELS", "check_question", "check_model", "check_daily_limit"]
}
```

필요할 때 `ast` 로 이름을 찾아 잘라 옵니다. 줄 번호가 아니라 **이름**이라 위쪽 코드가 밀려도 안 깨지고, 원본을 고치면 정답도 따라 바뀝니다. 같은 코드가 두 곳에 있지 않습니다.

`ast` 로 코드를 읽는 건 [test_layers.py](../backend/tests/test_layers.py) 가 이미 쓰는 기법이라 새로 배울 게 없습니다.

### 검증 — 문제가 틀렸는지 먼저 본다

```bash
python drill/run.py 검증
```

`시작.py` 의 머리말에 **원본 함수를 그대로 붙여 넣고** 채점기를 돌립니다. 여기서 실패하면 틀린 것은 푸는 사람이 아니라 문제입니다.

정답을 저장해 두는 게 아니라 **그때그때 원본에서 잘라 오는** 것이라 위의 원칙과 어긋나지 않습니다.

문제를 만들면서 실제로 두 번 걸렸습니다.

| 걸린 것 | 무엇이 틀렸나 |
| --- | --- |
| `17_비밀번호` | 채점기가 `verify_password(raw, None)` 에 `False` 를 요구했는데, 원본은 `(ValueError, TypeError)` 만 잡아 `AttributeError` 가 샌다 |
| `12_리포지토리` | 한 행이 문서가 아니라 **버전**이라, 버전 2개짜리 문서를 1행으로 센 기대값이 틀렸다 |

둘 다 채점기가 원본보다 많은 것을 요구한 경우입니다. 못 잡았으면 **아무리 잘 짜도 통과할 수 없는 문제**가 남았을 겁니다.

### 요구사항.md 쓰는 법

문제를 새로 만들 때의 기준입니다. 여기가 진짜 일이고 도구가 대신 못 해줍니다.

| 적는다 | 안 적는다 |
| --- | --- |
| 무엇을 만족해야 하는가 | 어떤 함수를 어떤 순서로 부를지 |
| 판정 기준 (테스트가 뭘 보는지) | 원본 코드 조각 |
| 왜 이게 필요한가 | 힌트 |

### 화면이 얇아지는 이유

판정이 전부 `run.py` 안에 있습니다.

```python
def 채점(문제id: str) -> dict:
    # {"문제", "제목", "통과": bool, "출력": str, "diff": dict | None, "개념": str}
```

CLI 는 이 dict 를 출력만 합니다. Streamlit 도 같은 함수를 부르고 `st.write` 만 하면 됩니다. **화면에 판정 로직이 들어가는 순간 이 설계는 깨집니다.**

### 정한 것

- **답안(`drill/작업/`)은 커밋하지 않는다.** 남는 것은 문제와 채점기이고, 답안은 매번 새로 쓰는 게 요점입니다. 남기고 싶으면 `.gitignore` 에서 한 줄 지우면 됩니다
- **다시 풀면 덮어쓴다.** `풀기` 는 이미 있는 답안을 건드리지 않고, `--다시` 를 줘야 되돌립니다
- **채점기는 매번 원본으로 덮어쓴다.** 채점기를 고쳐서 통과시키는 일이 없도록

### 남은 것

- **화면(Streamlit)** — 설계대로 마지막입니다. `채점()` 이 dict 를 주므로 `text_area` + 버튼 + `write` 면 됩니다
- **과목 3 이후 문제** — 체인·RAG 가 `backend/app/agent/` 에 자리를 잡은 뒤에 붙입니다
- **골든형 문제** — RAG·에이전트는 pytest 로 못 잡습니다. 정답이 문자열 하나가 아니라서요. 그건 [[29_골든셋_회귀테스트]]에서 이미 푼 문제라 `golden.json` + 판정 함수로 갑니다. 형식은 4과목 수업을 듣고 확정합니다

참고: drill/run.py, drill/problems/, backend/tests/, concepts/2_AI-Native_아키텍처_테스트/29_골든셋_회귀테스트.md
