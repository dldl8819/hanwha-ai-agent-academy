# 예외 계층

앱이 던지는 예외를 한 뿌리에서 갈라 놓는다. 그래야 라우터에서 **한 번만 잡아** HTTP 응답으로 번역할 수 있다.

## 만들 것

### `AgentError` — 모든 예외의 뿌리
| 갖출 것 | 값 |
| --- | --- |
| `status_code` | `400` |
| `code` | `"agent_error"` |
| `message` | 생성자로 받은 메시지 |
| `detail` | 선택. 기본값 `None` |

- `detail` 은 **키워드로만** 받는다 (`AgentError("x", "y")` 는 `TypeError`)
- `print(e)` · `str(e)` 했을 때 메시지가 그대로 나와야 한다

### 하위 예외

| 클래스 | status_code | code |
| --- | --- | --- |
| `NotFound` | 404 | `not_found` |
| `GuardTripped` | 400 | `guard_tripped` |
| `RateLimited` | 429 | `rate_limited` |
| `AuthFailed` | 401 | `auth_failed` |

`AuthFailed` 만 다르다. **메시지를 안 줘도 만들어져야 한다.** 로그인 실패는 어디서 던지든 사용자에게 같은 문장을 보여줘야 하기 때문이다 — 사번이 틀렸는지 비밀번호가 틀렸는지 알려주면 안 된다.

## 채점이 보는 것

- 하위 예외가 전부 `AgentError` 로 잡히는가
- `status_code` · `code` 가 표대로인가
- `str(e)` 가 메시지인가
- `detail` 이 키워드 전용인가
- `AuthFailed()` 가 인자 없이 만들어지고, 비어 있지 않은 기본 메시지를 갖는가

## 왜 이렇게 하는가

라우터마다 `try/except` 를 달면 빠뜨린 자리가 생긴다. 뿌리를 하나 두면 **예외 처리기 한 곳**에서 `e.status_code` 와 `e.code` 만 읽어 응답을 만들 수 있다. 새 예외를 추가해도 처리기는 고치지 않는다.
