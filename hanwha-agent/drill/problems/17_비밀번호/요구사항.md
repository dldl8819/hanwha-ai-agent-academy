# 비밀번호 해싱

평문을 저장하지 않는다. 대신 **되돌릴 수 없는 값**으로 바꿔 저장하고, 로그인할 때는 다시 해싱해서 비교한다.

## 만들 것

### `hash_password(raw: str) -> str`
평문을 받아 저장할 문자열을 돌려준다.

- 같은 평문을 두 번 해싱하면 **서로 다른 값**이 나와야 한다
- DB 에 넣을 것이므로 `bytes` 가 아니라 `str` 을 돌려준다

### `verify_password(raw: str, hashed: str) -> bool`
평문과 저장된 값이 맞는지 `True` / `False` 로만 답한다.

- `hashed` 가 **문자열이되** 해시 형식이 아니면 **예외를 밖으로 내보내지 않고** `False` 를 돌려준다
  (`bcrypt` 가 던지는 `ValueError` · `TypeError` 를 받아낸다)

## 채점이 보는 것

- 해시가 평문과 다른가
- 같은 평문의 해시 두 개가 서로 다른가
- 맞는 비밀번호 `True`, 틀린 비밀번호 `False`
- 빈 문자열·깨진 값·평문을 `hashed` 로 줬을 때 예외 없이 `False`
- 한글·이모지 같은 비ASCII 평문이 되는가

## 왜 이렇게 하는가

**같은 평문인데 해시가 달라야 하는 이유**가 이 문제의 전부다. 매번 같은 값이 나오면 해시 목록만 봐도 "이 둘은 같은 비밀번호를 쓴다"가 드러나고, 미리 계산해 둔 표로 원문을 되찾을 수 있다. 그래서 매번 다른 소금을 섞는다.

`verify` 가 예외를 삼키는 것도 같은 성격이다. DB 값이 깨졌을 때 로그인 화면이 500 으로 죽으면, **그 오류 자체가 "이 계정은 뭔가 다르다"는 정보**가 된다.
