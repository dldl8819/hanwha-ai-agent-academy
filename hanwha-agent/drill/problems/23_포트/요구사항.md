# 포트와 어댑터

서비스가 Claude 를 직접 부르면 모델을 바꿀 때 서비스를 고쳐야 한다. 사이에 **규약**을 하나 두고, 서비스는 그 규약만 알게 한다.

## 만들 것

### `LLMResult` — 호출 한 번의 결과
데이터클래스로 만든다.

| 필드 | 타입 | 기본값 |
| --- | --- | --- |
| `text` | `str` | 없음 (필수) |
| `model` | `str` | 없음 (필수) |
| `input_tok` | `int` | `0` |
| `cache_tok` | `int` | `0` |
| `output_tok` | `int` | `0` |
| `cost_krw` | `float` | `0.0` |
| `latency_ms` | `int` | `0` |
| `extras` | `dict` | 빈 딕셔너리 |

`extras` 기본값을 `{}` 라고 그냥 적으면 **모든 인스턴스가 같은 딕셔너리를 공유한다.**

### `LLMPort` — 어댑터가 지켜야 할 규약
`Protocol` 로 만들고, `isinstance()` 로 확인할 수 있게 한다.

```python
def answer(self, *, question: str, contexts: list[dict], user: dict) -> LLMResult: ...
```

세 인자는 **키워드 전용**이다.

## 채점이 보는 것

- `LLMResult(text=..., model=...)` 만으로 만들어지고 나머지가 기본값인가
- 인스턴스 둘의 `extras` 가 **서로 다른 객체**인가
- `isinstance(어댑터, LLMPort)` 가 동작하는가
- 규약대로 만든 어댑터를 키워드로 불렀을 때 `TypeError` 가 나지 않는가

## 왜 이렇게 하는가

`runtime_checkable` 인 `Protocol` 은 **메서드 이름만 본다.** 인자 이름이 달라도 `isinstance` 는 통과하고, 실제로 부를 때가 되어서야 `TypeError` 가 난다.

그래서 채점기도 `isinstance` 만 보지 않고 **실제로 불러 본다.** 눈으로 읽으면 맞아 보이고 실행해야 틀린 게 드러나는 종류라서, 이 문제는 테스트가 없으면 통과했다고 착각하기 쉽다.
