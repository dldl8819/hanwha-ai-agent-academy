# 재시도 힌트와 폴백

모델 응답이 스키마를 어기면 다시 부른다. 그냥 다시 부르면 같은 실수를 반복하므로 **무엇이 틀렸는지 알려주고** 다시 부른다. 세 번 다 실패하면 정해둔 답으로 대신한다.

`AskOut` 은 머리말에 있다.

## 만들 것

### `FALLBACK_ANSWER`
세 번 다 실패했을 때 사용자에게 보여줄 문장. 비어 있지 않은 문자열이면 된다.

내부 사정(스키마·검증·재시도 같은 말)을 사용자에게 흘리지 않는다.

### `_hint_from(errors: list[dict]) -> str`
Pydantic 이 돌려준 오류 목록을 **모델에게 다시 보낼 한 줄**로 만든다.

오류 하나는 이런 모양이다.

```python
{"loc": ("sources", 0, "doc_id"), "msg": "Field required"}
```

| 규칙 | |
| --- | --- |
| 한 건의 모양 | `위치: 메시지` |
| 위치가 여러 단계면 | `.` 으로 잇는다 → `sources.0.doc_id` |
| 위치가 비어 있으면 | `(최상위)` |
| 여러 건이면 | `/` 로 잇는다 |

### `_fallback(run_id: str, attempts: int) -> AskOut`
사용자에게 돌려줄 최종 응답을 만든다.

| 필드 | 값 |
| --- | --- |
| `answer` | `FALLBACK_ANSWER` |
| `sources` | 빈 목록 |
| `enough_evidence` | `False` |
| `run_id` | 받은 값 |
| `attempts` | 받은 값 |
| `fallback_used` | `True` |

## 채점이 보는 것

- 오류 한 건·여러 건·중첩 위치·빈 위치가 규칙대로 조립되는가
- `_fallback` 이 **예외가 아니라 정상 응답 객체**를 돌려주는가
- `fallback_used` 로 폴백인지 구분되는가
- 폴백 문장에 내부 용어가 섞이지 않았는가

## 왜 이렇게 하는가

**폴백이 예외가 아니라 정상 응답인 것**이 핵심이다. 화면은 평소와 같은 모양의 데이터를 받으니 깨지지 않는다. 대신 `fallback_used` 를 보고 "근거를 찾지 못했습니다" 같은 표시를 따로 붙일 수 있다.

예외로 던지면 화면이 500 을 받고, 사용자는 왜 실패했는지 모른 채 빈 화면을 본다. **실패를 숨기는 게 아니라, 실패한 채로 정상 경로를 타게 하는 것**이다.
