# 요청·응답 스키마

채팅 API 가 주고받는 모양을 Pydantic 모델로 정의한다. 검사 코드를 따로 쓰지 않고 **타입과 제약만으로** 걸러지게 하는 것이 목적이다.

## 만들 것

### `DOC_ID`
인용할 수 있는 문서 번호. 지금은 세 건으로 고정한다.

```
DOC-HR-014   DOC-PU-007   DOC-SE-003
```

목록에 없는 번호는 **검증에서 걸려야 한다.** `str` 로 두고 나중에 `if` 로 검사하는 방식은 안 된다.

### `ChatRequest` — 들어오는 것
| 필드 | 조건 |
| --- | --- |
| `question` | 문자열. 2자 이상 2000자 이하 |

### `AnswerSource` — 근거 한 건
| 필드 | 조건 |
| --- | --- |
| `doc_id` | 위의 `DOC_ID` |
| `title` | 문자열 |
| `version` | 문자열 |
| `locator` | 문자열 |

### `AnswerOut` — 모델이 돌려줘야 하는 모양
| 필드 | 조건 |
| --- | --- |
| `answer` | 문자열 |
| `sources` | `AnswerSource` 목록 |
| `enough_evidence` | 불리언 |

세 필드 모두 **필수**다. 기본값을 주면 모델이 빠뜨렸을 때 그냥 통과한다.

## 채점이 보는 것

- 2자 미만·2000자 초과 질문이 거부되는가
- 등록되지 않은 `doc_id` 가 거부되는가
- `sources` 안쪽 항목까지 검증되는가 (문자열 목록이 아니라 모델 목록인가)
- 필수 필드를 빠뜨렸을 때 거부되는가
- `/docs` 에 설명이 뜨도록 각 필드에 `description` 을 달았는가

## 왜 이렇게 하는가

모델은 시키는 대로만 답하지 않는다. 없는 문서 번호를 지어내는 일이 실제로 생긴다. 그걸 `if` 로 막으면 검사를 빠뜨린 자리가 생기지만, 타입으로 막으면 **빠뜨릴 자리가 없다.**
