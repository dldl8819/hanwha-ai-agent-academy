# 가드

모델에 보내기 **전에** 거른다. 보내고 나서 거르면 이미 돈이 나간 뒤다.

설정(`get_settings()`)과 예외(`GuardTripped` · `RateLimited`)는 머리말에 있다.

## 만들 것

### `MIN_QUESTION_LEN`
질문의 최소 길이. `2`

### `ALLOWED_MODELS`
쓸 수 있는 모델 이름의 집합. 지금은 `claude-haiku-4-5` 하나.

막을 것을 나열하지 말고 **쓸 수 있는 것만** 적는다.

### `check_question(text) -> str`
통과하면 **앞뒤 공백을 걷어낸 질문**을 돌려준다.

| 상황 | 결과 |
| --- | --- |
| 공백을 뺀 길이가 `MIN_QUESTION_LEN` 미만 | `GuardTripped` |
| `settings.max_input_chars` 초과 | `GuardTripped` — 메시지에 **실제 길이와 상한**이 들어간다 |
| `None` 이 들어옴 | `GuardTripped` (터지지 않는다) |

### `check_model(model) -> str`
허용 목록에 있으면 그대로 돌려주고, 없으면 `GuardTripped`. 메시지에 **문제의 모델 이름**이 들어간다.

### `check_daily_limit(used_today) -> None`
`settings.daily_call_limit` **이상**이면 `RateLimited`. 통과하면 아무것도 돌려주지 않는다.

## 채점이 보는 것

- 공백이 걷어진 값이 돌아오는가
- 짧은 질문·긴 질문·`None` 이 전부 `GuardTripped` 인가
- 한도는 **초과**가 아니라 **도달**에서 막히는가 (`limit` 자체가 실패)
- 긴 질문 메시지에 숫자가 들어 있는가

## 왜 이렇게 하는가

**허용 목록으로 쓰는 것**이 요점이다. 금지 목록은 새 모델이 생길 때마다 빠뜨릴 수 있지만, 허용 목록은 모르는 이름이면 무조건 막힌다. 실수하는 방향이 안전한 쪽이다.

값을 그대로 통과시키지 않고 **정리해서 돌려주는 것**도 의도된 모양이다. 부르는 쪽이 `check_question(q)` 의 반환값을 쓰게 되므로, 검사만 하고 원본을 그대로 쓰는 실수를 할 수 없다.
