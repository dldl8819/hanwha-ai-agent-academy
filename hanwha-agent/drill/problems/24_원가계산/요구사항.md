# 원가 계산

호출 한 번이 얼마인지 원화로 어림잡는다. 이 값이 `usage_logs.cost_krw` 에 그대로 저장된다.

## 만들 것

### `PRICING` — 100만 토큰당 USD
| 항목 | 단가 |
| --- | --- |
| `input` | 1.0 |
| `cache_write` | 1.25 |
| `cache_read` | 0.1 |
| `output` | 5.0 |

### `USD_KRW`
환율. `1400.0`

### `estimate_cost_krw(input_tok: int, output_tok: int) -> float`
입력·출력 토큰 수를 받아 **원화**를 돌려준다.

- 단가는 100만 토큰 기준이다
- 소수 **첫째 자리**까지 반올림한다
- 캐시 단가는 아직 반영하지 않는다 (입력은 전부 `input` 단가로 센다)

## 채점이 보는 것

- 0 토큰이면 0.0
- 입력 100만 토큰 = 1400.0원, 출력 100만 토큰 = 7000.0원
- 같은 토큰 수일 때 출력이 입력의 정확히 5배인가
- 소수 둘째 자리 이하가 잘려 있는가
- 단가표와 환율이 **숫자로 박혀 있지 않고** 이름으로 분리되어 있는가

## 왜 이렇게 하는가

이 함수가 돌려준 값을 그때그때 저장해 둔다. 조회할 때마다 다시 계산하지 않는 이유는 **단가와 환율이 바뀌기 때문**이다. 다시 계산하면 작년 사용량이 올해 단가로 찍힌다.

단가표를 서비스가 아니라 어댑터 파일에 두는 것도 이유가 있다. 공급자마다 가격이 다르므로, 모델을 바꾸면 이 파일 하나만 고치면 된다.
