## 1. 못 읽는 다섯 형식 — 같은 에러, 다른 이유

지금까지 파서는 `.docx`, `.pdf`, `.hwpx` 셋이었습니다. `_formats` 폴더의 재료를 넣어 보면 다섯이 막혔습니다. 이날 핸들러를 더한 뒤 다시 돌려 봤습니다.

```text
sample_table.xlsx   -> 블록 1개
sample_notice.pptx  -> 블록 1개
sample_memo.txt     -> ValidationFailed: 지원하지 않는 형식입니다: .txt  | detail=핸들러를 추가하면 지원할 수 있습니다
sample_guide.md     -> ValidationFailed: 지원하지 않는 형식입니다: .md  | detail=핸들러를 추가하면 지원할 수 있습니다
sample_page.html    -> ValidationFailed: 지원하지 않는 형식입니다: .html  | detail=핸들러를 추가하면 지원할 수 있습니다
```

`.xlsx` 와 `.pptx` 는 핸들러를 더해서 풀렸습니다. 남은 셋은 핸들러로 풀 문제가 아닙니다. `detail` 이 "핸들러를 추가하면 지원할 수 있습니다"라고 안내하는데 그게 맞는 말이 아닙니다. `.txt` 를 그냥 읽어 보면 드러납니다.

```text
[그냥 읽으면]  71자
출장 정산 안내

9월부터 출장 정산은 그룹웨어에서만 접수합니다.
종이 서류는 받지 않습니다.

문의: 인사총무팀 김지원 과장

[parse_local 에 넣으면]
ValidationFailed: 지원하지 않는 형식입니다: .txt
```

글자가 이미 다 있는데 파서를 찾다가 막혔습니다. `.txt` 와 `.md` 는 파싱할 것이 없습니다. `.xlsx` 와 `.pptx` 는 반대로 전용 라이브러리가 필요합니다. 같은 "못 읽음"이 아니니 처리도 달라야 합니다.

## 2. 파서 진입점을 따로 둡니다

그래서 `parse_local` 앞에 자리를 하나 더 만들었습니다.

```python
_PLAIN = {".txt", ".md"}         # 파싱 없이 바로 읽는다
_HTML = {".html", ".htm"}        # 태그를 걷어내야 글자가 남는다
_LOCAL_ONLY = {".hwp", ".hwpx"}  # 상용 API 로 보내지 않는다

def parse(path: str | Path, *, use_upstage: bool = False) -> ParsedDoc:
    p = Path(path)
    ext = p.suffix.lower()
    if ext in _PLAIN:
        return _parse_plain(p)
    if ext in _HTML:
        return _parse_html(p)
    if use_upstage and ext not in _LOCAL_ONLY:
        from app.integrations.upstage import UpstageParser
        return UpstageParser().parse(str(p))
    return parse_local(p)
```

`_LOCAL_ONLY` 가 상용 API 조건 뒤에 오는 것이 요점입니다. 스위치를 켜고 꺼 보면 보입니다.

```text
[use_upstage=False]
  sample_table.xlsx    -> parse_local
  …v2.0.hwpx           -> parse_local

[use_upstage=True]
  sample_table.xlsx    -> upstage        (바뀐다)
  …v2.0.hwpx           -> parse_local    (그대로)
```

한글 문서는 설정을 켜도 밖으로 나가지 않습니다. 사내 규정에 대외비 등급이 섞여 있어서 기술 선택이 아니라 보안 결정입니다. 임베딩 모델을 로컬로 받아 둔 것과 같은 판단입니다.

플레인 파서는 빈 줄로 자릅니다.

```python
def _parse_plain(p: Path) -> ParsedDoc:
    text = p.read_text(encoding="utf-8", errors="replace")
    blocks = [
        ParsedBlock("조항", f"{p.name} {i + 1}단락", part.strip())
        for i, part in enumerate(text.split("\n\n"))
        if part.strip()
    ]
    return ParsedDoc(blocks=blocks, page_count=1, table_count=0)
```

`errors="replace"` 는 인코딩이 틀린 글자를 `?` 로 바꿔 넣습니다. 예외를 올리는 대신 읽히는 만큼 읽습니다. 메모 한 줄 때문에 적재 전체가 멈추지 않게 했습니다.

## 3. HTML — 표를 먼저 떼어냅니다

태그를 한 번에 지우면 어떻게 되는지부터 봤습니다.

```python
flat = re.sub(r"\s+", " ", re.sub(r"<[^>]+>", " ", html)).strip()
```

```text
사내 공지 추석 연휴 근무 안내 연휴 기간 중 당직 근무자는 아래와 같습니다. 날짜 당직자 연락처 10/03 김민준 내선 2201 10/04 이서연 내선 2202
블록 1개
```

전부 한 줄이 됩니다. 표가 본문에 녹아 버려서 `날짜 당직자 연락처 10/03 김민준` 이 어디가 열 이름이고 어디가 값인지 알 수 없습니다.

순서를 바꿉니다. 표를 먼저 떼어내고 본문을 정리합니다.

```python
raw = re.sub('<(script|style)[^>]*>.*?</\\1>', ' ', raw, flags=re.S | re.I)
tables = re.findall('<table.*?</table>', raw, flags=re.S | re.I)   # 모아 두고
body = re.sub('<table.*?</table>', ' ', raw, flags=re.S | re.I)    # 본문에서 뺀다
body = re.sub('\\s+', ' ', re.sub('<[^>]+>', ' ', body)).strip()
```

```text
[좋은 예] 블록 2 · 표 1 · 쪽 1 · 글자 89자
  [1] 조항  sample_page.html          43자  사내 공지 추석 연휴 근무 안내 연휴 기간 중 당직 근무자는 아래와 같습니다.
  [2] 표    sample_page.html · 표1     46자  날짜 당직자 연락처 10/03 김민준 내선 2201 10/04 이서연 내선 2202
```

블록이 둘로 갈렸습니다. `<script>` 와 `<style>` 을 먼저 지우는 것은 그 안의 글자가 본문이 아니기 때문입니다. 자바스크립트 코드가 규정 문장처럼 검색되면 안 됩니다.

## 4. 엑셀은 시트 하나가 표 하나

```python
def parse_xlsx(path: Path) -> ParsedDoc:
    from openpyxl import load_workbook

    wb = load_workbook(str(path), data_only=True)
    blocks: list[ParsedBlock] = []
    for ws in wb.worksheets:
        rows = [
            ["" if c is None else str(c) for c in row]
            for row in ws.iter_rows(values_only=True)
            if any(c is not None for c in row)
        ]
        if not rows:
            continue
        blocks.append(ParsedBlock("표", ws.title, _table_to_markdown(rows[0], rows[1:])))
    return ParsedDoc(blocks=blocks, page_count=len(wb.worksheets), table_count=len(blocks))
```

`data_only=True` 가 중요합니다. 끄면 `=SUM(B2:B4)` 라는 수식이 그대로 나와서 검색에 쓸 수 없습니다. 계산된 값이 필요합니다.

시트 이름을 `locator` 로 쓰는 것도 의도입니다. 출처가 "출장비 집계"가 되니 파일명보다 어디서 왔는지가 분명합니다.

```text
블록 1 · 표 1 · 쪽 1 · 글자 161자
  kind    : 표
  locator : 출장비 집계
| 부서 | 1분기 | 2분기 | 3분기 |
|---|---|---|---|
| 인프라사업부 2팀 | 4200000 | 3800000 | 5100000 |
```

표를 마크다운으로 바꾸는 함수는 17일차에 만든 것을 그대로 썼습니다. 형식이 늘어도 표의 모양은 하나입니다.

## 5. PPT — 발표자 노트는 슬라이드 밖에 있습니다

슬라이드는 도형 여럿으로 이뤄져 있어서 글자가 든 도형만 골라야 합니다.

```python
lines = [shape.text.strip() for shape in slide.shapes
         if shape.has_text_frame and shape.text.strip()]
```

`has_text_frame` 으로 거릅니다. 이미지나 선, 차트에는 글자 틀이 없어서 `shape.text` 를 바로 읽으면 거기서 예외가 납니다.

```text
슬라이드 : 1장, 70자
출장 여비 규정 개정 안내
일비 25,000 → 30,000원
광역시 숙박비 상한 70,000원 신설
시행 2025-07-01
```

여기까지는 화면에 보이는 것만 긁었습니다. 발표자 노트는 `slide.shapes` 에 없습니다.

```python
if slide.has_notes_slide:
    note = slide.notes_slide.notes_text_frame.text.strip()
    if note:
        lines.append(f"[발표자 노트] {note}")
```

```text
슬라이드 : 1장, 99자
...
[발표자 노트] 인사총무팀 설명용 발표 노트입니다.
```

70자에서 99자로 늘었습니다. 늘어난 29자는 슬라이드를 봐도 안 보이는 내용입니다. 규정 설명 자료라면 그 29자가 정작 찾고 싶은 근거일 수 있습니다.

다섯 형식을 전부 등록하고 청킹까지 보내 봤습니다.

```text
sample_memo.txt     블록  3  표 0  →  조항 단위 1 + 표 단위 0 = 1 청크
sample_guide.md     블록  7  표 0  →  조항 단위 1 + 표 단위 0 = 1 청크
sample_page.html    블록  2  표 1  →  조항 단위 1 + 표 단위 1 = 2 청크
sample_table.xlsx   블록  1  표 1  →  조항 단위 0 + 표 단위 1 = 1 청크
sample_notice.pptx  블록  1  표 0  →  조항 단위 1 + 표 단위 0 = 1 청크
```

## 6. 스캔본은 라이브러리를 바꿔도 안 됩니다

형식을 다섯까지 늘렸는데 하나가 남습니다. `sample_scanned.pdf` 입니다.

```text
sample_scanned.pdf
 ValidationFailed : 문서에서 글자를 찾지 못했습니다: sample_scanned.pdf

DOC-HR-014_국내출장_여비_규정_v2.0.pdf
블록 16, 표 0, 페이지 16
```

둘 다 아쉬운데 지점이 다릅니다. 스캔본은 글자가 0입니다. 일반 PDF 는 글자는 16쪽 다 읽혔는데 표가 0입니다. 라이브러리 둘로 재 보면 갈립니다.

```text
scanned!
 pypdf 페이지 1, 글자 0
 plumber 페이지 1, 글자 0, 표 0

normal!
 pypdf  페이지 16, 표 0
 plumber  페이지 16, 표 7
```

`pdfplumber` 가 일반 PDF 에서 표 7개를 찾습니다. 19일차에 "PDF 표를 살리려면 파서를 고쳐야 한다"고 적었는데 그 방법이 이것입니다.

스캔본은 다릅니다. `pdfplumber` 도 0자입니다. 글자가 글자로 들어 있지 않고 그림으로 들어 있습니다. 어떤 텍스트 추출기를 써도 꺼낼 것이 없습니다. 여기서는 OCR 이 필요합니다.

## 7. 상용 파서 어댑터

Upstage Document Parser 는 문서를 넣으면 요소 목록으로 쪼개 돌려줍니다.

| 돌려주는 것 | 무엇 |
| --- | --- |
| `elements[]` | 조각 하나하나 |
| `.category` | `table` · `paragraph` · `heading` · `header` · `footer` · `figure` · `chart` |
| `.page` | 몇 쪽에서 나왔는지 |
| `.content` | `text` · `html` · `markdown` 세 모양 |

`category` 가 우리가 손으로 하던 판단을 대신합니다. `parse_docx` 가 `p` 와 `tbl` 을 구별하는 일, HTML 파서가 `<table>` 을 먼저 떼어내는 일, 청킹이 정규식으로 조 제목을 찾는 일입니다.

어댑터는 포트와 어댑터 모양을 그대로 씁니다.

```python
class UpstageParser:
    name = "upstage"

    def parse(self, path: str) -> ParsedDoc:
        p = Path(path)
        if not p.exists():
            raise ExternalServiceError(f"파일을 찾을 수 없습니다. : {path}")
        return _to_doc(p, _post(p))
```

로컬 파서와 같은 `ParsedDoc` 을 돌려주는 것이 전부입니다. 부르는 쪽은 어느 파서가 읽었는지 몰라도 됩니다.

카테고리를 셋으로 가릅니다.

```python
_TEXT = {"paragraph", "heading1", "heading2", "heading3",
         "list", "index", "caption", "equation", "code", "footnote"}
_SKIP = {"header", "footer", "figure"}
```

`header` 와 `footer` 를 버리면 우리가 못 걸렀던 문제가 풀립니다. HTML 파서에서 `<title>` 의 "사내 공지"가 본문에 섞여 들어왔습니다. 상용 파서는 그게 머리말인지 본문인지를 알려 줍니다.

키가 없는 사람도 수업을 따라갈 수 있게 해 뒀습니다.

| | 키가 있다 | 키가 없다 |
| --- | --- | --- |
| 발급 | 콘솔에서 각자 | 아무것도 안 함 |
| 부르기 | `UpstageParser().parse(path)` | 미리 넣어 둔 상수 |
| 받는 것 | `ParsedDoc` | `ParsedDoc` |

받는 모양이 같으니 뒤쪽 코드는 어느 길로 왔는지 모릅니다. 포트와 어댑터를 쓰는 이유가 여기서 한 번 더 나옵니다.

## 이날의 소감

이날 찾은 버그 셋이 전부 같은 성격이었습니다. **실행은 되는데 틀린 것**입니다.

HTML 파서가 표를 `ParsedBlock` 대신 평범한 튜플로 넣고 있었습니다. 노트북에서 블록 수와 글자 수만 찍어 보면 멀쩡해 보입니다. 튜플도 길이를 셀 수 있습니다. 그런데 청킹에 넘기면 `'tuple' object has no attribute 'kind'` 로 무너집니다.

인증 헤더를 만드는 줄에서는 괄호가 빠져 있었습니다.

```text
Bearer <bound method _SecretBase.get_secret_value of SecretStr('**********')>
```

키가 전혀 안 실려서 401 이 돌아옵니다. 그런데 401 안내 문구는 "키가 잘못되었거나 차단된 키"라고 말합니다. 콘솔에서 키를 다시 발급받는 쪽으로 한참 헤맬 수 있습니다. 호출 한 번마다 돈이 드는 자리입니다. 네트워크를 타기 전에 헤더 모양만 찍어 보는 편이 쌉니다.

세 번째는 `return ExternalServiceError(...)` 였습니다. `raise` 가 아니라 `return` 이라 예외 객체가 `ParsedDoc` 자리에 돌아갑니다. 넣은 곳에서 바로 터지지 않아서 찾기 어려운 종류입니다.

셋 다 "타입이 다른 것을 같은 자리에 넣으면 터지는 곳이 넣은 곳이 아니다"로 묶입니다. 라이브러리 사용법만 알면 이런 자리는 안 보입니다. 직접 만들어 보고 눌러 봐야 드러납니다.

남은 숙제도 적어 뒀습니다. 마크다운 제목이 독립 블록이 되는 것, 엑셀 병합 셀이 빈칸이 되는 것, 슬라이드 안의 표가 사라지는 것 셋입니다. 병합 셀은 특히 조용한 실패입니다 — 표가 그럴듯하게 나오는데 1,200,000원이 어느 부서 것인지가 빈칸으로 사라집니다.
