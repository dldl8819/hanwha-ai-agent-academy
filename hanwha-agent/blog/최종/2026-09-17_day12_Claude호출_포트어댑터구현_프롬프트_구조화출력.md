## 1. Claude API 첫 호출

문서를 읽기 전에 SDK 코드에서 필수 파라미터를 직접 뽑아봤습니다.

```python
import inspect
from anthropic.resources.messages import Messages

params = inspect.signature(Messages.create).parameters
required = [name for name, p in params.items()
            if p.default is inspect.Parameter.empty and name != "self"]
print(required)   # ['max_tokens', 'messages', 'model']
```

`max_tokens`가 필수입니다. 출력 토큰 상한을 정하지 않으면 호출 자체가 되지 않습니다. 출력이 입력보다 5배 비싼 구조에서 SDK가 상한을 강제하는 것은 합리적인 설계입니다.

첫 호출은 이렇게 했습니다.

```python
response = client.messages.create(
    model=settings.llm_model,
    max_tokens=settings.max_tokens,
    system="너는 사내 규정 질의 응답 도우미다. 근거가 없으면 없다고 말해야해.",
    messages=[{"role": "user", "content": "제주도 출장 숙박비 한도가 얼마인가요?"}],
)

print("".join(b.text for b in response.content if b.type == "text"))
```

응답의 `content`는 문자열이 아니라 블록 리스트라서, `type`이 `text`인 블록만 모아 이어 붙입니다. 모델명과 `max_tokens`는 코드에 적지 않고 설정에서 가져옵니다.

실제 결과에서 세 가지를 확인했습니다.

**근거가 없으니 지어내지 않았습니다.** 아직 문서를 하나도 넘기지 않았는데, 숙박비 금액을 만들어내지 않고 "사내 규정 정보를 가지고 있지 않다"고 답했습니다.

**같은 질문인데 답이 달랐습니다.**

| | 입력 토큰 | 출력 토큰 |
| --- | --- | --- |
| 1회차 | 67 | 176 |
| 2회차 | 67 | 236 |

입력은 한 글자도 바뀌지 않았는데 출력 길이와 문장이 모두 달랐습니다. 어제 가짜 객체로 재현했던 비결정성이 실제 API에서 그대로 나왔고, 출력 토큰이 달라지니 비용도 매번 달라집니다.

**어림값보다 실제가 쌌습니다.** 어제 어림한 값은 3.9원이었는데 실제로는 1.7원이었습니다. 근거 문서 없이 질문만 보내서 입력이 67토큰뿐이었기 때문이고, 문서를 붙이면 입력이 크게 늘어납니다.

## 2. 포트와 어댑터 실제 구현

어제 개념으로 정리한 구조를 `backend/app/integrations/` 아래 세 파일로 만들었습니다.

| 파일 | 역할 |
| --- | --- |
| `ports.py` | 결과 형태(`LLMResult`)와 규약(`LLMPort`) |
| `llm_claude.py` | Claude API 실물 어댑터 |
| `factory.py` | 어떤 어댑터를 쓸지 고르는 단 한 곳 |

```python
@dataclass
class LLMResult:
    text: str
    model: str
    input_tok: int = 0
    cache_tok: int = 0
    output_tok: int = 0
    cost_krw: float = 0.0
    latency_ms: int = 0
    extras: dict = field(default_factory=dict)
```

`extras`의 기본값을 `{}`가 아니라 `field(default_factory=dict)`로 둡니다. `{}`를 직접 쓰면 모든 인스턴스가 딕셔너리 하나를 공유하게 되는데, `dataclass`는 이 실수를 막으려고 아예 `ValueError`를 냅니다.

어댑터는 `anthropic`을 파일 맨 위가 아니라 생성자 안에서 import 합니다. 맨 위에 두면 SDK가 없는 환경에서 이 파일을 import 하는 순간 앱 전체가 뜨지 않습니다.

팩토리는 mock과 live 분기가 모이는 유일한 자리입니다.

```python
@lru_cache
def _live_llm() -> LLMPort:
    from app.integrations.llm_claude import ClaudeLLM
    return ClaudeLLM()

def get_llm() -> LLMPort:
    if not get_settings().is_live:
        raise ModeNotAvailable("테스트용 mock 어댑터는 만들지 않았습니다. ...")
    return _live_llm()
```

mock 모드에서는 live 어댑터를 대신 돌려주지 않고 막습니다. 가짜 어댑터가 아직 없는 상태에서 조용히 live로 넘기면 개발 중에 실제 과금이 발생하기 때문입니다. mock 모드에서 `get_llm()`을 부른 뒤 불러온 모듈을 확인해보니, `anthropic`도 `llm_claude`도 **아예 로드되지 않았습니다.** 함수 안 import가 실제로 작동한다는 증거입니다.

어제 만든 계층 검사 테스트도 다시 돌렸습니다. 서비스는 `factory`만 import 할 수 있고 `llm_claude`를 직접 부르면 실패하는 규칙인데, 5개 모두 통과했습니다.

## 3. 프롬프트를 파일로 분리하기

프롬프트를 코드에 박아두면 로그에 남은 응답과 그때의 프롬프트 버전을 이을 수 없고, 같은 지시를 여러 곳에서 고쳐야 합니다. 그래서 `.md` 파일로 문서화하고 코드는 읽어서 쓰기만 합니다.

역할 분담의 기준은 **"매번 같은가"**입니다.

| | `system` | `user` 메시지 |
| --- | --- | --- |
| 성질 | 매 요청 같은 것 | 매번 다른 것 |
| 담는 것 | 역할, 규칙, 출력 형식, 인용 규칙 | 사용자 정보, 근거 문서, 질문 |
| 어디에 두나 | 파일 `answer_system.md` | 코드가 조립 |

`answer_system.md`에는 역할, 규칙 다섯 개, 출력 형식, 근거 인용 규칙을 넣었습니다. 규칙들이 겨냥하는 것은 전부 그럴듯한 오답입니다. 다른 문서로 유추해서 메우지 말 것, 금액은 근거의 숫자를 그대로 옮길 것, "아마"나 "일반적으로" 같은 표현으로 빈틈을 메우지 말 것.

파일을 읽는 함수에는 함정이 하나 있습니다.

```python
def _load_prompt(name: str) -> str:
    path = PROMPTS / name
    return path.read_text(encoding="utf-8") if path.exists() else ""
```

```text
정상 이름 : 글자 수 1078
오타 이름 : 글자 수 0
```

파일이 없으면 에러가 아니라 빈 문자열을 돌려줍니다. 이름을 틀리면 **규칙이 하나도 없는 system 프롬프트**로 조용히 호출됩니다.

## 4. 컨텍스트 구성

Claude Haiku 4.5의 컨텍스트 윈도우는 200K 토큰이지만, 중요한 것은 크기보다 성질입니다. 사람은 앞의 대화를 기억하지만 **모델은 기억하지 못해서** 매 요청마다 필요한 것을 전부 다시 실어 보내야 합니다. 그래서 무엇을 넣고 뺄지가 곧 품질이고, 넣은 만큼이 곧 비용입니다.

근거 문서는 모델이 읽기 좋은 문자열로 바꿔서 넣습니다.

```text
[근거 1] 국내출장 여비 규정 v2.0 · 제12조(숙박비) · p.6 (유사도 0.91)
서울·광역시: 1박 70,000원 이내

[근거 2] 정보보안 지침 v2.2 · 제4조 · p.2 (유사도 0.48)
대외비 문서는 열람 권한이 확인된 임직원에게만 제공한다.
```

근거가 0건이면 빈 칸이 아니라 `(근거 문서 없음)`을 넣습니다. 빈 칸이면 모델이 근거가 없다는 사실 자체를 모르기 때문에, 명시해야 "모르면 모른다고 말한다"는 규칙이 작동합니다.

## 5. 구조화 출력

화면에 답변과 근거 목록, 근거 충분 여부를 따로 보여주려면 모델 응답이 문장이 아니라 구조여야 합니다.

```python
DOC_ID = Literal["DOC-HR-014", "DOC-PU-007", "DOC-SE-003"]

class AnswerSource(BaseModel):
    doc_id: DOC_ID
    title: str
    version: str
    locator: str

class AnswerOut(BaseModel):
    answer: str
    sources: list[AnswerSource]
    enough_evidence: bool
```

`doc_id`를 `Literal`로 막아서, 모델이 목록에 없는 문서 번호를 지어내면 검증에서 걸리게 했습니다.

그런데 프롬프트에 "코드펜스 없이 JSON만 보내라"고 적어도, 모델은 ```` ```json ```` 으로 감싸서 보낼 때가 있습니다. 그대로 검증에 넣으면 첫 글자인 백틱에서 멈춥니다. 부탁만으로는 막을 수 없어서 받는 쪽에서 벗겨내는 함수를 만들었습니다.

```python
def _extract_json(text: str) -> dict:
    fenced = re.search(r"```(?:json)?\s*(\{.*?\})\s*```", text, re.S)
    raw = fenced.group(1) if fenced else text
    start, end = raw.find("{"), raw.rfind("}")
    if start == -1 or end == -1:
        return {}
    try:
        return json.loads(raw[start : end + 1])
    except json.JSONDecodeError:
        return {}
```

```text
① 그대로 넣으면 : Invalid JSON: expected value at line 1 column 1
② 벗기고 검증   : answer='1박 70,000원 이내' · 근거 1건 · 충분함 True
③ JSON 이 아니면 : {}
```

펜스가 있으면 안쪽만 꺼내고, 없으면 첫 `{`부터 마지막 `}`까지만 남깁니다. 꺼내지 못하면 빈 딕셔너리를 돌려주는데, 그러면 뒤의 `AnswerOut` 검증에서 필드 3개 누락으로 확실히 실패합니다. 파싱과 검증을 두 단계로 나눠두면 형식이 깨진 것인지 내용이 규칙에 안 맞는 것인지 구분할 수 있습니다.

## 6. 실습 중 만난 문제

오늘 실습하며 만난 문제 세 가지는 공통점이 있었습니다. **에러가 나지 않거나, 나더라도 엉뚱한 곳에서 늦게 납니다.**

**어댑터의 인자 이름 오타.** 어댑터의 `answer` 메서드 인자를 `user`가 아니라 `usser`로 적었는데, 포트 검사인 `isinstance(ClaudeLLM(), LLMPort)`는 여전히 True였습니다. `runtime_checkable`은 메서드 이름만 보기 때문입니다. 노트북에서 포트와 어댑터의 서명을 나란히 찍어보고서야 차이가 드러났습니다.

```text
LLMPort.answer   : (self, *, question, contexts, user)
ClaudeLLM.answer : (self, *, question, contexts, usser)
```

**`Literal`의 한 글자 오타.** 문서 번호 목록에 `DOC-SE-003`을 `DOC_SE-003`으로 적었습니다. 프롬프트에는 올바른 번호가 있으니 모델은 맞게 답하는데, 스키마가 틀려서 **정답이 검증에 걸립니다.** 막아야 할 오답이 아니라 정답을 막는 상황이었습니다.

**프롬프트 섹션 중복.** 출력 형식을 평문에서 JSON으로 바꾸면서 기존 절을 교체하지 않고 아래에 추가했더니, "세 덩어리 평문으로 써라"와 "JSON만 보내라"가 한 파일에 같이 들어갔습니다. 근거 인용 규칙도 "문서 번호를 빼라"와 "문서 번호를 넣어라"가 동시에 남았습니다. 코드는 같은 이름을 두 번 정의하면 뒤의 것이 이기지만, 프롬프트에는 그런 규칙이 없어서 모델이 어느 쪽을 따를지 알 수 없습니다.

## 오늘의 소감

한화 내일 아카데미 ICT부문 과정에서 처음으로 실제 모델을 호출한 날이었는데, 호출 자체보다 **호출 앞뒤를 감싸는 코드**가 대부분이었습니다. 요청 쪽에서는 무엇을 어떤 형식으로 보여줄지 정하고, 응답 쪽에서는 모델이 약속을 어겼을 때 받아내는 장치를 만들었습니다.

같은 질문에 출력 토큰이 176과 236으로 달라진 것, "JSON만 달라"고 적어도 코드펜스로 감싸 온 것은 둘 다 모델이 매번 같은 일을 하지 않는다는 사실을 보여줍니다. 그래서 프롬프트로 부탁하는 것에 더해 스키마와 파싱 함수로 한 번 더 확인하는 구조가 필요합니다.

실습 중 만난 문제 세 가지도 같은 결론으로 이어집니다. 서명 오타는 `isinstance`를 통과했고, `Literal` 오타는 정답을 막았고, 섹션 중복은 에러 없이 지시를 흐렸습니다. 확인하는 장치를 만들 때는 **그 장치 자체가 무엇을 못 보는지**까지 함께 알고 있어야 합니다.
