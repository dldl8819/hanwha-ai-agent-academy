## 1. 마크다운 제목을 블록이 아니라 출처로

20일차에 `## 1. 신청` 이 8자짜리 블록 하나가 되는 문제를 적어 뒀습니다. 빈 줄로만 자르면 제목도 한 덩이가 되기 때문입니다.

해결 방향이 뜻밖이었습니다. 제목을 **그 아래 본문의 출처**로 씁니다.

```python
for line in text.split("\n"):
    if re.match(r"#{1,6}\s", line):
        flush()                              # 앞 절을 닫고
        locator = line.lstrip("#").strip()   # 이 제목을 다음 절의 출처로
    else:
        buffer.append(line)
flush()
```

```text
블록 3 -> 조항 단위 1 + 표 단위 0 = 1 청크
 [1. 신청] 출장 3일 전까지 그룹웨어에서 신청합니다.
 [2. 승인] 팀장 승인 후 확정됩니다. 5일 초과 출장은 본부장 승인이 필요합니다.
 [3. 정산] 복귀 후 7일 이내에 영수증을 첨부해 정산합니다.
```

블록이 7개에서 3개로 줄었습니다. 그러면서 출처가 좋아졌습니다. `sample_guide.md 2단락` 보다 `1. 신청` 이 어디서 나온 답인지 분명합니다.

`#{1,6}\s` 에서 공백까지 봅니다. 그래서 `#태그` 같은 줄을 제목으로 잡지 않습니다. 그리고 `flush()` 를 반복문 뒤에 한 번 더 부르는 자리를 빠뜨리기 쉽습니다. 마지막 절은 다음 제목이 없어서 반복문 안에서 닫히지 않습니다.

HTML 의 `<title>` 문제는 더 간단하게 풀렸습니다. `<head>` 를 통째로 지웁니다.

```text
사내 공지
추석 연휴 근무 안내 연휴 기간 중
False
```

마지막 `False` 가 `body.startswith(title)` 입니다. 본문이 "사내 공지"로 시작하지 않는다는 뜻입니다.

## 2. 엑셀 병합 셀과 수식, 두 줄 머리행

병합 셀은 `openpyxl` 이 첫 칸에만 값을 주고 나머지를 `None` 으로 줍니다. 그래서 1,200,000원이 어느 부서 것인지 사라집니다.

```text
| 인프라사업부 | 4200000 | 3800000 |
| 인프라사업부 | 1200000 | 1400000 |
| 구매팀 | 900000 | 1000000 |
```

병합 범위를 읽어 왼쪽 위 값을 범위 전체에 복사하면 됩니다. 그런데 여기 설명이 안 되는 줄이 있어서 눌러 봤습니다.

```python
ws["C3"] = "부서"
print(ws.min_row)                       # 3
list(ws.iter_rows(values_only=True))    # 1행부터 훑으면서 빈 칸이 만들어진다
print(ws.min_row)                       # 1
```

`iter_rows()` 를 부르면 `min_row` 가 1로 내려갑니다. 리스트의 0번째가 시트 1행이니, **리스트를 먼저 만든 뒤에 기준 좌표를 읽어야** 자리가 맞습니다. 두 줄의 순서를 바꾸면 조용히 깨집니다.

수식은 다른 문제였습니다.

```text
data_only 로 읽은 B5 : None
| 합계 | =SUM(B2:B3) (계산값 없음) |
```

`data_only=True` 는 엑셀이 저장할 때 계산해 둔 값을 줍니다. 파이썬으로 만든 파일에는 그 값이 없어서 `None` 이 옵니다. 빈칸으로 두면 "값이 없는 것"과 "계산이 안 된 것"을 구별할 수 없으니, 수식 문자열을 그대로 적고 꼬리를 붙입니다.

두 줄 머리행도 다뤘습니다.

```text
2026 출장 · 교육비 집계

| 구분 | 1분기 출장비 | 1분기 교육비 | 2분기 출장비 | 2분기 교육비 |
|---|---|---|---|---|
| 인프라사업부 | 4200000 | 1200000 | 3800000 | 1400000 |
```

`1분기` 와 `출장비` 를 이어 붙여 `1분기 출장비` 로 만듭니다. 마크다운 표는 머리행이 한 줄이어야 합니다. `A1:E1` 로 병합한 제목은 표 위로 올려 따로 적습니다.

한 시트에 표가 둘이면 빈 줄을 경계로 쪼갭니다.

```text
블록 2 · 쪽 1 · 표 2
--- [표] 요약 · 표1
--- [표] 요약 · 표2
```

## 3. PPT 그룹 도형과 차트

슬라이드 안의 표는 `has_table` 로 따로 봐야 합니다. `has_text_frame` 으로는 안 잡히는 도형입니다.

그런데 하나가 더 있었습니다. 도형을 그룹으로 묶으면 겉에서는 하나로 보입니다.

```text
맨 바깥 도형     : ['GroupShape']
블록 2 · 표 1
--- [조항] 슬라이드 1
숙박비 상한(그룹 안)
--- [표] 슬라이드 1 · 표1
| 광역시 | 그 밖 |
```

겉으로는 `GroupShape` 하나인데 안의 글자와 표가 둘 다 나왔습니다. 안쪽으로 한 겹 들어가는 재귀가 필요합니다.

```python
if isinstance(shape, GroupShape):
    yield from _walk_shapes(shape.shapes)
```

이게 없으면 그룹 안의 글자와 표가 통째로 빠집니다. 실무 자료에서 도형을 묶는 일은 흔하니 조용히 빠지기 쉬운 자리입니다.

차트도 표로 바꿉니다. 숫자가 든 자료라 검색 대상입니다.

```text
--- [표] 슬라이드 1 · 차트1
분기별 집행액

| 항목 | 출장비 | 교육비 |
|---|---|---|
| 1분기 | 4200000 | 1200000 |
| 2분기 | 3800000 | 1400000 |
```

엑셀 숫자가 전부 `float` 로 와서 `4200000.0` 이 됩니다. 정수면 소수점을 떼야 읽힙니다.

## 4. PDF 가 워드와 같아졌습니다

"HWPX 와 DOCX 는 같고 PDF 만 다르다"고 19일차에 적었습니다. 그게 뒤집혔습니다.

```text
parse_pdf         블록 16 · 쪽 16 · 표 0  →  조항 단위 45 + 표 단위 0 = 45 청크
parse_pdf_tables  블록 23 · 쪽 16 · 표 7  →  조항 단위 46 + 표 단위 7 = 53 청크
(같은 규정 .docx)  블록 233 · 쪽 1 · 표 7  →  조항 단위 46 + 표 단위 7 = 53 청크
```

`pdfplumber` 로 읽는 파서를 쓰면 PDF 가 워드와 **똑같은 53청크**를 냅니다. 블록 수는 23 대 233 으로 전혀 다른데 청크는 같습니다. 청킹이 조 단위로 다시 묶기 때문입니다.

표가 본문에 두 번 실리지 않는 것도 확인했습니다.

```text
p.11 · 표1
| 직급 | 일비 | 숙박비(광역시) | 숙박비(그 밖의 지역) | 식비 |
|---|---|---|---|---|
| 1~2급 | 40,000 | 100,000 | 80,000 | 30,000 |

「100,000」 이 표에    : True
「100,000」 이 본문에도 : False
```

표 상자 안의 글자를 본문에서 걸러낸 결과입니다. 이게 없으면 같은 숫자가 조항 블록과 표 블록에 두 벌 들어가서 검색 결과가 중복됩니다.

이 파서는 기본으로 꺼 두었습니다. `pdfplumber` 가 `pypdf` 보다 느려서 표가 필요한 문서에만 켭니다.

## 5. 스캔본만 남습니다

형식을 다섯까지 늘리고 표까지 살렸는데 하나가 남습니다.

```text
쪽 수             : 3
쪽마다 든 그림     : [1, 1, 1]
pypdf 글자        : 0
pdfplumber 글자   : 0 · 표 0
parse_local       막힘 — 문서에서 글자를 찾지 못했습니다
```

쪽마다 그림이 하나씩이고 글자는 0입니다. 글자가 글자로 들어 있지 않고 그림으로 들어 있으니, 어떤 텍스트 추출기를 써도 꺼낼 것이 없습니다. 라이브러리를 바꿔 해결할 문제가 아닙니다.

## 6. OCR 결과를 세어 봤습니다

여기서 상용 API 를 씁니다. 그냥 돌려 보고 "잘 되네"로 끝내지 않으려면 재는 방법을 먼저 정해야 합니다. 별표1 의 금액 10개를 미리 적어 두고 대조합니다.

```text
상용 파싱 완료: …_스캔본.pdf, 블록 25, 표 1
OCR  블록 25 · 쪽 3 · 표 1 · 글자 1530
별표1 값 중 OCR 에 나온 것 : 10 / 10
설정은 원래대로 : ocr = auto
```

0자였던 문서에서 1,530자가 나오고 금액 10개가 전부 나왔습니다.

마지막 줄이 중요합니다. OCR 을 반드시 돌리는 설정은 값이 비싸서 셀 하나를 위해 바꾼 뒤 되돌려야 합니다.

```python
before = settings.upstage_parse_ocr
settings.upstage_parse_ocr = "force"
try:
    ocr_doc = UpstageParser().parse(str(SCAN))
finally:
    settings.upstage_parse_ocr = before
```

`finally` 가 없으면 설정이 뒤 셀까지 따라가서 모르는 사이에 계속 OCR 을 돌립니다.

키가 없는 사람도 노트북을 끝까지 돌릴 수 있게 해 뒀습니다.

```python
HAS_KEY = bool(settings.upstage_api_key)
if HAS_KEY:
    ...
else:
    print("키가 없습니다 — 이 셀은 부르지 않고 지나갑니다(비용 0)")
```

## 7. 로컬 파서와 상용 파서 비교

| | 로컬 파서 | 상용 API |
| --- | --- | --- |
| 스캔본 PDF | 글자 0 · 표 0 — 막습니다 | OCR 로 읽습니다 |
| PDF 표 | pypdf 0개 · pdfplumber 7개 | 읽습니다 |
| 워드·한글 표 | 읽습니다 | 읽습니다 |
| `.hwpx` | 읽습니다 | 보내지 않습니다 |
| PPT 표·차트 | 읽습니다 | — |
| 엑셀 | 읽습니다 | — |
| 비용 | 0원 | 쪽당 $0.01 |
| 네트워크 | 오프라인 가능 | 오프라인 불가 |

**상용 API 가 더 하는 일은 사실상 OCR 하나입니다.** 표도 한글 문서도 로컬로 됩니다.

비용을 재 보면 규모가 보입니다. 16쪽 규정 하나와 1쪽 스캔본이면 17쪽 × $0.01 로 약 240원입니다. 받은 크레딧의 1.7% 입니다. 질문할 때는 들지 않습니다. 문서를 올릴 때 드는 돈입니다. 다시 적재하면 다시 듭니다.

그래서 `.hwpx` 는 로컬만, 글자 있는 PDF 와 워드는 로컬로 충분합니다. 스캔본에만 API 를 씁니다. 사내 규정에 대외비가 섞여 있어서 한글 문서는 설정을 켜도 밖으로 보내지 않습니다.

## 이날의 소감

20일차에 남겨 둔 숙제가 전부 풀렸습니다. 푸는 과정보다 **왜 그게 문제였는지를 먼저 적어 둔 것**이 도움이 됐습니다. 코드가 두 배로 늘어났을 때는 막막했습니다. 늘어난 함수들을 하나씩 보니 대부분 이미 아는 문제의 답이었습니다.

그중 하나는 혼자 읽을 때 절대 못 알아챌 자리였습니다. 병합 셀을 채우는 함수에서 두 줄의 순서가 바뀌면 조용히 깨집니다. 코드만 봐서는 왜 그 순서여야 하는지 알 수 없습니다. `iter_rows()` 가 시트의 메타 정보를 바꿔 놓는다는 걸 직접 찍어 봐야 나옵니다. 라이브러리 사용법만 외우면 이런 자리는 안 보입니다.

재는 방법을 먼저 정하는 습관도 또 한 번 값을 했습니다. OCR 을 돌려 놓고 "글자가 많이 나왔다"로 끝냈다면 10개 중 몇 개가 맞는지는 몰랐을 것입니다. 금액 10개를 미리 적어 둔 덕에 10/10 이라고 말할 수 있었습니다. 지금까지 익힌 것 중 결과를 숫자로 확인하는 습관이 가장 오래 남을 것 같습니다.

남은 숙제는 하나입니다. 청크에 붙는 출처가 아직 거짓말을 합니다. 제목이 없는 문서에서 "1단락"이라고 적힌 청크가 1~3단락을 담고 있습니다. 파싱 쪽은 끝났고 이건 청킹 쪽 문제입니다.
