# 팀 프로젝트 기획서 — AI 에이전트 기반 웹 접근성 자동 진단 도구

## 1. 배경 및 목표

GitHub에 공개된 개인/팀 프로젝트의 웹 페이지를 대상으로, AI 에이전트가 웹 접근성(Web Accessibility) 이슈를 자동으로 진단하고 개선 방향을 제안해주는 서비스.

- **공식 인증이 목표가 아님**: 웹와치 등 NIA(한국지능정보사회진흥원) 지정 공식 인증기관은 33개 검사항목 전체를 전문 심사원이 수동으로 심사해 법적 효력이 있는 인증마크를 발급한다. 이 프로젝트는 그 수준을 재현하지 않는다.
- **목표는 "자동 사전진단 + 개선 제안"**: 기계적으로 검증 가능한 항목을 자동 검사하고, 판단이 필요한 항목은 LLM이 참고 의견을 제시하는 보조 도구.
- 커리큘럼 취지(AI 에이전트 아카데미)에 맞게, 단순 CRUD가 아니라 "저장소/사이트를 가져오기 → 검사 도구 실행 → 결과를 LLM으로 요약·우선순위화"라는 에이전트형 파이프라인 구조를 따른다.

## 2. 참고 표준

**한국형 웹 콘텐츠 접근성 지침 2.2 (KWCAG 2.2, KS X OT0003:2022)** — 국립전파연구원(과학기술정보통신부) 제정, W3C WCAG 2.1 기반.

- 4개 원칙: 인식의 용이성 / 운용의 용이성 / 이해의 용이성 / 견고성
- 14개 지침, 33개 검사항목

### 자동 검사가 비교적 쉬운 항목 (MVP 우선순위)

| 검사항목 | 내용 |
|---|---|
| 5.1.1 | 이미지 등에 대체 텍스트(alt) 제공 여부 |
| 5.4.3 | 텍스트-배경 명도 대비 4.5:1 이상 |
| 5.4.2 | 소리 자동 재생 여부 |
| 6.4.1 | 반복 영역 건너뛰기 링크(skip navigation) 존재 여부 |
| 6.4.2 | 페이지/프레임 제목(title) 존재 여부 |
| 7.1.1 | 페이지 기본 언어(lang 속성) 명시 여부 |
| 7.3.2 | 입력 필드에 대응하는 label 연결 여부 |
| 8.1.1 | 마크업 문법 오류(태그 열고 닫음, id 중복 등) |

### 판단이 필요해 LLM 참고 의견으로만 다루는 항목 (예시)

- 6.4.3 적절한 링크 텍스트 (맥락상 의미 있는지)
- 5.3.3 명확한 지시사항 제공
- 7.3.3 접근 가능한 인증 (인지 테스트 의존 여부)

## 3. 스코프 결정이 필요한 지점 (미확정)

실제 배포된 URL을 헤드리스 브라우저(Playwright 등)로 렌더링해 검사할지, GitHub 저장소의 정적 HTML/코드만 정적 분석할지 아직 미정.

| 구분 | 장점 | 단점 |
|---|---|---|
| 배포 URL 렌더링 검사 | 실제 사용자 경험과 동일, 정확도 높음 | 헤드리스 브라우저·axe-core 등 커리큘럼에 없는 새 기술 학습 필요 |
| 저장소 정적 코드 분석 | 지금 배운 스택(Python)만으로 구현 가능 | JS로 렌더링되는 콘텐츠는 놓침, 실제 렌더링 결과와 차이 발생 가능 |

→ 팀 인원/일정에 맞춰 다음 논의에서 확정 필요.

## 4. 단계별 로드맵

### Phase 1 — 백엔드 기반 (기존 커리큘럼 스택으로 완성 가능)
- FastAPI + SQLAlchemy로 프로젝트 등록, 스캔 이력 저장 CRUD API
- 레이어드 아키텍처, 예외 계층, 로깅, pytest 테스트 적용

### Phase 2 — 자동 검사 엔진
- 위 "자동 검사가 쉬운 항목" 표 기준으로 검사 로직 구현
- (스코프 확정에 따라) 정적 HTML 파싱 또는 헤드리스 브라우저 렌더링

### Phase 3 — LLM 연동
- 검사 결과를 LLM에 컨텍스트로 전달해 우선순위·요약·개선 제안 생성
- 판단 필요 항목에 대한 참고 의견 생성

### Phase 4 — 여유 시
- 프론트엔드 대시보드
- 인증/권한, 스캔 히스토리 비교

## 5. 기술 스택

- 기존 확보: FastAPI, SQLAlchemy/SQLite, Pydantic, pytest, 레이어드 아키텍처
- 신규 학습 필요: (스코프에 따라) Playwright/axe-core 또는 HTML 파서, LLM API 연동, 프롬프트 설계

## 6. 리스크

- LLM 연동(API 키 관리, 프롬프트 설계)은 커리큘럼에 없어 팀 자습 필요
- 스코프(렌더링 검사 vs 정적 분석) 미확정 — 팀 논의로 조기 확정 필요
