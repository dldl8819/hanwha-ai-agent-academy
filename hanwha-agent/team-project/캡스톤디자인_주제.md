## 2. 과제별 상세

### 과제 1. Ontology 기반 제조 Product 정보 생성 및 등록 자동화 — 상

- **배경**: 신규 제품·부품을 등록할 때 담당자가 설계 문서, 사양서, BOM을 직접 읽고 수작업으로 입력한다. 담당자마다 표기 방식이 달라 누락·중복·오류가 생기고 시간이 많이 든다.
- **목표**: 제품 문서를 입력하면 사전에 정의된 온톨로지(분류 체계, 속성, 관계)에 맞춰 제품 정보를 추출·정규화하고 등록용 데이터를 자동 생성한다.
- **주요 기능**
  - 제품 문서(PDF, Excel 등) 업로드 및 파싱
  - LLM 기반 제품 속성 추출 및 온톨로지 클래스 매핑
  - 기존 등록 제품과의 중복·유사 제품 검사
  - 필수 항목 누락, 단위·형식 오류 자동 검증
  - 담당자 검토·수정 화면 → 최종 등록(DB 저장 또는 표준 JSON 출력)
- **결과물**: 웹 데모, 온톨로지 스키마 정의서, 속성 추출 정확도 평가 결과
- **입력 데이터**: 가상 제품 사양서 30~50건, 간이 제품 분류 체계표(온톨로지 샘플), 기존 등록 제품 목록 샘플
- **난이도 메모**: 온톨로지 설계는 교육 범위 밖이라 간이 스키마를 사전 제공하는 것을 권장

### 과제 2. 사내 규정·업무 가이드 AI Agent — 하~중

- **배경**: 규정·지침·매뉴얼이 여러 곳에 흩어져 있어 찾기 어렵고, 같은 문의가 담당 부서에 반복해서 들어온다.
- **목표**: 사내 규정과 업무 가이드를 근거로 답하고, 근거 조항·문서를 함께 제시하는 질의응답 에이전트를 만든다.
- **주요 기능**
  - 규정·가이드 문서 수집, 청킹, 임베딩 및 검색(RAG)
  - 질문 의도 분류 및 근거 조항을 인용한 답변 생성
  - 규정 개정 이력 반영(최신 버전 우선 답변)
  - 답변 불가 시 담당 부서·담당자 안내
  - (선택) 신청서 양식 안내, 결재 절차 안내 등 툴 연동
- **결과물**: 챗봇 웹 데모, RAG 성능 평가 결과(답변 정확도, 근거 일치율)
- **입력 데이터**: 가상 사내 규정집(인사·복무·출장·보안·구매 등) 20~30종, 예상 질의응답 평가 세트 50~100건
- **난이도 메모**: RAG 기본기를 충실히 적용하는 과제로, 입문 난이도 팀에 적합

### 과제 3. 제안서·입찰자료 분석 AI Agent — 중

- **배경**: 입찰공고문과 제안요청서(RFP)의 분량이 방대해 요구사항 파악, 참가 자격 확인, 평가 항목 정리에 많은 시간과 인력이 든다.
- **목표**: 입찰자료를 분석해 요구사항·참가 자격·평가 기준·일정을 구조화하고, 요구사항 대응 여부를 점검할 추적표 초안을 자동 생성한다.
- **주요 기능**
  - RFP 문서 파싱(표·목차 포함)
  - 요구사항 추출 및 분류(기능 / 비기능 / 관리)
  - 평가 배점, 제출 일정, 필수 제출 서류 요약
  - 과거 제안서와 유사 요구사항 매칭 및 참고 문안 제시
  - 요구사항 추적표(Compliance Matrix) 초안 자동 생성 및 Excel 출력
- **결과물**: 입찰자료 분석 리포트 자동 생성 데모, 요구사항 추적표(Excel)
- **입력 데이터**: 공개된 공공 입찰공고문·제안요청서 10~20건(공공 조달 사이트 공개 자료), 가상 과거 제안서 샘플
- **난이도 메모**: 문서 내 표 구조 처리가 핵심 난관. 문서 형식을 PDF 등으로 한정하면 조절 가능

### 과제 4. 회의록 기반 Follow-up AI Agent — 중

- **배경**: 회의 후 결정사항과 액션아이템이 정리·공유되지 않거나 담당자·기한 추적이 빠져 후속 조치가 늦어진다.
- **목표**: 회의록(또는 녹취 텍스트)에서 결정사항, 액션아이템, 담당자, 기한을 추출하고 후속 알림과 진행 현황 추적까지 자동화한다.
- **주요 기능**
  - 회의록 또는 음성 인식(STT) 텍스트 입력
  - 회의 요약, 결정사항, 액션아이템(담당자·기한 포함) 추출
  - 후속 안내 메일 초안 작성 및 캘린더·업무관리 도구 연동(모의 API)
  - 이전 회의와 연결해 미완료 항목 자동 리마인드
  - 주간 액션아이템 진행 현황 리포트 생성
- **결과물**: 웹 데모, 메일·캘린더 연동 시연
- **입력 데이터**: 가상 회의록 30~50건(프로젝트 회의 시나리오), 가상 조직도·구성원 목록
- **난이도 메모**: 메일·캘린더 연동은 모의 API로 구현해 난이도 조절 가능

### 과제 5. 사내 IT 장애·문의 대응 AI Agent — 중

- **배경**: 반복 문의와 장애 접수가 몰려 대응이 늦어지고 담당자 부담이 크다.
- **목표**: 1차 문의는 AI가 직접 응대하고, 장애 유형과 긴급도를 분류해 해결 가이드를 주거나 담당자에게 티켓을 자동 생성·배정한다.
- **주요 기능**
  - IT FAQ·장애 대응 매뉴얼 기반 답변(RAG)
  - 문의 유형 및 긴급도 자동 분류
  - 과거 유사 장애 이력 검색 및 조치 방법 제안
  - 해결 불가 시 티켓 자동 생성 및 담당자 배정(모의 티켓 시스템)
  - 문의·장애 처리 현황 대시보드
- **결과물**: 챗봇 + 티켓 시스템 연동 데모, 처리 현황 대시보드
- **입력 데이터**: 가상 IT FAQ·장애 대응 매뉴얼, 가상 장애 티켓 이력 200~500건
- **난이도 메모**: RAG와 에이전트 툴 연동을 고르게 쓰는 표준형 과제

### 과제 6. 업무 인수인계 AI Agent — 중

- **배경**: 담당자가 바뀔 때 인수인계가 개인 역량에 의존해 누락이 잦고, 후임자가 업무를 파악하는 데 오래 걸린다.
- **목표**: 문서·메일·일정 등 흩어진 자료를 모아 인수인계서를 자동 생성하고, 후임자의 업무 질문에 답하는 에이전트를 만든다.
- **주요 기능**
  - 업무 자료(문서·메일·일정) 수집 및 분류
  - 표준 양식 기반 인수인계서 자동 생성(업무 목록, 진행 중 이슈, 관계자, 주기 업무)
  - 후임자 질의응답(RAG, 출처 제시)
  - 인수인계 누락 항목 점검 체크리스트 생성
- **결과물**: 인수인계서 자동 생성 및 Q&A 웹 데모, 인수인계서 샘플
- **입력 데이터**: 가상 담당자 업무 자료 세트(문서·메일·일정) 2~3명분, 인수인계서 표준 양식
- **난이도 메모**: 다양한 형식의 자료를 통합하는 데이터 준비 비중이 큼

### 과제 7. 채용 End-to-End 자동화 Agent — 중~상

- **배경**: 공고 작성, 서류 검토, 면접 일정 조율, 안내 메일 발송 등 채용 전 과정에 반복 업무가 많다.
- **목표**: 공고 작성 → 서류 검토 지원 → 면접 질문 생성 → 일정 조율 → 결과 안내를 여러 에이전트가 역할을 나눠 처리하는 파이프라인을 만든다.
- **주요 기능**
  - 직무기술서 기반 채용 공고 초안 생성
  - 이력서 파싱 및 직무 요건 대비 적합도 요약(최종 판단은 담당자)
  - 지원자별 맞춤 면접 질문 생성
  - 면접 일정 조율 및 안내 메일 자동화(모의 캘린더·메일 API)
  - 채용 단계별 진행 현황 대시보드
- **결과물**: 멀티 에이전트 기반 채용 자동화 웹 데모, 단계별 시연
- **입력 데이터**: 가상 직무기술서 5~10건, 가상 이력서 50~100건
- **난이도 메모**: 개인정보 보호와 AI 평가 공정성 이슈가 있어 합격·불합격 자동 결정이 아닌 담당자 보조로 범위 한정

### 과제 8. 고객 요구사항 기반 시스템 기능·데이터 모델 자동 설계 Agent — 상

- **배경**: 구축 프로젝트 초기에 요구사항 문서를 분석해 기능 명세와 데이터 모델을 설계하는 데 시간과 숙련된 경험이 많이 필요하다.
- **목표**: 요구사항 문서를 입력하면 기능 목록, 기능 명세서, 데이터 모델(ERD) 초안을 자동 생성하고 요구사항과 설계 결과 간 추적성을 확인한다.
- **주요 기능**
  - 요구사항 문서 분석 및 기능 / 비기능 요구사항 분류
  - 기능 명세서 초안 생성(기능 ID, 설명, 우선순위)
  - 엔티티·속성·관계 도출 → ERD 초안 시각화 및 DDL 생성
  - 요구사항 ↔ 기능 ↔ 테이블 추적표 생성
  - 설계 검토 에이전트가 누락·모순 사항 점검
- **결과물**: 설계 자동화 웹 데모, 기능 명세서·ERD·DDL 산출물 샘플
- **입력 데이터**: 가상 요구사항 정의서 5~10건(예: 재고관리, 설비관리 시스템)
- **난이도 메모**: 교육생 간 설계 지식 편차를 고려해 대상 도메인을 1~2개로 한정 권장

### 과제 9. 프로젝트 산출물 기반 기술 지식 자산화 Agent — 중

- **배경**: 프로젝트가 끝나면 설계서·보고서·이슈 기록이 저장만 되고 재활용되지 않아, 유사 프로젝트에서 같은 시행착오가 반복된다.
- **목표**: 산출물에서 핵심 기술 지식(적용 기술, 문제 해결 사례, 교훈)을 추출·분류해 검색 가능한 지식 베이스를 만든다.
- **주요 기능**
  - 다양한 형식(Word, PDF, PPT, Excel)의 산출물 파싱
  - 기술 키워드, 문제-해결 사례, 교훈(Lessons Learned) 추출
  - 표준 지식 카드 형태로 정리 및 태깅
  - 지식 검색 및 질의응답(RAG, 출처 제시)
  - 신규 프로젝트 정보 입력 시 유사 프로젝트·참고 지식 추천
- **결과물**: 지식 베이스 구축 및 검색·Q&A 웹 데모, 지식 카드 샘플
- **입력 데이터**: 가상 프로젝트 산출물 세트 3~5개 프로젝트분(설계서, 결과보고서, 이슈 목록 등)
- **난이도 메모**: 형식이 다양할수록 어려워지므로 2~3종으로 한정하면 조절 가능

### 과제 10. 제조 설비 이상정보 기반 원인·대응정보 생성 Agent — 중~상

- **배경**: 설비 이상 시 원인 파악과 조치가 숙련자 경험에 의존하고, 과거 고장·정비 이력이 체계적으로 활용되지 않는다.
- **목표**: 설비 알람·센서 이상 정보를 입력받아 과거 고장 이력과 정비 매뉴얼을 근거로 추정 원인과 대응 절차를 생성한다.
- **주요 기능**
  - 이상 이벤트(알람 코드, 센서 값) 입력 및 해석
  - 과거 고장·정비 이력 중 유사 사례 검색
  - 정비 매뉴얼 기반 점검·조치 절차 생성(근거 제시)
  - 원인 후보 우선순위 제시 및 정비 보고서 초안 작성
  - (선택) 간단한 이상 탐지 규칙과 연동한 자동 알림
- **결과물**: 이상 대응 지원 웹 데모, 정비 보고서 자동 생성 샘플
- **입력 데이터**: 공개 설비 데이터셋(예: UCI AI4I 2020 예지보전 데이터셋) 또는 가상 알람·정비 이력 300건 이상, 가상 정비 매뉴얼
- **난이도 메모**: 센서 데이터 해석이 필요해, 이상 이벤트를 정리된 형태로 제공하면 조절 가능

## 4. 추천

### 1순위 — 과제 3. 제안서·입찰자료 분석 AI Agent

- **실데이터로 만들 수 있다.** 나라장터 등에 공개된 실제 RFP를 쓸 수 있어, 다른 팀이 가상 데이터를 만드는 시간에 기능을 만들 수 있고 시연 설득력도 높다.
- **이미 만든 것을 그대로 쓴다.** 공공 RFP는 HWP/HWPX 비중이 높은데, 개인 프로젝트에서 HWPX 읽기와 확장자별 파일 라우팅을 이미 구현했다. 과제에서 "핵심 난관"으로 꼽은 표 파싱에 먼저 도달해 있는 셈이다.
- **결과물이 분명하다.** 요구사항 추적표(Excel)라는 구체적인 산출물이 있어, 정답 세트를 만들어 요구사항 추출 재현율·분류 정확도로 평가하기 쉽다.
- **에이전트 구성이 자연스럽다.** 파싱 → 요구사항 추출·분류 → 과거 제안서 매칭(RAG) → 추적표 생성으로 역할이 나뉘어, 과목 5·6(툴 연동, 멀티 에이전트)을 보여 주기 좋다.
- **주의점**: 범위를 "PDF + HWPX 두 형식", "특정 분야(예: SW 구축 사업) RFP 10~20건"으로 먼저 한정해야 한다. 과거 제안서 샘플은 가상으로 만들어야 한다.

### 2순위 — 과제 5. 사내 IT 장애·문의 대응 AI Agent

- RAG, 분류, 티켓 생성 툴, 대시보드가 모두 들어가 과목 4~6을 고르게 보여 줄 수 있는 가장 무난한 선택이다.
- 지금 만들고 있는 규정 RAG 챗봇 구조(FastAPI + Streamlit, 근거 제시 답변)를 거의 그대로 확장할 수 있다.
- 다만 FAQ·매뉴얼·티켓 200~500건을 가상으로 만들어야 하고, 표준형 과제라 여러 팀이 고를 가능성이 높아 차별화는 따로 고민해야 한다.

### 피하는 편이 나은 과제

- **과제 2**: 난이도는 가장 낮지만 수업 실습과 개인 프로젝트에서 이미 하고 있는 내용이라, 캡스톤으로 새로 보여 줄 것이 적다.
- **과제 1·8**: 온톨로지 설계나 ERD 품질처럼 결과물의 좋고 나쁨을 판단하기 어렵고, 기간 안에 완성도를 끌어올리기 힘들다.
- **과제 7**: 개인정보·공정성 이슈 때문에 범위가 "보조 기능"으로 제한돼 멀티 에이전트의 장점을 살리기 어렵다.

### 팀 논의 때 확인할 것

- 팀원 중 도메인 경험(제조, 인사, SI 제안 등)이 있는 사람이 있으면 그 과제의 우선순위를 올린다. 도메인 지식이 가상 데이터 품질과 평가 세트를 좌우한다.
- 1·2순위 모두 "평가 세트를 먼저 만들고 기능을 붙인다"는 순서로 가야 발표 때 정량 결과를 낼 수 있다.
