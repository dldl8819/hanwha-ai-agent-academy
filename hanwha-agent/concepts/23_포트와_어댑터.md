# 포트와 어댑터 (헥사고날 아키텍처)

## 문제 — 분기가 코드 전체로 퍼진다

같은 기능을 mock으로도, 실제 호출로도 돌려야 한다. 가장 먼저 떠오르는 방법은 함수마다 모드를 확인하는 것이다.

```python
def answer_service(question: str, mode: str) -> str:
    if mode == "mock":
        return f"[{mode}] {FIXED_ANSWER}"
    return f"[{mode}] {FIXED_ANSWER} (진짜 호출을 했다고 치자)"

def draft_service(question: str, mode: str) -> str:
    if mode == "mock":
        return f"[{mode}] {DOC_ID} 근거 신청 초안 (고정)"
    return f"[{mode}] {DOC_ID} 근거 신청 초안 (진짜 호출을 했다고 치자)"

def search_service(question: str, mode: str) -> str:
    if mode == "mock":
        return f"[{mode}] {DOC_ID} 국내출장 여비 규정 v2.0"
    return f"[{mode}] {DOC_ID} 국내출장 여비 규정 v2.0 (진짜 호출을 했다고 치자)"
```

기능이 셋이면 분기도 셋이다. 여기에 **모드가 하나 늘거나 공급자가 바뀌면 고칠 자리가 기능 수만큼 늘어난다.** [[22_AI_Native_애플리케이션]]에서 "모델은 6~12개월마다 바뀐다"고 한 전제와 정면으로 부딪히는 구조다.

## 포트 · 어댑터 · 팩토리

분기를 **한 곳으로 모으는** 것이 해법이다. 역할을 셋으로 나눈다.

| 이름 | 무엇 | 이 프로젝트에서 |
| --- | --- | --- |
| **포트(Port)** | 바깥과 주고받을 내용을 정한 **규약**. 구현을 담지 않는다 | `LLMPort` — `answer()`, `draft()` |
| **어댑터(Adapter)** | 포트를 실제 기술로 **구현**한 것 | `MockLLM`(고정 응답), `ClaudeLLM`(진짜 호출) |
| **팩토리(Factory)** | 어떤 어댑터를 쓸지 고르는 **단 한 곳** | `integrations/factory.py` |

서비스는 "LLM에게 물어본다"까지만 알고, 그게 Claude인지 고정 응답인지는 모른다. 모드 분기는 팩토리 한 곳에만 남는다.

```text
services ──▶ LLMPort(규약) ◀── MockLLM
                           ◀── ClaudeLLM
                 ▲
          factory 가 고른다
```

이렇게 안쪽(업무 규칙)을 가운데 두고 바깥 기술을 갈아 끼우는 구조를 **헥사고날 아키텍처(포트 & 어댑터)** 라고 한다. 원래 **테스트를 위해** 고안된 방식이다. 외부 호출을 가짜로 바꿔 끼울 수 있어야 테스트가 네트워크 없이 돌기 때문이다.

## `typing.Protocol` 로 규약 만들기

```python
from dataclasses import dataclass
from typing import Protocol, runtime_checkable

@dataclass
class LLMResult:
    text: str
    model: str
    input_tok: int
    output_tok: int
    cost_krw: float
    latency_ms: int

@runtime_checkable
class LLMPort(Protocol):
    def answer(self, *, question: str, contexts: list[dict], user: dict) -> LLMResult: ...

class FixedLLM:                       # LLMPort 를 상속하지 않았다
    def answer(self, *, question: str, contexts: list[dict], user: dict) -> LLMResult:
        return LLMResult(text=FIXED_ANSWER, model="fixed", input_tok=0,
                         output_tok=0, cost_krw=0.0, latency_ms=0)
```

돌려보면 이렇게 나온다.

```text
LLMPort in FixedLLM.__mro__     : False   ← 상속 관계가 아니다
isinstance(FixedLLM(), LLMPort) : True    ← 그런데 통과한다
```

**상속하지 않았는데 통과한다.** Protocol은 "이 클래스를 물려받았는가"가 아니라 **"약속한 메서드를 갖고 있는가"** 로 판단하기 때문이다(구조적 타이핑). 어댑터를 만들 때 포트를 import 해서 상속할 필요가 없고, 규약 쪽이 어댑터를 몰라도 된다.

### `LLMResult` 가 text만 담지 않는 이유

응답 문자열 외에 모델명, 입력/출력 토큰, 비용, 지연 시간을 같이 담는다. [[22_AI_Native_애플리케이션]]의 운영 원칙 — **호출 한 번마다 돈과 시간이 들고, "나중에 최적화"가 안 통한다** — 를 자료 구조에 박아둔 것이다. 나중에 붙이려면 모든 어댑터를 다시 고쳐야 한다. UI 킷의 `meta_footer`가 이 값들을 그대로 받아 화면에 찍는 자리다.

## Protocol 과 ABC 의 차이

| | `typing.Protocol` | `abc.ABC` |
| --- | --- | --- |
| 판단 기준 | 메서드를 갖고 있는가 (구조적) | 그 클래스를 상속했는가 (명목적) |
| 상속 | 필요 없다 | **반드시** 상속해야 한다 |
| 미구현 시 | 조용히 `isinstance` 가 False | 인스턴스를 만들 때 `TypeError` |
| 어울리는 곳 | 남이 만든 클래스, 갈아끼우는 외부 연동 | 우리가 직접 만드는 클래스 묶음의 공통 뼈대 |

직접 확인한 결과다.

```text
ABC  - isinstance(NotInherited(), LLMBase) : False        ← 메서드가 같아도 상속 안 했으면 아니다
ABC  - 미구현 상태로 인스턴스화            : TypeError    ← 만들 때 바로 막아준다
```

ABC는 강제력이 강한 대신 상속을 요구한다. 외부 SDK를 감싸는 어댑터에는 Protocol 쪽이 편하다. 공급자가 준 클래스를 그대로 쓰면서도 규약을 만족시킬 수 있기 때문이다.

### `runtime_checkable` 의 한계

```python
class WrongSignature:
    def answer(self, x): ...          # 인자 이름도 타입도 다르다

isinstance(WrongSignature(), LLMPort)   # → True
```

`runtime_checkable`이 붙은 Protocol의 `isinstance`는 **메서드 이름만 본다.** 인자 구성이 달라도 통과한다. 실제 호출 시점에 가서야 `TypeError`가 난다. 서명까지 확인하려면 mypy 같은 정적 타입 검사기를 돌려야 한다. `isinstance` 통과를 "제대로 구현했다"는 뜻으로 읽으면 안 된다.

## 규칙을 테스트로 강제하기

팩토리를 한 곳으로 정해도, 급할 때 서비스에서 어댑터를 직접 import 하면 그대로 무너진다. 그래서 [[04_레이어드_아키텍처]]의 계층 검사 테스트에 이 규칙도 넣어뒀다.

```python
def test_services_reach_integrations_only_through_factory() -> None:
    offenders = _violations(
        "services",
        forbidden=("app.integrations",),
        allowed=("app.integrations.factory",),   # factory 만 예외
    )
    assert not offenders, "services 가 어댑터를 직접 import 합니다. ..."
```

`backend/app/integrations/`를 만든 뒤부터 이 테스트가 실제로 의미를 가진다. 서비스에서 `llm_claude`를 직접 import 하는 순간 빌드가 깨진다.

## 실제 구현 — `backend/app/integrations/`

| 파일 | 클래스/함수 | 역할 |
| --- | --- | --- |
| `ports.py` | `LLMResult`, `LLMPort` | 결과 형태와 규약(포트) |
| `llm_claude.py` | `ClaudeLLM` | Claude API 실물 어댑터 |
| `factory.py` | `get_llm()` | 어떤 어댑터를 쓸지 고르는 단 한 곳 |

### `ports.py`

```python
from dataclasses import dataclass, field
from typing import Protocol, runtime_checkable

@dataclass
class LLMResult:
    text: str
    model: str
    input_tok: int = 0
    cache_tok: int = 0
    output_tok: int = 0
    cost_krw: float = 0.0
    latency_ms: int = 0
    extras: dict = field(default_factory=dict)   # 화면에 필요한 여분 데이터

@runtime_checkable
class LLMPort(Protocol):
    def answer(self, *, question: str, contexts: list[dict], user: dict) -> LLMResult: ...
```

앞의 실습 버전에서 `cache_tok`과 `extras`가 추가됐고, 대부분의 필드에 기본값이 생겼다. 고정 응답 어댑터는 토큰이 없으니 `text`와 `model`만 넣으면 된다.

**`extras: dict = {}`가 아니라 `field(default_factory=dict)`인 이유**: 기본값으로 `{}`를 직접 쓰면 모든 인스턴스가 **같은 딕셔너리 하나를 공유**한다. 한 결과에 값을 넣으면 다른 결과에도 들어가 있는 사고가 난다. `default_factory`는 인스턴스를 만들 때마다 새 딕셔너리를 만든다. `dataclass`는 이 실수를 막으려고 가변 기본값을 직접 쓰면 아예 `ValueError`를 낸다.

`*`(별표) 뒤의 인자는 **키워드로만** 받는다. `answer("질문", [], {})`처럼 순서로 넘기면 에러가 나고, `answer(question=..., contexts=..., user=...)`로 이름을 붙여야 한다. 인자가 셋 다 비슷해 보여서 순서를 바꿔 넘기는 실수를 막는다.

### `llm_claude.py` — 어댑터

```python
PRICING = {'input': 1.0, 'cache_write': 1.25, 'cache_read': 0.1, 'output': 5.0}  # USD / 100만 토큰
USD_KRW = 1400.0

def estimate_cost_krw(input_tok: int, output_tok: int) -> float:
    usd = input_tok / 1000000 * PRICING['input'] + output_tok / 1000000 * PRICING['output']
    return round(usd * USD_KRW, 1)
```

가격표와 환율이 어댑터 파일 안에 있다. **공급자가 바뀌면 가격도 같이 바뀌기 때문**이다. 서비스는 `LLMResult.cost_krw`만 읽으면 된다.

```python
class ClaudeLLM:
    name = 'claude'

    def __init__(self) -> None:
        try:
            from anthropic import Anthropic          # import 를 함수 안에서 한다
        except ImportError as exc:
            raise ExternalServiceError("anthropic 패키지가 설치 되어 있지 않습니다.") from exc

        settings = get_settings()
        key = settings.anthropic_api_key            # SecretStr | None
        if key is None:
            raise ExternalServiceError("ANTHROPIC_API_KEY 가 비어있습니다.")
        self._client = Anthropic(api_key=key.get_secret_value())
        self._model = settings.llm_model
```

**`anthropic`을 파일 맨 위가 아니라 `__init__` 안에서 import 한다.** 맨 위에 두면 패키지가 없는 환경에서 이 파일을 import 하는 순간 앱 전체가 뜨지 않는다. mock 모드로만 쓰는 사람도 막힌다. 함수 안에 두면 **실제로 `ClaudeLLM`을 만들 때만** 필요해지고, 그때 없으면 우리 예외로 알려준다.

```python
    def _call(self, system: str, user_text: str) -> tuple[str, dict, int]:
        started = time.perf_counter()
        try:
            response = self._client.messages.create(
                model=self._model,
                max_tokens=get_settings().max_tokens,
                system=system,
                messages=[{"role": "user", "content": user_text}],
            )
        except Exception as exc:
            log.exception("Claude 호출 실패")
            raise ExternalServiceError("Claude 호출에 실패했습니다.") from exc

        text = "".join(b.text for b in response.content if getattr(b, "type", "") == "text")
        usg = response.usage
        usage = {
            "input": getattr(usg, "input_tokens", 0) or 0,
            "cache_read": getattr(usg, "cache_read_input_tokens", 0) or 0,
            "cache_write": getattr(usg, "cache_creation_input_tokens", 0) or 0,
            "output": getattr(usg, "output_tokens", 0) or 0,
        }
        elapsed = int((time.perf_counter() - started) * 1000)
        return text, usage, elapsed
```

- `_call`은 **호출 한 번의 공통 작업**만 한다 — 보내고, 받고, 텍스트·토큰·시간을 뽑는다. `answer`, `draft`처럼 기능이 늘어도 호출 방식은 여기 한 곳에만 있다.
- `time.perf_counter()`는 시간 **차이**를 재기 위한 시계다. 벽시계(`time.time()`)는 시스템 시간 조정에 영향을 받지만 이건 단조 증가만 한다.
- `getattr(usg, "...", 0) or 0` — 필드가 **없어도**(`getattr`의 기본값), **`None`이어도**(`or 0`) 0으로 맞춘다. SDK 버전이나 캐시 사용 여부에 따라 값이 빠지거나 `None`으로 오기 때문이다.

```python
    def answer(self, *, question: str, contexts: list[dict], user: dict) -> LLMResult:
        system = _load_prompt("answer_system.md")
        prompt = (
            f"## 사용자\n{user.get('name')} - {user.get('dept')}\n\n"
            f"## 근거 문서\n{_context_block(contexts)}\n\n"
            f"## 질문\n{question}"
        )
        text, usage, ms = self._call(system, prompt)
        total_in = usage["input"] + usage["cache_read"] + usage["cache_write"]
        return LLMResult(
            text=text, model=self._model,
            input_tok=total_in, cache_tok=usage["cache_read"], output_tok=usage["output"],
            cost_krw=estimate_cost_krw(total_in, usage["output"]),
            latency_ms=ms,
        )
```

프롬프트를 `## 사용자` / `## 근거 문서` / `## 질문`으로 나눠 조립한다. 모델이 어디까지가 근거이고 어디부터가 질문인지 구분하게 하려는 것이다. `_load_prompt`(프롬프트 파일 읽기)와 `_context_block`(근거 문서 문자열 만들기)은 이후 실습에서 만든다.

### `factory.py` — mock / live 분기의 유일한 지점

```python
from functools import lru_cache

from app.core.config import get_settings
from app.core.exceptions import ModeNotAvailable
from app.integrations.ports import LLMPort

@lru_cache
def _live_llm() -> LLMPort:
    from app.integrations.llm_claude import ClaudeLLM    # live 일 때만 import
    return ClaudeLLM()

def get_llm() -> LLMPort:
    settings = get_settings()
    if not settings.is_live:
        raise ModeNotAvailable(
            "테스트용 mock 어댑터는 만들지 않았습니다. "
            ".env의 APP_MODE 를 live로 두고 터미널에서 부르세요."
        )
    return _live_llm()
```

**반환 타입이 `LLMPort`다.** 서비스는 `get_llm().answer(...)`만 부르고, 받은 것이 `ClaudeLLM`인지 다른 어댑터인지 모른다. 이 문서 맨 앞의 "기능마다 퍼지던 `if mode == "mock"` 분기"가 이 파일 하나로 모였다.

**mock 모드에서는 조용히 넘어가지 않고 막는다.** 가짜 어댑터를 아직 만들지 않은 상태에서 mock일 때 live 어댑터를 대신 돌려주면, 개발·테스트 중에 **실제 API가 호출되고 과금된다.** 그래서 `ModeNotAvailable`(409)로 명시적으로 멈춘다.

```text
is_live : False
ModeNotAvailable (409)
테스트용 mock 어댑터는 만들지 않았습니다. .env의 APP_MODE 를 live로 두고 터미널에서 부르세요.
```

**`ClaudeLLM` import를 함수 안에 둔 효과는 직접 확인할 수 있다.** mock 모드에서 `get_llm()`을 부른 뒤 `sys.modules`를 보면 이렇다.

```text
anthropic import 됨?  : False
llm_claude import 됨? : False
```

mock으로 쓰는 동안에는 Anthropic SDK를 **아예 불러오지 않는다.** `llm_claude.py`의 `__init__` 안에서 `anthropic`을 import 하는 것과 합쳐 이중으로 막혀 있다. SDK가 설치되지 않은 환경에서도 mock 모드로는 앱이 뜬다.

**`@lru_cache` — 어댑터를 한 번만 만든다.** 인자가 없는 함수라 첫 호출 결과가 계속 재사용된다. 요청마다 `Anthropic` 클라이언트를 새로 만들지 않고 연결을 재사용한다. 다만 [[20_Docker와_PostgreSQL]]의 `get_settings` 캐시와 같은 성격이라, **만들어진 시점의 모델명과 키를 계속 쥐고 있다.** 실행 중에 `.env`를 바꾸면 `_live_llm.cache_clear()`로 비워야 반영된다.

**문자열 두 개를 나란히 쓰면 공백 없이 붙는다.** 괄호 안에서 `"...않았습니다." ".env의..."`처럼 이어 쓰면 파이썬이 하나로 합치는데, 사이에 공백을 넣지 않으면 `않았습니다..env의`처럼 붙어서 출력된다. 앞 문자열 끝에 공백을 하나 두는 게 좋다.

### 의존 방향 전체

```text
api/v1 (라우터) ──▶ services ──▶ repositories ──▶ models
                       │
                       └──▶ integrations/factory ──▶ ports (LLMPort)
                                      │
                                      └──▶ llm_claude (ClaudeLLM)   ← 서비스는 이걸 모른다
```

### 노트북에서 방금 만든 모듈 불러오기

```python

from app.integrations.ports import LLMPort, LLMResult

from app.integrations import llm_claude
llm_claude = importlib.reload(llm_claude)   # 이미 불러온 모듈을 다시 읽는다
```

- `invalidate_caches()` — 파이썬은 한 번 훑은 폴더의 파일 목록을 기억한다. 노트북이 켜진 상태에서 **새 파일을 만들면** 그 파일을 못 찾을 수 있어서 기억을 비운다.
- `reload()` — 이미 import 한 모듈은 다시 import 해도 새로 읽지 않는다. **기존 파일을 고친 뒤**에는 `reload`로 다시 읽어야 바뀐 코드가 반영된다.

### 실습 중 만난 이슈: 포트와 서명이 달라도 알아채지 못한다

노트북에서 포트와 어댑터의 서명을 나란히 찍어봤다.

```python
sig_port = inspect.signature(ports.LLMPort.answer, eval_str=True)
sig_impl = inspect.signature(llm_claude.ClaudeLLM.answer, eval_str=True)
```

```text
LLMPort.answer   : (self, *, question: str, contexts: list[dict], user: dict) -> LLMResult
ClaudeLLM.answer : (self, *, question: str, contexts: list[dict], usser: dict) -> LLMResult
```

어댑터 쪽 인자 이름이 `usser`로 오타가 나 있었다. 앞에서 정리한 **`runtime_checkable`의 한계**가 그대로 드러난 사례다. `isinstance(ClaudeLLM(), LLMPort)`는 메서드 이름 `answer`만 보므로 **여전히 True**다. 실제로 `answer(..., user=...)`로 부르는 순간에야 `TypeError: got an unexpected keyword argument 'user'`가 난다.

서명을 직접 찍어 비교하는 셀이 이 한계를 사람 눈으로 메워주는 장치였다. 테스트로 옮기면 이렇게 고정할 수 있다.

```python
def test_claude_adapter_matches_port_signature() -> None:
    port = inspect.signature(LLMPort.answer, eval_str=True)
    impl = inspect.signature(ClaudeLLM.answer, eval_str=True)
    assert list(port.parameters) == list(impl.parameters)
```
