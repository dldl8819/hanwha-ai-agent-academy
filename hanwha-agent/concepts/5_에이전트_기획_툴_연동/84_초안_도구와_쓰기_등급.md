# 초안 도구와 쓰기 등급

[[78_에이전트_루프와_멈추는_조건]]의 부작용 등급에서 `internal` 칸에 처음 들어온 도구다.
검색은 아무것도 바꾸지 않았다. 초안 도구는 DB 에 한 행을 쓴다.

## 흐름

```text
1바퀴  search_documents 요청 → 검색 실행 → 근거
2바퀴  create_draft 요청     → drafts 에 1행 저장 → 초안
3바퀴  end_turn              → AskOut(answer, sources, draft)
```

## 저장 자리

```python
class Draft(Base, TimestampMixin):
    __tablename__ = "drafts"
    id:       Mapped[int] = mapped_column(primary_key=True)
    run_id:   Mapped[str] = mapped_column(ForeignKey("runs.id"), nullable=False, index=True)
    doc_type: Mapped[str] = mapped_column(String(32))
    fields:   Mapped[dict] = mapped_column(JSON)
    body:     Mapped[str] = mapped_column(Text)
```

`run_id` 가 외래키다. 어느 질문에서 만들어졌는지가 남는다. [[78_에이전트_루프와_멈추는_조건]]에서
`internal` 은 「즉시 + 감사 로그」라고 했는데 감사 로그 테이블은 따로 없다. `runs` 와 `drafts` 를
`run_id` 로 이으면 「누가 무슨 질문을 해서 무엇이 저장됐나」가 나온다. 지금은 이것이 감사 로그다.

마이그레이션은 강사님 파일을 가져오지 않고 직접 만들었다. 이 저장소의 리비전 체인
(`c50400eb2ecf` 가 head)이 강사님 것과 번호가 달라 `down_revision` 이 맞지 않는다.
autogenerate 결과에 `drafts` 생성만 나온 것을 확인하고 올렸다([[21_Alembic_마이그레이션]]).

## 도구 정의

```python
SIDE_EFFECT = "internal"
DOC_TYPES = ("국내출장 신청서",)

"properties": {
    "doc_type": {"type": "string", "enum": list(DOC_TYPES)},
    "fields":   {"type": "object", "description": "양식의 칸과 값. 예: {\"출장지\": \"부산\"}"},
},
```

```python
def run(*, run_id: str, doc_type: str, fields: dict, user: dict) -> dict:
    if doc_type not in DOC_TYPES:
        return {"error": f"모르는 양식입니다: {doc_type}. 가능한 값: {list(DOC_TYPES)}"}
    rows = {k: str(v) for k, v in fields.items()}
    rows["성명 / 소속"] = f"{user.get('name', '')} / {user.get('dept', '')}"
    ...
```

셋을 본다.

- **양식은 `enum` 으로 묶었다.** 스키마가 막고, 그래도 오면 `run()` 이 한 번 더 막는다.
- **막을 때 예외가 아니라 `error` 를 돌려준다.** [[79_도구_정의와_tool_result]]에서 인자 하나 틀리면
  루프가 터진다고 적었다. 여기서는 모델이 읽고 고칠 수 있는 문장으로 돌려준다. `is_error`
  플래그는 아직 안 붙는다.
- **신청자는 서버가 넣는다.** `rows["성명 / 소속"]` 은 `user` 에서 온다. 모델이 `fields` 에
  같은 칸을 넣어도 덮어쓴다.

## 서버가 넣는 인자를 도구마다

```python
ours = {search_documents.NAME: {"user": user},
        create_draft.NAME:     {"user": user, "run_id": run_id}}
out = runner(**c.args, **ours[c.name])
```

[[79_도구_정의와_tool_result]]의 `runner(**c.args, user=user)` 가 도구마다 넣을 값이 달라지면서
표가 됐다. 원리는 같다 — 스키마에 없는 칸은 모델이 못 정한다. `run_id` 를 모델이 정할 수 있다면
남의 실행 기록에 초안을 붙일 수 있다.

## 출처가 사라졌다

```text
검색 도구를 돈 뒤 : sources 3건
초안 도구를 돈 뒤 : sources 0건   ← 사라졌다
```

[[81_출처와_판정이_답과_어긋난다]]의 `last_out` 덮어쓰기가 초안 도구에서 바로 터졌다. 초안 결과에는
`sources` 가 없으니 검색 → 초안 순서면 출처가 0건이 된다.

```python
if runner and c.name == create_draft.NAME:
    made = out
elif runner:
    last_out = out
```

초안을 따로 받는 것으로 막았다. **절반만 고쳐졌다.** 검색을 두 번 부르면 앞 검색의 출처가
사라지는 경우([[81_출처와_판정이_답과_어긋난다]]의 일비 + 재택근무)는 그대로다. 도구 이름으로
갈래를 나누는 방식이라 도구가 늘 때마다 `elif` 가 는다.

## 화면

`AskOut.draft: DraftOut | None` 이 생기고, 화면에 「업무 문서까지 작성 (도구 사용)」 체크박스가
생겼다. 체크하면 `POST /chat/messages?tools=true` 로 가서 `ask_with_tools()` 가 답한다.
기본은 여전히 `ask()` 다.

초안은 카드로 그리고 「아직 아무 곳에도 전송되지 않았습니다」를 붙인다. `internal` 과 `external`
의 경계를 화면 문구로도 긋는 셈이다.

## 실제로 돌려 봤다

| 질문 | 모델이 한 일 | 결과 |
| --- | --- | --- |
| 10월 27~29일 부산 고객사 미팅 출장 신청서 초안 | 검색 없이 바로 `create_draft` | 초안 저장, 출처 0, `enough=False` |
| 출장 신청서 써줘 | 도구 없이 되물음 | 초안 없음 |
| 싱가포르 해외 출장 신청서, 11/3~7 | 검색만 세 번 | 상한, 초안 없음 |
| 부산 숙박비 한도 + 10/27~29 신청서 | 검색 → 초안 → 답 | 출처 3, 초안 1 |

넷째가 수업의 흐름이고 `made` 분리 덕에 출처도 남았다. 나머지에서 넷이 나왔다.

**연도를 지어냈다.**

```json
{"출장지": "부산", "출장시작일": "2024년 10월 27일", "출장종료일": "2024년 10월 29일", "출장목적": "고객사 미팅"}
```

질문에 연도가 없고 시스템 프롬프트에도 날짜가 없다. 모델이 2024 를 넣었고 그대로 `drafts` 에
저장됐다. 조회 도구였다면 답 문장이 틀릴 뿐인데 쓰기 도구에서는 **틀린 값이 남는다.**
현재 날짜는 서버가 프롬프트에 넣어 주거나 `run()` 이 날짜 칸을 검사해야 한다.

**칸 이름이 매번 다르다.** 첫째는 `출장시작일·출장종료일·출장목적`, 넷째는 `출장기간` 하나에
목적 칸이 없다. `fields` 가 `{"type": "object"}` 라 무엇이든 받는다. 양식 이름은 `enum` 으로
묶었는데 양식 안의 칸은 묶지 않았다. 신청서라면 칸이 정해져 있어야 결재로 넘길 수 있다.
`fields` 를 `properties` + `required` 로 바꾸면 스키마가 모델에게 칸을 알려 준다.

**초안이 「근거 부족」 안내와 같이 나온다.** 첫째는 검색을 안 했으니 `enough_evidence=False` 다.
화면은 이 값이 거짓이면 「등록된 문서에서 근거를 확인하지 못했습니다」를 띄운다. 잘 만든 초안
아래에 그 안내가 붙는다. 근거 충분 표시는 규정 질문에 맞춘 것이라 초안 요청에는 맞지 않는다.
[[81_출처와_판정이_답과_어긋난다]]의 「표시가 답과 어긋난다」가 한 가지 더 늘었다.

**해외 양식이 없으면 찾기만 반복한다.** 국내 양식으로 억지로 만들지 않은 것은 맞다. 대신
해외 규정을 찾아 검색어를 세 번 바꾸다 상한에 닿았다. [[80_도구_루프를_돌려_보다]]의 해외
비즈니스석과 같은 모양이다. 「없다」를 말하게 하는 신호가 도구 결과에 없다.

둘째(되묻기)는 잘 됐다. 출장지·목적·기간이 없으니 초안을 만들지 않고 물었다. 칸을 지어내지
않은 경우다. 첫째와 둘째를 가른 것은 질문에 값이 있었는지뿐이고, 연도처럼 빠진 값 하나는
묻지 않고 채웠다.
