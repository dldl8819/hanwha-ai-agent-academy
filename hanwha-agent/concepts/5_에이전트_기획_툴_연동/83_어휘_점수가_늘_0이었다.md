# 어휘 점수가 늘 0이었다

[[82_수업_코드_고친_것_일곱]]의 4·5번은 숫자를 바꾸는 수정이다. 하나씩 넣어 다시 쟀다.

## 정규식 한 글자

```python
_TOKEN = re.compile(r"[가-힣A-Za-z0-9]")       # 전
_TOKEN = re.compile(r"[가-힣A-Za-z0-9]+")      # 후

def _tokens(text: str) -> set[str]:
    return {t for t in _TOKEN.findall(text or "") if len(t) > 1}
```

`+` 가 없으면 `findall` 이 글자를 하나씩 돌려준다. 바로 아래 `len(t) > 1` 이 한 글자짜리를
버린다. **집합이 늘 비고 `score()` 는 늘 0.0 이다.**

[[75_리랭킹_두_가지]]에 적은 숫자로 확인된다.

```text
표2               코사인 0.5724 × 0.7 + 0 × 0.3 + 0.03 = 0.4307
제11조(일비)        코사인 0.6084 × 0.7 + 0 × 0.3        = 0.4259
```

기록된 rerank 점수와 소수 넷째 자리까지 같다. 간이 리랭커는 설명과 달리
**`0.7 × 코사인 + 표 가산점`** 이었다. [[75_리랭킹_두_가지]]에서 「BM25 와 다른 어휘 중복률」을
설명한 부분은 코드가 의도한 동작이고, 실제로 돈 적은 없다.

## 하나씩 넣어 쟀다

같은 골든셋 v2 30문항, 같은 DB. 한 프로세스에서 `_TOKEN` 과 `judge_gate` 를 바꿔 끼웠다.

```text
                         수정 전   _TOKEN+   _TOKEN+ & judge_gate
 기본 검색                  90.0
 + Multi-Query             86.7
 + 하이브리드                80.0
 + 리랭킹 (간이)              93.3      90.0      90.0
 + 크로스 인코더              90.0       -        93.3
```

수정 전 다섯 숫자는 [[76_정책_필터를_되돌리고_다시_재다]]와 같다. 측정이 재현된다는 것을 먼저
확인하고 나서 수정의 효과를 읽었다. `_TOKEN` 은 간이 리랭커만, `judge_gate` 는 크로스 인코더
행만 건드리므로 각 열에서 바뀌는 것은 한 칸씩이다.

**1등이 바뀌었다.** 간이 93.3 → 90.0, 크로스 인코더 90.0 → 93.3.

## 간이 리랭커: G16 이 다시 틀렸다

```text
G16  직급별 일비를 표로 정리해주세요     기대 kind=표

--- 수정 전 (어휘 늘 0)
    코사인 0.5700 rerank 0.4307 어휘 0.000 [표]  표2                 ← 정답
    코사인 0.6100 rerank 0.4259 어휘 0.000 [조항] 제3장 제1절 제11조(일비)
    코사인 0.6000 rerank 0.4185 어휘 0.000 [조항] 별표1

--- _TOKEN 수정
    코사인 0.6100 rerank 0.5010 어휘 0.250 [조항] 제3장 제1절 제11조(일비)
    코사인 0.5900 rerank 0.4894 어휘 0.250 [조항] DOC-HR-014_v2.0
    코사인 0.5600 rerank 0.4669 어휘 0.250 [조항] 제1장 제5조(여비의 종류)
    질문 토큰: ['일비를', '정리해주세요', '직급별', '표로']
```

`+` 를 붙여도 토큰은 **조사가 붙은 어절**이다. 「일비를」은 본문의 「일비」와, 「표로」는
「표」와 맞지 않는다. 넷 중 「직급별」 하나만 걸려 조항 셋이 똑같이 0.25(=1/4)를 받는다.
0.3 × 0.25 = 0.075 가 더해지니 가산점 0.03 으로는 따라잡지 못하고, 표2 는 3위 밖으로 나갔다.

[[75_리랭킹_두_가지]]에서 「표 가산점 0.03 이 결정적」이라고 적었다. 맞는 말이었는데 이유가
달랐다. **어휘 점수가 0 이라서 0.03 이 결정적일 수 있었다.** 어휘가 돌기 시작하니 0.03 은
작다. [[73_키워드_검색과_RRF]]의 토크나이저 문제(쉼표가 금액을 부순다)에 조사 문제가 하나 더
붙은 셈이다. 형태소 분석 없이 어절로 겹침을 세면 한국어에서는 거의 겹치지 않는다.

## 크로스 인코더: G26 이 맞았다

```text
G26  해외 체류비는 하루에 얼마인가요?     (규정에 없는 질문)
    코사인 0.6000 rerank 0.1788 [조항] 제3장 제1절 제11조(일비)
    코사인 0.5700 rerank 0.0360 [조항] 제12조(식비)
    코사인 0.5800 rerank 0.0230 [조항] 제22조(장기 출장)
```

코사인 최고 0.6000 ≥ 임계값 0.60 — 「근거 있음」이었다. 크로스 인코더 최고 0.1788 < 합격선 0.2
— 「근거 없음」이다. 「규정에 없는 사항」 유형이 83.3 → 100.

[[77_점수를_재면서_쓰지_않는다]]에서 잰 분포가 그대로 맞았다. 답 없음 문항의 크로스 인코더
최대가 0.1788 이라고 적었는데 그게 G26 이다. 코사인으로는 0.01 틈 위에 걸려 있던 문항이
여유 0.0612 쪽으로 오자 걸러졌다. [[77_점수를_재면서_쓰지_않는다]]의 고칠 순서 ②번이 수업에서
그대로 고쳐졌다.

## 같은 93.3% 가 아니다

| | 29일차 간이 93.3% | 지금 크로스 인코더 93.3% |
| --- | --- | --- |
| 틀린 문항 | G07, G26 | G07, G04 |
| 운으로 맞은 것 | G16(어휘 0 덕분), G04(목차 조각) | 없음 |
| 판정 점수 | 코사인 (여유 0.01) | 크로스 인코더 (여유 0.0612) |

남은 둘의 성격도 분명하다. G07 은 `DOC-FI-009` 가 색인되지 않았다(검색 밖). G04 는 목차 조각을
크로스 인코더가 4위로 내리고 정답 조항이 13위 밖이라 다시 읽지도 못한다([[77_점수를_재면서_쓰지_않는다]]).

[[77_점수를_재면서_쓰지_않는다]]에서 「목차를 빼면 93.3% 보다 내려갈 수도 있다, 그래도 내려간 쪽이
사실에 가깝다」고 적었다. 이번에는 내려가지 않고 1등이 바뀌었다. 간이 리랭커는 사실에 가까워지며
90.0 으로 내려갔고 크로스 인코더는 판정을 바로잡아 93.3 으로 올라갔다.

## 왜 몰랐나

리포트에는 최종 점수(`score`, `rerank_score`)만 남는다. 어휘 점수는 `rerank_score` 안에 섞여
들어가 따로 보이지 않는다. 0 이 세 줄 나란히 있었다면 바로 이상하다고 알았을 것이다.

[[74_기법을_더했는데_떨어졌다]] 이후로 문항을 열어 보는 습관은 생겼는데, 점수를 만드는
**함수**는 열지 않았다. 「어휘 점수가 0 일 수 있는가」를 묻는 테스트 하나면 잡혔다.

```python
def test_score_overlaps():
    assert score("숙박비 상한", "숙박비 상한은 70,000원") > 0
```

부분 점수를 리포트에 남기는 것과 이 테스트가 다음에 할 일이다.

참고: backend/app/rag/reranker.py, evals/run_eval.py, evals/golden_set.yaml
