# 출처와 판정이 답과 어긋난다

`ask_with_tools` 는 「출처는 모델에게 다시 묻지 않는다」로 끝난다. 답은 모델이 쓰고
출처와 `enough_evidence` 는 코드가 붙인다. [[80_도구_루프를_돌려_보다]]의 여섯 질문에서
둘이 서로 다른 말을 하는 경우가 셋 나왔다.

## 출처는 마지막 호출에서만 꺼낸다

```python
last_out = out if runner else last_out
...
for s in last_out.get("sources", []):
    sources.append(AnswerSource(**s))
```

`last_out` 은 덮어쓰기다. 도구를 세 번 부르면 앞의 두 번 결과는 버려진다.

```text
출장 일비와 재택근무 장비 지원 기준을 같이 알려주세요
  답    : 4급 상당 직원의 국내출장 일비는 1일 30,000원입니다 ...
  출처  : DOC-HR-021 v1.2 제10조(장비) · 제2조(정의) · 제6조(신청 절차)
```

답의 첫 절반이 출장 일비인데 출처에는 재택근무 지침만 있다. 일비의 근거(DOC-HR-014)는
1턴에서 찾았고 3턴 전에 덮였다. **답에 있는 금액의 출처가 화면에서 사라졌다.**

## enough_evidence 가 답과 반대로 나온다

`enough_evidence=bool(last_out.get("passed"))` — 마지막 검색이 임계값을 넘었는지다.
모델이 그 근거로 답을 했는지와는 상관이 없다.

| 질문 | 모델의 답 | `enough_evidence` |
| --- | --- | --- |
| 법인카드 한도가 얼마인가요? | 「규정에서 확인하지 못했습니다」 | **True** |
| 해외 출장 비즈니스석 | (상한에 닿아 답을 마치지 못했습니다) | **True** |
| 개정 전 국내출장 숙박비 | v2.0 개정 내역을 근거로 설명 | **False** |

법인카드는 [[76_정책_필터를_되돌리고_다시_재다]]에 적은 G07 그대로다 — `DOC-FI-009` 가
색인되지 않아 국내출장 규정 제30조(법인카드)가 0.61 로 걸렸다. 모델은 그 조항을 읽고
한도가 없다고 맞게 판단했다. 코드는 0.61 ≥ 0.60 이니 근거 충분이라고 표시했다.

해외 출장은 세 번째 검색어 `해외 출장 규정 여비` 가 「목적·다른 규정과의 관계·정의」에
걸려 통과했다. 그 결과는 모델이 읽지도 않았다([[80_도구_루프를_돌려_보다]]).
화면에는 「답을 마치지 못했다」와 「근거 충분」과 국내출장 조항 세 개가 함께 나온다.

## 임계값 게이트가 없어졌다

`ask()` 에서는 임계값 미달이면 모델을 부르지 않았다.

```python
if not found.passed:
    out = _fallback(run_id, attemps=1)
    ...
    return out
```

`ask_with_tools` 에는 이 자리가 없다. `passed=False` 인 결과도 모델에게 그대로 가고,
모델이 그걸로 답을 쓴다. 「개정 전 숙박비」가 그랬다. 근거 부족을 막는 일이 코드에서
`agent_system.md` 의 한 줄(「근거에 없으면 '규정에서 확인하지 못했습니다' 라고 말합니다」)로
옮겨 갔다.

이번 여섯 질문에서는 그 한 줄이 대체로 지켜졌다. 법인카드에서 모델은 지어내지 않았다.
다만 [[28_가드와_재시도_폴백]]에서 코드로 막던 것을 프롬프트로 막게 된 것은 확률로 막게 된
것이다. 그리고 모델에게는 `passed` 가 보이는데 쓰라는 말이 없다.

## 정책이 읽는 문장이 바뀌었다

```python
found = LiveRetriever().search(question=query, user=user, session=session)
```

`question=` 에 사용자 질문이 아니라 **모델이 고른 검색어**가 들어간다. 정책은 이 문장에서
「개정 전」을 찾아 만료본을 보여줄지 정한다([[62_현행_판과_보안등급]]).

- 사용자가 「개정 전」이라고 했는데 모델이 검색어에서 빼면 만료본이 안 나온다.
- 사용자가 안 했는데 모델이 넣으면 만료본이 나온다.

보안등급은 `user` 로 가니 영향이 없다. 버전 정책만 모델 손에 들어갔다. 만료본은 숨길 정보가
아니라서 위험하지는 않지만, 정책이 사용자의 의도가 아니라 모델의 표현을 보게 된 것은 맞다.

## version_note 의 [0]

강사님 코드의 `retriever.py` 마무리는 `b.split(" - ")` 뒤에 `[0]` 이 없다.

```text
강사님: ['국내출장 여비 규정 v1.1', '만료 버전']은(는) 만료된 버전이라 ...
수정본: 국내출장 여비 규정 v1.1은(는) 만료된 버전이라 ...
```

`ask()` 에서는 이 문장이 화면에만 갔다. 도구 루프에서는 `version_note` 가 tool_result 에
실려 **모델에게 간다.** 리스트 표기가 그대로 모델의 입력이 된다. 이 저장소는 [[76_정책_필터를_되돌리고_다시_재다]]
때부터 `[0]` 이 있는 쪽을 쓴다.

같은 실험에서 하나 더 보였다. 「법인카드 한도」를 검색해도 note 가 「국내출장 여비 규정 v1.1
은 만료」다. 후보 안에 v1.1 조각이 섞여 있다가 걸러졌기 때문이다. 질문과 상관없는 문서의
만료 안내가 붙는다.

## 고친 것과 남긴 것

| | |
| --- | --- |
| 고쳤다 | `retriever.py` 의 `[0]` · 로그 오타 「상항」→「상한」, 「건너띕니다」→「건너뜁니다」 · `_cotext_block` 은 가져오지 않음(이 저장소는 `_context_block`) |
| 남겼다 | 출처 덮어쓰기 · `enough_evidence` 판정 · 게이트 없음 · `is_error` 미사용 · `stop_reason` 미확인 · 상한 턴의 버려지는 검색 |

남긴 것은 수업 코드대로 두었다. 다음 수업이 이 루프 위에 쌓일 것이라 지금 구조를 바꾸면
비교가 어려워진다([[77_점수를_재면서_쓰지_않는다]]와 같은 이유).

고친다면 순서는 이렇게 본다.

1. **출처를 모든 호출에서 모은다** — `last_out` 대신 목록에 누적하고 `doc_id+locator` 로 중복 제거.
   답에 있는 금액의 출처가 사라지는 것은 사용자에게 바로 보이는 잘못이다.
2. **도구 실행을 try 로 감싸 `is_error` 로 돌려준다** — 지금은 인자 하나 틀리면 Run 이 「진행중」으로 남는다.
3. **`stop_reason == "max_tokens"` 를 따로 처리하고, 상한 턴에서는 도구 대신 마무리 호출을 한다.**
4. **`enough_evidence` 를 모델이 실제로 쓴 근거 기준으로** — 이건 모델에게 「근거 없음」을 구조로
   말하게 해야 하니 출력 형식을 다시 정해야 한다. 가장 크다.

backend/app/rag/retriever.py, backend/app/rag/policy.py
