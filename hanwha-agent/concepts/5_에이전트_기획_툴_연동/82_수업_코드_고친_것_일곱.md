# 수업 코드 고친 것 일곱

w8/day02 첫 시간은 새 기능이 아니라 그동안 쌓인 결함을 고쳤다. 일곱 가지이고 성격이 다르다.

| # | 증상 | 자리 | 성격 |
| --- | --- | --- | --- |
| 1 | 첫 질문만 40초 넘게 걸린다 | `main.py` lifespan | 속도 |
| 2 | 모델이 읽는 근거가 220자에서 잘린다 | `_context_block`, `SOURCE_KEYS` | **답변 품질** |
| 3 | 폴백일 때 화면에 이유가 없다 | `views/chat.py` | 화면 |
| 4 | 간이 리랭커의 어휘 점수 | `reranker._TOKEN` | **측정값** → [[83_어휘_점수가_늘_0이었다]] |
| 5 | 판정이 리랭킹 점수를 안 쓴다 | `judge_gate` | **측정값** → [[83_어휘_점수가_늘_0이었다]] |
| 6 | 화면 이동이 한 박자 늦다 | `router.go` | 화면 |
| 7 | 업로드 진행률이 83%에서 멈춘다 | `run_ingest_job` | 화면 |

4·5 는 숫자가 바뀌는 수정이라 따로 쟀다. 여기서는 나머지를 본다.

## 1. 서버가 뜰 때 모델을 연다

```python
def _warm_up_models() -> None:
    settings = get_settings()
    if not settings.warm_up_models:
        return
    started = time.perf_counter()
    try:
        if settings.embed_provider == "local":
            factory.get_embedder()
        if settings.reranker == "cross_encoder":
            factory.get_cross_encoder()
    except AgentError as e:
        log.warning("모델을 미리 열지 못했습니다 - %s (첫 질문에서 다시 엽니다)", e.message)
        return
```

`factory.get_embedder()` 는 `@lru_cache` 로 한 번 만든 객체를 계속 돌려준다([[23_포트와_어댑터]]).
그래서 미리 한 번 부르기만 하면 첫 질문이 그 객체를 받는다. 따로 저장할 필요가 없다.
리랭커는 여는 데 44.7초였다([[75_리랭킹_두_가지]]). 그 시간이 첫 사용자에서 서버 시작으로 옮겨 간다.

실패해도 서버는 뜬다. 모델 폴더가 없으면 경고만 남기고, 첫 질문에서 같은 예외가 다시 난다.
「못 열었다」가 서버를 죽일 이유는 아니라고 본 것이다.

강사님 코드는 이름이 `warn_up_models` 다. warm-up 의 오타로 보고 `warm_up_models` 로 옮겼다.
설정 필드 이름이라 [[75_리랭킹_두_가지]]의 `RERANKER_MODEL_DIR` 와 같은 함정이 있다 —
`.env` 에 `WARM_UP_MODELS=false` 를 적어도 필드 이름이 다르면 아무 일이 안 일어난다.

## 2. 모델이 잘린 근거를 읽고 있었다

```python
# 전
f"...\n{c.get('quote') or c.get('text') or ''}"
# 후
f"...\n{c.get('text') or c.get('quote') or ''}"
```

`quote` 는 화면에 보여 주려고 220자에서 자른 것이다.

```python
def _shorten(text: str, limit: int = 220) -> str:
    text = " ".join((text or "").split())
    return text if len(text) <= limit else text[:limit - 1] + "..."
```

`or` 의 순서 때문에 `quote` 가 있으면 늘 그쪽이 먼저였다. 적재된 조각 길이를 세 봤다.

```text
청크 205개 · 평균 129자 · 중앙 106자 · 최대 667자
220자 초과 22개 (10.7%)  — 조항 13 / 190, 표 9 / 15
```

조항은 7% 만 잘리는데 **표는 15개 중 9개, 60%가 잘렸다.** 표는 마크다운으로 바뀌면서 `|`
와 칸이 붙어 길어진다([[40_표_추출과_마크다운]]). 「표 안의 조건 조합」 유형에서 리랭킹으로 표를
1위에 올려 놓고([[75_리랭킹_두_가지]]), 정작 모델에게는 표의 앞 220자만 보내고 있었다.
직급별 일비 표라면 아래쪽 직급 행이 통째로 빠진다.

이건 검색 측정([[76_정책_필터를_되돌리고_다시_재다]])에 드러나지 않는다. 채점기는 `text`
전체에서 키워드를 찾는다. 검색은 맞았고 그 뒤 모델에게 가는 길에서 잘렸다.

도구 쪽도 같다. `SOURCE_KEYS` 에 `text` 를 더해 tool_result 에 원문이 실린다. 대신 근거가
길어진 만큼 입력 토큰이 는다 — [[80_도구_루프를_돌려_보다]]에서 턴마다 1,100 토큰씩 쌓이던
그 자리다. 이제 `quote` 와 `text` 가 둘 다 실리니 220자까지는 같은 글자가 두 번 간다.

## 3. 폴백 이유를 화면에

`ask()` 는 임계값 미달이면 모델을 부르지 않고 폴백한다([[28_가드와_재시도_폴백]]).
그때 화면에 「등록된 문서에서 근거를 확인하지 못했습니다」를 띄운다. 이 저장소는 이미
들어가 있었다.

## 6. 화면 이동이 한 박자 늦다

```python
def go(page: str) -> None:
    st.session_state["page"] = page
    st.rerun()
```

Streamlit 은 버튼을 누르면 스크립트를 위에서 아래로 한 번 다시 실행한다([[16_Streamlit]]).
화면을 고르는 코드(`current_page()`)는 위쪽에 있고 버튼은 아래쪽 화면 안에 있다. 버튼 처리에서
`page` 를 바꿔도 이번 실행은 이미 이전 화면을 고른 뒤다. 다음 상호작용에서야 바뀐다.
`st.rerun()` 은 그 자리에서 실행을 끊고 처음부터 다시 돌린다.

같은 날 필터 값도 고쳤다.

```python
for key in ("f_dept", "f_level", "f_status", "f_q"):
    st.session_state[key] = st.session_state[key]
```

자기 자신을 대입하는 줄이라 아무것도 안 하는 것처럼 보인다. 위젯 `key` 로 쓰인 상태는
그 위젯이 그려지지 않는 실행이 지나가면 Streamlit 이 지운다. 목록 화면에서 다른 화면으로
갔다 오면 필터가 초기화되던 이유다. 다시 대입하면 위젯 소유가 아니라 일반 상태로 남는다.

## 7. 진행률이 83% 에서 멈췄다

업로드 작업은 여섯 단계를 보여 주는데 [[58_임베딩_적재]] 때 다섯 단계만 `ok` 로 바꾸고
진행률을 `5/6 = 83%` 에 두었다. 마지막 「검색 반영 및 현행 버전 지정」이 구현되지 않았다고
봤기 때문이다.

다시 보니 현행 지정은 이 작업이 시작되기 **전에** 끝난다. 업로드 요청이 `create_document()`
에서 버전을 등록할 때 이전 현행을 만료로 내리고 새 판을 현행으로 넣는다. 배경 작업이 끝나면
여섯 단계가 다 끝난 상태다.

강사님 코드는 `steps[5]["time"] = "현행 지정 완료"` 를 넣고 진행률을 100% 로 올렸는데
`steps[5]["state"]` 는 `todo` 로 남는다. 「완료」 글자와 회색 아이콘이 같이 나온다.
이 저장소는 `_DONE_STEPS = 6` 으로 여섯 단계 모두 `ok` 로 바꿨다.

하나 남는다. 재임베딩(`start_reindex_job`)도 같은 작업 함수를 쓴다. 만료된 판을 재임베딩해도
「현행 지정 완료」가 찍힌다. 재임베딩은 현행을 바꾸지 않으니 거짓 표시다.
