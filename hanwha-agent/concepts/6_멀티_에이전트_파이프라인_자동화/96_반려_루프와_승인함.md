# 반려 루프와 승인함

[[94_HITL_승인]]에서 「반려 뒤 다시 쓰기는 분기는 있는데 탈 길이 없다」고 적었다. 길이 생겼고, 그 위에 API 와 화면이 붙었다.

## 반려하면 다시 쓰고 다시 멈춘다

```text
START → draft → gate ──(승인)──────────────────────────→ send → END
                 ↑  └─(반려 · 다시 쓴 횟수 < 2)──→ rewrite ─┐
                 └──────────────────────────────────────────┘
                    └─(반려 · 상한)──→ END
```

```python
def pick(state: dict) -> str:
    if state["decision"].get("approved"):
        return "send"
    return "rewrite" if rewrite is not None and state.get("rewrites", 0) < MAX_REWRITES else "end"

if rewrite is not None:
    g.add_node("rewrite", rewrite)
    g.add_edge("rewrite", "gate")
```

`rewrite` 를 넘겨야만 순환이 생긴다. 안 넘기면 [[94_HITL_승인]]의 그래프 그대로다.

```python
def _rewrite(state: dict) -> dict:
    note = state["decision"].get("note", "")
    return {"text": f"{state['text']} (사유 반영: {note})", "rewrites": state.get("rewrites", 0) + 1}
```

반려 → rewrite → gate 에서 다시 `interrupt()`. `reject()` 는 재개 결과에 `__interrupt__` 가 다시 있으면 요청을 새 문구로
**다시 대기**로 돌리고 결정자·결정 시각을 비운다.

```text
반려 1 : 대기중 · 부산 출장 신청서 승인 요청 10/27 (사유 반영: 금액 확인)
반려 2 : 대기중 · ... (사유 반영: 금액 확인) (사유 반영: 기간 확인)
반려 3 : 반려됨
감사 로그 : 승인 대기 · 반려 · 재작성 · 반려 · 재작성 · 반려
반려 확정 뒤 승인 : PermissionDenied 이미 처리된 요청: 반려됨
```

[[94_HITL_승인]]의 `again` 분기가 그대로 쓰였다. 함수 쪽은 미리 있었고 그래프에 선이 없었을 뿐이다.
[[77_점수를_재면서_쓰지_않는다]]의 「분기는 있는데 같은 일을 한다」와 달리, 이번엔 선 하나로 살아났다.

다시 쓰기는 지금 **사유를 덧붙이는 것**이다. 반려가 쌓일수록 괄호가 는다. 사유를 읽고 실제로 고쳐 쓰는 일은 모델이
맡을 자리이고 `_rewrite` 하나만 바뀐다.

## 승인함 API

| 경로 | 하는 일 |
| --- | --- |
| `GET /api/v1/approvals` | 대기 목록 + 지표 넷 |
| `POST /api/v1/approvals/{id}/approve` | 승인하고 그 자리에서 실행 |
| `POST /api/v1/approvals/{id}/reject` | 사유와 함께 반려 (`note` 는 `min_length=1`) |

```python
def get_checkpointer() -> Iterator[object]:
    url = get_settings().database_url.replace("postgresql+psycopg://", "postgresql://", 1)
    with PostgresSaver.from_conn_string(url) as cp:
        yield cp

CheckpointerDep = Annotated[object, Depends(get_checkpointer)]
```

[[10_FastAPI]]의 `yield` 의존성이다. 요청마다 저장소 연결을 열고 응답이 끝나면 닫는다.

실제로 불렀다.

```text
헤더 없이 승인     401 로그인이 필요합니다
사원이 승인        403 승인 권한이 없습니다
사유 없이 반려     422
팀장이 반려        200 대기중 — 사유를 반영한 문구로 다시 대기합니다
다른 팀장이 승인   200 실패 · 전송 꺼짐
```

막는 자리가 셋이다. 401 은 라우터(누구인가), 422 는 요청 스키마(무엇을 보냈나), 403 은 서비스의 `_decide`(그럴 권한이 있나).
[[94_HITL_승인]]에서 넣은 「본인 요청은 본인이 승인할 수 없다」는 이번 수업 코드에도 들어왔다.

## 지표 넷

```python
return {"waiting": ..., "approved_today": sum(1 for row in decided if row.status == DONE),
        "rejected_today": sum(1 for row in decided if row.status == REJECTED), "avg_minutes": ...}
```

「오늘 승인」은 `승인·실행`(DONE)만 센다. 승인했지만 전송이 꺼져 `실패 · 전송 꺼짐` 이 된 건은 승인에도 반려에도
안 들어가고 평균 처리 시간에만 들어간다. 확인할 때 승인 1건·반려 1건이 있었는데 지표는 `approved_today: 0, rejected_today: 1` 이었다.
[[94_HITL_승인]]의 「승인과 실행은 다른 칸」이 지표에서는 「승인했는데 셀 칸이 없다」로 나온다.

## 승인함 화면

지표 넷 · 대기 표 · 고른 요청의 상세(실행 유형 + 「되돌릴 수 없음」 배지, 대상 채널, 보낼 메시지, 감사 로그) · 승인/반려 버튼.

```python
def _can_decide(user: dict | None) -> bool:
    return (user or {}).get("role") in ("팀장", "관리자")
```

버튼은 팀장·관리자에게만 열린다. **화면에서 끄는 것은 편의이고 막는 것은 서버다.** 화면을 거치지 않고 API 를 직접 부르면
403 이 나오는 것을 위에서 봤다. 화면의 역할 목록과 서버의 `can_approve`(`User` 모델)가 같은 규칙을 두 곳에 적고 있다.

사이드바 승인함 메뉴 옆의 대기 건수는 화면이 다시 그려질 때마다 목록 API 를 한 번씩 불러 얻는다. 버튼을 누를 때마다
요청이 하나씩 더 나간다.

## 보낸 메시지를 남긴다

```python
class SlackMessageLog(Base):
    __tablename__ = "slack_message_log"
    approval_id, channel, ts, text, sent_at, deleted_at
```

전송이 성공하면 Slack 이 돌려준 `ts`(메시지 식별자)와 함께 남긴다. `ts` 가 있어야 그 메시지를 찾아 지우거나 고칠 수 있다.
`deleted_at` 칸이 그 자리다. [[87_외부_전송과_승인_경계]]에서 「보냈다는 것은 Slack 이 돌려준 ok·ts 가 말한다」고 했는데, 그 값을 DB 에 남기게 됐다.

강사님 코드의 칸 이름은 `sent_ad` 였다. `sent_at` 의 오타로 보고 고쳐 옮겼다. 칸 이름은 마이그레이션으로 DB 에 박히므로
처음에 고치는 편이 싸다. 이 마이그레이션은 [[93_체크포인트]]의 `include_name` 덕에 표 생성 한 가지만 담겼다.

## Slack 봇과 오타 세 번째

워크스페이스·채널을 만들고 Slack API 에서 앱을 만들어 봇 토큰 범위를 넷 추가하고 토큰을 발급한다. `.env` 의 `SLACK_BOT_TOKEN` 에
넣고 채널에서 `/invite @앱이름` 으로 봇을 초대한다. 봇이 채널에 없으면 토큰이 맞아도 못 보낸다.

수업 중 따라 적은 설정은 `slack_default_channle` 이었다. [[75_리랭킹_두_가지]]의 `RERANKER_MODEL_DIR`,
[[82_수업_코드_고친_것_일곱]]의 `warn_up_models` 에 이어 세 번째다. 설정 칸은 이름이 틀려도 오류 없이 기본값으로 돈다.
설정을 하나 넣으면 값을 바꿔 보고 동작이 달라지는지 확인한다.

직접 보내 보는 `slack_send.py` 는 토큰이 없을 때 `SlackResult(..., simulate=True)` 를 만드는데 칸 이름은 `simulated` 다.
토큰 없는 사람은 그 줄에서 `TypeError` 가 난다. 고쳐 옮겼다.
