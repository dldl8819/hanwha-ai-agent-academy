# 도구 등록소

[[84_초안_도구와_쓰기_등급]]까지 도구 연결은 서비스 안에 흩어져 있었다.

```python
TOOLS = [search_documents.SCHEMA, create_draft.SCHEMA]
TOOL_RUNNERS = {search_documents.NAME: search_documents.run,
                create_draft.NAME: create_draft.run}
```

도구 하나를 늘리면 `chat_service.py` 의 import·목록·실행표 세 군데를 고쳐야 했다. 그리고
[[78_에이전트_루프와_멈추는_조건]]에서 「`SIDE_EFFECT` 칸만 있고 읽는 코드가 없다」고 적은 그대로였다.
등록소가 두 문제를 같이 푼다.

## 구조

```python
class SideEffect(str, Enum):
    NONE = "none"
    INTERNAL = "internal"
    EXTERNAL = "external"

@dataclass
class Tool:
    name: str
    description: str
    side_effect: SideEffect
    fn: Callable
    schema: dict
    reversible: bool = True

    def run(self, **kwargs) -> dict:
        if self.side_effect is SideEffect.EXTERNAL:
            raise ApprovalRequired(f"'{self.name}'은(는) 승인 없이 실행할 수 없습니다.", ...)
        return self.fn(**kwargs)

_REGISTRY: dict[str, Tool] = {}
def register(tool: Tool) -> Tool: ...
def get(name: str) -> Tool: ...
def all_tools() -> list[Tool]: ...
def load_all() -> None: ...
```

| 칸 | 하는 일 |
| --- | --- |
| `SideEffect` | 등급이 문자열이 아니라 열거형. 오타(`"externl"`)는 `register` 에서 `ValueError` |
| `Tool.run()` | **등급을 실행 직전에 강제한다.** external 이면 `fn` 을 부르지 않는다 |
| `reversible` | 되돌릴 수 있는가. Slack 은 `False` |
| `load_all()` | 도구 모듈을 모아 등록한다 |

`str, Enum` 을 같이 상속해서 `SideEffect("none")` 으로
문자열에서 만들 수 있고 `SideEffect.NONE == "none"` 도 참이다. 검색·초안 모듈은 여전히
`SIDE_EFFECT = "none"` 문자열을 갖고 있고 `register()` 가 바꿔 끼운다.

## 서비스가 도구 이름을 모른다 (절반)

```python
registry.load_all()
tools = registry.all_tools()
schemas = [t.schema for t in tools]
by_name = {t.name: t for t in tools}
...
tool = by_name.get(c.name)
out = tool.run(**c.args, **ours.get(c.name, {}))
```

목록과 실행표는 등록소에서 받는다. 도구를 늘려도 이 부분은 그대로다.

그런데 루프 아래쪽은 여전히 이름을 안다.

```python
ours = {"search_documents": {"user": user},
        "create_draft": {"user": user, "run_id": run_id}}
...
if tool and c.name == "create_draft":
    made = out
elif tool and c.name == "search_documents":
    last_out = out
elif tool and c.name == "send_slack" and not out.get("approval_required"):
    sent = out
```

서버가 넣는 인자(`ours`)와 결과를 어디에 담을지(`made`/`last_out`/`sent`)가 이름으로 갈린다.
[[84_초안_도구와_쓰기_등급]]에서 「도구가 늘 때마다 `elif` 가 는다」고 적은 것이 그대로 남았다.
`Tool` 에 「어떤 서버 값을 받는가」와 「결과가 어디로 가는가」를 칸으로 두면 이것도 등록소로 옮길 수 있다.

## 등록하는 길이 둘이다

```python
def load_all() -> None:
    from app.tools import create_draft, search_documents
    for m in (search_documents, create_draft):
        register(Tool(name=m.NAME, ..., side_effect=m.SIDE_EFFECT, fn=m.run, schema=m.SCHEMA))

    from app.tools import send_slack   # import 하면 모듈이 스스로 register() 한다
```

검색·초안은 등록소가 모듈 상수를 읽어 감싸고, Slack 은 모듈 맨 아래에서 스스로 등록한다.
같은 일을 두 방식으로 한다.

import 로 등록하는 방식에는 함정이 있다. 파이썬은 모듈을 한 번만 실행한다. 노트북에서
`importlib.reload(registry)` 로 `_REGISTRY` 를 비우면 `send_slack` 은 이미 import 돼 있어
`register()` 가 다시 불리지 않는다. 수업 노트북이 `registry` 와 `send_slack` 을 **둘 다** reload 한
이유다. 하나만 reload 하면 Slack 이 목록에서 조용히 사라진다.

`load_all()` 은 질문마다 불린다. 검색·초안은 매번 새 `Tool` 로 덮어쓰고 Slack 은 처음 한 번만
등록된다. 결과는 같지만 하는 일이 다르다.

정의가 따라간다.
