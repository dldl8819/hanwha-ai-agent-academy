# 시스템 프롬프트가 두 번 들어갔다

w8/day03 첫 시간은 [[36_체인을_앱에_붙이기]] 때 만든 `ask()` 경로의 결함 둘을 고쳤다. 하나는 코드,
하나는 프롬프트 파일이다. 둘이 한 질문에서 같이 드러났다.

## 체인이 system 메시지를 질문에 섞었다

```python
def call_port(value) -> LLMResult:
    messages = value.to_messages()
    question = "\n\n".join(str(m.content) for m in messages)      # 전
    return llm.answer(question=question, contexts=port_contexts, user=port_user)
```

`ChatPromptTemplate` 은 `[SystemMessage(answer_system), ("human", "{question}")]` 두 개다.
`to_messages()` 가 둘을 돌려주고 그걸 전부 이어 붙여 `question` 으로 넘겼다. 그런데 어댑터의
`answer()` 는 `answer_system.md` 를 따로 읽어 `system=` 에 싣는다.

```text
system  = answer_system.md                          ← 어댑터가 실은 것
user    = ## 사용자 ... ## 근거 문서 ... ## 질문
          answer_system.md 전문 + 사용자 질문        ← 체인이 섞은 것
```

같은 규칙이 system 과 user 양쪽에 들어갔다. 실제 질문을 가로채 길이를 쟀다.

```text
                         수정 전      수정 후
모델에게 간 question       1,271자       19자
입력 토큰 (부산 숙박비)       2,857       1,928    (−33%)
```

```python
question = str(messages[-1].content)                              # 후
if system_prompt is None:
    return llm.answer(question=question, contexts=port_contexts, user=port_user)
return llm.answer(question=question, contexts=port_contexts, user=port_user,
                  system=str(messages[0].content))
```

마지막(human) 메시지만 질문으로 넘긴다. 체인에 다른 system 프롬프트를 줬을 때만 그걸 어댑터의
`system` 으로 넘긴다 — `LLMPort.answer()` 에 `system: str | None = None` 이 생긴 이유다.

[[36_체인을_앱에_붙이기]]에서 「프롬프트 → 어댑터 → 결과」를 파이프로 이었을 때 프롬프트 템플릿과
어댑터가 **둘 다** system 을 정하고 있었다. 누가 system 을 정하는지 한 곳으로 모으지 않은 결과다.

같은 시간에 `ask()` 맨 위의 체인 생성도 지웠다. 근거 없이(`NO_CONTEXTS`) 만든 체인을 아무도
쓰지 않고, 검색 뒤에 근거를 넣어 다시 만들고 있었다.

## 프롬프트에 문서가 세 건만 있었다

```text
등록된 근거 문서는 다음 세 건입니다.
| DOC-HR-014 | 국내출장 여비 규정 | v2.0 | ...
| DOC-PU-007 | 구매·계약 규정    | v4.0 | ...
| DOC-SE-003 | 정보보안 지침     | v2.2 | ...
```

[[26_프롬프트_설계와_컨텍스트]] 때 문서가 셋이었다. 그 뒤 여덟 건으로 늘었는데 프롬프트는 그대로였다.
같은 파일 아래쪽 `doc_id` 규칙에는 여덟 개가 다 있었다. 한 파일 안에서 「셋」과 「여덟」이 같이 있었다.

수정 전에 재택근무 질문을 넣어 봤다.

```text
재택근무 신청은 며칠 전까지 해야 하나요?
  수정 전  attempts=2  입력 2,650 + 2,770
           "근거 문서가 등록되지 않아 답변할 수 없습니다. 질문 내용과 관련된
            '재택근무 운영 지침' 문서는 ..."
  수정 후  attempts=1  입력 1,721
           "재택근무 희망일 2일 전까지 그룹웨어로 신청하고 부서장의 승인을 받아야 합니다."
```

검색은 `DOC-HR-021` 을 제대로 찾아 넘겼다. 모델이 프롬프트의 「등록된 문서는 세 건」을 믿고
근거로 받은 재택근무 지침을 등록되지 않은 문서로 판단했다. 그 답이 스키마 검증에 한 번 걸려 재시도까지
했다([[28_가드와_재시도_폴백]]).

고친 프롬프트는 목록을 여덟 건으로 늘리고 **버전 칸을 뺐다.**

```text
등록된 근거 문서는 다음 여덟 건입니다. 버전은 개정될 때마다 바뀌므로, 근거 블록에 적힌 버전을 그대로 씁니다.
```

버전을 프롬프트에 박으면 개정될 때마다 프롬프트를 고쳐야 한다. [[62_현행_판과_보안등급]]에서 현행 판은
DB 가 정한다고 했다. 프롬프트가 같은 사실을 따로 들고 있으면 둘이 어긋난다. 문서 목록도 같은 문제를
안고 있다 — 아홉 번째 문서가 들어오면 또 고쳐야 한다.

## 검색 측정에 안 잡힌 이유

[[76_정책_필터를_되돌리고_다시_재다]]와 [[83_어휘_점수가_늘_0이었다]]의 측정은 검색만 본다.
재택근무 질문은 검색에서 맞았고, 그 뒤 모델이 프롬프트를 읽고 거절했다. [[82_수업_코드_고친_것_일곱]]의
「근거가 220자에서 잘렸다」와 같은 자리다 — **검색 다음, 모델 앞**. 이 구간을 재는 측정이 아직 없다.
