# 외부 전송과 승인 경계

[[78_에이전트_루프와_멈추는_조건]]의 부작용 등급 셋 중 마지막 `external` 이 처음 들어왔다.
Slack 으로 메시지를 보내는 도구다. 이번에는 **구조만** 만들었고 실제 전송은 승인(HITL)
단계에서 붙는다.

## 막는 자리가 셋이다

```text
모델이 send_slack 요청
   │
   ├─ ① Tool.run()           external 이면 ApprovalRequired          ← 지금 여기서 멈춘다
   │
   └─ (승인 서비스가 _execute 를 직접 부를 때)
        ├─ ② factory.get_slack()  ALLOW_EXTERNAL_SEND=false 면 ModeNotAvailable
        └─ ③ SlackClient()        SLACK_BOT_TOKEN 이 없으면 ExternalServiceError
```

| 문 | 무엇을 본다 | 누가 연다 |
| --- | --- | --- |
| ① 등록소 | 도구의 등급 | 승인 (사람) |
| ② 팩토리 | 서버 설정 스위치 | 운영자 (`.env`) |
| ③ 어댑터 | 토큰 | 운영자 (`.env`) |

①은 「이 요청을 사람이 허락했는가」, ②③은 「이 서버가 밖으로 나갈 수 있게 설정됐는가」다. 성격이
다르다. 승인을 받아도 개발 서버에서는 스위치가 꺼져 있어 나가지 않는다.

[[03_Pydantic]] 때 설정에 넣어 둔 `allow_external_send: bool = False` 가 처음으로 읽혔다.

## 막힌 사실을 모델에게 돌려준다

```python
try:
    out = tool.run(**c.args, **ours.get(c.name, {}))
except ApprovalRequired as e:
    out = {"error": str(e), "approval_required": True}
```

[[79_도구_정의와_tool_result]]에서 「도구가 실패하면 루프가 터진다, `is_error` 가 답」이라고 적었다.
여기서는 예외를 잡아 문장으로 돌려준다. 루프는 끊기지 않고 모델이 그 결과를 읽는다. `is_error`
플래그는 여전히 안 붙는다 — `approval_required` 라는 우리 칸을 만들었다.

프롬프트에도 한 줄이 들어갔다.

```text
밖으로 내보내는 도구는 승인을 거쳐야 실행됩니다. 「승인이 필요하다」는 결과가 오면
다시 부르지 않고, 보내지 않았다고 그대로 말합니다.
```

실제로 돌려 봤다.

```text
부산 출장 숙박비 한도를 팀 슬랙 채널에 공유해 줘
  턴1  search_documents("부산 출장 숙박비 한도")
  턴2  send_slack(text="📍 부산 출장 숙박비 안내 ... 1박당 70,000원 ...")   → approval_required
  턴3  end_turn  "슬랙 메시지 전송에 팀장 승인이 필요합니다. 승인을 받지 못해
                   채널에 공유하지 못했습니다. 다만 ... 1박당 70,000원입니다."
  sent = None
```

다시 부르지 않았고, 보내지 않았다고 말했고, 원래 물은 값은 답에 넣었다. 프롬프트 규칙이 지켜졌다.

## sent 는 비어 있어야 맞다

```python
elif tool and c.name == "send_slack" and not out.get("approval_required"):
    sent = out
```

막힌 결과는 `sent` 에 담지 않는다. 지금 구조에서 `send_slack` 은 루프 안에서 늘 막히므로 `sent` 는
**항상 None** 이다. 채워질 길은 승인 서비스가 생긴 뒤다. 화면이 `sent` 를 보고 「보냈습니다」를 띄운다면
그 근거가 모델의 문장이 아니라 실제 결과(`ts` 메시지 식별자)여야 한다는 것을 구조로 정해 둔 것이다.

[[81_출처와_판정이_답과_어긋난다]]에서 「답은 모델이, 출처는 코드가」라고 했다. 전송도 같다.
「보냈다」는 모델이 말하는 것이 아니라 Slack 이 돌려준 `ok`·`ts` 가 말한다.

## 모델이 보내려 한 것

```text
이번 프로젝트 출장비 기준을 찾아서, 10월 13일부터 15일까지 부산 출장 신청서를
작성하고, 팀 채널에 올려 줘.

  턴1 search_documents  턴2 create_draft  턴3 send_slack  턴4 end_turn
  send_slack(text="10월 13~15일 부산 출장 신청서 초안을 작성했습니다.
                   [국내출장 신청서] 출장자: 김민준 / 부서: 인프라사업부 2팀 / ...
                   출발일: 2024년 10월 13일 ...")
```

`MAX_TOOL_TURNS` 를 3 에서 4 로 올린 이유가 보인다. 검색·초안·전송에 마무리 답 한 번이면 4 턴이다.

보내려던 문구에 세 가지가 실려 있었다.

- **신청자 이름과 부서.** 초안 도구에서는 서버가 `user` 로 넣었는데([[84_초안_도구와_쓰기_등급]]),
  전송 문구는 모델이 쓴다. 모델이 초안 결과를 읽고 옮겨 적었다. 서버가 막은 값을 모델이 다른 도구로
  다시 내보낼 수 있다.
- **지어낸 연도.** 「2024년 10월 13일」이 초안에도 전송 문구에도 있다. [[84_초안_도구와_쓰기_등급]]의
  문제가 이제 밖으로 나가는 길에 올라탔다.
- **Slack 이 못 읽는 서식.** `**굵게**` 와 이모지. Slack 은 `*굵게*` 를 쓴다.

승인 화면은 이 문구를 사람에게 그대로 보여 줘야 한다. 「무엇을 보내려 하는가」를 확인하는 자리가
승인이다.

## 강사님 코드에 없던 것

`SlackClient` 는 `settings.slack_bot_token`, `settings.slack_default_channel` 을 읽는데 `Settings` 에 그 필드가
없다. pydantic-settings 는 선언하지 않은 필드를 `.env` 에서 읽지 않으므로 `AttributeError` 가 난다.
지금은 ①에서 늘 막혀 여기까지 오지 않으니 드러나지 않는다. 승인 서비스가 붙는 날 처음 터진다.
이 저장소는 두 필드를 넣어 두었다.
