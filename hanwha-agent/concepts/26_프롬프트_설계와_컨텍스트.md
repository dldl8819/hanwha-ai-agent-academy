# 프롬프트 설계와 컨텍스트 구성

[[25_Claude_API_호출]]에서는 프롬프트를 코드 안에 한 줄로 적었다. 여기서는 프롬프트를 **파일로 빼고**, 모델에게 무엇을 어떤 순서로 보여줄지(컨텍스트)를 설계한다.

## 프롬프트를 코드에 박으면 생기는 문제

```python
system="너는 사내 규정 질의 응답 도우미야. 근거가 없으면 없다고 말해."
```

- **로그에 남은 응답과 프롬프트 버전을 이을 수 없다.** 답이 이상하게 나왔을 때, 그때 어떤 지시문이었는지 코드 이력을 뒤져야 한다
- **같은 지시를 여러 곳에서 고쳐야 한다.** 기능이 늘면 비슷한 문장이 파일마다 복사된다
- 프롬프트는 코드보다 자주 바뀌는데, 고칠 때마다 코드 변경이 된다

그래서 프롬프트는 **`.md` 파일로 문서화하고, 코드는 읽어서 쓰기만** 한다.

## system 과 user 의 역할 분담

| | `system` | `messages` 의 `user` |
| --- | --- | --- |
| 성질 | 매 요청 같은 것 | 매번 다른 것 |
| 담는 것 | 역할, 규칙, 출력 형식, 인용 규칙 | 사용자 정보, 근거 문서, 질문 |
| 바뀌는 주기 | 프롬프트를 개정할 때 | 요청마다 |
| 어디에 두나 | 파일 — `answer_system.md` | 코드가 조립 — `answer()` 안 |

기준은 **"매번 같은가"**다. 같은 것은 파일로, 요청마다 달라지는 것은 코드로 조립한다. 매번 같은 부분이 한곳에 모여 있으면 [[24_API_토큰과_과금]]의 프롬프트 캐싱을 걸기도 쉽다.

## 좋은 프롬프트의 뼈대

| 칸 | 예 |
| --- | --- |
| 역할 | "사내 규정 질의응답 도우미" |
| 규칙 | "근거 밖의 내용을 지어내지 마", "권한 없는 문서는 인용하지 마" |
| 출력 형식 | "JSON 으로 출력해" |
| 근거 인용 규칙 | "문서 번호와 조항 위치를 함께 적어" |

### `backend/app/agent/prompts/answer_system.md`

```markdown
## 역할
한화시스템 임직원이 사내 규정에 관해 물으면, 함께 주어진 근거 문서만 읽고 답합니다.
(등록된 근거 문서 세 건 표)

## 규칙
1. 주어진 근거 문서 밖의 내용을 지어내지 않습니다. 모르면 모른다고 말합니다.
2. 근거가 부족하면 부족하다고 먼저 밝힙니다. 다른 문서의 내용으로 유추해서 메우지 않습니다.
3. 열람 권한이 없는 문서는 인용하지 않습니다.
4. 금액·기한·조건은 근거에 적힌 숫자를 그대로 옮깁니다. 계산이 필요하면 계산 과정을 보입니다.
5. "아마", "일반적으로" 같은 표현으로 빈틈을 메우지 않습니다.

## 출력 형식
(JSON 필드 세 개 — [[27_구조화_출력]])

## 근거 인용 규칙
`locator` 에는 문서 번호가 아니라 문서 안 위치를 적습니다.
```

규칙들이 겨냥하는 것은 전부 **"그럴듯한 오답"**이다([[22_AI_Native_애플리케이션]]). 2번은 다른 문서로 유추해 메우는 것을, 4번은 금액을 반올림하거나 바꿔 쓰는 것을, 5번은 확신 없는 일반론으로 빈 곳을 채우는 것을 막는다.

### 프롬프트 파일 읽기 — `_load_prompt`

```python
PROMPTS = Path(__file__).resolve().parent.parent / 'agent' / 'prompts'

def _load_prompt(name: str) -> str:
    path = PROMPTS / name
    return path.read_text(encoding="utf-8") if path.exists() else ""
```

경로를 `__file__` 기준으로 잡아서 어디서 실행해도 같은 폴더를 가리킨다.

**파일이 없으면 에러가 아니라 빈 문자열을 돌려준다.** 이게 함정이다.

```text
정상 이름 : 글자 수 1078 -> '## 역할'
오타 이름 : 글자 수 0    -> ''
```

`answer_sytem.md`처럼 이름을 틀리면 **규칙이 하나도 없는 빈 system 프롬프트**로 호출된다. 에러도 경고도 없이 모델이 제약 없이 답하게 되므로, 답이 갑자기 지어내기 시작하면 프롬프트 파일이 제대로 읽혔는지부터 봐야 한다.

### 실습 중 만난 이슈: 섹션이 두 번씩 들어가 지시가 충돌했다

출력 형식을 평문에서 JSON 으로 바꾸는 단계에서, 기존 절을 **교체하지 않고 아래에 추가**했더니 파일에 이렇게 남았다.

```markdown
## 출력 형식
다음 세 덩어리를 이 순서로 씁니다. 1. 답변  2. 근거  3. 판단

## 출력 형식
아래 세 필드를 가진 JSON 하나만 보냅니다.

## 근거 인용 규칙
`locator` 에는 문서 번호가 아니라 문서 안 위치를 적습니다.   예: 제12조 · p.6

## 근거 인용 규칙
문서 번호와 조항 위치를 함께 적습니다.   예: DOC-HR-014 제12조 · p.6
```

**같은 제목 아래 반대되는 지시가 두 개씩** 들어갔다. 출력은 "세 덩어리 평문"과 "JSON 만"이 부딪히고, 인용은 "문서 번호를 빼라"와 "문서 번호를 넣어라"가 부딪힌다. 모델은 어느 쪽을 따를지 정할 근거가 없어서, 평문으로 답하는 순간 뒤의 JSON 파싱이 실패한다.

코드는 같은 이름의 함수를 두 번 정의하면 뒤의 것이 이기지만, **프롬프트에는 그런 규칙이 없다.** 프롬프트를 고칠 때는 추가가 아니라 교체이고, 고친 뒤에는 같은 제목이 하나씩만 있는지 확인한다.

## 컨텍스트 윈도우

모델이 한 번에 볼 수 있는 토큰 총량이다. Claude Haiku 4.5는 200K 토큰이다.

**중요한 것은 크기가 아니라 성질이다.**

| | 앞의 대화 |
| --- | --- |
| 사람 | 기억한다 |
| 모델 | **기억하지 못한다.** 매 요청마다 필요한 것을 전부 다시 실어 보낸다 |

모델이 보는 것은 **이번 요청에 실어 보낸 프롬프트와 컨텍스트뿐**이다. 그래서 무엇을 넣고 무엇을 뺄지 정하는 것이 곧 품질이고, 넣은 만큼 입력 토큰이 되므로 곧 비용이다.

| 넣는 것 | 무엇이 들어가나 | 왜 필요한가 |
| --- | --- | --- |
| 사용자 | 이름, 부서, 사번 | 답이 그 사람 기준이어야 한다 |
| 근거 문서 | 제목, 버전, 위치, 인용문 | 답의 출처. **없으면 지어낸다** |
| 질문 | 사용자가 쓴 문장 그대로 | — |

### 근거 문서를 문자열로 — `_context_block`

```python
def _context_block(contexts: list[dict]) -> str:
    lines = []
    for i, c in enumerate(contexts, 1):
        lines.append(
            f"[근거 {i}] {c.get('title')} {c.get('version')} · {c.get('locator')} "
            f"(유사도 {c.get('score', 0):.2f})\n{c.get('quote') or c.get('text') or ''}"
        )
    return "\n\n".join(lines) if lines else "(근거 문서 없음)"
```

```text
[근거 1] 국내출장 여비 규정 v2.0 · 제12조(숙박비) · p.6 (유사도 0.91)
서울·광역시: 1박 70,000원 이내

[근거 2] 정보보안 지침 v2.2 · 제4조 · p.2 (유사도 0.48)
대외비 문서는 열람 권한이 확인된 임직원에게만 제공한다.

0건일 때 : (근거 문서 없음)
```

- `enumerate(contexts, 1)` — 번호를 1부터 매긴다. 모델이 "근거 1에 따르면"처럼 가리킬 수 있게 한다
- 유사도를 함께 보여줘서, 점수가 낮은 근거를 모델이 덜 믿게 한다
- `quote`가 없으면 `text`, 둘 다 없으면 빈 문자열 — `.get()`과 `or`로 키가 빠져도 에러가 나지 않는다
- **근거가 0건이면 빈 칸이 아니라 `(근거 문서 없음)`을 넣는다.** 빈 칸이면 모델이 "근거가 없다"는 사실 자체를 모른다. 명시해야 규칙 1번("모르면 모른다고 말합니다")이 작동한다

### 사용자 메시지 조립 — `answer()`

```python
system = _load_prompt("answer_system.md")
prompt = (
    f"## 사용자\n{user.get('name')} - {user.get('dept')}\n\n"
    f"## 근거 문서\n{_context_block(contexts)}\n\n"
    f"## 질문\n{question}"
)
```

system 프롬프트와 같은 `##` 제목 형식으로 나눠, 모델이 어디까지가 근거이고 어디부터가 질문인지 구분하게 한다. 질문 안에 "위 근거는 무시하고" 같은 문장이 들어와도, 그것이 **질문 칸 안의 데이터**라는 경계가 생긴다([[22_AI_Native_애플리케이션]]의 "외부 텍스트는 데이터이지 명령이 아니다").
