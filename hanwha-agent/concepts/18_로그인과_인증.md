# 로그인과 인증

[[17_비밀번호_해싱_bcrypt]]에서 만든 `verify_password`와 `password_hash` 컬럼을 실제 로그인 흐름에 연결한다. 백엔드에 인증 API를 만들고, 프론트엔드에서 로그인 화면과 로그인 상태 유지를 붙이는 것까지가 한 묶음이다.

## 로그인 처리 경로

| 경로 | 하는 일 |
| --- | --- |
| `POST /api/v1/auth/login` | 사번 + 비밀번호를 받아 사용자 정보를 돌려준다 |
| `GET /api/v1/auth/me` | 지금 요청을 보낸 사람이 누구인지 돌려준다 |

로그인한 뒤 상태 유지는 **`X-Emp-No` 헤더에 사번을 실어 보내는 방식**으로 처리한다. 이건 진짜 인증이 아니다. 사번만 알면 아무나 남의 정보를 조회할 수 있기 때문에, 헤더 값을 검증할 수단(JWT 토큰)은 나중에 붙인다. 지금은 "누구인지 서버에 알려주는 통로"만 먼저 뚫어두는 단계다.

## 백엔드 — 계층별로 나눠 담기

[[12_리포지토리_패턴]]·[[13_서비스_계층]]에서 나눈 구조를 그대로 따라간다. 스키마 → 리포지토리 → 서비스 → 라우터 순으로 쌓는다.

### 스키마 — `schemas/auth.py`

```python
# 로그인 요청 모델
class LoginIn(BaseModel):
    emp_no: str = Field(examples=["2016-0231"])  # 사번
    password: str = Field(min_length=1)          # 비밀번호

# 로그인 성공 시 응답할 사원 정보 모델
class UserOut(BaseModel):
    id: int
    emp_no: str = Field(examples=["2016-0231"])
    name: str
    dept: str = Field(examples=["인사총무"])
    role: Literal["일반", "팀장", "관리자"]
    clearance: Literal["일반", "3급", "대외비"]
```

요청 모델에는 `password`가 있지만 **응답 모델에는 비밀번호 관련 필드가 아예 없다.** `password_hash`를 응답에 실어 보내면 해시가 그대로 노출되므로, 모델을 그대로 내보내지 않고 응답 전용 스키마를 따로 두는 이유가 여기서도 그대로 적용된다.

### 리포지토리 — `repositories/user_repo.py`

```python
def get_by_emp_no(session: Session, emp_no: str) -> User | None:
    stmt = select(User).where(User.emp_no == emp_no).options(joinedload(User.dept))
    return session.scalars(stmt).first()
```

- `joinedload(User.dept)`를 거는 이유는 뒤에서 `user.dept.name`을 읽기 때문이다. 이게 없으면 부서 이름을 읽는 순간 쿼리가 한 번 더 나간다.
- `.one()`이 아니라 `.first()`를 쓴다. `one()`은 결과가 없으면 예외를 던지는데, **사번이 없는 것은 예외 상황이 아니라 로그인 실패라는 정상적인 결과**다. 없으면 `None`을 받아서 서비스가 판단하게 둔다.

### 서비스 — `services/auth_service.py`

```python
# User(ORM 객체) -> UserOut이 받을 수 있는 dict로 변환
def _to_out(user: User) -> dict:
    return {
        "id": user.id,
        "emp_no": user.emp_no,
        "name": user.name,
        "dept": user.dept.name,
        "role": user.role,
        "clearance": user.clearance,
    }

# 사번 + 비밀번호 검증 (비밀번호 확인 O)
def authenticate(emp_no: str, password: str) -> dict:
    with session_scope() as s:
        user = user_repo.get_by_emp_no(s, emp_no)
        if user is None or not verify_password(password, user.password_hash):
            raise AuthFailed()
        return _to_out(user)

# 사번으로 현재 사용자 조회 (비밀번호 확인 X)
def get_me(emp_no: str) -> dict:
    with session_scope() as s:
        user = user_repo.get_by_emp_no(s, emp_no)
        if user is None:
            raise AuthFailed()
        return _to_out(user)
```

**사번이 없는 경우와 비밀번호가 틀린 경우를 `if`문 하나로 묶어 같은 `AuthFailed`를 던진다.** 나눠서 "없는 사번입니다" / "비밀번호가 틀립니다"로 응답하면, 그 차이만으로 어떤 사번이 실제 등록돼 있는지 알아낼 수 있다. [[05_예외_계층_설계]]에서 만든 `AuthFailed`의 기본 메시지가 "사번 또는 비밀번호가 올바르지 않습니다"인 것도 같은 이유다.

`get_me`가 비밀번호를 확인하지 않는 것은 임시 방식이기 때문이다. JWT를 붙이면 토큰 자체가 위조 여부를 증명하므로 이 자리가 토큰 검증으로 바뀐다.

### 라우터 — `api/v1/auth.py`

```python
router = APIRouter(prefix="/auth", tags=["auth"])

@router.post("/login", response_model=UserOut)
def login(body: LoginIn) -> dict:
    return auth_service.authenticate(body.emp_no, body.password)

@router.get("/me", response_model=UserOut)
def me(x_emp_no: Annotated[str | None, Header()] = None) -> dict:
    if x_emp_no is None:
        raise AuthFailed("로그인이 필요합니다.")
    return auth_service.get_me(x_emp_no)
```

`Header()`를 쓰면 **파이썬 변수명 `x_emp_no`가 HTTP 헤더 `X-Emp-No`에 대응된다.** 언더스코어가 하이픈으로 바뀌고 대소문자는 구분하지 않는다. 헤더가 없으면 기본값 `None`이 들어오므로 그 자리에서 `AuthFailed`를 던진다.

라우터 함수는 `dict`를 돌려주는데 `response_model=UserOut`이 붙어 있어서, FastAPI가 그 dict를 `UserOut` 기준으로 걸러서 내보낸다. 서비스가 실수로 필드를 더 담아도 응답에는 스키마에 선언된 것만 나간다.

## main.py 라우터 연결

```python
from app.api.v1 import auth, documents   # 모듈째로 가져와서 auth.router / documents.router 로 쓴다

app.include_router(documents.router, prefix="/api/v1")
app.include_router(auth.router, prefix="/api/v1")
```

`include_router`는 **라우터를 한 번에 하나만 받는다.** 시그니처가 `include_router(self, router, *, prefix=..., tags=..., dependencies=...)` 형태라 `*` 뒤는 전부 키워드 전용이고, 라우터를 두 개 넘기면 `TypeError`가 난다.

```python
# TypeError: include_router() takes 2 positional arguments but 3 were given
app.include_router(documents.router, auth.router, prefix="/api/v1")
```

이렇게 설계된 이유는 라우터마다 옵션이 달라지기 때문이다. `tags`는 `/docs`에서 묶이는 그룹이라 라우터별로 다르고, 특히 `dependencies`는 인증을 붙이는 순간 갈라진다. 문서 API에는 로그인 검사를 걸어야 하지만 로그인 API에까지 걸면 로그인을 할 수 없다.

## 프론트엔드 — 로그인 상태 유지

Streamlit은 이벤트가 있을 때마다 스크립트를 처음부터 다시 실행하므로([[16_Streamlit]] 재실행 모델), 로그인 상태는 반드시 `session_state`에 있어야 한다. 이걸 화면 코드에 흩어놓지 않고 `core/` 아래로 모았다.

```text
frontend/
    core/
        session.py     # 로그인 상태와 필터값 보관
        router.py      # 지금 어느 화면인지
    views/
        login.py       # 로그인 화면
    app.py             # 진입점 + 인증 게이트
```

### `core/session.py` — 상태의 단일 창구

```python
DEFAULTS: dict = {
    "page": "login",
    "user": None,
    "f_dept": "전체", "f_level": "전체", "f_status": "전체", "f_q": "",
}

def init_state() -> None:
    for key, value in DEFAULTS.items():
        st.session_state.setdefault(key, value)   # 이미 있으면 건드리지 않는다

def is_authenticated() -> bool:
    return current_user() is not None

def login(user: dict) -> None:
    st.session_state["user"] = user
    st.session_state["page"] = "documents"        # 로그인 성공 -> 문서 목록으로

def logout() -> None:
    st.session_state["user"] = None
    st.session_state["page"] = "login"
    for key in ("f_dept", "f_level", "f_status", "f_q"):
        st.session_state[key] = DEFAULTS[key]      # 필터도 같이 초기화
```

`setdefault`라서 재실행될 때마다 불러도 기존 값을 덮어쓰지 않는다. 로그아웃에서 검색 필터까지 되돌리는 것은, 다음 사람이 로그인했을 때 앞사람이 걸어둔 조건이 남아 있으면 안 되기 때문이다.

### `core/router.py` — 화면 키 하나로 분기

```python
def current_page() -> str:
    return st.session_state.get("page", "login")

def go(page: str) -> None:
    st.session_state["page"] = page
```

`st.session_state["page"]`를 화면마다 직접 만지지 않고 이 두 함수로만 통하게 한다.

### `views/login.py` — 로그인 화면

```python
def render() -> None:
    st.title("사내 업무 에이전트")
    st.text_input("사번", key="login_emp_no", placeholder="예) 2016-0231")
    st.text_input("비밀번호", type="password", key="login_pw")

    if not st.button("로그인"):
        return                      # 버튼을 안 눌렀으면 여기서 끝 (재실행마다 통과)

    try:
        from core import api_client
    except ImportError:
        st.info("백엔드 호출 통로(core/api_client.py)는 추후에 붙입니다.")
        return

    try:
        user = api_client.login(st.session_state["login_emp_no"], st.session_state["login_pw"])
    except api_client.ApiError as exc:
        st.error(str(exc))
        return

    session.login(user)
    st.rerun()                      # 상태가 바뀌었으니 화면을 다시 그린다
```

- `if not st.button(...): return` 형태를 쓰는 이유는 재실행 모델 때문이다. 버튼은 눌린 그 실행에서만 `True`라서, 누르지 않은 실행은 여기서 바로 빠져나간다.
- `api_client`를 `try/except ImportError`로 감싼 것은 아직 그 파일이 없기 때문이다. 화면 먼저 만들고 통신은 다음에 붙이는 순서라, 없으면 안내만 띄우고 넘어간다.
- 로그인에 성공하면 `session.login(user)`로 상태를 바꾸고 `st.rerun()`으로 다시 그린다. `rerun` 없이 끝내면 이번 실행은 이미 로그인 화면을 그린 뒤라서, 한 번 더 조작해야 화면이 넘어간다.

### `app.py` — 인증 게이트

```python
def main() -> None:
    session.init_state()

    if not session.is_authenticated():
        login_view.render()
        return            # 사이드바를 그리지 않고 끝낸다

    render_sidebar()

    page = router.current_page()
    ...
```

`return`으로 끊는 것이 핵심이다. 이게 없으면 로그인 전에도 사이드바와 본문이 같이 그려진다.

사이드바에는 로그인한 사용자 정보와 로그아웃 버튼이 붙는다.

```python
user = session.current_user()
if user is not None:
    st.sidebar.markdown(
        '<div class="ag-user"><div>'
        f'<div class="ag-user-name">{html.escape(user["name"])}</div>'
        f'<div class="ag-user-role">{html.escape(user["dept"])}</div>'
        '</div></div>',
        unsafe_allow_html=True,
    )
    if st.sidebar.button("로그아웃", key="nav_logout"):
        session.logout()
        st.rerun()
```

이름과 부서는 DB에서 온 값이라 `html.escape`를 거쳐 넣는다. `unsafe_allow_html=True`로 그리는 자리에 외부 값을 그대로 넣으면 화면이 깨지거나 스크립트가 섞일 수 있다.
