# 체인을 앱에 붙이기

[[34_LangChain_기초]]·[[35_체인_합성]]은 노트북 안의 이야기였다. 여기서는 그 체인을 실제 앱(`backend/app/agent/chain.py`)에 넣는다.

붙일 자리는 세 군데다.

```text
prompt          →  llm            →  parser
ChatPromptTemplate  우리 LLMPort      PydanticOutputParser
                    (Runnable 아님)   (LLMResult 를 모름)
```

가운데 둘이 LangChain 부품이 아니라서, **그대로는 파이프에 안 들어간다.** 오늘 한 일은 이 두 자리에 어댑터를 끼우는 것이다.

## prompt — 중괄호가 변수로 읽힌다

시스템 프롬프트는 `app/agent/prompts/answer_system.md` 파일에 있다([[26_프롬프트_설계와_컨텍스트]]). 파일 내용을 문자열로 넣으면 문제가 생긴다.

```python
ChatPromptTemplate.from_messages([
    ("system", raw),            # raw 안의 { } 를 변수로 읽는다
    ("human", "{question}"),
])
```

지금 `answer_system.md` 는 **40줄에 중괄호가 0개**라 통과한다. 그런데 출력 예시를 한 줄 넣는 순간 깨진다.

```python
risky = raw + '\n\n예시: {"answer": "...", "sources": [{"doc_id": "DOC-HR-011"}]}'
```

```text
ValueError: Invalid format specifier in f-string template.
            Nested replacement fields are not allowed.
```

**"JSON 으로 답하라"는 프롬프트에 JSON 예시를 넣는 것은 지극히 자연스러운 일이다.** 그 순간 터진다는 게 이 문제의 고약한 점이다. 지금 안 터지는 것은 예시를 아직 안 넣었기 때문이지 안전해서가 아니다.

`{{ }}` 로 이스케이프할 수도 있지만, 파일을 고쳐야 하고 사람이 계속 신경 써야 한다. 더 나은 길이 있다.

```python
from langchain_core.messages import SystemMessage

ChatPromptTemplate.from_messages([
    SystemMessage(content=risky),   # 템플릿이 아니라 "완성된 메시지"
    ("human", "{question}"),
])
```

```text
input_variables = ['question']
```

튜플 `("system", ...)` 은 **템플릿**이라 포맷팅을 거치고, `SystemMessage` 는 **이미 만들어진 메시지**라 그대로 실린다. 변수 목록에 `question` 하나만 남는 것이 그 증거다.

시스템 메시지에는 어차피 채울 변수가 없다. **포맷팅이 필요 없는 자리를 템플릿으로 두었기 때문에 생긴 문제였다.**

## llm — 우리 포트를 Runnable 로 바꾼다

우리 `LLMPort`([[23_포트와_어댑터]])는 `invoke` 가 없어서 파이프에 못 들어간다. [[35_체인_합성]]에서 본 그대로, `RunnableLambda` 로 감싸면 된다.

```python
def call_port(value) -> LLMResult:
    messages = value.to_messages()                       # PromptValue → 메시지 목록
    question = "\n\n".join(str(m.content) for m in messages)
    return llm.answer(question=question, contexts=port_contexts, user=port_user)

llm_step = RunnableLambda(call_port).with_config(run_name="LLMPort")
```

```text
result.text  : 부산 출장 일비는 1일 4만원입니다.
result.model : mock
```

`with_config(run_name="LLMPort")` 를 붙이는 이유는 관측이다. 안 붙이면 LangFuse·트레이스에 `RunnableLambda` 라고만 찍힌다([[31_관측과_실행_기록]]). 람다가 여러 개면 어느 것이 터졌는지 구분되지 않는다.

**이 함수가 경계선이다.** 위로는 LangChain 의 `PromptValue`, 아래로는 우리 포트의 `question: str`. 한쪽 세상을 다른 쪽 말로 옮기는 자리라서, 여기만 고치면 프롬프트 구조가 바뀌어도 어댑터는 그대로다.

## parser — LLMResult 는 파서가 모른다

`StrOutputParser` 를 바로 붙이면 안 된다.

```python
(prompt | llm_step | StrOutputParser()).invoke({"question": "부산 출장 일비는?"})
```

```text
ValidationError: 1 validation error for Generation
```

파서는 LangChain 의 `AIMessage` 나 문자열을 기대하는데 우리는 `LLMResult` 를 준다. 중간에 한 칸을 더 둔다.

```python
text_chain = prompt | llm_step | RunnableLambda(lambda r: r.text)
```

```text
부산 출장 일비는 1일 4만원입니다.
```

### PydanticOutputParser — 검증까지 체인 안에서

문자열 대신 검증된 객체를 받고 싶으면 `PydanticOutputParser` 를 쓴다. [[27_구조화_출력]]에서 손으로 하던 `_extract_json` + `model_validate` 를 파서 하나가 대신한다.

```python
parser = PydanticOutputParser(pydantic_object=AnswerOut)
parsed_chain = prompt | llm_step | RunnableLambda(lambda r: r.text) | parser
```

```text
결과 타입        : AnswerOut
answer          : 부산 출장 일비는 1일 2만원입니다.
enough_evidence : True
```

형식을 안 지킨 답이 오면 이렇게 걸린다.

```text
OutputParserException: Invalid json output: 죄송합니다. 잘 모르겠습니다.
```

**이 예외가 [[28_가드와_재시도_폴백]]의 재시도 조건 자리에 들어간다.** 지금은 `ValidationError` 를 잡고 있는데, 체인으로 옮기면 잡을 예외가 바뀐다.

### 형식 지시문을 어디에 둘 것인가

파서는 "이런 JSON 을 달라"는 설명문을 만들어 준다.

```python
parser.get_format_instructions()
# The output should be formatted as a JSON instance that conforms to the JSON schema below. ...
```

| 방법 | 문제 |
| --- | --- |
| 파서만 붙인다 | **모델은 JSON 을 달라는 말을 들은 적이 없다.** 운에 기댄다 |
| 형식 지시문을 프롬프트에 넣는다 | 모델이 무엇을 내야 하는지 안다 |

`answer_system.md` 에 이미 출력 형식을 적어 뒀지만, 파서가 만든 지시문을 덧붙이면 **스키마가 바뀔 때 프롬프트가 따라 바뀐다.** 손으로 적은 설명은 안 따라온다.

```python
system_prompt = f"{base}\n\n{parser.get_format_instructions()}"
```

`ChatPromptTemplate(...).partial(format_instructions=...)` 으로 변수 한 칸을 미리 채워두는 방법도 있다. 다만 그러면 그 칸이 다시 중괄호가 되므로, 위의 `SystemMessage` 방식과 섞어 쓸 때 조심해야 한다.

## 실제 코드 — `backend/app/agent/chain.py`

함수 네 개로 정리했다. 작은 것에서 큰 것 순으로 쌓인다.

| 함수 | 돌려주는 것 |
| --- | --- |
| `load_prompt(name)` | `prompts/<name>.md` 내용 |
| `build_prompt(*, system_prompt=None)` | `ChatPromptTemplate` (system + human 두 칸) |
| `build_result_chain(llm, ...)` | 질문 → `LLMResult` |
| `build_answer_chain(llm, ...)` | 질문 → 답변 문자열 |
| `build_parsed_chain(llm, *, schema, ...)` | 질문 → 검증된 스키마 객체 |

```python
def build_answer_chain(llm: LLMPort, **kwargs) -> Runnable:
    return build_result_chain(llm, **kwargs) | RunnableLambda(lambda r: r.text)

def build_parsed_chain(llm: LLMPort, *, schema: type, **kwargs) -> Runnable:
    parser = PydanticOutputParser(pydantic_object=schema)
    base = kwargs.pop("system_prompt", None) or load_prompt("answer_system")
    system_prompt = f"{base}\n\n{parser.get_format_instructions()}"
    return build_answer_chain(llm, system_prompt=system_prompt, **kwargs) | parser
```

파일 맨 위 주석에 **여기서 하지 않는 일**을 적어 뒀다.

```text
mock / live 분기 처리 X
재시도, 폴백 처리 X
```

분기는 `factory.py` 한 곳에만 있고([[23_포트와_어댑터]]), 재시도·폴백은 `chat_service` 에 있다([[28_가드와_재시도_폴백]]). `chain.py` 는 **어댑터를 받아서 체인을 만들어 주기만 한다.** `llm` 을 인자로 받는 것이 그 표시다 — 스스로 `get_llm()` 을 부르지 않는다.

`build_result_chain` 이 재시도를 넣지 않고 `Runnable` 을 그대로 돌려주는 것도 같은 판단이다. 받은 쪽에서 `.with_retry()` 를 붙일 수 있다.

## 짚어둘 것

### 인자 이름 하나가 파서 실패로 보인다

노트북에서 "형식을 안 지켰을 때" 를 확인하려고 만든 가짜 모델이 이렇게 돼 있었다.

```python
class MockLLMPlain:
    def answer(self, *, question, context, user):   # contexts 가 아니라 context
```

```text
형식을 안 지켰을 때 : TypeError
```

`TypeError` 는 파서가 낸 게 아니다. **인자 이름이 달라서 호출 자체가 안 된 것**이다([[23_포트와_어댑터]]의 `runtime_checkable` 함정 그대로다). 이름을 맞추면 진짜 예외가 보인다.

```text
OutputParserException: Invalid json output: 죄송합니다. 잘 모르겠습니다.
```

확인하려던 것과 다른 이유로 실패했는데 **둘 다 "실패"라서 구분이 안 됐다.** 예외 타입을 찍어 본 것이 살린 셈이다.

### `encoding="utf=8"`

`load_prompt` 에 하이픈 대신 등호가 들어가 있었다.

```python
path.read_text(encoding="utf=8")
```

**그런데 돌아간다.** 파이썬이 코덱 이름을 찾을 때 영숫자가 아닌 글자를 `_` 로 바꿔 정규화하기 때문이다.

```text
codecs.lookup("utf=8").name == "utf-8"   # True
```

에러로 드러나지 않는 종류라 `occured_at`([[32_사용량과_원가_기록]])과 같은 자리다. 고쳐 뒀다.
