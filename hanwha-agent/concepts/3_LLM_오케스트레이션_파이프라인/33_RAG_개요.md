# RAG 개요

**R**etrieval — 검색해서 가져오고, **A**ugmented — 가져온 것을 프롬프트에 붙여서, **G**eneration — 모델이 그것을 근거로 답하게 하는 방식이다.

## 왜 필요한가

모델은 사내 규정을 학습한 적이 없다. 그런데도 물어보면 답한다.

```text
사용자 ──"부산 출장 숙박비 얼마야?"──▶ LLM ──▶ 답변(?)
```

[[25_Claude_API_호출]]에서 근거 없이 물었을 때 "사내 규정 정보를 가지고 있지 않다"고 답한 것은 프롬프트로 그렇게 시켜뒀기 때문이다. 시키지 않으면 그럴듯한 숫자를 만들어 낸다. 이게 할루시네이션이고, **모델을 바꾸거나 프롬프트를 다듬는 것으로는 없앨 수 없다.** 모델에게 없는 정보이기 때문이다.

RAG는 문제를 다르게 푼다. 모델에게 규정을 **외우게** 하는 대신, 물어볼 때마다 **찾아서 보여준다.**

```text
사용자 ──"부산 출장 숙박비 얼마야?"──▶ 검색 ──▶ 출장비규정.pdf
                                                "광역시 출장 시 숙박비는
                                                 1박 최대 100,000원"
                                                      │
                                    질문 + 검색한 문서 ▼
                                                   Prompt ──▶ Claude
                                                                │
                              "부산 출장 숙박비 한도는 1박 100,000원입니다. ◀┘
                               출처: 출장비규정 제8조"
```

모델을 다시 학습시키지 않아도 문서만 바꾸면 답이 바뀐다는 점이 중요하다. 규정이 개정되면 파일을 갈아 끼우면 된다.

## 전체 구조 — 준비와 질의는 다른 시간에 일어난다

```text
                  [ 원본 데이터 ]
           PDF / DOCX / HWP / HTML / DB / API
                        │
                 ① Document Loading      문서를 읽어 들인다
                        │
                 ② Parsing / Cleaning    머리글·바닥글 같은 군더더기를 걷어낸다
                        │
                    ③ Chunking           검색 단위로 자른다
                        │
                   ④ Embedding           텍스트를 벡터로 바꾼다
                        │
                ⑤ Vector Database        PostgreSQL + pgvector
                        │
════════════════════════╪══════════════════════════════════
       여기까지가 문서를 미리 준비하는 과정 (질문과 무관하게 먼저)
════════════════════════╪══════════════════════════════════
                        │
사용자 질문              │
       │                │
  ⑥ Query Processing    │   질문도 같은 방식으로 벡터로 바꾼다
       │                │
       └───────────────▶│
                   ⑦ Retrieval           가까운 벡터를 찾는다
                        │
               ⑧ Filter / Reranking      권한·최신성으로 거르고 순서를 다시 매긴다
                        │
                  ⑨ Prompt 구성          질문 + 검색 문서
                        │
                     ⑩ LLM
                        │
                 ⑪ Answer + Citation     답 + 출처
```

**①~⑤와 ⑥~⑪은 다른 시간에 돈다.** 앞쪽은 문서를 올릴 때 한 번, 뒤쪽은 질문할 때마다다. 이 경계를 놓치면 "질문할 때마다 PDF를 파싱하는" 느리고 비싼 구조가 된다.

| 단계 | 여기서 잘못되면 |
| --- | --- |
| ② Parsing | 표가 뭉개지거나 머리글이 섞여 들어와, 검색은 맞는데 답이 이상해진다 |
| ③ Chunking | 너무 크면 관계없는 내용까지 프롬프트에 실려 비싸지고, 너무 작으면 문맥이 끊긴다 |
| ⑦ Retrieval | 엉뚱한 문서를 가져오면 그 뒤가 아무리 좋아도 답이 틀린다 |
| ⑧ Filter | **권한이 없는 문서가 통과하면 보안 사고가 된다** |
| ⑪ Citation | 출처가 없으면 사용자가 답을 확인할 방법이 없다 |

⑧과 ⑪은 지금까지 만든 것과 이어진다. [[27_구조화_출력]]에서 `doc_id`를 `Literal`로 묶어 등록된 문서만 인용하게 한 것이 ⑧의 화이트리스트에 해당하고, `sources`에 `version`과 `locator`를 담게 한 것이 ⑪이다.

## LangChain과 LangGraph는 어디에 쓰이나

[[30_LLM_프레임워크_개요]]에서 정리한 차이가 RAG에서 이렇게 갈린다.

**LangChain** — 한 줄로 흐르는 경우

```text
Question → Search → Prompt → LLM → Answer
```

**LangGraph** — 갈라지고 되돌아오는 경우

```text
                  Question
                     │
                 질문 분석
           ┌─────────┴─────────┐
       문서 질문             일반 질문
           │                   │
          RAG                Claude
           │
      검색 결과 충분?
       ┌───┴────┐
      YES      NO
       │        │
      답변     재검색 ──▶ Reranking ──┐
                                      │
                          다시 판단 ◀─┘
```

"검색 결과가 충분한가"를 판단해서 부족하면 다시 검색하는 **되돌아오는 화살표**가 생기는 순간 LangChain만으로는 관리가 어려워진다. [[28_가드와_재시도_폴백]]의 재시도 루프가 바로 이 모양의 작은 조각이다.

## 우리가 만들 시스템

```text
                         사용자
                           ▼
                  ┌─────────────────┐
                  │  Streamlit UI   │
                  └────────┬────────┘
                  ┌────────▼────────┐
                  │ FastAPI Backend │
                  └────────┬────────┘
                  ┌────────▼────────┐
                  │   LangChain     │
                  │  Orchestration  │
                  └────────┬────────┘
                  ┌────────┴────────┐
             Retriever            Claude
                  │                 ▲
              pgvector              │
                  ▲                 │
              Embedding             │
                  ▲                 │
            Chunked Docs            │
                  ▲                 │
         PDF / DOCX / HWP           │
                  └─────────────────┘

        복잡한 Agent Workflow  →  LangGraph
        전체 실행 관측 / 평가   →  Langfuse
```
