# 검색 정책

[[62_현행_판과_보안등급]]에서 결과에 실려만 있고 아무도 읽지 않던 두 칸이 있었다.
`version_status` 와 `security_level` 이다. 그 둘을 실제로 쓰는 자리를 만든다.

작업 단계 목록에서 내내 `todo` 였던 마지막 칸이다.

## 거르는 기준을 한 파일에 모은다

`backend/app/rag/policy.py` 를 새로 만들었다. `store.vector_search()` 안에 조건을
더하지 않고 밖에 둔 이유가 있다.

| | |
| --- | --- |
| 검색 안에 넣으면 | 거른 것이 그냥 사라진다. 왜 빠졌는지 알 수 없다 |
| 밖에 두면 | 통과한 것과 **사유**를 함께 돌려줄 수 있다 |

```python
def filter_candidates(rows, *, user, question, policy=DEFAULT) -> tuple[list[dict], list[str]]:
```

돌려주는 값이 둘이다. 두 번째가 "무엇을 왜 뺐는지" 다. 답이 부실할 때 모델이 못한 것인지 애초에 근거가 안 넘어간 것인지 가릴 수 있어야 한다.

## 정책을 값으로 들고 다닌다

```python
@dataclass
class SearchPolicy:
    current_only: bool = True           # 현행 버전만 검색 대상에 넣는다
    allow_past_on_request: bool = True  # 사용자가 명시하면 이전 버전도 본다
    respect_clearance: bool = True      # 보안 등급으로 문서를 거른다
    threshold: float = 0.55             # 이 점수에 못 미치면 '근거 부족'
```

`if` 문으로 박아 두지 않고 객체로 뺐다. 그래서 정책을 바꿔 가며 같은 질문을 돌려
볼 수 있다.

```text
만료 버전 · 평범한 질문                 False
만료 버전 · '예전' 이 든 질문            True
일반 등급 사용자 → 대외비 문서             False
대외비 사용자 → 대외비 문서               True
current_only=False 로 끄면        True
```

마지막 줄이 그 값이다. 정책 하나만 바꿔 끼우면 같은 함수가 다르게 판정한다.
운영에서는 기본값을 쓰고, 조사할 일이 있으면 꺼서 전체를 본다.

## 과거 판은 질문이 부르면 열린다

```python
def wants_past_version(question: str) -> bool:
    q = (question or "").replace(" ", "")
    hints = ("예전", "이전버전", "과거버전", "개정전", "구버전", "예전규정")
    return any(hint in q for hint in hints) or "v1." in q
```

[[62_현행_판과_보안등급]]에서 "만료된 판을 지우면 안 된다"고 적은 이유가 여기서 쓰인다.
`작년 기준으로는 숙박비가 얼마였습니까` 같은 질문에는 열어야 한다. 지웠으면 열 수 없다.

공백을 지우고 찾는 것은 `이전 버전` 과 `이전버전` 을 따로 적지 않으려는 것이다.

다만 이건 정확한 판정이 아니다. 글자만 본다. `예전에는 몰랐는데 지금 숙박비가`
같은 문장도 과거를 묻는 것으로 읽는다. 놓치는 쪽보다 넓게 잡는 쪽이 낫다고 보고
두었지만 넓게 잡으면 만료본이 섞여 들어온다. 질문의 의도를 가리는 일은
⑩LLM 쪽이 더 잘할 수 있는 종류라, 나중에 옮길 자리로 본다.

## 등급은 모르면 낮게 본다

```python
return CLEARANCE.get(user_clearance, 1) >= CLEARANCE.get(doc_level, 1)
```

`CLEARANCE` 는 등급 이름을 숫자로 바꾼 표다. 사용자 등급이 문서 등급 이상이어야 통과한다.

기본값이 둘 다 `1` 인 것이 중요하다. 등급 이름에 오타가 나면 **더 보이는 쪽이 아니라
덜 보이는 쪽으로 틀린다.** 사용자 등급이 모르는 값이면 가장 낮게 보고, 문서 등급이
모르는 값이면 가장 낮은 문서로 본다. 열람 권한을 다루는 코드는 틀릴 때 닫히는 쪽으로
틀려야 한다.

## 걸러 본 결과

```text
통과 1건
 · 국내출장 여비 규정 v2.0
걸러진 사유 3건
 · 국내출장 여비 규정 v1.1 - 만료 버전
 · 구매·계약 규정 - 보안등급(대외비) 차단
 · 정보보안 지침 v2.2 - 만료 버전
```

네 건 중 하나만 남았다.

**정보보안 지침은 만료이면서 대외비인데 사유에는 「만료 버전」만 적혔다.** 버전을 먼저
보고 걸리면 `continue` 하기 때문에 등급 검사까지 가지 않는다. 사유가 하나만 남는다는
뜻이고, 「이 문서는 등급 때문에도 안 됩니다」는 알 수 없다.

지금은 문제가 안 된다. 사유를 사용자에게 그대로 보여 줄 생각이라면 달라진다.

## 사유에 문서 제목이 남는다

```python
reason.append(f"{row['title']} - 보안등급({row.get('security_level')}) 차단")
```

등급 때문에 가린 문서의 제목이 사유에 적힌다. 「구매·계약 규정은 못 보여 드립니다」는
그 문서가 있다는 사실을 알려 주는 말이다. 제목만으로도 새는 정보가 있다.

사유는 담당자가 보는 로그로 두고, 사용자에게는 건수만 보여 주는 쪽이 맞다고 본다.
지금은 그대로 두고 적어만 둔다.

## 현행은 하나뿐이게 만든다

정책이 `현행` 만 본다면 현행이 하나여야 한다. 지금까지는 올리는 족족 전부 현행이었다.

```python
for past in document.versions:
    if past.status == "현행":
        past.status = "만료"
        past.expires_at = effective_from - timedelta(days=1)
        past.index_status = "보관"
```

새 판을 넣기 **전에** 기존 현행을 내린다.

- `expires_at` 은 새 판 시행일의 **하루 전**이다. 두 판의 유효 기간이 하루도 겹치지 않는다.
  같은 날로 두면 그날 하루는 어느 규정을 따르는지 답이 둘이 된다.
- `index_status` 를 `"보관"` 으로 바꾸는 것이 핵심이다. `is_searchable` 은 상태와
  색인을 **둘 다** 본다([[55_청크_저장]]). 상태만 만료로 바꾸고 색인을 그대로 두면
  검색에는 계속 걸린다.

청크는 지우지 않는다. 과거 질문에 답하려면 벡터가 남아 있어야 한다.

## 임계값 0.55

```python
retrieval_threshold: float = Field(default=0.55, ge=0.0, le=1.0)
retrieval_top_k: int = Field(default=12, ge=1, le=100)
```

[[60_벡터_검색]]에서 "답이 DB에 없을 때 1위가 0.557, 있을 때 0.6795" 라고 적었다.
그 사이에 선을 그은 값이다.

**근거가 약하다는 것을 알고 쓴다.** 관측치 두 개로 그은 선이고 문서가 바뀌면 분포도
바뀐다. 0.557 이 "없을 때" 의 값이었으므로 0.55 는 그 바로 아래다. 지금 재료에서
겨우 가르는 수준이다.

그래도 숫자를 적어 두는 쪽이 낫다고 본다. 선이 없으면 "근거 부족" 이라는 판정 자체가
생기지 않고, 모델은 언제나 무언가를 답한다([[29_골든셋_회귀테스트]]).

### 비슷한 이름이 둘이다

`config.py` 에 `top_k = 3` 이 이미 있었다. 초기 실습에서 만든 값이고 지금은 아무도
쓰지 않는다. 거기에 `retrieval_top_k = 12` 가 더해져 이름이 겹쳤다.

쓰이지 않는 설정이 비슷한 이름으로 옆에 있으면 나중에 둘 중 하나를 고치고 왜 안
바뀌는지 찾게 된다. 지우거나 이름을 가르는 쪽이 맞다.

상위 세 줄이 전부 현행 `v2.0` 이 됐다. 옛 금액이 근거에 섞이지 않는다.

셋째 줄은 임계값이 하는 일이다. 규정에 없는 것을 물었더니 0.48 이 나왔고 근거
부족으로 끊겼다. 선이 없었으면 "반려동물"과 가장 비슷한 조항이 답의 근거로 올라갔을
것이다. 보안등급 차단도 여기서 처음 실제로 걸렸다 — `장비 반출입 절차` 는 3급이고
사용자는 일반이다.

### 과거를 물었는데 상위는 여전히 현행이다

둘째 줄이 그렇다. `예전` 이 들어 있어 만료본이 열렸고 12건이 전부 통과했는데,
**상위 세 줄은 다시 `v2.0` 현행이다.**

열어 주는 것과 앞에 두는 것은 다른 문제다. 정책은 후보에 넣을지만 정하고 순서는
점수가 정하는데 점수는 현행인지 만료인지를 모른다. 과거를 물은 사람에게 현행 조문을
세 줄 보여 주는 셈이다.

제대로 하려면 `예전` 이 감지됐을 때 만료본을 **우선**해야 한다. 지금은 거기까지 가 있지 않다.

최고 점수도 0.69 에서 0.60 으로 떨어졌다. `예전 규정으로는` 이라는 말 자체가 질문
벡터를 조문에서 멀어지게 만든다. 질문에 붙은 메타적인 말이 검색을 흐리는 쪽으로
작용한다는 뜻이고, 그 말을 떼고 검색하는 방법도 생각해 볼 자리다.
