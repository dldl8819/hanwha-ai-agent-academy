# 리랭킹 두 가지

[[72_질의_재작성과_Multi_Query]]의 일곱 단계 중 6번이 리랭킹이었다. [[74_기법을_더했는데_떨어졌다]]에서
그 자리가 비어 있어 정답이 밀려났으니 이제 채운다.

두 방식을 만들었다.

| 방식 | 하는 일 | 모델 |
| --- | --- | --- |
| `simple` | 벡터 점수에 어휘 중복률을 섞고 표 조각에 가산점 | 없다 |
| `cross_encoder` | 질문과 조각을 한 번에 읽어 0~1 점수를 매긴다 | bge-reranker-v2-m3 |

## 간이 리랭커

```python
def score(query: str, text: str) -> float:
    q, d = _tokens(query), _tokens(text)
    if not q or not d:
        return 0.0
    return len(q & d) / len(q)

def _simple(query: str, pool: list[dict], vector_weight: float) -> None:
    for c in pool:
        lexical = score(query, c.get("text", ""))
        bonus = 0.03 if c.get("kind") == "표" else 0.0
        c["rerank_score"] = round(
            vector_weight * c.get("score", 0.0) + (1 - vector_weight) * lexical + bonus, 4
        )
        c["rerank_by"] = "simple"
```

`0.7 × 벡터 + 0.3 × 어휘중복 + 표 가산점` 이다. [[73_키워드_검색과_RRF]]에서 가중합을
쓰지 않겠다고 했는데 여기서는 쓴다. 차이가 있다 — RRF 는 **서로 다른 척도**(코사인과
BM25)를 합치는 자리였고, 여기는 둘 다 0~1 로 정규화된 값이라 더해도 한쪽이 삼키지 않는다.

`score()` 가 BM25 와 다른 점도 짚어 둘 만하다. BM25 는 빈도와 희소성을 보는데 이쪽은
**질의 낱말 중 몇 퍼센트가 본문에 있는지**만 본다. 분모가 질의라 긴 문서가 유리해지는
문제가 없다.

### 표 가산점 0.03 이 하는 일

작아 보이는데 결정적이다. [[74_기법을_더했는데_떨어졌다]]에서 「표 안의 조건 조합」이
5/6 에서 2/6 으로 무너진 것이 이 한 줄로 6/6 이 된다([[76_정책_필터를_되돌리고_다시_재다]]).

G16 을 보면 이유가 보인다.

```text
G16  직급별 일비를 표로 정리해주세요   기대 kind=표

--- + 하이브리드
    코사인 0.6100 rerank 0.0000 [조항] 제3장 제1절 제11조(일비) · 별표1
    코사인 0.5600 rerank 0.0000 [조항] 제1장 제5조(여비의 종류) · 별표1
    코사인 0.5900 rerank 0.0000 [조항] DOC-HR-014_v2.0

--- + 리랭킹
    코사인 0.5700 rerank 0.4307 [표 ] 표2                      ← 정답이 1위로
    코사인 0.6100 rerank 0.4259 [조항] 제3장 제1절 제11조(일비) · 별표1
    코사인 0.6000 rerank 0.4185 [조항] 별표1
```

**코사인으로는 표2 가 0.5700 으로 3위권인데 리랭킹 후 1위다.** 1·2위 차이가 0.0048 이라
가산점 0.03 이 없으면 뒤집히지 않는다.

[[73_키워드_검색과_RRF]]에 적은 토크나이저 문제의 보상이라고 본다. 쉼표가 금액을 부수니
표는 어휘 중복으로 이길 수 없다. 그래서 종류를 보고 점수를 얹는다. 원인을 고치는 것이
아니라 결과를 밀어 올리는 방식이고, 청킹 쪽을 고치면 이 가산점은 필요 없어진다.

## 크로스 인코더

바이 인코더와 크로스 인코더가 나뉘는 자리다.

| | 하는 일 | 속도 |
| --- | --- | --- |
| 바이 인코더 (1차 검색) | 질문과 조각을 **따로** 벡터로 만들어 거리를 잰다 | 빠르다 — 조각 벡터는 미리 만들어 둔다 |
| 크로스 인코더 (2차 리랭킹) | 질문과 조각을 **한 쌍으로 묶어** 모델에 넣고 점수 하나를 뽑는다 | 느리다 — 후보마다 모델을 돌린다 |

1차에서 넓게 긁고 2차에서 좁게 다시 읽는 구조다. 크로스 인코더로 전체를 훑을 수 없는
이유가 속도라서, 후보를 줄인 뒤에만 쓴다.

```python
rerank_candidates: int = Field(default=12, ge=1, le=100)
```

그래서 후보 12건만 다시 읽는다. **13위 밖에 있는 것은 크로스 인코더가 건지지 못한다.**
간이 리랭커는 전체를 보므로 이 제한이 없다.

### 점수를 0~1 로 만든다

```python
def _sigmoid(x: float) -> float:
    if x >= 0:
        return 1.0 / (1.0 + math.exp(-x))
    z = math.exp(x)
    return z / (1.0 + z)
```

모델이 내놓는 값은 범위가 없는 로짓이라 시그모이드를 씌운다. 두 갈래로 나눈 것은
오버플로를 피하려는 것이다 — `x` 가 크게 음수면 `exp(-x)` 가 터진다.

```python
self._model = CrossEncoder(str(folder), max_length=settings.rerank_max_length,
                           activation_fn=torch.nn.Identity())
```

모델 쪽 활성함수를 `Identity` 로 두고 로짓을 그대로 받아 직접 시그모이드를 씌운다.
모델이 알아서 씌우게 두면 라이브러리 버전에 따라 범위가 달라질 수 있다.

### 모델이 없을 때를 먼저 막는다

```python
folder = Path(settings.rerank_model_dir)
if not folder.is_dir():
    raise ExternalServiceError(
        f"리랭커 모델 폴더를 찾을 수 없습니다: {folder}",
        detail="... 모델 없이 사용하려면 RERANKER=simple로 지정하세요."
    )
os.environ["HF_HUB_OFFLINE"] = "1"
```

폴더를 먼저 보고, 없으면 **무엇을 하면 되는지까지** 예외에 담는다.
`HF_HUB_OFFLINE=1` 은 모델 이름을 폴더가 아닌 저장소 이름으로 읽어 인터넷에 나가는 일을
막는다. 오프라인 전제를 코드가 강제하는 셈이다.

## 실제로 재 봤다

```text
모델 열림 (44.7s) · name=cross_encoder

질문 : 해외 출장 시 비즈니스석 탑승 기준이 어떻게 되나요?   (규정에 없다)
  0.0004  제7조(출장 신청) ① 출장을 하려는 임직원은 출장 개시일 3일 전까지…
  0.0000  제14조(숙박비) ② 광역시 지역의 숙박비는 1박당 70,000원을 상한으로…
두 쌍 0.40s · 합격선 0.2
```

**같은 질문에 벡터는 0.5646, BM25 는 1.00, 크로스 인코더는 0.0004 다.**
([[73_키워드_검색과_RRF]]에서 BM25 가 1.00 을 준 그 질문이다.)

차이가 어디서 오는지가 분명하다. 벡터와 BM25 는 질문과 조각을 따로 보고 비슷한지만
재는데, 크로스 인코더는 둘을 같이 읽고 **이 조각이 이 질문에 답하는가**를 본다.
「출장」이 겹친다는 사실이 답이 된다는 뜻은 아니라는 것을 아는 쪽이다.

모델을 여는 데 44.7초가 걸렸고 한 쌍 채점은 0.2초다. 질문마다 12쌍이면 2.4초다.
[[70_검색_평가와_답변_평가]]에 적은 「싼 검사를 먼저, 비싼 검사를 나중에」가 이 비용에서 온다.

## 고쳐 둔 것 셋

돌려 보기 전에 터진 것들이다.

| 자리 | 증상 |
| --- | --- |
| `factory.get_corss_encoder` | 오타. `reranker._cross_encoder` 가 `get_cross_encoder` 를 불러 `AttributeError` |
| `judge_gate` 의 `else` 누락 | 간이 리랭커 경로에서 `best` 가 바인딩되지 않아 `UnboundLocalError` |
| `.env` 의 `RERANKER_MODEL_DIR` | 필드 이름이 `rerank_model_dir` 이라 이 환경변수는 읽히지 않는다 |

세 번째가 조용한 쪽이다. 환경변수 이름이 틀렸는데 기본값이 마침 같은 경로여서
동작에는 차이가 없다. `.env` 를 고쳐도 아무 일이 안 일어나므로 틀린 줄 모른 채
남는다. 설정이 먹었는지는 값을 바꿔 보고 확인해야 안다.
