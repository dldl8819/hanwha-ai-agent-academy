# 파일 형식 분기와 차단

파서가 셋이 됐다([[39_문서_파싱]] · [[43_HWPX_파싱]]). 이제 **어느 파일을 어느 파서로 보낼지**를 정하는 자리가 필요하다.

[[39_문서_파싱]]에서 그린 분기의 1번이 이것이다.

## 확장자로 안 가르면 조용히 빠진다

파서 둘만 있을 때 재료 폴더를 통째로 훑어 봤다.

```python
NAIVE = {".docx": parse_docx, ".pdf": parse_pdf}

for p in sorted(SAMPLES.iterdir()):
    handler = NAIVE.get(p.suffix.lower())
    if handler is None:
        skipped += 1
        continue
```

```text
훑은 파일   : 24건
읽힘        : 20건
조용히 빠짐 : 4건
```

**`.hwpx` 세 건과 나머지 하나가 아무 말 없이 빠졌다.** `continue` 가 정상 흐름이라 로그도 예외도 없다. 문서를 올린 사람은 성공한 줄 안다.

`parse_hwpx` 를 더하면 숫자가 바뀐다.

```text
우리가 읽을 수 있는 형식 : ['.docx', '.pdf', '.hwpx']
```

## 대소문자

```text
규정_v2.0.hwpx -> .hwpx -> .hwpx -> parse_hwpx
규정_v2.0.HWPX -> .HWPX -> .hwpx -> parse_hwpx
규정_구버전.hwp -> .hwp  -> .hwp  -> (없음)
규정_구버전.rtf -> .rtf  -> .rtf  -> (없음)
```

`Path.suffix` 는 **원문 그대로** 준다. 윈도우 탐색기에서는 `.HWPX` 와 `.hwpx` 가 같은 파일이지만 딕셔너리 키로는 다르다. `.lower()` 한 번이 이걸 막는다.

같은 실수가 [[28_가드와_재시도_폴백]]의 `ALLOWED_MODELS` 에도 있을 수 있는 종류다 — **사람이 치는 값을 키로 쓸 때는 정규화를 먼저 한다.**

## 막을 때는 무엇을 하면 되는지 같이 준다

읽을 수 없는 형식이 두 종류다.

| | 뜻 | 사용자가 할 일 |
| --- | --- | --- |
| `.hwp` `.doc` `.ppt` `.xls` `.hwt` `.zip` | **읽을 방법이 없다** | 변환해서 다시 올린다 |
| `.rtf` 등 그 밖 | **아직 안 만들었다** | 없다 (우리가 할 일) |

둘을 같은 "안 됨"으로 묶으면 **둘 다 고쳐지지 않는다.** 그래서 메시지를 나눴다.

```python
_CONVERT_HINT = {
    '.hwp': '한글에서 열고 [다른 이름으로 저장] → HWPX 또는 PDF 로 내보내세요. '
            '구 .hwp 는 한컴 독자 바이너리라 열지 않고는 읽을 방법이 없습니다',
    '.doc': 'Word 에서 열고 .docx 로 저장하세요',
    '.ppt': 'PowerPoint 에서 열고 .pptx 로 저장하세요',
    '.xls': 'Excel 에서 열고 .xlsx 로 저장하세요',
    '.hwt': '한글 서식 파일입니다. 내용이 든 .hwpx 문서를 넣으세요',
    '.zip': '압축을 풀고 안의 문서를 한 건씩 넣으세요',
}
```

```text
[.hwp] 읽을 수 없는 형식입니다: .hwp
      안내 → 한글에서 열고 [다른 이름으로 저장] → HWPX 또는 PDF 로 내보내세요. …
[.rtf] 지원하지 않는 형식입니다: .rtf
      안내 → 핸들러를 추가하면 지원할 수 있습니다
```

`.hwt` 와 `.zip` 이 목록에 있는 것이 눈에 띈다. **둘 다 "문서처럼 생겼는데 문서가 아닌 것"** 이다. 서식 파일에는 내용이 없고, 압축 파일 안에는 여러 건이 들어 있다. 실제로 올라올 법한 것들이라 미리 적어 두었다.

예외는 [[05_예외_계층_설계]]의 `ValidationFailed` 를 쓴다. `AgentError` 하위라 `main.py` 의 처리기가 그대로 422 로 번역한다. **`detail` 에 안내를 싣는 자리가 이미 있었다.**

## 결말이 셋이다

```python
def parse_local(path: str | Path) -> ParsedDoc | None:
    handler = HANDLERS.get(ext)
    if handler is None:
        raise ValidationFailed(...)          # ① 막는다

    try:
        doc = handler(p)
    except Exception as exc:
        log.warning('로컬 파싱 실패 (%s): %s', p.name, exc)
        return None                          # ② 조용히 넘어간다

    if not doc.blocks:
        raise ValidationFailed(...)          # ③ 읽었지만 비었다
    return doc
```

| 결말 | 언제 | 왜 그렇게 |
| --- | --- | --- |
| **예외** | 형식이 안 맞는다 | 사용자가 고칠 수 있다 |
| **`None` + 로그** | 파서가 터졌다 | 사용자가 할 수 있는 게 없다 |
| **예외** | 읽었는데 글자가 0 | 스캔본일 수 있다 — 안내가 있다 |

```text
한글 문서 재료 → 읽음 : 블록 233 · 표 7 · 쪽 1
워드 재료     → 읽음 : 블록 233 · 표 7 · 쪽 1
PDF 재료      → 읽음 : 블록 16 · 표 0 · 쪽 16
대문자 확장자  → 읽음 : 블록 233 · 표 7 · 쪽 1
빈 .hwp       → 막힘 : 읽을 수 없는 형식입니다: .hwp
빈 .doc       → 막힘 : 읽을 수 없는 형식입니다: .doc
빈 .rtf       → 막힘 : 지원하지 않는 형식입니다: .rtf
스캔본        → 막힘 : 문서에서 글자를 찾지 못했습니다: sample_scanned.pdf
깨진 .hwpx    → None (로그를 위에서 보세요)
```

### 왜 파서가 터지면 예외가 아니라 `None` 인가

```text
WARNING  app.rag.local_parsers 로컬 파싱 실패 (broken.hwpx): File is not a zip file
```

`.hwpx` 인데 ZIP 이 아니면 `zipfile` 이 터진다. 이걸 그대로 올리면 사용자는 **`BadZipFile` 이라는 말을 보게 된다.** 고칠 방법도 없다.

[[31_관측과_실행_기록]]의 관측 어댑터와 같은 판단이다 — **우리 쪽 사정은 로그로 남기고, 사용자에게는 넘기지 않는다.** 다만 대가가 있다. `None` 이 돌아오면 부르는 쪽이 그것도 처리해야 하고, 안 하면 또 조용히 빠진다.

### 스캔본이 예외인 이유

```text
sample_scanned.pdf : 블록 0 · 표 0 · 쪽 1
예외가 났는가 : 아니오 (여기까지 왔다는 것이 곧 증거다)
```

`parse_pdf` 는 스캔본에서 예외를 내지 않는다([[39_문서_파싱]]). 빈 `ParsedDoc` 이 그냥 돌아온다. 그래서 **진입점에서 블록 수를 보고 막는다.**

```python
if not doc.blocks:
    raise ValidationFailed(
        f'문서에서 글자를 찾지 못했습니다: {p.name}',
        detail='스캔본(이미지)일 수 있습니다. .env 의 UPSTAGE_PARSE_OCR 를 force 로 두고 …',
    )
```

여기만 다르다 — 앞의 둘은 **들어오기 전에** 막는데 이건 **읽고 나서** 막는다. 읽어 봐야 비었는지 알 수 있기 때문이다.

`detail` 이 아직 없는 설정(`UPSTAGE_PARSE_OCR`)을 가리키고 있다. 상용 파싱 API 를 붙였을 때 쓸 자리를 미리 적어 둔 것이다([[41_기술_스택_지도]]).

## 테스트

```python
def test_parse_local_reads_hwpx_same_as_docx() -> None:
    hwpx_doc = parse_local(HWPX)
    docx_doc = parse_local(DOCX)
    assert len(hwpx_doc.blocks) == 233
    assert hwpx_doc.table_count == 7
    assert (len(hwpx_doc.blocks), hwpx_doc.table_count, hwpx_doc.page_count) == \
           (len(docx_doc.blocks), docx_doc.table_count, docx_doc.page_count)


def test_parse_local_blocks_unreadable_format_with_hint(tmp_path: Path) -> None:
    hwp = tmp_path / '출장규정_구버전.hwp'
    hwp.write_bytes(b'')
    with pytest.raises(ValidationFailed) as caught:
        parse_local(hwp)
    assert 'HWPX' in caught.value.detail
```

```text
6 passed
```

`assert 'HWPX' in caught.value.detail` 이 이 테스트의 값이다. **예외가 났다는 것만 보면 안내가 비어 있어도 통과한다.** 안내 문구가 있는지까지 봐야 "무엇을 하면 되는지 같이 준다"는 결정이 지켜진다.

`hwp.write_bytes(b'')` 로 **빈 파일**을 쓰는 것도 의도적이다. 확장자만 보고 막으므로 내용이 필요 없고, 테스트에 진짜 한글 파일을 넣지 않아도 된다.

## 짚어둘 것

`parse_local` 이 예외와 `None` 을 섞어 돌려준다. 부르는 쪽은 `try/except` 와 `if result is None` 을 **둘 다** 써야 한다.

지금은 노트북에서만 부르고 있어서 티가 안 난다. [[13_서비스_계층]]에 붙일 때 이 모양을 그대로 둘지, `None` 도 예외로 올릴지 정해야 한다. **어느 쪽이든 부르는 자리가 한 군데일 때 정하는 편이 쉽다.**

`HANDLERS` 와 `_CONVERT_HINT` 가 파일 끝에 상수로 있는 것도 짚어 둔다. `.env` 의 `LLM_MODEL` 과 `ALLOWED_MODELS` 를 따로 관리하던 것과 같은 자리다([[28_가드와_재시도_폴백]]) — 새 파서를 더하면 `HANDLERS` 에 넣는 것을 잊지 말아야 한다.
