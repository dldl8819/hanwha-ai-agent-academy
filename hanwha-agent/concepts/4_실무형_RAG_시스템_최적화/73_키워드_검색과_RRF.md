# 키워드 검색과 RRF

[[72_질의_재작성과_Multi_Query]]는 낱말이 다른 문제를 다뤘다. 이쪽은 **글자 자체가
중요한데 벡터가 못 잡는** 문제다.

## 벡터는 숫자와 고유명사에 약하다

글자로 찾은 것과 벡터로 찾은 것을 나란히 놓았다.

```text
[글자] LIKE '%100,000%'     → 1건  ['표2']
[글자] LIKE '%KTX%'         → 3건  ['제3장 제3절 제18조(철도)', '표4', '제3장 제10조(교통비)']

[벡터] "100,000" 상위 3건
       1 표2    score 0.451   글자 있음
       2 표2    score 0.438   글자 없음
       3 표3    score 0.413   글자 없음
```

읽을 것이 두 가지다.

**벡터가 못 찾은 것이 아니다.** 1위가 실제로 `100,000` 이 든 `표2` 다. 문제는
**점수가 0.451 이라 임계값 0.55 를 못 넘는다**는 것이다. 찾았는데 근거 부족으로
끊긴다.

그리고 2·3위는 글자가 없는데 점수가 1위와 거의 같다. 0.451 / 0.438 / 0.413 이다.
숫자 하나를 질문으로 주면 벡터 공간에서 숫자가 든 조각들이 다 비슷하게 가깝다.
어느 숫자인지는 구분하지 못한다.

[[59_거리_연산자와_색인]]에서 임베딩이 뜻을 재는 도구라고 적었는데, `100,000` 에는
뜻이 거의 없다. 뜻이 없는 것을 뜻으로 찾으려니 안 되는 것이다.

## BM25 — 빈도와 희소성으로 점수를 매긴다

```bash
python -m pip install "rank-bm25==0.2.2"
```

BM25 는 낱말이 문서에 몇 번 나오는지(빈도)와 그 낱말이 얼마나 흔한지(희소성)로
점수를 매기는 전통적인 방식이다. 뜻을 모르고 글자만 센다. 그래서 벡터의 약점을 메운다.

```python
def keyword_search(session: Session, query: str, *, limit: int = 12) -> list[dict]:
    rows = list(session.execute(stmt))
    ...
    scores = BM25Okapi([_tokenize(c.text) for c, _, _ in rows]).get_scores(_tokenize(query))
    top = max(scores) if len(scores) else 0.0
    out = [_row(chunk, version, doc, (s / top) if top else 0.0) ...]
```

### 두 군데가 눈에 띈다

전체 청크를 매번 읽는다. `stmt` 에 `limit` 이 없고 `rows` 에 다 담은 뒤 BM25 색인을
그 자리에서 만든다. 205청크라 지금은 돌아가지만 청크가 늘면 질문마다 전체를 읽는다.
벡터 검색은 [[59_거리_연산자와_색인]]의 HNSW 색인이 DB 안에 있는데 BM25 는 색인이
메모리에 매번 새로 생긴다.

최고점으로 나눈다. `s / top` 으로 0~1 로 맞춘다. BM25 점수는 상한이 없어서 그대로
두면 코사인 유사도와 같은 자리에 놓을 수 없다. 이 정규화가 뒤에서 함정이 된다.

```python
def _tokenize(text: str) -> list[str]:
    return [t for t in re.findall(r"[가-힣A-Za-z0-9]+", text or "") if len(t) > 1]
```

한 글자를 버린다. 조사와 토씨가 전부 걸려 점수를 흐리기 때문이다. 본문과 질의를
같은 규칙으로 쪼개는 것이 중요하다 — 다르게 쪼개면 겹칠 낱말이 안 생긴다.

### 그런데 이 토크나이저가 금액을 쪼갠다

돌려 보고 나서야 봤다.

```text
'숙박비는 1박당 70,000원'          → ['숙박비는', '1박당', '70', '000원']
'100,000'                        → ['100', '000']
'1~2급 직원의 숙박비 상한은 얼마인가요?'  → ['2급', '직원의', '숙박비', '상한은', '얼마인가요']
```

쉼표가 금액을 둘로 가른다. `[가-힣A-Za-z0-9]+` 에 쉼표가 없어서 `100,000` 이
`100` 과 `000` 이 된다. `1~2급` 은 물결표에서 갈리고 남은 `1` 은 한 글자라 버려져
`2급` 만 남는다.

질문과 정답 표의 겹침을 세어 봤다.

```text
질문 토큰 : ['2급', '직원의', '숙박비', '상한은', '얼마인가요']
표2 토큰  : ['2급', '40', '000', '100', '000', '80', '000', '30', '000']
겹친 것   : ['2급']
```

**겹치는 것이 `2급` 하나다.** 금액은 한 글자도 보태지 않는다. 오히려 `000` 이 표마다
네 번씩 나와 흔한 낱말이 되고, BM25 는 흔한 낱말에 낮은 점수를 준다.

여기서 앞뒤가 어긋난다. 키워드 검색을 더한 이유가 「고유명사·숫자를 못 잡는다」였는데
([[72_질의_재작성과_Multi_Query]]) 잡으려던 그 숫자를 토크나이저가 먼저 부순다.
`KTX` 처럼 쉼표 없는 영문은 `['KTX']` 로 온전히 남으니 고유명사 쪽은 통하는데
금액 쪽은 통하지 않는다.

이게 [[74_기법을_더했는데_떨어졌다]]에서 표가 조항에 밀린 이유의 절반이다. 표는
칸마다 금액뿐이라 남는 토큰이 `000` 같은 조각이고, 조항은 문장이라 질문과 겹치는
낱말이 많다.

고치려면 쉼표를 지우고 숫자를 붙여서 한 토큰으로 만들거나(`100,000` → `100000`),
쉼표를 낱말 문자에 넣어야 한다. 지금은 그 자리가 비어 있다.

## 둘을 나란히 돌려 봤다

```text
질문 : 1~2급 직원의 숙박비 상한은 얼마인가요?

  [ 벡터 ]                                      [ 키워드 BM25 ]
  1 DOC-HR-014 표2 0.714                        1 DOC-HR-014 제3장 제11조(숙박비) · 별표1 1.000
  2 DOC-HR-014 제3장 제2절 제14조(숙박비) 0.691   2 DOC-HR-014 표2 0.849
  3 DOC-HR-014 표2 0.690                        3 DOC-HR-014 표2 0.846

정답(100,000)이 어디에 있나
  벡터     12건 중 1위
  키워드    12건 중 2위
```

이 질문에서는 둘 다 정답을 찾았다. 벡터가 1위, 키워드가 2위다.

다만 키워드 1위가 `제3장 제11조(숙박비)` 인데 이건 `v1.1` 의 옛 조문이다
([[62_현행_판과_보안등급]]에서 본 그 조항이다). BM25 는 현행인지 만료인지 모르고
글자만 센다. 거르는 일은 정책이 해야 한다.

## 가중합이 아니라 순위로 합친다 — RRF

`0.7 * 벡터 + 0.3 * BM25` 같은 가중합을 쓰면 **값의 범위가 큰 쪽이 결과를 좌우한다.**
그래서 값이 아니라 순위로 합친다.

```text
RRF = 1 / (k + rank)        k 기본값 60
```

```python
def fuse(vector_rows, keyword_rows, *, k: int = 60) -> list[dict]:
    ranks: dict[int, dict] = {}
    for source, rows in (("vector", vector_rows), ("keyword", keyword_rows)):
        for rank, row in enumerate(rows, 1):
            if row["chunk_id"] not in ranks:
                first = row["score"] if source == "vector" else 0.0
                ranks[row["chunk_id"]] = {**row, "score": first, "keyword_score": 0.0, "_rrf": 0.0}
            entry = ranks[row["chunk_id"]]
            entry["_rrf"] += 1.0 / (k + rank)
            if source == "keyword":
                entry["keyword_score"] = row["score"]
```

`k = 60` 이 하는 일을 숫자로 보면 이렇다. 1위는 `1/61 = 0.0164`, 2위는 `1/62 = 0.0161`
이다. 차이가 거의 없다. `k` 를 크게 두면 순위 사이의 격차가 완만해지고, 두 검색에서
모두 중간쯤 나온 것이 한 검색에서만 1위인 것을 이긴다.

양쪽에 다 걸리면 두 번 더해지므로 유리하다. 한쪽에만 있으면 한 번만 더해진다.
**합의된 것을 위로 올리는 방식**이다.

`first` 를 두는 이유가 있다. 벡터에서 처음 본 것은 유사도를 그대로 들고 오고, 키워드에만
있는 것은 벡터 점수가 없으니 0 으로 둔다. 그래야 뒤에서 어느 것이 다시 재야 하는지
구분된다.

## BM25 점수를 임계값에 쓰면 안 되는 이유

규정에 답이 없는 질문으로 키워드 검색을 돌려 봤다.

```text
질문(규정에 없음) : 해외 출장 시 비즈니스석 탑승 기준이 어떻게 되나요?

  [키워드 BM25]
    1.00  DOC-HR-014 제2장 제7조(출장 신청)   겹친 낱말 ['출장']
    0.98  DOC-HR-014 표3                  겹친 낱말 ['출장']
    0.97  DOC-HR-014 제2장 제6조(출장 신청)   겹친 낱말 ['출장']

  키워드 최고 점수 : 1.00
  벡터  최고 점수 : 0.5646   (임계값 0.55)
```

**겹친 낱말이 「출장」 하나인데 점수가 1.00 이다.**

최고점으로 나누는 정규화 때문이다. 상위 1위는 **무엇이든 1.00 이 된다.** 답이 있든
없든, 겹친 낱말이 열 개든 하나든 1위는 1.00 이다.

이 점수를 임계값(0.55)과 비교하면 [[64_골든셋과_채점기]]의 `unanswerable` 6문항이
전부 「지어낼 위험」으로 판정된다. 근거 부족을 감지하는 기능이 통째로 죽는다.

그래서 후보를 합친 뒤 점수를 다시 잰다.

```python
sims = store.vector_scores(session, question_vec, [c["chunk_id"] for c in candidates])
for c in candidates:
    c["score"] = sims.get(c["chunk_id"], 0.0)
```

```python
def vector_scores(session, query_vec, chunk_ids) -> dict[int, float]:
    distance = Chunk.embedding.cosine_distance(query_vec)
    stmt = (select(Chunk.id, distance)
            .where(Chunk.id.in_(chunk_ids))
            .where(Chunk.embedding.is_not(None)))
    return {cid: round(1.0 - float(dist), 4) for cid, dist in session.execute(stmt)}
```

[[60_벡터_검색]]의 `vector_search` 와 방향이 반대다. 그쪽은 가까운 것을 찾아오고
이쪽은 정해진 것들의 거리를 재기만 한다. `WHERE id IN (...)` 이라 색인을 타지 않고
후보 열몇 건만 계산한다.

## 순서는 RRF, 점수는 코사인

이 구조가 오늘 가장 중요한 설계라고 본다.

| | 정하는 것 |
| --- | --- |
| RRF | 후보의 **순서** — 어느 3건을 남길지 |
| 코사인 유사도 | 그 후보들의 **점수** — 임계값을 넘는지 |

둘을 섞지 않는다. 섞으면 위의 1.00 함정에 걸린다.

대신 부작용이 하나 생긴다. **표시되는 순서가 점수 순이 아니게 된다.**
[[74_기법을_더했는데_떨어졌다]]에서 상위 3건이 `0.4500 / 0.5000 / 0.5000` 으로 나오는
자리가 그것이다. 사용자에게 근거를 보여 주는 화면에서는 첫 줄이 가장 높은 점수가
아닐 수 있다.
