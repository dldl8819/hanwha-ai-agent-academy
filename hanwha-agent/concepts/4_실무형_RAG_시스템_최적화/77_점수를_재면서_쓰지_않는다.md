# 점수를 재면서 쓰지 않는다

[[76_정책_필터를_되돌리고_다시_재다]]의 93.3% 를 뜯어 보니 두 가지가 나왔다.
측정값이 맞게 나오면서 안을 들여다보지 않게 만드는 자리들이다.

## 합격선이 출력문에만 있다

측정 머리에 임계값이 둘 찍힌다.

```text
문항 30개. 임계값 벡터 0.6. 크로스 인코더 0.2. 상위 3건
```

그런데 `rerank_threshold` 를 읽는 곳을 세어 보면 셋이다.

```text
backend/app/core/config.py:62    rerank_threshold: float = Field(default=0.2, ...)
evals/run_eval.py:130            f"크로스 인코더 {settings.rerank_threshold}. 상위 ..."
evals/run_eval.py:142            "rerank_threshold": settings.rerank_threshold,
```

**정의한 자리, 출력하는 자리, 리포트에 적는 자리다. 판정하는 자리가 없다.**

판정은 `judge_gate` 가 하는데 두 갈래가 같은 값을 돌려준다.

```python
def judge_gate(rows: list[dict]) -> tuple[float, float, bool]:
    settings = get_settings()
    if any(r.get("rerank_by") == "cross_encoder" for r in rows):
        best = max((float(r.get("score", 0.0)) for r in rows), default=0.0)
        threshold = settings.retrieval_threshold
    else:
        best = max((float(r.get("score", 0.0)) for r in rows), default=0.0)
        threshold = settings.retrieval_threshold
    return best, threshold, best >= threshold
```

`if` 와 `else` 의 몸이 글자까지 같다. 크로스 인코더인지 보고 갈라 놓고 같은 일을 한다.
`rerank_score` 는 어디에도 안 쓰인다 — 코사인 유사도로만 판정한다.

분기를 만들어 둔 것이 뜻을 보여 준다고 본다. 쓸 자리를 비워 둔 모양이다. 다만 머리에
「크로스 인코더 0.2」가 찍히니 그 선으로 판정하는 것처럼 읽힌다. 비어 있는 것과
비어 있는 줄 모르게 되어 있는 것은 다르다.

## 비워 둔 쪽이 더 잘 가른다

쓰지 않는 점수가 쓸모없는 점수인지 재 봤다. 크로스 인코더 설정으로 30문항을 돌려
상위 3건의 최고 점수를 두 자로 모았다.

```text
답이 있는 문항 24개 · 답이 없는 문항 6개

[코사인]
  답 있음 : 최소 0.6100 · 중앙 0.6850 · 최대 0.7300
  답 없음 : 최소 0.5100 · 중앙 0.5400 · 최대 0.6000
  간격    : 0.0100

[크로스 인코더]
  답 있음 : 최소 0.2400 · 중앙 0.8766 · 최대 0.9949
  답 없음 : 최소 0.0006 · 중앙 0.1788 · 최대 0.1788
  간격    : 0.0612
```

둘 다 깨끗이 갈린다. 겹치는 문항이 없다.

다른 것은 여유다. 코사인은 답 없음의 최대가 0.6000, 답 있음의 최소가 0.6100 이다.
임계값 0.60 이 그 **0.01 틈 사이에** 놓여 있다. 0.61 로 올리면 답이 있는 문항이 막히고
0.59 로 내리면 없는 문항이 통과한다.

크로스 인코더는 0.1788 과 0.2400 사이이고 합격선 0.2 가 그 가운데다. 여유가 여섯 배다.

분포 모양도 다르다. 코사인은 양쪽이 0.51~0.73 의 좁은 띠에 몰려 있는데
([[74_기법을_더했는데_떨어졌다]]에서 쓸 수 있는 폭이 0.2 라고 적은 그 띠다),
크로스 인코더는 답 없음이 0.0006~0.1788 로 바닥에 깔리고 답 있음은 중앙 0.8766 으로
천장에 붙는다.

**더 잘 가르는 점수를 계산해 놓고 덜 가르는 점수로 판정한다.** 모델을 44초 열고
질문마다 2.4초를 들여 매긴 점수가 리포트 JSON 에만 남는다.

## 93.3% 안에 목차로 통과한 한 건이 있다

G04 가 리랭킹에서는 맞고 크로스 인코더에서는 틀린다. 어느 쪽이 나은 판단인지 보려고
열었다.

```text
G04  출장 여비 규정은 어디에 적용되나요?
     기대 DOC-HR-014 v2.0 · 키워드 ['국내', '적용']

--- + 리랭킹 → 정답
    제1장 제1조(목적)              키워드 ['국내']
    DOC-HR-014_v2.0              키워드 ['국내', '적용']   ← 이 조각으로 통과
    제1장 제2조(정의) · 별표2         키워드 []

--- + 크로스 인코더 → 오답
    제1장 제1조(목적)              키워드 ['국내']
    DOC-HR-002 v3.1 제4장 제22조(출장)   키워드 ['국내']
    제1장 제2조(정의) · 별표2         키워드 []
```

통과시킨 조각이 `DOC-HR-014_v2.0` 이다. 문서 표지와 목차 조각이다.
조문 제목을 전부 나열하니 거기에 「제3조(적용 범위)」가 들어 있어 `적용` 이 걸리고,
문서 제목에 「국내출장」이 있어 `국내` 가 걸린다. 두 키워드를 다 품는다.

진짜 답인 「제1장 제3조(적용 범위)」는 어디 있는지 세어 봤다.

```text
간이 리랭킹 (정책 통과 17건)
   2위  rerank 0.4693  DOC-HR-014_v2.0        ← 목차 조각
   7위  rerank 0.4365  제1장 제3조(적용 범위)      ← 진짜 정답

크로스 인코더 (정책 통과 17건)
   4위  rerank 0.4151  DOC-HR-014_v2.0        ← 목차 조각
```

**정답 조항은 7위이고 채점은 3위까지만 본다.** 목차 조각이 2위로 들어와 정답 판정을
받았다. 크로스 인코더는 그 목차를 4위로 내리고 대신 다른 문서의 「제22조(출장)」을
올렸다 — 적용 범위를 묻는 질문에 복무 규정의 출장 조항은 틀린 답이지만 목차보다
내용이 있다.

크로스 인코더 쪽에 진짜 정답이 안 보이는 이유도 있다. `rerank_candidates = 12` 라
후보 12건만 다시 읽는다([[75_리랭킹_두_가지]]). 13위 밖은 점수조차 받지 못한다.

### 두 번째 목차 사고다

[[74_기법을_더했는데_떨어졌다]]에서 G16 이 목차 조각에 밀려 틀렸다. 오늘은 G04 가
목차 조각 **덕분에** 맞았다. 같은 조각이 한 번은 깎고 한 번은 보탰다.

[[65_측정값_뜯어보기]]의 G25 와 모양이 같다. 거기서는 「근거가 나빠져서 점수가
내려갔고, 점수가 내려가서 정답이 됐다」였고 여기서는 「내용 없는 조각이 키워드를 다
품어서 정답이 됐다」다. 둘 다 **채점기가 맞다고 한 것이 검색이 잘된 것은 아닌** 경우다.

93.3% 에서 한 건을 떼면 90.0% 다. 크로스 인코더의 90.0% 와 같아진다.
숫자로는 간이 리랭커가 이기는데 안을 보면 한 건이 운이다.

## 고친 것과 남긴 것

| | |
| --- | --- |
| 고쳤다 | `factory` 의 `get_corss_encoder` 오타 · `judge_gate` 의 `else` 누락 · `.env` 환경변수 이름 |
| 남겼다 | `judge_gate` 가 `rerank_score` 를 쓰지 않는 것 · 목차 조각이 색인에 있는 것 |

남긴 둘은 수업에서 만든 대로 두고 적어만 뒀다. 고치면 숫자가 바뀌고, 지금 숫자는
수업과 맞춰 둬야 비교할 수 있다([[76_정책_필터를_되돌리고_다시_재다]]에서 임계값을
0.60 으로 올린 것과 같은 이유다).

고치는 순서는 정해 뒀다.

1. **목차·표지 조각을 색인에서 뺀다** — G04 의 운과 G16 의 손해가 같이 사라지고,
   [[75_리랭킹_두_가지]]의 표 가산점 0.03 도 덜 필요해진다.
2. **`judge_gate` 가 `rerank_score` 와 `rerank_threshold` 를 쓰게 한다** — 여유가 0.01 에서
   0.0612 로 늘어난다.
3. `DOC-FI-009` 재색인 — G07 이 풀린다.

셋 다 하고 다시 재면 숫자가 어떻게 움직일지 모르겠다. 93.3% 보다 내려갈 수도 있다.
목차로 통과한 한 건이 없어지기 때문이다. 그래도 내려간 쪽이 사실에 가깝다.
