# 문서 파싱

[[33_RAG_개요]]의 11단계 중 ①②를 만든다. 문서를 읽어 들이고 군더더기를 걷어내는 자리다.

```text
문서 ─▶ 파싱(오늘) ─▶ 청킹 ─▶ 임베딩 ─▶ 적재 ─▶ 검색
```

## 어느 파서로 보낼 것인가

파일이 들어오면 세 갈래로 나뉜다.

```text
파일이 들어온다
      │
      ▼
① 못 읽는 형식인가?        .hwp .doc .ppt .xls  ──▶ "…로 변환해 주세요" 안내하고 막는다
      │ (아니면 통과)
      ▼
② 로컬로만 읽는 형식인가?   .hwpx                ──▶ 로컬 파서
      │
      ▼
③ 그 밖                                          ──▶ 상용 API, 실패하면 로컬 파서로 대체
```

**①에서 막는 것이 친절이다.** 구형 형식을 어떻게든 읽어보려다 깨진 글자를 넣으면, 검색은 되는데 답이 이상해지는 [[33_RAG_개요]] ②번 자리의 사고가 된다. 읽을 수 없다고 먼저 말하는 편이 낫다.

오늘 만든 것은 ②의 로컬 파서다. 실습 재료는 30개였다.

```text
파일 30개
 .docx 10개 , .pdf 11개 , .hwpx 3개 , 그 밖의 파일 6개
```

python -m pip install "pypdf==6.17.0" "python-docx==1.2.0" "pdfplumber==0.11.10"

## PDF — 페이지가 단위다

PDF 안에는 두 가지가 섞여 있다.

| | 꺼낼 수 있나 | 어떤 파일인가 |
| --- | --- | --- |
| 텍스트 레이어 | **된다** | 워드·한글에서 PDF 로 내보낸 문서 |
| 이미지 | **안 된다** | 종이를 스캔해서 만든 PDF |

그리고 **PDF 에는 "몇 번째 줄"이라는 단위가 없다.** 글자마다 좌표가 있을 뿐이다. 그래서 페이지를 단위로 읽는다 — `p.6` 처럼 근거를 대려면 어차피 페이지가 필요하다([[27_구조화_출력]]의 `locator`).

```python
from pypdf import PdfReader

reader = PdfReader(str(PDF))
print("쪽수 : ", len(reader.pages))
```

```text
쪽수 :  16
```

페이지마다 글자 수를 세어 보면 문서의 모양이 드러난다.

```text
p.1  108자     p.5  1070자     p.9   961자     p.13  310자
p.2  231자     p.6   903자     p.10  222자     p.14  244자
p.3  443자     p.7  1005자     p.11  281자     p.15  211자
p.4  272자     p.8  1042자     p.12  282자     p.16  216자
---------------
16 페이지, 합계 약 7,800 자
```

앞뒤는 표지와 별표라 짧고, 본문인 5~9쪽이 1,000자 안팎이다.

### 스캔본은 0자가 나온다

```text
쪽수 :  1
p.1  0자
---------------
1 페이지, 합계 약 0 자
```

**에러가 나지 않는다.** 빈 문자열이 나온다. 그래서 모르고 지나가면 "문서는 넣었는데 검색에 안 걸리는" 상태가 된다.

로그로 남긴다.

```python
if not text:
    log.info("텍스트 없음 (스캔본으로 보임): %s p.%d", path.name, page_no)
    continue
```

```text
14:48:54 INFO  app.rag.local_parsers 텍스트 없음 (스캔본으로 보임): sample_scanned.pdf p.1
블록 0개
```

나중에 OCR 을 붙일 자리이기도 하다. 지금은 **조용히 빠지지 않게** 하는 것까지가 할 일이다.

## DOCX — ZIP 안의 XML

워드 파일은 압축 파일이다.

```text
첫 4바이트 : b'PK\x03\x04'   ← ZIP 표식
엔트리 17개
  [Content_Types].xml
  _rels/.rels
  docProps/core.xml
  docProps/app.xml
  word/document.xml  ← 본문이 여기 있습니다
  word/_rels/document.xml.rels
```

`python-docx` 가 이걸 대신 열어 준다.

```python
doc = Document(str(path))
doc.paragraphs   # 문단 목록
doc.tables       # 표 목록
```

### 문단과 표가 따로 나온다 — 여기가 함정이다

`doc.paragraphs` 는 **본문 바깥 층만** 훑는다. 표 안의 문단은 표에 속해 있어서 여기 안 나온다.

```text
본문
  문단      ← doc.paragraphs
  문단
  표        ← doc.tables
      행
        칸
          문단   ← doc.paragraphs 에 없다
  문단
```

그래서 "문단 먼저, 표는 나중에" 읽으면 이렇게 된다.

```python
bad = [p.text.strip() for p in doc.paragraphs if p.text.strip()]
for table in doc.tables:
    cells = [c.text.strip() for row in table.rows for c in row.cells]
    bad.append(" ".join(c for c in cells if c))
```

```text
총 블록 233개
표가 들어간 자리 : 227 ~ 233 번째  (전부 맨 끝)
```

원문 순서로 읽으면 표의 자리는 이렇다.

```text
본문 자식 233개   종류 : p 226 · tbl 7
tbl 위치 : [10, 218, 221, 224, 227, 229, 232]
```

**첫 표는 원문에서 10번째인데 227번째로 밀린다.** 그 자리를 찍어 보면 무엇을 잃는지 분명해진다.

```text
 9번째 항목 :  제·개정 이력
10번째 항목 :  [표1]
```

**표 바로 앞이 그 표의 제목이다.** 둘을 떼어 놓으면 표만 보고는 무엇의 이력인지 알 수 없다. 217칸을 건너뛰어 맨 뒤 별표들 사이에 끼는 셈이다.

청킹은 앞뒤 블록을 붙여 조각을 만드는데([[33_RAG_개요]] ③), 자리가 틀리면 **관계없는 글이 한 조각에 묶인다.** 검색은 되는데 답이 흐려지는 경로다.

표를 아예 빼먹으면 얼마나 잃는지도 재 봤다.

```text
문단만 읽었을 때 : 6,230자
표까지 읽었을 때 : 7,358자
표 안 글자 1,128자 = 전체의 15.3%
```

규정 문서에서 표에 들어가는 것은 **금액·기한·한도** 같은 숫자다. 사람이 실제로 묻는 것이 거기 있다.

### 본문 XML 을 순서대로 훑는다

`python-docx` 가 주는 목록 대신 XML 자식을 직접 돈다.

```python
body = doc.element.body
for child in body.iterchildren():
    tag = child.tag.split("}")[-1]      # "{긴 주소}p" → "p"
    if tag == "p":
        text = Paragraph(child, doc).text.strip()
    elif tag == "tbl":
        table = Table(child, doc)
```

`child.tag` 가 `{http://…}p` 형태라 `}` 뒤만 떼어 쓴다. 라이브러리가 감춰 둔 한 겹을 걷고 원문 순서를 되찾는 것이다.

## 결과를 담을 모양

형식마다 결과 타입이 다르면 쓰는 쪽이 매번 분기해야 한다.

```python
blocks = parse_pdf(path)   # list[str]
data   = parse_docx(path)  # dict
```

그래서 공통 모양을 정한다. [[23_포트와_어댑터]]의 `LLMResult` 와 같은 자리다.

### `backend/app/integrations/ports.py`

```python
@dataclass
class ParsedBlock:
    kind: str        # 덩어리 종류 : 조항, 표
    locator: str     # 원본 어디서 나왔나 : p.6, 표2
    text: str        # 덩어리 글자들

@dataclass
class ParsedDoc:
    blocks: list[ParsedBlock] = field(default_factory=list)
    page_count: int = 0      # 페이지 개념이 없는 docx 는 1 로 둔다
    table_count: int = 0

@runtime_checkable
class ParserPort(Protocol):
    def parse(self, path: str) -> ParsedDoc: ...
```

`ParserPort` 를 둔 이유는 **상용 파싱 API 로 갈아끼울 자리**를 미리 잡아 두기 위해서다(위 분기의 ③). 로컬 파서든 API 든 이 모양만 맞추면 쓰는 쪽 코드는 그대로다.

`locator` 가 형식마다 다른 값을 담는 것이 이 설계의 요점이다.

| | `page_count` | `locator` 예시 |
| --- | --- | --- |
| PDF | 실제 쪽수 | `p.6` |
| DOCX | **1** | 문서 이름, `표2` |

DOCX 에 페이지 수가 없는 것은 **페이지가 인쇄할 때 정해지기 때문**이다. 같은 파일도 용지와 글꼴에 따라 쪽수가 달라진다.

## 파서

### `backend/app/rag/local_parsers.py`

```python
def parse_pdf(path: Path) -> ParsedDoc:
    from pypdf import PdfReader

    reader = PdfReader(str(path))
    blocks: list[ParsedBlock] = []

    for page_no, page in enumerate(reader.pages, 1):
        text = (page.extract_text() or "").strip()
        if not text:
            log.info("텍스트 없음 (스캔본으로 보임): %s p.%d", path.name, page_no)
            continue
        blocks.append(ParsedBlock("조항", f"p.{page_no}", text))

    return ParsedDoc(blocks=blocks, page_count=len(reader.pages), table_count=0)
```

```text
블록 16 · page_count 16 · table_count 0
여섯 번째 블록 : kind=조항  locator=p.6
```

`import` 를 함수 안에 둔 것은 [[23_포트와_어댑터]]의 `factory` 와 같은 판단이다. PDF 를 안 쓰는 경로에서는 `pypdf` 가 아예 로드되지 않는다.

`parse_docx` 는 XML 자식을 순서대로 돌며 문단은 `"조항"`, 표는 `"표"` 로 담는다. 표 본문을 어떻게 채우는지는 [[40_표_추출과_마크다운]]에서 이어진다.

## 짚어둘 것 — 이름을 돌려쓰다 생긴 일

노트북 `00.문서파싱.ipynb` 의 뒷부분이 한동안 전부 실패한 채였다. 원인은 이 한 줄이었다.

```python
from docx import Document
# doc = Document(str(파일경로))    ← 주석 처리돼 있다
doc.paragraphs
```

```text
AttributeError: 'ParsedDoc' object has no attribute 'paragraphs'
```

`doc` 은 앞 셀에서 `parse_pdf(SCAN)` 의 결과가 들어 있던 이름이었다. **새로 만들지 않아 옛 값이 그대로 잡혔고, 타입이 달라 엉뚱한 자리에서 터졌다.**

`NameError` 였다면 바로 알았을 텐데 `AttributeError` 라 "python-docx 쓰는 법이 틀렸나" 쪽을 먼저 보게 된다. 노트북은 셀마다 이름이 살아 있어서, **같은 이름을 다른 타입으로 돌려쓰면 실패가 엉뚱한 곳에서 드러난다.**

`texts` 도 정의된 적이 없었다. 표를 덧붙이기 **전**의 문단 목록이어야 해서, 따로 남겨 두도록 고쳤다.

```python
texts = [p.text.strip() for p in doc.paragraphs if p.text.strip()]
bad = list(texts)
```

두 줄을 고치고 맨 위부터 다시 돌리니 19개 셀이 에러 없이 끝났다. 이 노트의 숫자는 전부 그 결과다.
