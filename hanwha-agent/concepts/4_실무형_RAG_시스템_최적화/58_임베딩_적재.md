# 임베딩 적재

[[55_청크_저장]]에서 조각을 테이블에 남겼다. 글자만 남겼다. 그래서 질문을 글자로만
찾을 수 있었고, 그게 왜 모자란지가 오늘의 출발점이다.

RAG 11단계 중 ④임베딩과 ⑤적재다. [[56_배경_작업과_작업_번호]]에서 `todo` 로 비워 둔
다섯 번째 단계가 이것이다.

## 글자로 찾으면 질문이 안 걸린다

같은 문서에 `LIKE` 로 네 번 물었다.

```text
'숙박'                         → 5줄
'숙박비'                        → 5줄
'출장 갈 때 숙박비 얼마?'             → 0줄
'출장 숙박비'                     → 0줄

넷 중 2개가 0 줄입니다.
```

단어를 정확히 치면 찾고, 문장으로 물으면 못 찾는다. `출장 숙박비` 조차 0 줄인데
띄어쓰기 하나로 연속된 글자가 아니게 되기 때문이다. 사용자는 단어가 아니라 문장으로
묻는다. `LIKE` 로는 그 간극을 메울 수 없다.

> 이 출력은 수업에서 나온 값이다. 내 DB 는 `chunks` 가 비어 있어 네 개 다 0 줄이 나왔다.
> 0 줄의 이유가 다르면 보여 주는 것도 다르다.

## PostgreSQL 에는 `vector` 타입이 없다

두 가지를 따로 깔아야 한다. 이름이 비슷해서 하나로 착각하기 쉽다.

| | 무엇 | 어디에 |
| --- | --- | --- |
| 확장 `vector` | DB 가 `vector` 자료형을 알게 한다 | PostgreSQL 안 |
| 패키지 `pgvector` | SQLAlchemy 가 그 타입을 파이썬에서 다루게 한다 | 가상환경 안 |

```bash
docker compose exec postgres psql -U agent -d agent -c "CREATE EXTENSION IF NOT EXISTS vector;"
python -m pip install "pgvector==0.5.0"
```

```text
vector 확장 : 이미 켜져 있습니다 — 0.8.6
```

확장은 DB 에 붙는 것이라 컨테이너를 지우고 다시 만들면 다시 켜야 한다. 그리고 이것도
마이그레이션에 없다. `alembic upgrade head` 만으로는 안 생긴다.

## 차원을 한 곳에서 정한다

```python
# models/base.py
EMBED_DIM = 1024
```

```text
models/base.py 의 EMBED_DIM : 1024
settings.embed_dim          : 1024
settings.embed_provider     : local
settings.embed_model_dir    : models/bge-m3
```

칼럼과 설정이 같은 숫자를 봐야 한다. 칼럼은 `Vector(1024)` 로 굳어 있는데 설정이 768 이면
적재할 때 터진다. 그래서 `settings.embed_dim` 의 기본값을 `EMBED_DIM` 에서 가져온다.

1,024 를 고른 이유는 [[49_임베딩_모델_고르기]]에 적어 뒀다. 받아 둔 두 모델이 둘 다
1,024차원이고, pgvector 색인이 2,000차원까지만 걸린다.

```python
embedding: Mapped[list[float] | None] = mapped_column(Vector(EMBED_DIM), nullable=True)
```

`nullable=True` 다. 이미 들어가 있는 청크에 칼럼을 더하는 마이그레이션이라 기존 행은
비어 있어야 한다. 아래에서 조회할 때 `embedding IS NOT NULL` 로 거르는 이유가 이것이다.

## 포트와 어댑터

[[23_포트와_어댑터]]에서 LLM 에 쓴 구조를 임베딩에 그대로 쓴다.

```python
@runtime_checkable
class EmbedderPort(Protocol):
    dim: int
    def embed_documents(self, texts: list[str]) -> list[list[float]]: ...
    def embed_query(self, text: str) -> list[float]: ...
```

문서용과 질문용이 나뉘어 있다. 지금 로컬 어댑터는 `embed_query` 가 `embed_documents([text])[0]`
를 부르는 한 줄이라 둘이 같다. 나눠 둔 것은 모델이 둘을 다르게 다루는 경우가 있어서다.
상용 어댑터는 실제로 `passage` 와 `query` 로 구분해 보낸다.

`factory.get_embedder()` 가 설정을 보고 로컬과 상용 중 하나를 고르고, `@lru_cache` 로
한 번 만든 것을 재사용한다. 모델을 여는 데 몇 초가 걸리므로 매번 열면 안 된다.

### 로컬 어댑터는 모델을 열면서 차원을 물어본다

```python
self.dim: int = int(self._model.get_embedding_dimension())
```

설정에 적힌 1,024 를 믿지 않고 모델에게 묻는다. 모델을 바꿨는데 설정을 안 고치면
그 차이가 여기서 드러난다.

```text
로컬 임베딩 모델 준비: ..\models\bge-m3 / 1024차원
```

`os.environ["HF_HUB_OFFLINE"] = "1"` 을 `import` 전에 세운다. 이게 없으면
`sentence-transformers` 가 모델 이름을 허브에서 확인하려 들어, 망이 막힌 자리에서 멈춘다.

## 적재 — `store.save_chunks()`

[[55_청크_저장]]의 `ingest_document` 안에 있던 삭제·삽입을 `store.py` 로 옮기고
벡터를 같이 넣는다.

```python
for i, (d, vec) in enumerate(zip(drafts, vectors, strict=False)):
    session.add(Chunk(version_id=version.id, ord=i, kind=d.kind,
                      locator=d.locator, text=d.text, embedding=vec))
```

`zip(..., strict=False)` 다. 청크 수와 벡터 수가 어긋나면 짧은 쪽에서 조용히 멈춘다.
`strict=True` 면 그 자리에서 터진다. 지금은 바로 위에서 같은 목록으로 만들어 수가
어긋날 수 없지만, 배치로 나눠 임베딩하다 한 배치가 실패하면 달라질 수 있는 자리다.

```text
청크 적재 : DOC-HR-014 v9.9 - 53청크 - 53벡터
조항 단위 46 + 표 단위 7 = 53 청크
status=완료 progress=83 chunk_count=53
  ok    파일 검증
  ok    문서 파싱
  ok    표 -> 마크다운 변환
  ok    청킹                         53청크
  ok    임베딩                        53벡터
  todo  검색 반영 및 현행 버전 지정
```

여섯 중 다섯이 끝나 66% 였던 진행률이 83% 가 됐다([[56_배경_작업과_작업_번호]]).
마지막 하나는 아직 없다. 그게 무엇인지는 [[60_벡터_검색]]에서 드러난다.

### 화면 쪽 제한시간을 10초에서 60초로 올렸다

[[56_배경_작업과_작업_번호]]에서 "파싱은 0.1초지만 10초를 넘기면 업로드는 성공했는데
화면에는 실패로 뜬다"고 적어 뒀다. 임베딩을 붙이자 그게 실제 문제가 됐다.

```python
TIMEOUT = 60.0   # 10.0 이었다
```

53청크를 올려 보니 요청 하나가 **66.5초** 걸렸다. 올려 둔 60초도 넘긴다.
모델을 여는 데 14초, 53청크를 임베딩하는 데 53초였다.

동기로 부르면 이 66초를 요청이 통째로 매달린다. 배경으로 돌렸기 때문에
업로드 응답은 즉시 나가고 이 시간은 작업 쪽에서 흐른다([[56_배경_작업과_작업_번호]]).
숫자가 커질수록 그 결정이 맞았다는 쪽으로 간다.

올린 것은 임시 대응이다. 작업 번호를 받아 폴링하는 구조([[56_배경_작업과_작업_번호]])를
이미 만들어 뒀으니 업로드 요청 자체는 길어질 이유가 없는데, 지금은 업로드와
작업 조회가 같은 `TIMEOUT` 을 쓴다. 둘을 나누면 올리지 않아도 되는 값이다.

## 붙여 넣다 import 두 줄을 빠뜨렸다

```text
터진다 → NameError : name 'get_settings' is not defined
```

`embedder.model_label()` 이 `get_settings()` 와 `Path` 를 쓰는데 파일 맨 위에
그 둘이 없었다. 함수 안에서만 쓰는 이름이라 `import` 해도 모듈이 뜨고,
**부를 때까지 조용하다.**

터지는 자리가 나쁘다. `model_label()` 을 부르는 곳이 `ingest_document` 안이고,
그건 배경 작업에서 돈다([[56_배경_작업과_작업_번호]]). 업로드는 201 로 끝나고
화면은 정상으로 보인다. 작업 상태를 물어봐야 비로소 `NameError` 가 나온다.

문법 오류였다면 서버가 뜨지 않아 바로 알았을 것이다. 이름 오류는 그 줄을 지나갈 때만
난다. 코드를 받아 붙일 때 `import` 를 먼저 맞추는 쪽이 싸다.
