# 청킹 테스트와 형식 차이

[[50_청킹_규칙]]의 규칙 넷을 테스트로 고정하고, 같은 규정을 세 형식으로 넣어 비교했다.

## 규칙을 테스트로 바꾼다

`backend/tests/test_chunker.py` 에 넷을 넣었다.

| 테스트 | 막는 것 |
| --- | --- |
| `test_table_is_never_split` | 표가 한도를 넘어도 쪼개는 것 |
| `test_articles_are_kept_whole` | 조가 블록 단위로 흩어지는 것, 상호참조가 갈리는 것 |
| `test_toc_lines_do_not_become_chunks` | 목차 줄이 독립 청크가 되는 것 |
| `test_same_document_different_format_gives_same_chunks` | 형식에 따라 결과가 달라지는 것 |

### 합성 문서로 잰다

셋은 실제 파일을 열지 않는다. `ParsedDoc` 를 손으로 만들어 넣는다.

```python
doc = ParsedDoc(blocks=[
    ParsedBlock('조항', 'p.3', '제12조(숙박비) 숙박비는 다음 각 호에 따라 지급한다.'),
    ParsedBlock('조항', 'p.3', '① 광역시 지역의 숙박비는 1박당 70,000원을 상한으로 한다.'),
    ParsedBlock('조항', 'p.3', '② 그 밖의 지역은 1박당 60,000원을 상한으로 한다.'),
])
chunks = chunk(doc)
assert len(chunks) == 1
```

조 하나가 블록 셋에 걸친 상황을 세 줄로 만든다. 실제 파일에서 이 상황을 찾으려면
문서를 뒤져야 하고, 문서가 바뀌면 테스트가 깨진다. **파서를 지나지 않고 청킹만 잰다**는
점에서 [[23_포트와_어댑터]]의 가짜 어댑터와 같은 생각이다.

### 실문서에 없는 조건은 만들어서 잰다

"표는 길이를 무시한다"는 규칙이 문제였다. 실문서의 가장 긴 표가 378자라
한도(1,200)에 한참 못 미쳐서, 그냥 돌리면 **규칙이 작동한 건지 길이가 짧아서 안 걸린 건지
구별이 안 된다.**

```python
big_table = '| 직급 | 일비 | 숙박비 |\n|---|---|---|\n' + '\n'.join(
    f'| {i}급 | {i * 1000}원 | {i * 10000}원 |' for i in range(1, 121))
assert len(big_table) > 1200
```

120행을 만들어 한도를 확실히 넘긴 뒤, 쪼개지지 않고 글자 하나 안 바뀌는지 본다.

### 장 제목 줄과 상호참조를 한 테스트에 넣는다

```python
assert [c.locator for c in chunks] == ['제4장 제26조(재해 대응 출장)', '제5장 제27조(가지급)']
assert '제14조의 상한' in chunks[0].text   # 상호참조는 안 갈린다
assert '제5장' not in chunks[0].text       # 장 제목 줄은 본문에 안 남는다
```

[[50_청킹_규칙]]의 조 단위 조정 셋이 한 번에 걸린다. `제14조의 상한을 초과하여` 가
조로 갈리면 첫 단언이 깨지고, 장 제목 줄이 본문에 남으면 셋째가 깨진다.

### 숫자를 박아 둔 단언

```python
assert summarize(a) == '조항 단위 46 + 표 단위 7 = 53 청크'
```

골든 단언이다([[29_골든셋_회귀테스트]]). 청킹 규칙을 고치면 여기도 같이 고쳐야 하는데,
**고칠 때 왜 달라졌는지 설명할 수 있어야 한다**는 것이 이 단언의 목적이다.
모르는 사이에 53이 99가 되는 것을 막는다.

```text
4 passed, 1 warning in 8.43s
```

## 같은 문서, 다른 형식

같은 규정을 세 형식으로 읽어 청킹까지 돌렸다.

```text
[hwpx] blocks=233 tables=7 pages= 1 → 조항 단위 46 + 표 단위 7 = 53 청크
[docx] blocks=233 tables=7 pages= 1 → 조항 단위 46 + 표 단위 7 = 53 청크
[pdf ] blocks= 16 tables=0 pages=16 → 조항 단위 45 + 표 단위 0 = 45 청크
```

**HWPX 와 DOCX 는 완전히 같고 PDF 만 다르다.** 두 갈래를 따로 봐야 한다.

### HWPX = DOCX 는 지켜야 하는 계약이다

파서 코드가 전혀 다르다. 하나는 ZIP 안의 XML 을 읽고([[43_HWPX_파싱]]) 하나는
`python-docx` 로 본문 자식을 훑는다([[39_문서_파싱]]). 그런데 결과가 같아야 한다.

같지 않으면 **같은 규정을 hwpx 로 올린 사람과 docx 로 올린 사람이 다른 답을 받는다.**
그래서 이것만 테스트에 넣었다.

### PDF 가 다른 것은 파서 한계다

```text
docx 블록 종류 : ['조항', '표']      마크다운 표 기호 | : 323개
pdf  블록 종류 : ['조항']           마크다운 표 기호 | : 0개
```

`pypdf` 는 쪽 단위 텍스트만 준다([[39_문서_파싱]]). 그래서 블록이 16개(=16쪽)이고
표라는 것을 알아본 블록이 하나도 없다. 파이프 기호가 0개인 것이 그 증거다.

표 내용이 사라진 것은 아니다. 갈 곳이 바뀌었다.

```text
docx 숙박비 상한액이 들어간 청크 3개
     조항   | 제3장 제2절 제14조(숙박비) · 별표1
     표    | 표2
     표    | 표3
pdf  숙박비 상한액이 들어간 청크 3개
     조항   | 제3장 제2절 제14조(숙박비) · 별표1
     조항   | 별표1
     조항   | 별표2
```

DOCX 에서 `표2`·`표3` 이던 것이 PDF 에서는 `별표1`·`별표2` 라는 조항 청크 안의 평문이 됐다.
그 청크를 펴 보면 무엇이 사라졌는지가 보인다.

```text
pdf 쪽 청크 : kind=조항 · locator=별표1 · 281자
  [별표1] 직급별 여비 지급 기준표 (제5조제2항, 제11조제3항, …) ⏎ 직급 ⏎ 일비 ⏎ 숙박비(광역시) ⏎ 숙박비(그 …
```

`직급`, `일비`, `숙박비(광역시)` 가 **줄바꿈으로만 구분된 한 줄**이 됐다. 열 이름은 남았는데
어느 값이 어느 열에 속하는지가 없다. [[40_표_추출과_마크다운]]에서 표를 마크다운으로 바꿔 둔
이유가 여기서 드러난다 — 그 변환이 일어나지 않으면 행과 열의 관계가 글자 순서로만 남는다.

## 청킹 규칙은 파서에 얹혀 있다

"표는 자르지 않는다"는 규칙은 **파서가 표라고 알려 줬을 때만** 작동한다.
PDF 에는 `kind == '표'` 인 블록이 없으니 이 규칙은 한 번도 실행되지 않는다.

| | DOCX·HWPX | PDF |
| --- | --- | --- |
| 표 규칙이 도나 | 돈다 | 블록이 없어 안 돈다 |
| 조 규칙이 도나 | 돈다 | 돈다 |
| 청크 수 | 53 | 45 |

조 단위 규칙은 PDF 에서도 돈다. 조 제목이 글자로 남아 있어서 정규식이 찾기 때문이다.
표만 못 산다.

그래서 같은 문서를 올릴 때 **어느 형식으로 올리는지가 검색 품질을 바꾼다.**
[[44_파일_형식_분기와_차단]]에서 `.hwp` 를 막고 `.hwpx` 로 저장하라고 안내한 것과 같은 성격의
문제인데, PDF 는 읽히기는 해서 막을 근거가 약하다.

## 짚어둘 것

### PDF 표를 살리려면 파서를 고쳐야 한다

`pdfplumber` 로 표를 찾는 것은 [[40_표_추출과_마크다운]]에서 이미 해 봤다(33개 중 9개).
그걸 `parse_pdf` 에 넣으면 PDF 도 `표` 블록을 갖게 되고, 청킹 규칙은 손대지 않아도 된다.

청킹을 고칠 문제가 아니라 파서를 고칠 문제라는 것이 요점이다.

### 테스트가 재료 파일에 묶여 있다

넷 중 하나는 `sandbox/w5/day01/samples/` 의 파일을 연다. 이 파일들은 저장소에 들어 있어서
clone 하면 그대로 돌지만, 재료를 옮기면 그 테스트만 skip 된다.

```python
def _require(path: Path) -> None:
    if not path.is_file():
        pytest.skip(f'실습 재료를 찾지 못했습니다: {path}')
```

실패가 아니라 skip 으로 둔 이유는 **파일이 빠진 것과 청킹이 틀린 것은 다른 문제**이기 때문이다.
섞어 놓으면 빨간불의 원인을 찾느라 시간을 쓴다.

참고: backend/tests/test_chunker.py, backend/app/rag/chunker.py, sandbox/w5/day03/01.임베딩_모델비교_청킹.ipynb
