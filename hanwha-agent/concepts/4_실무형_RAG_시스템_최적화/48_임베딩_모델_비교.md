# 임베딩 모델 비교

받아 둔 모델 둘([[42_임베딩_모델_받기]])을 처음으로 열어서, [[47_벡터와_코사인_유사도]]에서 손으로 계산했던 것을 실제 값으로 바꿔 봤다.

## 인터넷을 타지 않게 한다

`SentenceTransformer` 에 이름을 주면 저장소에 접속한다. 폴더 경로를 주면 디스크에서 읽는다.

```python
SentenceTransformer("nlpai-lab/KURE-v1")   # 저장소에 붙는다
SentenceTransformer(str(KURE))             # 디스크에서 읽는다
```

경로를 줬는데도 라이브러리가 갱신을 확인하러 나가는 경우가 있어서 환경변수로 한 겹 더 막는다.

```python
os.environ["HF_HUB_OFFLINE"] = "1"
```

**`import` 보다 먼저 설정해야 먹는다.** 라이브러리가 불려 올 때 이 값을 읽기 때문이다. [[42_임베딩_모델_받기]]에서 `HF_HUB_DOWNLOAD_TIMEOUT` 을 import 전에 넣어야 했던 것과 같은 이유다.

`embed_compare.py` 가 그 순서를 지키고 있다.

```python
import os
os.environ["HF_HUB_OFFLINE"] = "1"
...
def main() -> None:
    ...
    from sentence_transformers import SentenceTransformer   # 함수 안에서 import
```

`sentence_transformers` 를 함수 안에서 불러오는 것이 요점이다. 파일 맨 위에 두면 환경변수를 설정하는 줄보다 먼저 실행될 수 있다.

## 받은 것 확인

가중치 파일 이름이 다른 것은 어제 본 그대로다. 2.27GB 짜리 하나가 사실상 모델 전부이고 나머지는 토크나이저다.

## 재는 방법을 먼저 정한다

문장쌍 6개에 사람이 미리 답을 적어 둔다.

```python
PAIRS = [
    ("광역시 숙박비 상한", "잠자리 비용 한도", "같은 뜻"),
    ("출장 전에 신청서를 낸다", "출장은 사전 신청이 원칙이다", "같은 뜻"),
    ("법인카드로 결제한다", "법인카드 사용 지침을 따른다", "가까움"),
    ("일비는 하루 단위로 준다", "숙박비는 1박 단위로 준다", "가까움"),
    ("출장 신청서를 낸다", "재택근무를 신청한다", "다름"),
    ("숙박비 상한액", "정보보안 지침 위반", "남남"),
]
```

기대값을 먼저 적고 모델을 돌리는 방식이다([[29_골든셋_회귀테스트]]). 점수만 보면 잘한 것처럼 보이므로 무엇이 나와야 하는지를 먼저 고정한다.

비교 기준으로 자카드를 같은 쌍에 걸어 둔다.

```text
 1 [같은 뜻] 자카드 0.154
 2 [같은 뜻] 자카드 0.400
 3 [가까움] 자카드 0.312
 4 [가까움] 자카드 0.538
 5 [다름] 자카드 0.308
 6 [남남] 자카드 0.000

가까운 쌍 평균 : 0.351
먼 쌍 평균     : 0.154
```

### 얻은 것

1번 쌍이 이 실습의 목적이었다. 겹치는 글자가 "비"와 "한" 둘뿐이라 자카드가 0.154 였고 `LIKE` 로는 0건이었던 짝([[47_벡터와_코사인_유사도]])이 **0.6585 로 올라왔다.** 글자가 안 겹쳐도 뜻으로 찾는다는 것이 확인된다.

6번 쌍도 제대로 갈렸다. 0.3898 로 확실히 낮다.

### 못 한 것

5번 쌍이 문제다.

| | 가까운 쌍 최저 | 먼 쌍 최고 |
| --- | --- | --- |
| KURE-v1 | 0.6585 (1번) | **0.7216 (5번)** |
| bge-m3 | 0.6573 (1번) | **0.7626 (5번)** |

**먼 쌍이 가까운 쌍보다 높다.** 두 모델 모두 그렇다. "0.7 이상이면 관련 있다"처럼 임계값 하나를 걸면 5번이 통과하고 1번이 걸러진다. 순서가 뒤집혀 있으니 임계값을 어디에 두어도 이 여섯 쌍을 옳게 가를 수 없다.

자카드도 같은 쌍에서 실패했다(5번 0.308 vs 3번 0.312). 방법을 바꿨는데 같은 자리에서 걸린다.

### 5번은 라벨이 틀렸을 수 있다

```text
출장 신청서를 낸다  ↔  재택근무를 신청한다
```

둘 다 **사내 절차를 신청하는 문장**이다. 모델이 0.72 를 준 것이 틀렸다고 보기 어렵다. "출장 신청 어떻게 해?"라고 물었을 때 재택근무 신청 규정이 후보로 올라오는 것은 [[33_RAG_개요]] ⑧ 단계에서 걸러낼 일이고, ④ 임베딩이 할 일은 아니다.

즉 이 결과는 모델의 실패가 아니라 **문장쌍 6개로는 모델을 평가할 수 없다**는 뜻으로 읽는 쪽이 맞다. 라벨을 정하는 것 자체가 판단이고, 그 판단이 틀리면 점수가 아무것도 말해 주지 않는다.

## 어느 쪽이 나은가

| | 가까운 쌍 평균 | 먼 쌍 평균 | 차 |
| --- | --- | --- | --- |
| KURE-v1 | 0.742 | 0.556 | **0.186** |
| bge-m3 | 0.754 | 0.596 | 0.158 |

bge-m3 가 6쌍 중 4쌍에서 점수가 높다. 쌍별로 차이를 보면 쏠린 자리가 있다.

| 쌍 | bge-m3 − KURE-v1 |
| --- | --- |
| 1 같은 뜻 | −0.0012 |
| 2 같은 뜻 | **+0.0471** |
| 3 가까움 | +0.0025 |
| 4 가까움 | −0.0011 |
| 5 다름 | **+0.0410** |
| 6 남남 | **+0.0396** |

가까운 쌍 넷 중 셋은 0.003 안쪽으로 같고 2번만 올라갔다. 반면 먼 쌍은 둘 다 0.04 씩 올라갔다. 멀어야 할 것을 덜 멀게 보는 쪽이라 벌어지는 폭이 좁아진다.

한국어로 미세조정한 KURE-v1 이 조금 나은 쪽으로 나왔지만 **6쌍으로 내릴 결론이 아니다.** 우리 문서에서 뽑은 질문과 정답 쌍을 수십 개 모아야 쓸 만한 비교가 된다.

## 짚어둘 것

`normalize_embeddings=True` 로 받아 두고 `cos_sim` 으로 재고 있다.

```python
v = model.encode(sents, normalize_embeddings=True)
score = float(cos_sim(v[i*2], v[i*2 + 1]))
```

정규화한 벡터끼리는 내적이 곧 코사인이라([[47_벡터와_코사인_유사도]]) `cos_sim` 이 나누는 크기는 둘 다 1이다. 계산만 한 번 더 하는 셈이다.

그런데 `normalize_embeddings=True` 도 이 두 모델에서는 하는 일이 없다. 끄고 크기를 재 봤다.

```text
normalize=False 로 받은 벡터 크기 : 1.000000
normalize=True  로 받은 벡터 크기 : 1.000000
```

`modules.json` 에 `Normalize` 가 마지막 단계로 들어 있어서 **모델이 이미 정규화한 벡터를 돌려준다**([[49_임베딩_모델_고르기]]). 인자로 끄더라도 모델 안에서 이미 크기가 1이 된 뒤다.

정규화가 두 번, 코사인 나눗셈이 한 번 겹쳐 있는 셈인데 값은 같으니 틀리지는 않는다. 적재할 때 정규화해 두면 검색은 내적만으로 끝난다.

점수 여섯 개를 눈으로 보는 방식도 여기까지다. 다음은 청크를 실제로 만들어([[46_블록과_청크]]) 벡터로 바꾸고 DB 에 넣는 단계다.
