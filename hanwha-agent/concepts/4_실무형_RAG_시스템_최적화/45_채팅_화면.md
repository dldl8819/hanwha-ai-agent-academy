# 채팅 화면

백엔드는 day13 에 이미 질문을 받고 있었다([[28_가드와_재시도_폴백]]). 그동안 `/docs` 나 노트북으로만 불렀는데, 사람이 쓸 화면을 붙였다.

## 서버 둘을 띄운다

```bash
uvicorn app.main:app --app-dir backend     # 8000
streamlit run frontend/app.py              # 8501
```

따로 도는 프로세스 둘이고 화면이 HTTP 로 백엔드를 부른다([[19_문서_목록_화면과_API_연동]]). 백엔드가 안 떠 있으면 화면은 뜨지만 질문이 실패한다.

## 대화 이력은 목록이다

한 마디가 딕셔너리 하나다.

```python
chat: list[dict[str, str]] = []

def append_turn(history: list[dict[str, str]], role: str, content: str) -> None:
    history.append({"role": role, "content": content})

append_turn(chat, "user", "오늘 날씨가 어때?")
append_turn(chat, "assistant", "기상청 정보를 조회할 수 없습니다.")
```

```text
user      오늘 날씨가 어때?
assistant 기상청 정보를 조회할 수 없습니다.
대화 이력 길이 : 2개
```

`role` 과 `content` 두 칸짜리 모양이 낯익다. Anthropic SDK 의 `messages` 가 같은 모양이고([[25_Claude_API_호출]]), LangChain 의 `SystemMessage`·`HumanMessage` 도 이걸 객체로 감싼 것이다([[36_체인을_앱에_붙이기]]).

**화면과 모델이 같은 자료구조를 쓴다.** 나중에 이력을 모델에 넘겨 이어 대화하게 할 때 변환이 거의 없다.

## 이력을 `session_state` 에 둔다

```python
if 'chat' not in st.session_state:
    st.session_state['chat'] = []
```

[[16_Streamlit]]의 재실행 모델이 여기서 그대로 걸린다. **입력이 들어올 때마다 스크립트가 처음부터 다시 돈다.** `chat = []` 을 그냥 두면 매번 빈 목록으로 초기화되어 대화가 한 마디도 안 쌓인다.

`if ... not in` 으로 감싸는 것이 요점이다 — 없을 때만 만든다.

## 백엔드 부르기

### `frontend/core/api_client.py`

```python
def ask(question: str) -> dict:
    return _request("POST", "/api/v1/chat/messages", json={"question": question})
```

한 줄이다. 주소·타임아웃·예외 변환은 `_request` 가 이미 다 한다([[19_문서_목록_화면과_API_연동]]).

**화면은 경로를 모른다.** `api_client.ask(question)` 만 부른다. 엔드포인트가 바뀌면 이 파일 한 줄을 고친다.

## 화면

### `frontend/views/chat.py`

```python
def render() -> None:
    page_header('AI 업무 도우미', subtitle="사내 규정을 근거로 답변합니다.")

    if 'chat' not in st.session_state:
        st.session_state['chat'] = []

    # ① 쌓여 있던 대화를 먼저 다 그린다
    for message in st.session_state['chat']:
        with st.chat_message(message['role']):
            st.markdown(message['content'])

    # ② 입력창. 입력이 없으면 여기서 끝난다
    question = st.chat_input('무엇을 도와드릴까요?')
    if not question:
        return

    # ③ 질문을 이력에 넣고 바로 그린다
    st.session_state['chat'].append({'role': 'user', 'content': question})
    with st.chat_message('user'):
        st.markdown(question)

    # ④ 답을 받아 그린다
    with st.chat_message('assistant'):
        with st.spinner('사내 규정 찾아보는 중...'):
            try:
                response = api_client.ask(question)
            except api_client.ApiError as e:
                st.error(str(e))
                return
        answer = response.get('answer', '')
        st.markdown(answer)

    # ⑤ 답도 이력에 넣는다
    st.session_state['chat'].append({'role': 'assistant', 'content': answer})
```

순서가 설계다.

| | 왜 |
| --- | --- |
| ① 먼저 다 그린다 | 재실행마다 화면이 비므로, 이력을 다시 그려야 대화가 이어져 보인다 |
| ② `if not question: return` | 입력이 없는 재실행(메뉴 클릭 등)에서는 아무 일도 하지 않는다 |
| ③ 질문을 먼저 그린다 | 답을 기다리는 동안 자기 질문이 화면에 있어야 한다 |
| ④ `st.spinner` | 기다리는 중이라는 표시. 이게 없으면 멈춘 것처럼 보인다 |

`with st.chat_message('assistant')` 블록 **안에서** 호출하는 것도 의도다. 회전 표시가 답변 말풍선 자리에 나타나서 답이 그 자리에 올 것임이 보인다.

`response.get('answer', '')` 로 꺼내는 것은 키가 없을 때를 막으려는 것인데, 대가가 있다([[44_파일_형식_분기와_차단]]의 조용한 실패와 같은 모양이다). 아래에 적었다.

## 메뉴에 연결

### `frontend/app.py`

```python
from views import chat as chat_view

NAV = [
    ("AI 업무 도우미", "chat"),       # None 이었다
    ("문서 관리", "documents"),
    ("승인함", None),
    ("운영 대시보드", None),
]

if page == "chat":
    chat_view.render()
elif page == "documents":
    documents_view.render()
```

`None` 이던 자리에 키를 넣었다. 아직 `None` 인 둘은 누르면 "아직 만들지 않은 화면입니다"가 뜬다 — **메뉴는 다 보이고 안 만든 것은 안 만들었다고 말한다.** 구조 지도의 화면 7종 중 둘이 찬 셈이다([[41_기술_스택_지도]]).

사이드바에 아바타도 붙였다.

```python
f'<div class="ag-avatar">{html.escape(user["name"][:1])}</div>'
```

이름 첫 글자를 원 안에 넣는다. `html.escape` 를 거치는 이유는 이름이 DB 에서 오기 때문이다 — `unsafe_allow_html=True` 로 그리는 자리에 사용자 입력을 그냥 넣으면 스크립트가 섞일 수 있다.

## 짚어둘 것

### `answer` 만 쓰고 나머지를 버린다

백엔드가 돌려주는 `AskOut` 에는 네 가지가 더 있다([[27_구조화_출력]]).

| 필드 | 화면에서 | |
| --- | --- | --- |
| `answer` | 쓴다 | |
| `sources` | **안 쓴다** | 근거 문서·조항·버전 |
| `fallback_used` | **안 쓴다** | 폴백으로 답한 것인지 |
| `attempts` | 안 쓴다 | 몇 번 만에 성공했는지 |
| `run_id` | 안 쓴다 | 이 질문의 실행 번호 |

`sources` 를 안 보여주는 것이 제일 크다. [[33_RAG_개요]] ⑪ Citation 자리인데 비어 있다. **출처 없이 답만 보여주면 사용자가 답을 확인할 방법이 없다.** 규정 답변에서는 그게 전부다.

`fallback_used` 도 그렇다. 세 번 다 실패해 정해둔 문장으로 답한 것인데([[28_가드와_재시도_폴백]]), 화면에는 평소 답과 똑같이 나온다. 표시를 붙일 수 있게 필드를 만들어 뒀는데 안 쓰고 있다.

`ui/source.py` 가 이미 있으니(`backend/README.md` 의 UI 킷) 붙일 자리는 준비돼 있다.

### 실패하면 질문만 남는다

```python
st.session_state['chat'].append({'role': 'user', 'content': question})   # ③ 먼저 쌓았다
...
except api_client.ApiError as e:
    st.error(str(e))
    return                                                                # ④ 여기서 끝
```

`return` 하면 ⑤가 실행되지 않아 assistant 메시지가 이력에 안 들어간다. 그런데 user 메시지는 ③에서 이미 들어갔다.

다음 재실행에서 무슨 일이 생기는가.

```text
이 실행   : 질문 + 빨간 오류 메시지
다음 실행 : 질문만. 오류 메시지는 사라진다
```

`st.error` 는 그 실행에서만 그려지고 `session_state` 에 남지 않는다. 사용자는 답이 안 온 질문 하나를 보게 되고 왜인지는 모른다.

고치는 길이 둘이다.

| | |
| --- | --- |
| 질문을 나중에 쌓는다 | 성공했을 때만 이력에 넣는다. 실패한 질문은 흔적이 없다 |
| 오류도 이력에 쌓는다 | `{'role': 'assistant', 'content': f'⚠ {e}'}` — 실패가 대화에 남는다 |

두 번째가 나아 보인다. **실패했다는 사실 자체가 대화 이력의 일부**다. 로그만 남기고 화면에서 지우는 것은 [[44_파일_형식_분기와_차단]]에서 `None` 을 돌려주던 것과 같은 선택인데, 여기는 사람이 보는 자리라 판단이 다르다.

### 기다리는 동안 멈춘다

`api_client.ask` 는 동기 호출이다. 답이 올 때까지 그 재실행이 끝나지 않는다. 회전 표시가 도니 멈춘 것처럼 보이지는 않지만 실제로 멈춰 있다.

[[37_비동기와_스트리밍]]에서 본 그대로다. 글자가 오는 대로 보여주려면 체인이 스트리밍돼야 하고 그건 `LLMPort` 부터 손봐야 한다. 화면은 마지막에 바뀐다.
