# 업로드 화면 연동

[[56_배경_작업과_작업_번호]]에서 작업 번호를 주는 쪽을 만들었다. 그 번호를
받아 물어보는 쪽을 붙인다. [[45_채팅_화면]] 이후로 손대지 않았던 화면 쪽이다.

## 파일은 `json` 으로 못 보낸다

지금까지의 요청은 전부 `json=` 이었다. 파일은 `multipart/form-data` 로 나가야 한다.

```python
    data: dict | None = None,   # 멀티파트 텍스트 필드
    files: dict | None = None,  # 멀티파트 파일 필드
```

한 요청의 본문 형식은 하나뿐이라 `json` 과 같이 쓰면 안 된다. 뒤에 오는 쪽이 이긴다.
멀티파트에서는 텍스트 칸과 파일 칸이 따로 실리기 때문에 인자도 둘로 나뉜다.

### `files` 의 값은 튜플이다

```python
files={"file": (filename, content)}
```

바이트만 주면 서버가 파일 이름을 모른다. 그러면 확장자를 알 수 없어
`ALLOWED_EXTS` 검사에서 걸린다. 이름과 바이트를 같이 보내야 한다.

### `up.getvalue()` 로 바이트를 꺼낸다

Streamlit 의 `file_uploader` 가 돌려주는 객체를 그대로 넘기면 안 된다.
파일 포인터가 한 번 읽히고 소진되어, 두 번째 읽기가 빈 바이트가 된다.
`getvalue()` 는 몇 번 불러도 같은 값을 준다.

### 날짜는 문자열로 보낸다

`effective_from` 을 `st.text_input` 으로 받아 문자열로 넘긴다. 변환은 서버에서
`Annotated[date, Form()]` 이 한다. 형식이 틀리면 422 로 돌아온다.

## 한 화면이 두 상태를 그린다

```python
job_id = st.session_state.get("upload_job")
if job_id:
    _render_progress(job_id)
else:
    _render_form()
```

업로드 응답은 "저장했다" 까지만 알려준다. 결과를 보려면 번호로 다시 물어야 하므로
화면도 폼과 진행 상태 둘로 나뉜다. 가르는 기준은 세션에 작업 번호가 있는지다.

`st.rerun()` 을 빼면 번호를 받아 놓고도 폼이 그대로 남는다. Streamlit 은 위에서
아래로 한 번 훑어 그리는 방식이라, 이미 그려진 폼을 지우려면 다시 그려야 한다.

## 폴링 — 1초에 한 번 묻는다

```python
if job["status"] not in ("완료", "실패"):
    time.sleep(1)
    st.rerun()
```

`sleep` 과 `rerun` 으로 만든다. 이 조건을 빼면 완료된 뒤에도 1초마다 서버를 두드린다.

`time.sleep(1)` 이 화면 그리는 스레드를 멈춘다. 그 1초 동안 이 사용자의 화면은
다른 입력을 받지 못한다. 작업이 몇 분 걸리는 일이라면 쓸 수 없는 방식이고,
그때는 서버가 밀어 주는 쪽(SSE·WebSocket)으로 바꿔야 한다.
업로드는 끝을 기다리는 화면이라 이 방식으로 둔다.

## 부서 코드는 화면과 DB 가 맞아야 한다

```python
DEPTS = {"HR": "경영지원팀", "HRGA": "인사총무", "INFRA2": "인프라사업부 2팀",
         "PMO": "PMO", "PU": "구매팀", "SE": "보안팀"}
...
dept_id = st.selectbox("소관 부서", options=list(DEPTS), format_func=DEPTS.get)
```

`options` 는 코드고 `format_func` 로 이름을 보여준다. 화면에는 이름을, 서버로는
코드를 보낸다. `seed_data.py` 의 `departments` 와 코드가 어긋나면 외래키에서 걸린다.

`views/documents.py` 의 `DEPTS` 는 거꾸로다. 거기는 이름이 키고 코드가 값이다. 용도가 달라서(목록은 필터라 "전체" 가 있다)
그대로 뒀지만, 같은 이름의 상수가 두 모양으로 있는 것은 헷갈릴 자리다.

## 확장자 목록이 두 곳에 있다

```python
ACCEPT = ["docx", "pdf", "txt"]
```

백엔드 `documents.py` 의 `ALLOWED_EXTS` 와 맞춰 둬야 한다.
화면만 늘리면 파일은 올라가고 서버에서 거절당한다. 반대로 서버만 늘리면
올릴 수 있는 파일을 화면이 막는다. [[44_파일_형식_분기와_차단]]에서 만든 차단이
화면 쪽에도 한 벌 더 있는 셈이다.

## 라우팅

```python
elif page == "document_upload":
    document_upload_view.render()
```

`views/documents.py` 의 "새 문서 업로드" 버튼이 `st.info("추후에 만듭니다")` 를
띄우던 자리를 `router.go("document_upload")` 로 바꿨다.
`documents.py` 의 import 에 `router` 를 추가해야 한다.

## 화면에 66% 가 보인다

```text
완료 · 19청크
  [  ok] 파일 검증
  [  ok] 문서 파싱                      표 2개 인식
  [  ok] 표 -> 마크다운 변환               표 2개
  [  ok] 청킹                         19청크
  [todo] 임베딩
  [todo] 검색 반영 및 현행 버전 지정
                                                    66%
```

배지는 "완료" 인데 막대는 66% 다. 모순으로 보이지만 그대로 뒀다.
`ui/status.py` 의 `steps()` 가 `todo` 상태를 `·` 와 `—` 로 그려서,
구현되지 않은 두 단계가 화면에서 구분된다.

화면에 설명을 한 줄 붙여 뒀다. 숫자만 보이면 버그로 읽힌다.

```python
st.caption("표 1개가 청크 1개로 저장됩니다. 임베딩은 아직 붙지 않아 66% 에서 멈춥니다.")
```

## 실패도 화면에 적는다

강사님 코드는 완료만 본문에 적는다. 실패하면 배지에 "실패" 만 뜨고 `message` 에
담긴 원인이 화면에 안 나온다. 배경 작업의 예외는 거기밖에 남지 않으므로
([[56_배경_작업과_작업_번호]]) 한 줄 더했다.

```python
elif job["status"] == "실패":
    st.error(job["message"])
```

## 서버 두 개를 띄워야 한다

```text
uvicorn app.main:app --app-dir backend --reload --port 8000
streamlit run frontend/app.py
```

둘 다 저장소 루트에서 띄운다. `--app-dir backend` 로 import 경로만 옮기고
cwd 는 루트로 둔다. `.env` 와 `uploads/` 가 루트 기준이기 때문이다.
`backend/` 로 들어가서 띄우면 `.env` 를 못 찾아 sqlite 로 붙는다.

참고: frontend/views/document_upload.py, frontend/core/api_client.py,
frontend/views/documents.py, frontend/app.py
