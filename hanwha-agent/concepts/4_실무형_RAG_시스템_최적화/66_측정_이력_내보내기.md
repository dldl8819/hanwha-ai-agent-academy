# 측정 이력 내보내기

[[65_측정값_뜯어보기]]까지 측정값은 터미널 출력과 JSON 파일에만 있었다. 화면이나 다른
도구가 읽으려면 경로가 있어야 한다.

`GET /api/v1/ops/eval-runs` 하나를 열었다.

## 운영용 라우터를 따로 둔다

```python
router = APIRouter(prefix='/ops', tags=['ops'])
```

`documents`·`auth`·`chat` 옆에 네 번째가 붙었다. 앞의 셋과 다른 점은 쓰는 사람이다.
문서 목록이나 채팅은 직원이 쓰고 `/ops` 는 만드는 쪽이 본다.

`tags` 를 따로 준 것은 `/docs` 에서 묶어 보려는 것이다. 경로 이름만 나누면
문서에서는 섞여 나온다.

## 서비스가 세션을 연다

```python
def list_eval_runs(*, limit: int = 20) -> list[dict]:
    with session_scope() as s:
        rows = s.execute(select(EvalRun).order_by(EvalRun.ord).limit(limit)).scalars().all()
```

라우터는 세션을 모른다. `deps.py` 에 `SessionDep` 가 정의돼 있는데 쓰지 않았다.
`document_service`·`chat_service`·`auth_service` 가 모두 서비스 안에서 `session_scope()`
를 여는 방식이라 같은 쪽으로 맞췄다.

`SessionDep` 은 지금 아무 라우터도 쓰지 않는다. [[63_검색_정책]]의 `top_k` 와 같은
모양이다 — 만들어 두고 쓰이지 않는 것이 옆에 있으면 나중에 둘 중 하나를 고치게 된다.

`order_by(EvalRun.ord)` 를 거는 이유는 `ord` 가 막대 그래프의 순서이기 때문이다.
`id` 순으로 돌려주면 삽입 순서를 따라가므로 지금은 같지만, 설정이 늘고 다시 저장되면
갈라진다. 화면이 기대하는 순서를 DB 가 아니라 `ord` 가 쥐고 있다.

### ORM 객체를 그대로 내보내지 않는다

```python
return [{"config": r.config, "ord": r.ord, ...} for r in rows]
```

세션을 닫은 뒤에도 컬럼 접근은 된다. `get_sessionmaker()` 가 `expire_on_commit=False`
라서 이미 읽어 둔 값은 살아 있다. 실제로 확인해 봤다.

```text
세션 닫은 뒤 컬럼 접근 : OK — 기본 검색 80.0
```

그래도 dict 로 베끼는 이유는 두 가지다. 관계를 따라가는 순간에는 터지고(그때는 세션이
필요하다), 응답에 무엇을 실을지는 모델이 아니라 서비스가 정해야 한다.

## 바깥에서 들어오는 숫자에는 경계를 둔다

```python
def list_eval_runs(limit: Annotated[int, Query(ge=1, le=100)]=20) -> list[dict]:
```

네 가지로 찔러 봤다.

```text
?limit=1     → 200
?limit=0     → 422  {"code": "validation_failed", "message": "입력값을 확인하세요 — limit"}
?limit=101   → 422
?limit=abc   → 422
```

422 본문이 저 모양인 것은 [[19_문서_목록_화면과_API_연동]]에서 만든
`RequestValidationError` 핸들러 때문이다. 필드 이름만 돌려주고 들어온 값은 감춘다.
라우터를 새로 추가했는데 예외 처리는 따라 붙는다 — 핸들러를 앱에 걸어 뒀기 때문이다.

## 이름은 이력인데 이력이 없다

```python
session.query(EvalRun).delete()
```

[[64_골든셋과_채점기]]에 적은 그대로 `save()` 는 저장할 때 기존 줄을 전부 지운다.
그래서 이 API 가 돌려주는 것은 마지막 측정 한 번이다.

```text
등록된 ops 경로 : ['/api/v1/ops/eval-runs']
GET /api/v1/ops/eval-runs → 200 · 행 1개
  기본 검색  ord=0  accuracy=80.0  item_count=30  measured_at=2026-10-12T11:25:28.207679+09:00
```

`limit=20` 의 기본값도 지금은 거를 것이 없다. 설정이 늘면 한 측정의 막대 수만큼
행이 생기고, 날짜별 추이를 보려면 테이블이 달라져야 한다. 지금 구조에서는
"어제보다 올랐는지"를 이 API 로 물을 수 없다.

### 시각이 두 벌이다

`main()` 은 측정을 끝낸 시각을 `report["measured_at"]` 에 적고, `save()` 는 그것을
쓰지 않고 `measured_at=datetime.now()` 를 다시 찍는다. 같은 측정인데 JSON 파일과
API 의 시각이 다르다. 30문항을 도는 데 걸린 시간만큼 벌어진다.

`datetime.now()` 는 시간대가 없는 값이고 컬럼은 `DateTime(timezone=True)` 다.
PostgreSQL 이 세션 시간대로 해석해 `+09:00` 을 붙였다. 지금 결과는 맞지만
서버 시간대가 바뀌면 같은 코드가 다른 시각을 적는다.

## 인증이 없다

`/ops/eval-runs` 는 누구나 부를 수 있다. 사번도 토큰도 보지 않는다.

다른 라우터도 같은 상태라 지금은 일관적이다. 다만 `/ops` 아래에 재색인이나 삭제가
붙는 순간 성격이 달라진다. 측정 결과는 민감하지 않지만 운영 조작은 다르다.
[[63_검색_정책]]에서 등급 기본값을 낮게 둔 것과 같은 쪽으로, 운영 경로는 닫힌 상태에서
열어 가는 순서가 맞다고 본다.
