# 파서 진입점과 형식 확장

[[44_파일_형식_분기와_차단]]에서 `parse_local` 이 확장자로 갈라 줬다. 그런데 거기 못 들어가는
형식이 있어서 그 앞에 진입점을 하나 더 뒀다.

## 못 읽는 다섯 형식

`_formats` 안의 재료를 `parse_local` 에 넣어 봤다.

```text
sample_table.xlsx   -> 블록 1개
sample_notice.pptx  -> 블록 1개
sample_memo.txt     -> ValidationFailed: 지원하지 않는 형식입니다: .txt  | detail=핸들러를 추가하면 지원할 수 있습니다
sample_guide.md     -> ValidationFailed: 지원하지 않는 형식입니다: .md  | detail=핸들러를 추가하면 지원할 수 있습니다
sample_page.html    -> ValidationFailed: 지원하지 않는 형식입니다: .html  | detail=핸들러를 추가하면 지원할 수 있습니다
```

`.xlsx` 와 `.pptx` 는 핸들러를 더해서 풀렸다(아래 참조). 남은 셋은 핸들러로 풀 문제가 아니다 —
`detail` 이 "핸들러를 추가하면 지원할 수 있습니다"라고 안내하는데 그게 맞는 말이 아니다.
`.txt` 를 그냥 읽어 보면 왜인지 알 수 있다.

```text
[그냥 읽으면]  71자
출장 정산 안내

9월부터 출장 정산은 그룹웨어에서만 접수합니다.
종이 서류는 받지 않습니다.

문의: 인사총무팀 김지원 과장

[parse_local 에 넣으면]
ValidationFailed: 지원하지 않는 형식입니다: .txt
```

**글자가 이미 다 있는데 파서를 찾다가 막혔다.** `.txt` 와 `.md` 는 파싱할 것이 없다.
`.xlsx` 와 `.pptx` 는 반대로 전용 라이브러리가 필요하다. 같은 "못 읽음"이 아니므로
처리도 달라야 한다.

## 진입점 — `backend/app/rag/parser.py`

파서가 필요한 형식과 필요 없는 형식을 가르는 자리를 만들었다.

```python
_PLAIN = {".txt", ".md"}         # 파싱 없이 바로 읽는다
_HTML = {".html", ".htm"}        # 태그를 걷어내야 글자가 남는다
_LOCAL_ONLY = {".hwp", ".hwpx"}  # 상용 API 로 보내지 않는다

def parse(path: str | Path, *, use_upstage: bool = False) -> ParsedDoc:
    p = Path(path)
    ext = p.suffix.lower()
    if ext in _PLAIN:
        return _parse_plain(p)
    if ext in _HTML:
        return _parse_html(p)
    if use_upstage and ext not in _LOCAL_ONLY:
        from app.integrations.upstage import UpstageParser
        return UpstageParser().parse(str(p))
    return parse_local(p)
```

| 순서 | 조건 | 가는 곳 |
| --- | --- | --- |
| 1 | `.txt` · `.md` | `_parse_plain` |
| 2 | `.html` · `.htm` | `_parse_html` |
| 3 | `use_upstage` 가 참이고 `_LOCAL_ONLY` 가 아니다 | 상용 API |
| 4 | 나머지 | `parse_local` |

`_LOCAL_ONLY` 가 3번 뒤에 오는 것이 요점이다. 한글 문서는 **상용 API 를 쓰는 설정이어도
밖으로 보내지 않는다.** [[42_임베딩_모델_받기]]에서 임베딩을 로컬로 정한 것과 같은 판단이다.

스위치를 켜고 꺼 보면 무엇이 바뀌는지 보인다.

```text
[use_upstage=False]
  sample_memo.txt      -> _parse_plain
  sample_page.html     -> _parse_html
  sample_table.xlsx    -> parse_local
  …v2.0.hwpx           -> parse_local

[use_upstage=True]
  sample_memo.txt      -> _parse_plain   (그대로)
  sample_table.xlsx    -> upstage        (바뀐다)
  …v2.0.hwpx           -> parse_local    (그대로)
```

`.hwpx` 는 스위치를 켜도 그대로다. `.txt` 도 그대로인데 이유가 다르다 —
보낼 이유가 없어서다.

## 플레인 파서 — 빈 줄로 자른다

```python
def _parse_plain(p: Path) -> ParsedDoc:
    text = p.read_text(encoding="utf-8", errors="replace")
    blocks = [
        ParsedBlock("조항", f"{p.name} {i + 1}단락", part.strip())
        for i, part in enumerate(text.split("\n\n"))
        if part.strip()
    ]
    return ParsedDoc(blocks=blocks, page_count=1, table_count=0)
```

`errors="replace"` 는 인코딩이 틀린 글자를 `?` 로 바꿔 넣는다. 예외를 올리는 대신
읽히는 만큼 읽는다 — 메모 한 줄 때문에 적재 전체가 멈추지 않게 하는 선택이다.

빈 줄(`\n\n`)로 자르는 것이 문단 단위에 가깝다.

```text
[1] 8자 : 출장 정산 안내
[2] 42자 : 9월부터 출장 정산은 그룹웨어에서만 접수합니다.
종이 서류는 받지 않습니다.
[3] 16자 : 문의: 인사총무팀 김지원 과장
블록 3개
```

### 마크다운 제목을 locator 로 올린다

제목이 블록이 되던 문제는 `_parse_markdown` 을 따로 만들어 풀었다.
제목을 블록으로 만들지 않고 **그 아래 본문의 출처**로 쓴다.

```python
for line in text.split("\n"):
    if re.match(r"#{1,6}\s", line):
        flush()                              # 앞 절을 닫고
        locator = line.lstrip("#").strip()   # 이 제목을 다음 절의 출처로
    else:
        buffer.append(line)
flush()
```

```text
locator='1. 신청'  23자  '출장 3일 전까지 그룹웨어에서 신청합니다.'
locator='2. 승인'  39자  '팀장 승인 후 확정됩니다. 5일 초과 출장은 본부장 승인이 필…'
locator='3. 정산'  27자  '복귀 후 7일 이내에 영수증을 첨부해 정산합니다.'
```

블록이 7개에서 3개로 줄고, 8자짜리 제목 조각이 사라졌다. 그러면서 출처가 좋아졌다 —
`sample_guide.md 2단락` 보다 `1. 신청` 이 어디서 나온 답인지 분명하다.

`#{1,6}\s` 에서 공백까지 보는 것이 요점이다. `#태그` 같은 줄을 제목으로 잡지 않는다.

`flush()` 를 반복문 뒤에 한 번 더 부르는 것도 빠뜨리기 쉬운 자리다. 마지막 절은
다음 제목이 없어서 반복문 안에서 닫히지 않는다.

## HTML 파서 — 표를 먼저 떼어낸다

태그를 한 번에 지우면 어떻게 되는지부터 봤다.

```python
flat = re.sub(r"\s+", " ", re.sub(r"<[^>]+>", " ", html)).strip()
```

```text
사내 공지 추석 연휴 근무 안내 연휴 기간 중 당직 근무자는 아래와 같습니다. 날짜 당직자 연락처 10/03 김민준 내선 2201 10/04 이서연 내선 2202
블록 1개
```

전부 한 줄이 된다. **표가 본문에 녹아 버려서** `날짜 당직자 연락처 10/03 김민준` 이
어디가 열 이름이고 어디가 값인지 알 수 없다. [[51_청킹_테스트와_형식_차이]]에서 PDF 가
겪은 것과 같은 일인데, 여기서는 막을 수 있다.

순서를 바꾼다. **표를 먼저 떼어내고 본문을 정리한다.**

```python
raw = re.sub('<(script|style)[^>]*>.*?</\\1>', ' ', raw, flags=re.S | re.I)
tables = re.findall('<table.*?</table>', raw, flags=re.S | re.I)   # 표를 모아 두고
body = re.sub('<table.*?</table>', ' ', raw, flags=re.S | re.I)    # 본문에서 뺀다
body = re.sub('\\s+', ' ', re.sub('<[^>]+>', ' ', body)).strip()
```

```text
[좋은 예] 블록 2 · 표 1 · 쪽 1 · 글자 89자
  [1] 조항  sample_page.html          43자  사내 공지 추석 연휴 근무 안내 연휴 기간 중 당직 근무자는 아래와 같습니다.
  [2] 표    sample_page.html · 표1     46자  날짜 당직자 연락처 10/03 김민준 내선 2201 10/04 이서연 내선 2202
```

블록이 둘로 갈렸다. `<script>` 와 `<style>` 을 먼저 지우는 것은 **그 안의 글자가 본문이 아니기**
때문이다. 자바스크립트 코드가 규정 문장처럼 검색되면 안 된다.

`<(script|style)[^>]*>.*?</\1>` 의 `\1` 이 앞에서 잡은 태그 이름을 다시 쓴다.
`<script>` 를 `</style>` 로 닫는 짝이 생기지 않게 한다.

## XLSX — 시트 하나가 표 하나

```python
def parse_xlsx(path: Path) -> ParsedDoc:
    from openpyxl import load_workbook

    wb = load_workbook(str(path), data_only=True)
    blocks: list[ParsedBlock] = []
    for ws in wb.worksheets:
        rows = [
            ["" if c is None else str(c) for c in row]
            for row in ws.iter_rows(values_only=True)
            if any(c is not None for c in row)
        ]
        if not rows:
            continue
        blocks.append(ParsedBlock("표", ws.title, _table_to_markdown(rows[0], rows[1:])))
    return ParsedDoc(blocks=blocks, page_count=len(wb.worksheets), table_count=len(blocks))
```

세 가지 판단이 들어 있다.

| | 왜 |
| --- | --- |
| `data_only=True` | 수식이 아니라 계산된 값을 가져온다. `=SUM(B2:B4)` 가 아니라 숫자가 필요하다 |
| 시트 이름을 `locator` 로 | 출처가 "출장비 집계" 가 된다. 파일명보다 어디서 왔는지가 분명하다 |
| `_table_to_markdown` 재사용 | [[40_표_추출과_마크다운]]에서 쓴 그 함수다. 형식이 늘어도 표의 모양은 하나다 |

```text
시트 목록 :  ['출장비 집계']
('부서', '1분기', '2분기', '3분기')
('인프라사업부 2팀', 4200000, 3800000, 5100000)
```

```text
블록 1 · 표 1 · 쪽 1 · 글자 161자
  kind    : 표
  locator : 출장비 집계
| 부서 | 1분기 | 2분기 | 3분기 |
|---|---|---|---|
| 인프라사업부 2팀 | 4200000 | 3800000 | 5100000 |
```

첫 행을 머리행으로 쓴다. 엑셀에 머리행이라는 개념이 따로 없으니 **첫 행이 머리행이라고
정한 것**이고, 그렇지 않은 시트에서는 어긋난다.

## PPTX — 슬라이드 하나가 블록 하나

슬라이드는 도형 여럿으로 이뤄진다. 글자가 든 도형만 골라야 한다.

```python
lines = [shape.text.strip() for shape in slide.shapes
         if shape.has_text_frame and shape.text.strip()]
```

`has_text_frame` 으로 거르는 것이 요점이다. 이미지·선·차트에는 글자 틀이 없고,
`shape.text` 를 바로 읽으면 거기서 예외가 난다.

```text
슬라이드 : 1장, 70자
출장 여비 규정 개정 안내
일비 25,000 → 30,000원
광역시 숙박비 상한 70,000원 신설
시행 2025-07-01
```

### 발표자 노트는 슬라이드 밖에 있다

여기까지는 화면에 보이는 것만 긁었다. 발표자 노트는 `slide.shapes` 에 없다.

```python
if slide.has_notes_slide:
    note = slide.notes_slide.notes_text_frame.text.strip()
    if note:
        lines.append(f"[발표자 노트] {note}")
```

```text
슬라이드 : 1장, 99자
...
[발표자 노트] 인사총무팀 설명용 발표 노트입니다.
```

70자에서 99자로 늘었다. 29자가 **슬라이드를 봐도 안 보이는 내용**이다.
규정 설명 자료라면 그 29자가 정작 찾고 싶은 근거일 수 있다.

`[발표자 노트]` 라고 표시를 붙여 두는 것은 나중에 답변에 인용될 때
발표 화면에 있던 말인지 아닌지를 구별하기 위해서다.

## 다섯 형식을 한 줄로 잇는다

`HANDLERS` 에 둘을 등록했다.

```python
HANDLERS = {
    '.docx': parse_docx,
    '.pdf': parse_pdf,
    '.hwpx': parse_hwpx,
    '.xlsx': parse_xlsx,
    '.pptx': parse_pptx,
}
```

이제 `parse_local` 이 분기표만 보고 보낸다. `parse_xlsx` 를 직접 부를 필요가 없다.

```text
HANDLERS 현재: ['.docx', '.pdf', '.hwpx', '.xlsx', '.pptx']

sample_table.xlsx   블록 1 - 표 1 - 쪽 1 - 161자
sample_notice.pptx  블록 1 - 표 0 - 쪽 1 -  99자
```

파싱에서 끝내지 않고 청킹까지 보내 봤다.

```text
sample_memo.txt     블록  3  표 0  →  조항 단위 1 + 표 단위 0 = 1 청크
sample_guide.md     블록  7  표 0  →  조항 단위 1 + 표 단위 0 = 1 청크
sample_page.html    블록  2  표 1  →  조항 단위 1 + 표 단위 1 = 2 청크
sample_table.xlsx   블록  1  표 1  →  조항 단위 0 + 표 단위 1 = 1 청크
sample_notice.pptx  블록  1  표 0  →  조항 단위 1 + 표 단위 0 = 1 청크
```

다섯 형식이 전부 지나간다. 표가 있는 둘은 표 청크가 따로 나온다.
그런데 앞의 둘에서 블록 수와 청크 수가 크게 어긋난다.

## 숙제 넷을 해결했다

[[51_청킹_테스트와_형식_차이]]와 위에 TODO 로 적어 둔 것들이다.
코드가 두 배로 늘었는데, 늘어난 대부분이 이 숙제들의 답이다.

### 병합 셀 — 가려진 칸을 채운다

`_fill_merged` 가 풀었다. 병합 범위를 읽어 왼쪽 위 값을 범위 전체에 복사한다.

```python
for rng in ws.merged_cells.ranges:
    top_left = grid[rng.min_row - r0][rng.min_col - c0]
    for r in range(rng.min_row, rng.max_row + 1):
        for c in range(rng.min_col, rng.max_col + 1):
            grid[r - r0][c - c0] = top_left
```

```text
| 인프라사업부 | 4200000 | 3800000 |
| 인프라사업부 | 1200000 | 1400000 |     ← 빈칸이 채워졌다
| 구매팀 | 900000 | 1000000 |
```

여기에 순서에 기대는 자리가 하나 숨어 있다.

```python
ws["C3"] = "부서"
print(ws.min_row)                       # 3
list(ws.iter_rows(values_only=True))    # 1행부터 훑으면서 빈 칸이 만들어진다
print(ws.min_row)                       # 1
```

`iter_rows()` 를 부르면 `min_row` 가 1로 내려간다. `grid[0]` 이 시트 1행이므로
**`grid` 를 먼저 만든 뒤에 `r0` 를 읽어야** 자리가 맞는다. 두 줄을 위로 올리면 조용히 깨진다.

### 슬라이드 안의 표와 차트

`_pptx_table` 과 `_pptx_chart` 가 풀었다. `has_text_frame` 으로는 안 잡히는 도형이라
`has_table` · `has_chart` 로 따로 본다.

차트까지 표로 바꾸는 것이 덧붙은 부분이다. 숫자가 든 자료라 검색 대상이다.

```python
def num(v) -> str:
    return _cell(int(v) if isinstance(v, float) and v.is_integer() else v)
```

엑셀 숫자는 전부 `float` 로 와서 `4200000.0` 이 된다. 정수면 소수점을 떼야 읽힌다.

그리고 `_walk_shapes` 가 하나 더 있다.

```python
if isinstance(shape, GroupShape):
    yield from _walk_shapes(shape.shapes)
```

그룹으로 묶인 도형은 `slide.shapes` 에서 하나로 보인다. 안쪽으로 들어가지 않으면
그룹 안의 글자와 표가 통째로 빠진다. 재귀로 한 겹씩 벗긴다.

### `<title>` 은 `<head>` 를 통째로 지워 해결했다

```python
raw = re.sub(r"<head.*?</head>", " ", raw, flags=re.S | re.I)
```

`<title>` 만 지우는 것보다 `<head>` 를 통째로 지우는 쪽이 간단하다. `<meta>` 의
`description` 같은 것도 본문이 아니라서 같이 빠지는 게 맞다.

```text
'추석 연휴 근무 안내 연휴 기간 중 당직 근무자는 아래와 같습니다.'
'사내 공지' 가 아직 있나 : False
```

### 인코딩을 모르는 파일

이건 숙제에 없던 것인데 같이 들어왔다. 사내 문서에는 `cp949` 로 저장된 `txt` 가 섞여 있다.

```python
for enc in ("utf-8-sig", "cp949"):
    try:
        text = raw.decode(enc)
    except UnicodeDecodeError:
        continue
```

`utf-8-sig` 를 먼저 보는 이유는 BOM 이 있으면 떼어 주고 없으면 `utf-8` 과 같게 동작하기
때문이다. 둘 다 아니면 `errors="replace"` 로 읽히는 만큼 읽는다 — 파일 한 건 때문에
적재 전체를 멈추지 않는다.

`cp949` 로 읽혔다는 것은 로그에 남긴다. 글자가 깨져 보일 때 먼저 볼 자리다.

## 짚어둘 것

### 청크의 locator 는 아직 거짓말을 한다

파싱 쪽 숙제는 다 끝났는데 **청킹 쪽 하나가 남았다.**

```text
파서  : 1단락(8자) · 2단락(42자) · 3단락(16자)
청킹  : 1단락(68자)   ← 1~3단락을 담고 있다
```

`chunk()` 가 조항 블록을 모을 때 처음 들어온 블록의 locator 만 기억한다([[50_청킹_규칙]]).
마크다운은 제목이 locator 가 되어 나아졌지만, `.txt` 처럼 제목이 없는 문서에서는 그대로다.
