# 파서 진입점과 형식 확장

[[44_파일_형식_분기와_차단]]에서 `parse_local` 이 확장자로 갈라 줬다. 그런데 거기 못 들어가는
형식이 있어서 **그 앞에 진입점을 하나 더** 뒀다.

## 못 읽는 다섯 형식

`_formats` 안의 재료를 `parse_local` 에 넣어 봤다.

```text
sample_table.xlsx   -> ValidationFailed: 지원하지 않는 형식입니다: .xlsx
sample_notice.pptx  -> ValidationFailed: 지원하지 않는 형식입니다: .pptx
sample_memo.txt     -> ValidationFailed: 지원하지 않는 형식입니다: .txt
sample_guide.md     -> ValidationFailed: 지원하지 않는 형식입니다: .md
sample_page.html    -> ValidationFailed: 지원하지 않는 형식입니다: .html
```

다섯이 같은 이유로 막힌 것은 아니다. `.txt` 를 그냥 읽어 보면 알 수 있다.

```text
[그냥 읽으면]  71자
출장 정산 안내

9월부터 출장 정산은 그룹웨어에서만 접수합니다.
종이 서류는 받지 않습니다.

문의: 인사총무팀 김지원 과장

[parse_local 에 넣으면]
ValidationFailed: 지원하지 않는 형식입니다: .txt
```

**글자가 이미 다 있는데 파서를 찾다가 막혔다.** `.txt` 와 `.md` 는 파싱할 것이 없다.
`.xlsx` 와 `.pptx` 는 반대로 전용 라이브러리가 필요하다. 같은 "못 읽음"이 아니므로
처리도 달라야 한다.

## 진입점 — `backend/app/rag/parser.py`

파서가 필요한 형식과 필요 없는 형식을 가르는 자리를 만들었다.

```python
_PLAIN = {".txt", ".md"}         # 파싱 없이 바로 읽는다
_HTML = {".html", ".htm"}        # 태그를 걷어내야 글자가 남는다
_LOCAL_ONLY = {".hwp", ".hwpx"}  # 상용 API 로 보내지 않는다

def parse(path: str | Path, *, use_upstage: bool = False) -> ParsedDoc:
    p = Path(path)
    ext = p.suffix.lower()
    if ext in _PLAIN:
        return _parse_plain(p)
    if ext in _HTML:
        return _parse_html(p)
    if use_upstage and ext not in _LOCAL_ONLY:
        from app.integrations.upstage import UpstageParser
        return UpstageParser().parse(str(p))
    return parse_local(p)
```

| 순서 | 조건 | 가는 곳 |
| --- | --- | --- |
| 1 | `.txt` · `.md` | `_parse_plain` |
| 2 | `.html` · `.htm` | `_parse_html` |
| 3 | `use_upstage` 가 참이고 `_LOCAL_ONLY` 가 아니다 | 상용 API |
| 4 | 나머지 | `parse_local` |

`_LOCAL_ONLY` 가 3번 뒤에 오는 것이 요점이다. 한글 문서는 **상용 API 를 쓰는 설정이어도
밖으로 보내지 않는다.** [[42_임베딩_모델_받기]]에서 임베딩을 로컬로 정한 것과 같은 판단이다.

스위치를 켜고 꺼 보면 무엇이 바뀌는지 보인다.

```text
[use_upstage=False]
  sample_memo.txt      -> _parse_plain
  sample_page.html     -> _parse_html
  sample_table.xlsx    -> parse_local
  …v2.0.hwpx           -> parse_local

[use_upstage=True]
  sample_memo.txt      -> _parse_plain   (그대로)
  sample_table.xlsx    -> upstage        (바뀐다)
  …v2.0.hwpx           -> parse_local    (그대로)
```

`.hwpx` 는 스위치를 켜도 그대로다. `.txt` 도 그대로인데 이유가 다르다 —
보낼 이유가 없어서다.

## 플레인 파서 — 빈 줄로 자른다

```python
def _parse_plain(p: Path) -> ParsedDoc:
    text = p.read_text(encoding="utf-8", errors="replace")
    blocks = [
        ParsedBlock("조항", f"{p.name} {i + 1}단락", part.strip())
        for i, part in enumerate(text.split("\n\n"))
        if part.strip()
    ]
    return ParsedDoc(blocks=blocks, page_count=1, table_count=0)
```

`errors="replace"` 는 인코딩이 틀린 글자를 `?` 로 바꿔 넣는다. 예외를 올리는 대신
읽히는 만큼 읽는다 — 메모 한 줄 때문에 적재 전체가 멈추지 않게 하는 선택이다.

빈 줄(`\n\n`)로 자르는 것이 문단 단위에 가깝다.

```text
[1] 8자 : 출장 정산 안내
[2] 42자 : 9월부터 출장 정산은 그룹웨어에서만 접수합니다.
종이 서류는 받지 않습니다.
[3] 16자 : 문의: 인사총무팀 김지원 과장
블록 3개
```

### 마크다운에서는 제목도 블록이 된다

같은 함수에 `.md` 를 넣으면 이렇게 나온다.

```text
[1] 13자 : # 출장 신청 빠른 안내
[2] 8자 : ## 1. 신청
[3] 23자 : 출장 3일 전까지 그룹웨어에서 신청합니다.
[4] 8자 : ## 2. 승인
[5] 39자 : 팀장 승인 후 확정됩니다. 5일 초과 출장은 본부장 승인이 필요합니다.
블록 7개
```

`## 1. 신청` 이 8자짜리 블록 하나다. [[46_블록과_청크]]에서 본 그 문제다 —
제목만 있고 내용이 없는 조각이 검색 단위가 된다. 제목을 다음 문단에 붙여야 하는데
아직 안 했다.

## HTML 파서 — 표를 먼저 떼어낸다

태그를 한 번에 지우면 어떻게 되는지부터 봤다.

```python
flat = re.sub(r"\s+", " ", re.sub(r"<[^>]+>", " ", html)).strip()
```

```text
사내 공지 추석 연휴 근무 안내 연휴 기간 중 당직 근무자는 아래와 같습니다. 날짜 당직자 연락처 10/03 김민준 내선 2201 10/04 이서연 내선 2202
블록 1개
```

전부 한 줄이 된다. **표가 본문에 녹아 버려서** `날짜 당직자 연락처 10/03 김민준` 이
어디가 열 이름이고 어디가 값인지 알 수 없다. [[51_청킹_테스트와_형식_차이]]에서 PDF 가
겪은 것과 같은 일인데, 여기서는 막을 수 있다.

순서를 바꾼다. **표를 먼저 떼어내고 본문을 정리한다.**

```python
raw = re.sub('<(script|style)[^>]*>.*?</\\1>', ' ', raw, flags=re.S | re.I)
tables = re.findall('<table.*?</table>', raw, flags=re.S | re.I)   # 표를 모아 두고
body = re.sub('<table.*?</table>', ' ', raw, flags=re.S | re.I)    # 본문에서 뺀다
body = re.sub('\\s+', ' ', re.sub('<[^>]+>', ' ', body)).strip()
```

```text
[좋은 예] 블록 2 · 표 1 · 쪽 1 · 글자 89자
  [1] 조항  sample_page.html          43자  사내 공지 추석 연휴 근무 안내 연휴 기간 중 당직 근무자는 아래와 같습니다.
  [2] 표    sample_page.html · 표1     46자  날짜 당직자 연락처 10/03 김민준 내선 2201 10/04 이서연 내선 2202
```

블록이 둘로 갈렸다. `<script>` 와 `<style>` 을 먼저 지우는 것은 **그 안의 글자가 본문이 아니기**
때문이다. 자바스크립트 코드가 규정 문장처럼 검색되면 안 된다.

`<(script|style)[^>]*>.*?</\1>` 의 `\1` 이 앞에서 잡은 태그 이름을 다시 쓴다.
`<script>` 를 `</style>` 로 닫는 짝이 생기지 않게 한다.

## XLSX — 시트 하나가 표 하나

```python
def parse_xlsx(path: Path) -> ParsedDoc:
    from openpyxl import load_workbook

    wb = load_workbook(str(path), data_only=True)
    blocks: list[ParsedBlock] = []
    for ws in wb.worksheets:
        rows = [
            ["" if c is None else str(c) for c in row]
            for row in ws.iter_rows(values_only=True)
            if any(c is not None for c in row)
        ]
        if not rows:
            continue
        blocks.append(ParsedBlock("표", ws.title, _table_to_markdown(rows[0], rows[1:])))
    return ParsedDoc(blocks=blocks, page_count=len(wb.worksheets), table_count=len(blocks))
```

세 가지 판단이 들어 있다.

| | 왜 |
| --- | --- |
| `data_only=True` | 수식이 아니라 계산된 값을 가져온다. `=SUM(B2:B4)` 가 아니라 숫자가 필요하다 |
| 시트 이름을 `locator` 로 | 출처가 "출장비 집계" 가 된다. 파일명보다 어디서 왔는지가 분명하다 |
| `_table_to_markdown` 재사용 | [[40_표_추출과_마크다운]]에서 쓴 그 함수다. 형식이 늘어도 표의 모양은 하나다 |

```text
시트 목록 :  ['출장비 집계']
('부서', '1분기', '2분기', '3분기')
('인프라사업부 2팀', 4200000, 3800000, 5100000)
```

```text
블록 1 · 표 1 · 쪽 1 · 글자 161자
  kind    : 표
  locator : 출장비 집계
| 부서 | 1분기 | 2분기 | 3분기 |
|---|---|---|---|
| 인프라사업부 2팀 | 4200000 | 3800000 | 5100000 |
```

첫 행을 머리행으로 쓴다. 엑셀에 머리행이라는 개념이 따로 없으니 **첫 행이 머리행이라고
정한 것**이고, 그렇지 않은 시트에서는 어긋난다.

## 짚어둘 것

### `parse_xlsx` 가 아직 연결되지 않았다

함수는 있는데 `HANDLERS` 에 등록이 안 됐다.

```python
HANDLERS = {'.docx': parse_docx, '.pdf': parse_pdf, '.hwpx': parse_hwpx}
```

그래서 직접 부르면 되지만 진입점을 거치면 막힌다.

```text
parse_xlsx 를 직접 부르면  : 블록 1 · 표 1 · 쪽 1
parser.parse() 를 거치면   : ValidationFailed: 지원하지 않는 형식입니다: .xlsx
```

`.pptx` 는 함수 자체가 아직 없다. 둘 다 다음에 잇는다.

### 표 블록을 `ParsedBlock` 으로 감싸지 않으면 바로 터진다

`_parse_html` 이 본문은 `ParsedBlock` 으로 만들고 표는 튜플로 넣고 있었다.

```python
blocks = [ParsedBlock("조항", p.name, body)] if body else []
blocks.append(('표', f'{p.name} · 표{i}', cleaned))   # ← 튜플
```

노트북에서 블록 수와 글자 수만 찍어 보면 멀쩡해 보인다. 튜플도 `len()` 이 되고
인덱스로 꺼낼 수 있기 때문이다. 그런데 `.kind` 를 보는 쪽에서 무너진다.

```text
AttributeError: 'tuple' object has no attribute 'kind'
```

`chunk()` 가 블록마다 `block.kind == "표"` 를 보므로([[50_청킹_규칙]]) 청킹에서 바로 터진다.
감싸고 나면 지나간다.

```text
블록 2 · 표 1 · 타입 ['ParsedBlock']
chunk() → 조항 단위 1 + 표 단위 1 = 2 청크
```

노트북 실습 코드는 튜플로 둬도 돌아가는데 실제 코드는 아니라는 점이 이 버그의 성격이다.

### `<title>` 이 본문에 들어온다

```text
[1] 조항  sample_page.html  43자  사내 공지 추석 연휴 근무 안내 …
```

"사내 공지" 는 `<title>` 의 내용이고 페이지 본문이 아니다. `<script>`·`<style>` 과 같이
지워야 할 것인데 아직 안 걸러진다. 코드에 TODO 로 적어 뒀다.
