# 스캔본과 상용 파서

[[52_파서_진입점과_형식_확장]]에서 형식을 다섯까지 늘렸다. 그래도 못 읽는 파일이 하나 남는다.
`_formats` 안의 `sample_scanned.pdf` 다.

## 두 가지 다른 실패

같은 PDF 두 개를 넣어 봤다.

```text
sample_scanned.pdf
 ValidationFailed : 문서에서 글자를 찾지 못했습니다: sample_scanned.pdf
 detail : 스캔본(이미지)일 수 있습니다. …

DOC-HR-014_국내출장_여비_규정_v2.0.pdf
블록 16, 표 0, 페이지 16
```

둘 다 아쉬운 결과인데 **아쉬운 지점이 다르다.** 스캔본은 글자가 0이고,
일반 PDF 는 글자는 16쪽 다 읽혔는데 표가 0이다.

라이브러리 둘로 재 보면 갈린다.

```text
scanned!
 pypdf 페이지 1, 글자 0
 plumber 페이지 1, 글자 0, 표 0

normal!
 pypdf  페이지 16, 표 0
 plumber  페이지 16, 표 7
```

| | 글자 | 표 | 무엇이 필요한가 |
| --- | --- | --- | --- |
| 일반 PDF · pypdf | 있다 | 0 | 표를 보는 라이브러리 |
| 일반 PDF · pdfplumber | 있다 | **7** | 해결됨 |
| 스캔본 · pypdf | 0 | 0 | — |
| 스캔본 · pdfplumber | **0** | 0 | 글자 자체가 없다 |

**`pdfplumber` 가 일반 PDF 의 표 7개를 찾는다.** [[51_청킹_테스트와_형식_차이]]에서
"PDF 표를 살리려면 파서를 고쳐야 한다"고 적었는데, 그 고치는 방법이 이것이다.
[[40_표_추출과_마크다운]]에서 이미 써 본 도구다.

스캔본은 다르다. `pdfplumber` 도 0자다. 페이지 안에 글자가 글자로 들어 있지 않고 그림으로
들어 있어서, 어떤 텍스트 추출기를 써도 꺼낼 것이 없다. 여기서 필요한 것은
다른 라이브러리가 아니라 OCR 이다.

## 상용 파서가 하는 일

Upstage Document Parser 는 문서를 통째로 넣으면 요소(Element) 목록으로 쪼개 돌려준다.

| 돌려주는 것 | 무엇 |
| --- | --- |
| `elements[]` | 조각 하나하나 |
| `elements[i].category` | 그 조각이 무엇인지 — `table` · `paragraph` · `heading` · `header` · `footer` · `figure` · `chart` · `list` · `index` |
| `elements[i].page` | 몇 쪽에서 나왔는지 |
| `elements[i].content` | `text` · `html` · `markdown` 세 모양으로 |

`category` 가 우리가 손으로 하고 있는 일을 대신한다. `parse_docx` 가 `p` 와 `tbl` 을
구별해 `kind` 를 붙이고([[39_문서_파싱]]), `_parse_html` 이 `<table>` 을 먼저 떼어내고,
`chunker` 가 정규식으로 조 제목을 찾는 그 판단들이다.

`header` 와 `footer` 를 따로 알려 주는 것도 눈에 띈다. [[52_파서_진입점과_형식_확장]]에서
`<title>` 이 본문에 섞여 들어온 문제를 우리는 아직 못 걸렀다.

`content` 를 세 모양으로 주는 것은 받는 쪽이 고를 수 있게 한다는 뜻이다.
우리는 표를 마크다운으로 정했는데([[40_표_추출과_마크다운]]) 같은 선택지를 준다.

OCR 은 요청할 때 `auto` 나 `force` 로 지정한다. 스캔본이 트리거다.

## 쓸지 말지는 형식마다 다르다

[[52_파서_진입점과_형식_확장]]의 분기에서 상용 API 는 `_LOCAL_ONLY` 보다 뒤에 있다.

```python
if use_upstage and ext not in _LOCAL_ONLY:
    from app.integrations.upstage import UpstageParser
    return UpstageParser().parse(str(p))
return parse_local(p)
```

한글 문서는 스위치를 켜도 안 나간다. [[42_임베딩_모델_받기]]에서 임베딩을 로컬로 정한 것과
같은 판단이고, 거기서 적었듯 **기술 선택이 아니라 보안 결정**이다.

그래서 셋으로 갈린다.

| | 어떻게 | 왜 |
| --- | --- | --- |
| `.hwpx` · `.hwp` | 로컬만 | 사내 규정이 대외비를 품고 있다 |
| 글자가 있는 PDF · DOCX | 로컬로 충분 | `pdfplumber` 를 넣으면 표까지 산다 |
| 스캔본 | 상용 API | OCR 을 직접 만들 수 없다 |

세 번째 줄만 남는다는 것이 결론이다. 상용 파서를 **전부에 쓰는 것이 아니라
로컬로 안 되는 것에만** 쓴다.

## 어댑터 — `backend/app/integrations/upstage.py`

[[23_포트와_어댑터]]의 모양을 그대로 쓴다. 바깥 서비스를 부르는 코드는 한 파일에 모은다.

```python
class UpstageParser:
    name = "upstage"

    def parse(self, path: str) -> ParsedDoc:
        p = Path(path)
        if not p.exists():
            raise ExternalServiceError(f"파일을 찾을 수 없습니다. : {path}")
        return _to_doc(p, _post(p))
```

로컬 파서와 **같은 `ParsedDoc` 을 돌려주는 것**이 전부다. 부르는 쪽은 어느 파서가 읽었는지
몰라도 된다([[52_파서_진입점과_형식_확장]]의 진입점이 그래서 가능하다).

### 상태 코드마다 할 일을 적어 둔다

```python
_HINT = {
    401: "API 키가 잘못되었거나, 차단된 키 입니다. …",
    403: "크래딧이 부족합니다. …",
    413: "파일이 너무 큽니다. 동기 요청에는 페이지 수/용량 상한이 있습니다.",
    415: "지원하지 않는 파일 형식입니다.",
    422: "파일이 손상되었거나 열 수 없습니다.",
    429: "요청이 너무 잦습니다. 잠시 후 다시 시도하세요.",
}
```

401 과 403 이 다른 안내인 것이 요점이다. 키가 틀린 것과 크레딧이 없는 것은
할 일이 다르다. [[44_파일_형식_분기와_차단]]에서 `.hwp` 에 저장 방법을 적어 둔 것과 같다.

### 카테고리를 셋으로 가른다

```python
_TEXT = {"paragraph", "heading1", "heading2", "heading3",
         "list", "index", "caption", "equation", "code", "footnote"}
_SKIP = {"header", "footer", "figure"}
```

| | 어떻게 |
| --- | --- |
| `table` · `chart` | `표` 블록. `표N · p.2` 로 locator |
| `_TEXT` | `조항` 블록. `p.1` 로 locator |
| `_SKIP` | 버린다 |

`header` 와 `footer` 를 버리는 것이 [[52_파서_진입점과_형식_확장]]에서 못 걸렀던
`<title>` 문제의 해답이다. 상용 파서는 그게 머리말인지 본문인지를 알려 준다.

가짜 응답을 만들어 넣어 봤다. 요소 6개 중 셋만 남는다.

```text
_to_doc (가짜 응답) : 블록 3 · 표 1 · 쪽 2
   조항 | p.1       | '# 제1조(목적)'
   조항 | p.1       | '이 규정은 여비를 정한다.'
   표   | 표1 · p.2 | '| 직급 | 일비 |…'
chunk() → 조항 단위 1 + 표 단위 1 = 2 청크
```

`header`·`footer`·`figure` 가 빠지고, 남은 것이 청킹까지 그대로 지나간다.

### `markdown` 만 받는다

```python
data={
    "model": settings.upstage_parse_model,
    "ocr": settings.upstage_parse_ocr,
    "output_formats": "['markdown']",
    "coordinates": "false",
}
```

세 모양 중 `markdown` 을 고른 이유는 표를 이미 마크다운으로 정해 뒀기 때문이다
([[40_표_추출과_마크다운]]). `coordinates=false` 는 좌표를 안 받는다는 뜻이다 —
화면에 원문을 겹쳐 보여줄 계획이 없으니 받을 이유가 없다.

`TIMEOUT = 180.0` 이 다른 호출보다 훨씬 길다. 문서 전체를 넘기고 OCR 까지 돌 수 있어서
LLM 한 번 부르는 것과는 시간 단위가 다르다.

## 키가 없어도 수업이 돌아가게

| | 키가 있다 | 키가 없다 |
| --- | --- | --- |
| 발급 | 콘솔에서 각자 | 아무것도 안 함 |
| 부르기 | `UpstageParser().parse(path)` | `UPSTAGE_TABLES` 상수 |
| 받는 것 | `ParsedDoc` | `ParsedDoc` |

받는 모양이 같으니 **뒤쪽 코드는 어느 길로 왔는지 모른다.** 포트와 어댑터를 쓰는 이유가
여기서 한 번 더 나온다 — 키가 없는 사람도 다음 진도를 따라갈 수 있다.

설정은 넷을 더했다.

```python
upstage_api_key: SecretStr | None = None
upstage_base_url: str = "https://api.upstage.ai/v1"
upstage_parse_model: str = "document-parse"
upstage_parse_ocr: str = "auto"
```

`SecretStr` 이라 로그나 화면에 찍으면 `**********` 로 나온다([[22_AI_Native_애플리케이션]]).
기본값을 `None` 으로 둔 것이 "키 없이도 돈다"는 쪽 설계다.

## 키 받기와 두는 자리

콘솔에서 가입하고 인증하면 크레딧 $10 을 받는다. 그걸로 API Key 를 발급한다.

```text
UPSTAGE_API_KEY=발급 받은 키값
```

`.env` 에만 넣는다. 저장소에는 키 이름만 남고 값은 안 남는다([[01_개발환경설정]]).

### 쓰지 않을 때는 주석으로 내린다

```text
UPSTAGE_API_KEY=
#UPSTAGE_API_KEY=up...
```

빈 값을 살려 두고 실제 키를 주석으로 내려 둔다. 왜 지우지 않는가 —
`upstage_api_key` 의 기본값이 `None` 이라 비어 있으면 `_headers()` 가 예외를 올리고 거기서 멈춘다.

```python
key = get_settings().upstage_api_key
if key is None:
    raise ExternalServiceError("UPSTAGE_API_KEY가 비어있습니다.")
```

쓸 때만 두 줄의 `#` 을 바꿔 끼운다. 키를 지웠다가 다시 발급받는 것보다 싸고,
크레딧이 $10 뿐이라 실수로 호출이 나가는 쪽이 더 아프다.

`APP_MODE=mock` 으로 두는 것과 같은 성격의 안전장치다([[23_포트와_어댑터]]).
**기본 상태가 아무것도 밖으로 안 나가는 쪽**이어야 한다.

## 짚어둘 것

### 괄호 하나가 401 로 돌아온다

```python
return {"Authorization": f"Bearer {key.get_secret_value}"}   # ← () 가 없다
```

`get_secret_value` 는 메서드다. 괄호를 빼면 메서드 객체가 그대로 문자열이 된다.

```text
Bearer <bound method _SecretBase.get_secret_value of SecretStr('**********')>
```

키가 전혀 안 실려서 **401 이 돌아온다.** `_HINT[401]` 이 "키가 잘못되었거나 차단된 키"라고
안내하니, 콘솔에서 키를 다시 발급받는 쪽으로 한참 헤맬 수 있는 증상이다.

호출 한 번마다 돈이 드는 자리라([[24_API_토큰과_과금]]) 네트워크를 타기 전에
헤더 모양만 찍어 보는 것이 싸다.

### 예외를 `return` 하면 값이 된다

```python
if not p.exists():
    return ExternalServiceError(f"파일을 찾을 수 없습니다. : {path}")
```

`raise` 가 아니라 `return` 이라 **예외 객체가 `ParsedDoc` 자리에 돌아간다.**
그 자리에서는 아무 일도 안 일어나고, 부르는 쪽에서 무너진다.

```text
AttributeError: 'ExternalServiceError' object has no attribute 'blocks'
```

[[52_파서_진입점과_형식_확장]]의 튜플 버그와 같은 종류다. 타입이 다른 것을 같은 자리에
넣어 두면 터지는 곳이 넣은 곳이 아니다.

### 키와 비용이 따라온다

로컬 파서는 전기값만 든다. 상용 API 는 문서 수에 비례해 돈이 나가고 키 관리가 붙는다
([[22_AI_Native_애플리케이션]]의 `.env` 규칙, [[32_사용량과_원가_기록]]의 기록).

임베딩 때와 같은 구조인데 한 가지가 다르다. 임베딩은 문서를 올릴 때 한 번씩 돌지만
파싱도 올릴 때 한 번이다. 둘 다 질문당 비용이 아니라 적재당 비용이라,
문서를 다시 적재할 때마다 다시 든다.

### 스캔본 안내 문구가 이미 그걸 가리킨다

```text
detail : 스캔본(이미지)일 수 있습니다. .env 의 UPSTAGE_PARSE_OCR 를 force 로 두고
         실동작 모드로 다시 적재해 보세요
```

[[44_파일_형식_분기와_차단]]에서 `.hwp` 에 "한글에서 열고 hwpx 로 저장하세요"를 붙인 것과
같은 자리다. 막을 때 이유만 말하지 않고 다음에 할 일을 적어 둔다.
