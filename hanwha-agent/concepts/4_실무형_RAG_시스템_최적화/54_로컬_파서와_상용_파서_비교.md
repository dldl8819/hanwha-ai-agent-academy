# 로컬 파서와 상용 파서 비교

[[52_파서_진입점과_형식_확장]]과 [[53_스캔본과_상용_파서]]에서 적어 둔 숙제 넷이 끝났다.
이제 로컬 파서가 어디까지 하고 상용 API 가 무엇을 더 하는지를 재 본다.

## 숙제 넷을 눌러 봤다

### 마크다운 제목이 출처가 됐다

```text
블록 3 -> 조항 단위 1 + 표 단위 0 = 1 청크
 [1. 신청] 출장 3일 전까지 그룹웨어에서 신청합니다.
 [2. 승인] 팀장 승인 후 확정됩니다. 5일 초과 출장은 본부장 승인이 필요합니다.
 [3. 정산] 복귀 후 7일 이내에 영수증을 첨부해 정산합니다.
```

7블록이던 것이 3블록이고, 8자짜리 제목 조각이 없다.

### `<title>` 이 본문에서 빠졌다

```text
사내 공지
추석 연휴 근무 안내 연휴 기간 중
False
```

마지막 `False` 가 `body.startswith(title)` 다. 본문이 "사내 공지"로 시작하지 않는다는 뜻이다.
`<head>` 를 통째로 지운 결과다.

### 엑셀 병합 셀이 채워졌다

```text
| 인프라사업부 | 4200000 | 3800000 |
| 인프라사업부 | 1200000 | 1400000 |
| 구매팀 | 900000 | 1000000 |
```

### 슬라이드 표와 차트가 나왔다

```text
--- [조항] 슬라이드 1
출장비 집행 현황
--- [표] 슬라이드 1 · 표1
| 부서 | 1분기 | 2분기 |
```

그룹으로 묶은 슬라이드도 확인했다.

```text
맨 바깥 도형     : ['GroupShape']
블록 2 · 표 1
```

도형이 겉으로는 `GroupShape` 하나인데 안의 글자와 표가 둘 다 나왔다 — `_walk_shapes` 가
한 겹 들어간 결과다.

차트는 표로 바뀐다.

```text
--- [표] 슬라이드 1 · 차트1
분기별 집행액

| 항목 | 출장비 | 교육비 |
|---|---|---|
| 1분기 | 4200000 | 1200000 |
```

## 숙제에 없던 것 셋

### cp949 로 저장된 txt

```text
���� ���� �ȳ�        ← utf-8 로 읽으면 이렇게 나온다
------------------------------------------------------------------------
INFO  app.rag.parser 인코딩을 cp949 로 읽었습니다: memo_cp949.txt
['출장 정산 안내', '9월부터 출장 정산은 그룹웨어에서만 접수합니다.\n종이 서류는 받지 않습니다.', …]
```

`_read_text` 가 `utf-8-sig` 로 실패한 뒤 `cp949` 로 다시 읽는다. 어느 인코딩으로 읽혔는지를
로그에 남기는 것이 요점이다 — 글자가 깨져 보일 때 먼저 볼 자리다.

### 계산값이 없는 수식

```text
data_only 로 읽은 B5 : None
| 합계 | =SUM(B2:B3) (계산값 없음) |
```

`data_only=True` 는 엑셀이 저장할 때 계산해 둔 값을 준다. 파이썬으로 만든 파일에는 그 값이
없어서 `None` 이 온다. **빈칸으로 두면 "값이 없는 것"과 "계산이 안 된 것"을 구별할 수 없다.**
수식 문자열을 그대로 적고 꼬리를 붙여 둔다.

### 두 줄 머리행과 제목행

```text
2026 출장 · 교육비 집계

| 구분 | 1분기 출장비 | 1분기 교육비 | 2분기 출장비 | 2분기 교육비 |
|---|---|---|---|---|
| 인프라사업부 | 4200000 | 1200000 | 3800000 | 1400000 |
```

`A1:E1` 로 병합한 제목은 표 위로 올리고, `1분기`/`2분기` 와 `출장비`/`교육비` 두 줄은
`1분기 출장비` 로 합친다. 머리행이 한 줄이어야 마크다운 표가 된다.

한 시트에 표가 둘이면 빈 줄을 경계로 쪼갠다.

```text
블록 2 · 쪽 1 · 표 2
--- [표] 요약 · 표1
--- [표] 요약 · 표2
```

## PDF 가 DOCX 와 같아졌다

[[51_청킹_테스트와_형식_차이]]에서 "HWPX·DOCX 는 같고 PDF 만 다르다"고 적었다. 그게 뒤집혔다.

```text
parse_pdf         블록 16 · 쪽 16 · 표 0  →  조항 단위 45 + 표 단위 0 = 45 청크
parse_pdf_tables  블록 23 · 쪽 16 · 표 7  →  조항 단위 46 + 표 단위 7 = 53 청크
(같은 규정 .docx)  블록 233 · 쪽 1 · 표 7  →  조항 단위 46 + 표 단위 7 = 53 청크
```

**`parse_pdf_tables` 를 쓰면 PDF 가 DOCX 와 똑같은 53청크를 낸다.** 블록 수는 23 대 233 으로
전혀 다른데 청크는 같다 — 청킹이 조 단위로 다시 묶기 때문이다([[50_청킹_규칙]]).

표가 본문에 두 번 실리지 않는 것도 확인했다.

```text
p.11 · 표1
| 직급 | 일비 | 숙박비(광역시) | 숙박비(그 밖의 지역) | 식비 |
|---|---|---|---|---|
| 1~2급 | 40,000 | 100,000 | 80,000 | 30,000 |

「100,000」 이 표에    : True
「100,000」 이 본문에도 : False
```

`page.filter(outside)` 가 표 상자 안의 글자를 본문에서 걸러낸 결과다. 이게 없으면
같은 숫자가 조항 블록과 표 블록에 두 벌 들어가 검색 결과가 중복된다.

## 스캔본만 남는다

```text
쪽 수             : 3
쪽마다 든 그림     : [1, 1, 1]
pypdf 글자        : 0
pdfplumber 글자   : 0 · 표 0
parse_local       막힘 — 문서에서 글자를 찾지 못했습니다
```

쪽마다 그림이 하나씩이고 글자는 0이다. **글자가 글자로 들어 있지 않으니 추출기를 바꿔도
꺼낼 것이 없다.** 여기서만 OCR 이 필요하다.

### OCR 결과

```text
INFO  app.integrations.upstage 상용 파싱 완료: …_스캔본.pdf, 블록 25, 표 1
OCR  블록 25 · 쪽 3 · 표 1 · 글자 1530
별표1 값 중 OCR 에 나온 것 : 10 / 10
설정은 원래대로 : ocr = auto
```

0자였던 문서에서 1,530자가 나왔다. 별표1 의 금액 10개를 미리 적어 두고 대조했더니
**10개 전부** 나왔다([[29_골든셋_회귀테스트]]처럼 기대값을 먼저 고정하고 재는 방식이다).

설정을 되돌리는 `try/finally` 도 눈에 둘 만하다.

```python
before = settings.upstage_parse_ocr
settings.upstage_parse_ocr = "force"
try:
    ocr_doc = UpstageParser().parse(str(SCAN))
finally:
    settings.upstage_parse_ocr = before
```

`force` 는 OCR 을 반드시 돌린다는 뜻이고 값이 비싸다. 셀 하나를 위해 바꾼 설정이
뒤 셀까지 따라가면 모르는 사이에 계속 OCR 을 돌린다.

## 어디까지 로컬로 하는가

| | 로컬 파서 | 상용 API |
| --- | --- | --- |
| 스캔본 PDF | 글자 0 · 표 0 — 막는다 | **OCR 로 읽는다** |
| PDF 표 | pypdf 0개 · **pdfplumber 7개** | 읽는다 |
| DOCX·HWPX 표 | **읽는다** | 읽는다 |
| `.hwpx` | **읽는다** | 보내지 않는다 |
| PPTX 표·차트 | **읽는다** | — |
| XLSX | **읽는다** | — |
| 비용 | 0원 | 쪽당 $0.01 (Enhanced $0.03) |
| 한도 | 없다 | 계정 등급에 달림 |
| 라이선스 | pypdf · pdfplumber · python-docx · openpyxl · python-pptx 모두 MIT | 과금 약관 |
| 네트워크 | 오프라인 가능 | 오프라인 불가 |

**상용 API 가 더 하는 일은 사실상 OCR 하나다.** 표도 한글 문서도 로컬로 된다.

비용을 재 보면 규모가 보인다. 16쪽 규정 하나와 1쪽 스캔본이면 17쪽 × $0.01 = $0.17,
약 240원이고 $10 크레딧의 1.7% 다. Enhanced 로 올리면 세 배다.

적재당 비용이라는 점이 중요하다([[53_스캔본과_상용_파서]]). 질문할 때 드는 돈이 아니라
문서를 올릴 때 드는 돈이고, 다시 적재하면 다시 든다.

## 짚어둘 것

### 키는 기본으로 꺼 둔다

```text
UPSTAGE_API_KEY=
#UPSTAGE_API_KEY=up...
```

빈 값을 살려 두고 실제 키를 주석으로 내린다. 노트북도 그 전제로 쓴다.

```python
HAS_KEY = bool(settings.upstage_api_key)
if HAS_KEY:
    ...
else:
    print("키가 없습니다 — 이 셀은 부르지 않고 지나갑니다(비용 0)")
```

키가 없으면 셀이 그냥 지나간다. **키 없는 사람도 노트북을 끝까지 돌릴 수 있어야** 한다.

### `PDF_TABLES` 는 꺼 두었다

```text
PDF_TABLES=false
```

`pdfplumber` 가 `pypdf` 보다 느리다. 표가 필요한 문서에만 켠다. 기본을 켜 두면
표가 없는 문서에서도 매번 표를 찾느라 시간을 쓴다.
