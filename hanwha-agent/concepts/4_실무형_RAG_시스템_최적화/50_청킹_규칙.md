# 청킹 규칙

[[46_블록과_청크]]에서 블록과 청크가 다르다는 것까지 봤다. 이제 어디서 자를지를 정한다.
[[33_RAG_개요]] ③ Chunking 이다.

## 글자 수로 자르면 표가 갈린다

여비 규정 `v2.0` 을 통째로 이어 붙이고 1,200자마다 끊어 봤다.

```python
joined = '\n'.join((b.text for b in doc.blocks))
naive = [joined[i:i + 1200] for i in range(0, len(joined), 1200)]
```

```text
8,505자 → 8 청크
  표1: 원문 위치  115~ 406 → 청크 #0~#0
  표2: 원문 위치 6370~6612 → 청크 #5~#5
  표3: 원문 위치 6701~6911 → 청크 #5~#5
  표4: 원문 위치 7035~7413 → 청크 #5~#6  두 조각으로 갈린다
  표5: 원문 위치 7475~7799 → 청크 #6~#6
  표6: 원문 위치 7833~8135 → 청크 #6~#6
  표7: 원문 위치 8191~8487 → 청크 #6~#7  두 조각으로 갈린다
```

일곱 개 중 둘이 갈렸다. 갈린 자리를 펴 보면 왜 문제인지가 보인다.

```text
── 앞 조각 끝부분 ──
| 교통수단 | 등급 | 지급 기준 | 승인 | 비고 |
|---|---|---|---|---|
| 철도(KTX·SRT) | 일반실 | 실비 | 팀장 | 3급 이상은 특실 가능 |
| 일반철도(무궁화·새마을) | 일반실 | 실비 | 팀장 |  |
| 고속·시외버스 | 우등 이하 | 실비 | 팀장

── 뒤 조각 앞부분 ──
 |  |
| 국내선 항공 | 일반석 | 실비 | 본부장 | 제19조 요건 충족 시 |
| 선박 | 2등실 이상 | 실비 | 팀장 | 도서 지역 출장 |
...
```

```text
앞 조각에 머리행이 있나 : True
뒤 조각에 머리행이 있나 : False
```

**뒤 조각에는 열 이름이 없다.** `| 국내선 항공 | 일반석 | 실비 | 본부장 |` 만 검색되면
이 숫자들이 무엇을 뜻하는지 알 수 없다. 표는 머리행과 본문이 같이 있어야 뜻이 산다
([[40_표_추출과_마크다운]]).

## 스플리터를 써도 마찬가지다

`RecursiveCharacterTextSplitter` 는 문단·줄 경계를 찾아 자른다. 넣어 봤다.

```python
splitter = RecursiveCharacterTextSplitter(chunk_size=1200, chunk_overlap=0)
pieces = splitter.split_text(joined)
```

```text
8,505자 → 8 청크
  표1: 한 조각에 통째로
  표2: 한 조각에 통째로
  표3: 한 조각에 통째로
  표4: ★ 두 조각으로 갈린다
  표5: 한 조각에 통째로
  표6: 한 조각에 통째로
  표7: ★ 두 조각으로 갈린다
```

같은 둘이 갈린다. 이 도구는 **줄 경계는 알아도 표라는 것은 모른다.** 한도를 넘으면 줄 사이 어디든 끊는다.
문서 구조를 아는 쪽이 먼저 갈라 주어야 한다.

## 규칙 1 — 표는 자르지 않는다

표 하나가 청크 하나다. 길이를 따지지 않는다. 한도를 넘기면 어쩌나 싶어 재 봤다.

```text
표1  291자 · 표2  242자 · 표3  210자 · 표4  378자
표5  324자 · 표6  302자 · 표7  296자

가장 긴 표 = 378자 · LIMIT 을 넘는 표 = 0개
```

규칙을 지키는 비용이 0이다. 가장 긴 표가 378자로 한도의 3분의 1이라, 표를 통째로 두어도
청크가 커지지 않는다. 다른 문서에서 1,200자를 넘는 표가 나오면 그때 다시 본다.

## 규칙 2 — 조는 통째로 묶는다

`제14조(숙박비)` 제목부터 다음 조 직전까지가 한 청크다. [[46_블록과_청크]]에서
답은 맞는데 어느 조인지 모르던 문제가 여기서 풀린다.

### 정규식은 캡처 그룹으로 쓴다

`re.split` 은 패턴을 괄호로 감쌌는지에 따라 결과가 다르다. 셋을 나란히 돌려 봤다.

```python
text = '제1조(목적) 이 규정은 여비를 정한다. 제8조(일비) 일비는 30,000원으로 한다.'
```

```text
캡처 그룹 ()      ← 우리가 쓸 형태
['', '제1조(목적)', ' 이 규정은 여비를 정한다. ', '제8조(일비)', ' 일비는 30,000원으로 한다.']
  parts[0] = 머리 · parts[1],[3],… = 조 제목 · parts[2],[4],… = 본문   (홀짝 규칙)

비캡처 (?:)      ← 조 제목이 통째로 사라진다
['', ' 이 규정은 여비를 정한다. ', ' 일비는 30,000원으로 한다.']

안쪽까지 캡처     ← 그룹이 셋이라 홀짝 규칙이 깨진다
['', '제1조(목적)', None, '(목적)', ' 이 규정은 여비를 정한다. ', '제8조(일비)', None, '(일비)', ...]
```

바깥 괄호 하나만 씌운다. 안 씌우면 **조 제목이 결과에서 사라져** 출처를 못 적고,
안쪽까지 씌우면 그룹이 늘어 홀짝으로 짝짓는 규칙이 깨진다.

```python
_ARTICLE = re.compile(r"(제\s*\d+\s*조(?:의\s*\d+)?\s*(?:\([^)]{1,30}\))?)")
```

`(?:...)` 는 "묶기만 하고 결과에는 안 넣기"다. `제12조의2` 같은 형태와 괄호 제목을
선택적으로 받으면서도 그룹은 하나로 유지한다.

### 기준값 셋

```python
MAX_CHARS = 1200    # 청크 하나의 최대 길이
MIN_CHARS = 30      # 첫 조 앞 머리말이 이보다 짧으면 버린다
TOC_BODY_MIN = 10   # 조 제목 뒤 본문이 이보다 짧으면 목차 줄로 본다
```

`TOC_BODY_MIN` 이 왜 필요한지는 돌려 보면 나온다.

```text
조각 101개
  ('', '일반\n국내출장 여비 규정\nv2.0\n문서번호  DOC-H …')
  ('제9조', '제9조 에 따라 관리한다.\n목차\n제1장 총칙')
  ('제1조(목적)', '제1조(목적)')
  ('제2조(정의)', '제2조(정의)')
  ('제3조(적용 범위)', '제3조(적용 범위)')
```

`('제1조(목적)', '제1조(목적)')` 는 본문이 없다. 목차에 적힌 줄이다.
문서 앞쪽 목차가 조 제목과 똑같이 생겨서 규정 본문처럼 잡힌다. 세어 보니 28개였다.

### 긴 조는 다시 자른다

조 하나가 1,200자를 넘으면 그때 스플리터에 맡긴다.

```python
splitter = RecursiveCharacterTextSplitter(
    chunk_size=limit,
    chunk_overlap=0,
    separators=["\n\n", "\n", "다. ", ". ", " ", ""],
    keep_separator="end",
)
```

| 인자 | 값 | 왜 |
| --- | --- | --- |
| `chunk_overlap` | 0 | 한 조 안이라 앞뒤를 겹쳐 붙일 이유가 없다 |
| `separators` | 문단 → 줄 → `"다. "` → `". "` → 공백 → 글자 | 앞에서부터 시도하고 그래도 크면 다음으로 넘어간다 |
| `keep_separator` | `"end"` | 끊은 자리의 `"다. "` 를 앞 조각 끝에 남겨 문장이 온전히 끝나게 한다 |

`"다. "` 가 구분자 목록에 있는 것이 한국어에 맞춘 부분이다. 규정 문장이 `~한다.` 로 끝나므로
문장 경계가 거기서 잡힌다.

```text
합성 예제 1,448자 → 2조각
  [0] 1183자
  [1]  263자

실문서에서 1,200자를 넘는 조항 : 0개
```

지금 문서에는 한 건도 없다. 쓰일 일이 없는 폴백을 먼저 만들어 둔 셈인데,
다른 규정에서는 걸릴 수 있고 없으면 그때 청크가 한도를 넘어 버린다.

## 조립

`chunker.chunk()` 가 이 규칙들을 순서대로 적용한다.

```python
for block in doc.blocks:
    if block.kind == "표":
        flush()                    # 앞에 쌓인 본문을 먼저 청크로 만들고
        out.append(ChunkDraft("표", block.locator, block.text))
        continue
    buffer.append(block.text)      # 본문은 모아 뒀다가 조 단위로 자른다
flush()
```

본문 블록을 `buffer` 에 모으는 이유는 **조 하나가 여러 블록에 걸칠 수 있어서**다.
파서는 문단마다 블록을 만들지만 조는 문단 여럿으로 이뤄진다([[46_블록과_청크]]).

표를 만나면 `flush()` 를 먼저 부르는 것이 순서를 지키는 부분이다. 안 그러면
표가 앞서 나오고 본문이 뒤로 밀린다.

## 조 단위 조정 — 세 가지를 더 막는다

규칙만으로는 덜 걸러진다. 실제로 돌려 보고 세 군데를 손봤다.

| | 규칙 | 어떻게 |
| --- | --- | --- |
| 조 제목 | 줄 맨 앞에 오고 괄호 제목까지 있어야 조 제목이다 | `^[ \t]*` + `re.M`, 괄호를 필수로 |
| 장·절·부칙 | 줄 전체가 제목인 줄은 본문에서 빼고, 뒤따르는 조들의 locator 앞에 붙인다 | `_HEADING` 추가 |
| 별표·서식 | `[별표2]` 부터는 장 밖이다. 뒤따르는 글의 locator 를 별표 이름으로 | `_ANNEX_HEAD` 추가 |

### 괄호 제목을 필수로 만든다

앞에서 상호참조 27건이 조 제목으로 잡혔다. 괄호 제목을 선택(`?`)이 아니라 필수로 바꾸면
`제32조 에 따라 반환한다` 는 안 걸린다.

```python
_ARTICLE = re.compile(r"^[ \t]*(제\s*\d+\s*조(?:의\s*\d+)?\s*\([^)\n]{1,30}\))", re.M)
```

조각이 101개에서 74개로 줄었다. `^[ \t]*` 가 들여쓰기를 허용하면서 줄머리만 보게 한다.

### 장·절은 본문에서 빼고 locator 로 올린다

```python
_HEADING = re.compile(r"^[ \t]*(?:(제\s*\d+\s*장)|(제\s*\d+\s*절)|(부\s*칙))(?:[ \t]+[^\n]{1,30})?[ \t]*$")
```

끝을 `$` 로 막는 것이 요점이다. 줄 전체가 제목인 줄만 잡으므로
`④ … 제4장의 특례를 적용한다` 같은 문장은 걸리지 않는다.

제목 줄을 만나면 거기서 본문을 끊고 현재 위치를 갱신한다.

```text
at=''                '일반 / 국내출장 여비 규정 / v2.0 / 문서번호  DOC-HR-014 …'
at='제1장'             '제1조(목적) / 제2조(정의) / 제3조(적용 범위) …'
at='제3장 제1절'         '제11조(일비) / 제12조(식비) / 제13조(식사 제공 시 감액)'
```

**장이 바뀌면 절을 비운다.** 안 그러면 앞 장의 절이 다음 장에 따라붙는다.
부칙은 장 자리에 넣어 본문 장 번호와 섞이지 않게 한다.

위치 정보(`where`)는 `chunk()` 가 하나 만들어 `flush()` 사이에 돌려 쓴다.
표를 만날 때마다 `flush()` 가 도는데, 그때마다 위치가 초기화되면 표 뒤의 조들이 장을 잃는다.

### 별표·서식은 장 밖이다

```python
_ANNEX_HEAD = re.compile(r"^[ \t]*\[(별표\s*\d+|별지[^\]]{0,20})\]")
```

`[별표2]` 를 만나면 장·절을 버리고 별표 이름만 위치로 쓴다. 장 제목 줄과 달리
**이 줄은 본문에 남긴다** — 별표의 시작이라 내용의 일부다.

locator 가 `제1장 제2조(정의) · 별표2` 까지 나온다. 장, 조, 그 조가 가리키는 별표가

```text

③ 「제N장」 으로 시작하는 locator  : 35개 / 조항 46개

   부칙 제1조(시행일) · 부칙 제2조(경과조치) · 부칙 제3조(다른 규정의 폐지)
   별표1 · 별표2 · 별표3 · 별지 제1호 서식 · 별지 제2호 서식
```

조항 46개 중 35개가 장을 갖고, 남은 11개는 장이 없는 게 맞는 것들이다 —
문서 머리말, 부칙, 별표·서식.

### 목차 줄을 거르면 절반이 준다

`TOC_BODY_MIN` 을 끄고 비교했다.

```text
정상 (TOC_BODY_MIN = 10) : 조항 단위  46 + 표 단위 7 =  53 청크 · 평균 156.4자
끔   (TOC_BODY_MIN =  0) : 조항 단위  92 + 표 단위 7 =  99 청크 · 평균  83.3자
차이 = 46개

30자 미만 청크 = 42개 · 가장 짧은 것들 —
  ('제1장 제1조(목적)',  7자)
  ('제3장 제1절 제11조(일비)',8자)
```

늘어난 46개가 전부 목차 줄이다. 평균 글자 수가 156자에서 83자로 떨어지는데,
**검색 결과의 절반이 7~8자짜리 제목**이 된다는 뜻이다.

## 짚어둘 것

### 괄호 제목이 없는 조는 못 잡는다

괄호 제목을 필수로 만들어 상호참조를 걸렀는데 대가가 있다.
`제5조` 처럼 **제목 없이 번호만 있는 조는 조 제목으로 안 잡힌다.**

이 문서는 모든 조에 괄호 제목이 붙어 있어서 문제가 없다. 그렇지 않은 규정에서는
그 조가 앞 조에 붙어 버린다. 문서를 보고 정할 문제다.

### 머리말 하나가 653자다

```text
조항   | DOC-HR-014_국내출장_여비_규정_v2.0         | 653자
```

목차 줄 46개가 첫 청크에 전부 합쳐진 결과다. 목차 줄을 앞 청크에 붙이는 규칙이
여기서는 한 청크를 크게 만든다. 한도(1,200) 안이라 지금은 넘어가지만,
목차가 긴 문서에서는 `_hard_wrap` 이 돌아 목차가 의미 없이 쪼개진다.

목차를 아예 버릴지 따로 모을지는 아직 정하지 않았다.
