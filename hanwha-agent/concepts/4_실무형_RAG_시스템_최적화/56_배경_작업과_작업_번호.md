# 배경 작업과 작업 번호

[[55_청크_저장]]에서 파싱부터 저장까지 이어 붙였다. 그 전부를 업로드 요청 안에서
돌리면 요청이 그만큼 매달린다. 응답을 먼저 끊고 진행 상태를 따로 묻게 만든다.

## 지금 재료로는 티가 안 난다

```text
파일                                         청크      1회차      2회차
DOC-FI-009_법인카드_사용_지침_v1.4.docx            19   0.014초   0.014초
DOC-FI-009_법인카드_사용_지침_v1.4.pdf             17   0.107초   0.027초
DOC-HR-014_국내출장_여비_규정_v2.0.docx            53   0.026초   0.028초
DOC-HR-014_국내출장_여비_규정_v2.0.pdf             45   0.096초   0.099초
```

`api_client` 의 `TIMEOUT` 이 10초인데 전부 0.1초 아래다. 동기로 불러도 아무 일 없다.

두 번 잰 이유는 첫 번째 값에 파서 라이브러리를 처음 올리는 비용이 섞이기 때문이다.
첫 PDF 가 0.107초에서 0.027초로 떨어지는데 이게 `pdfplumber` import 값이다.
파싱이 느린 것과 import 가 느린 것은 다른 문제라 섞어 재면 엉뚱한 곳을 고친다.

문제는 '지금 재료' 가 기준이 아니라는 점이다. 20쪽짜리가 0.1초면 수백 쪽은 몇 초다.
그 몇 초 동안 사용자는 멈춘 화면을 본다. 10초를 넘기면 `TIMEOUT` 에 걸려
업로드는 성공했는데 화면에는 실패로 뜬다.

## 세 가지 방식

| | 응답 | 진행 상황 | 실패를 아는 방법 |
| --- | --- | --- | --- |
| 동기 | 전부 끝난 뒤 | 알 수 없음 | 응답 코드 |
| 작업 번호 배부 | 즉시 | 번호로 물어본다 | 작업 상태 |
| 큐·워커 | 즉시 | 번호로 물어본다 | 작업 상태 + 재시도 |

오늘은 가운데를 만든다. 큐(Celery·RQ)는 프로세스를 따로 띄워야 해서 아직 이르다.

## `BackgroundTasks`

FastAPI 가 "응답을 보낸 뒤 호출할 함수" 를 담아 두는 상자를 준다.

```python
background: BackgroundTasks,     # 타입만 적으면 FastAPI 가 넣어 준다
...
background.add_task(document_service.run_ingest_job, job_id)
```

### 등록이지 호출이 아니다

`add_task(run_ingest_job, job_id)` 다. `add_task(run_ingest_job(job_id))` 로 쓰면
지금 당장 실행되고 그 반환값(`None`)이 배경 작업으로 등록된다.

```text
add_task(작업(1)) 를 호출:
   (작업이 지금 실행됨: 1 )
등록 끝. 이제 배경 작업을 돌려 본다:
   터졌다 → TypeError : the first argument must be callable
```

작업은 동기로 이미 끝났고, 그 뒤 배경에서 `None()` 을 부르다 터진다.
응답은 그 전에 201 로 나가므로 화면은 정상이고 로그에만 `TypeError` 가 남는다.
괄호 하나로 비동기가 사라지는데, 결과만 보면 잘 돌아간 것처럼 보인다.

### `async def` 로 만들면 안 된다

`BackgroundTasks` 는 동기 함수를 스레드풀에서 돌린다. `async def` 로 쓰면
이벤트 루프에서 직접 돌아가는데, 그 안에서 파싱처럼 CPU 를 붙잡는 일을 하면
루프가 막혀 서버 전체가 멈춘다. 평범한 `def` 로 둬야 한다.

### 인자 순서

```python
    file: Annotated[UploadFile, File()],
    background: BackgroundTasks,
    logger: LoggerDep,
```

`background` 는 기본값이 없는 인자다. 기본값이 있는 인자 뒤에 두면 문법 오류가 난다.

이 프로젝트에서는 그 제약이 걸리지 않는다. `LoggerDep` 이
`Annotated[logging.Logger, Depends(get_request_logger)]` 라서 기본값이 아니라
타입 주석이기 때문이다. 의존성을 `logger = Depends(get_request_logger)` 로 쓰는
코드에서는 순서가 문제가 된다. `Annotated` 로 쓰는 이유 중 하나가 이것이다.

## 작업 저장소

번호를 주려면 번호와 상태를 어딘가 적어 둬야 한다. 모듈 딕셔너리로 시작한다.

```python
_JOBS: dict[str, dict] = {}
```

강사님 코드의 타입은 `dict[str, str]` 인데 값은 dict 다. 실행에는 영향이 없지만
읽는 사람을 헷갈리게 해서 `dict[str, dict]` 로 적었다.

### 번호는 `uuid4().hex[:8]`

32자 중 앞 8자만 쓴다. 화면에 띄우고 눈으로 비교하기 위한 길이다.
잘라 쓰면 충돌 가능성이 생긴다. 한 프로세스 안의 임시 작업이라 감수한다.

### 프로세스 메모리라는 뜻

```text
_JOBS 에 들어 있는 작업 수: 1
서버를 재시작하면 0 이 된다. --reload 가 코드 변경으로 다시 떠도 사라진다.
```

- 서버를 재시작하면 진행 중이던 작업이 전부 사라진다
- `uvicorn --reload` 가 코드 변경을 감지해 다시 뜨면 똑같이 사라진다
- 워커를 2개 이상 띄우면 상태 조회가 다른 워커로 가 "작업을 찾을 수 없습니다" 가 난다

실제 운영이라면 DB 나 Redis 로 옮길 자리다.

## 단계 목록

```text
완료 · 66% · 19청크
조항 단위 17 + 표 단위 2 = 19 청크

  [  ok] 파일 검증
  [  ok] 문서 파싱                      표 2개 인식
  [  ok] 표 -> 마크다운 변환               표 2개
  [  ok] 청킹                         19청크
  [todo] 임베딩
  [todo] 검색 반영 및 현행 버전 지정
```

여섯 단계 중 넷만 돌아간다. 뒤 둘은 구현이 없다.

목록에서 지우지 않고 `todo` 로 남긴 것은 무엇이 빠졌는지 화면에 드러나게 하려는 것이다.
진행률도 4/6 으로 계산해 완료인데 66% 에서 멈춘다. 100% 로 적으면 임베딩이 끝난
것처럼 보인다. 덜 된 것을 덜 됐다고 두는 쪽이 맞다.

### 단계별 중간 보고는 안 한다

`ingest_document()` 가 파싱·청킹을 한 번에 끝내고 결과만 돌려준다. 그래서
"진행 중" 에서 네 단계가 함께 `ok` 로 바뀐다. 단계마다 갱신하려면
`ingest_document` 가 콜백을 받아야 한다.

## 배경 작업의 예외는 돌아갈 길이 없다

응답은 이미 201 로 나갔다. 배경에서 터진 예외를 잡지 않으면 화면은 "진행 중" 에
영원히 머물고 원인은 아무 데도 남지 않는다.

```python
except Exception as exc:
    job["status"] = "실패"
    job["message"] = str(exc)
```

실제로 한 번 걸렸다. `.env` 를 못 찾아 sqlite 로 붙은 상태에서 돌렸더니
`chunks` 테이블이 없었다.

```text
작업 상태: 실패 / 0 % / 0 청크
메시지: (sqlite3.OperationalError) no such table: chunks
   [  no] 파일 검증
   [todo] 문서 파싱
```

`get_settings()` 의 `env_file=".env"` 는 cwd 기준이다. `.env` 는 저장소 루트에 있어서
`backend/` 에서 띄우면 못 찾고 기본값 `sqlite:///./app.db` 로 떨어진다.
`uvicorn app.main:app --app-dir backend` 를 루트에서 치는 이유가 이것이다.

## 상태 조회

```python
@router.get("/jobs/{job_id}", response_model=JobOut)
```

선언 위치가 중요하다. `@router.get("/{doc_id}")` 보다 뒤에 두면 `jobs` 가
`doc_id` 로 잡혀 "문서를 찾을 수 없습니다" 가 난다. 경로는 위에서부터 맞춰 보므로
고정 문자열이 있는 쪽을 먼저 선언한다.

```text
404 {'code': 'not_found', 'message': '작업을 찾을 수 없습니다: deadbeef', 'detail': None}
```
