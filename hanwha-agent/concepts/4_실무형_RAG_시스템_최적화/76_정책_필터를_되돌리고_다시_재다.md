# 정책 필터를 되돌리고 다시 재다

[[74_기법을_더했는데_떨어졌다]]의 결론이 「파이프라인이 덜 끝난 상태로 측정했다」였다.
빠진 두 단계를 채우고 같은 조건으로 다시 쟀다.

## 빠진 것을 되돌린다

순서가 이렇게 정리됐다.

```text
키워드 검색 + RRF  →  정책 필터  →  리랭킹  →  판정
```

```python
#4. 정책 필터
kept, blocked = policy.filter_candidates(candidates, user=user, question=question)
if blocked:
    log.info("정책으로 제외: %s", "/".join(blocked[:5]))

#5. 리랭킹
top = (rerank(question, kept, top_n=settings.rerank_top_n, by=reranker)
       if rerank_on else kept[:settings.rerank_top_n])

#6. 임계값 검증
sources = [source_dict(r) for r in top]
best, threshold, passed = judge_gate(sources)
```

정책을 리랭킹 **앞**에 두는 것이 중요하다. 거를 것을 먼저 빼야 리랭커가 쓸데없는 것에
점수를 매기지 않는다. 크로스 인코더는 후보마다 모델을 돌리므로
([[75_리랭킹_두_가지]]) 순서가 바뀌면 비용이 그대로 늘어난다.

### 만료본을 걸렀다는 사실을 사용자에게 알린다

```python
expired = [b.split(" - ")[0] for b in blocked if "만료" in b]
note = (f"{expired[0]}은(는) 만료된 버전이라 검색에서 제외했습니다. "
        "과거 문서 버전을 보시려면 질문에 '개정 전' 처럼 적어 주세요.") if expired else None
```

[[62_현행_판과_보안등급]]에서 만료본을 지우지 않고 거르기로 한 이유가 여기서 쓰인다.
거른 것을 숨기지 않고 어떻게 하면 볼 수 있는지를 알려 준다.

[[63_검색_정책]]에 적은 「사유에 문서 제목이 실린다」는 문제는 그대로 남는다.
`expired[0]` 이 문서 제목이므로 「국내출장 여비 규정 v1.1 은 만료된 버전입니다」가
사용자에게 간다. 만료본의 제목은 현행본의 제목과 같으니 새는 정보는 없지만,
보안등급 때문에 걸린 것을 같은 방식으로 알리면 새어 나간다. 그래서 만료만 고른다.

## 골든셋이 v2 가 됐다

[[65_측정값_뜯어보기]]에서 문서 번호가 틀렸다고 적은 두 문항이 고쳐졌다.

| 문항 | 전 | 후 |
| --- | --- | --- |
| G23 | `DOC-PU-103` v1.0 | `DOC-PU-007` v4.0 · 키워드 `협력사 평가`·`협조도` |
| G24 | `DOC-SE-102` v1.0 · `requires_clearance: 3급` | `DOC-SE-003` v2.2 · `대외비` |

세 가지가 그대로 맞았다 — 문서 번호 둘과 G24 의 등급이다. 등급까지 틀렸다는 것은
채점기가 그 칸을 읽지 않아 결과에 드러나지 않던 것이었다([[65_측정값_뜯어보기]]).

[[69_골든셋_점검기]]를 다시 돌려 보면 숫자로 확인된다.

```text
골든셋 30문항 검사 — 오류 1 · 경고 0 (문항 1개에서)
  [오류] G07 (2) 버전 없음 — 개정으로 번호가 바뀌었다: v1.4 (DB: v2.1)
```

**오류 3 → 1.** 남은 하나가 G07 이고 이건 골든셋이 아니라 적재 쪽 문제다
(`DOC-FI-009` 가 색인되지 않았다). 시험지를 고쳐도 데이터를 안 고치면 남는다.

`meta.name` 이 `사내 규정 골든셋 v2` 가 됐다. [[68_골든셋_만드는_순서]]에 적은
「`version` 칸을 따로 두는 쪽이 맞다」는 그대로다 — 아직 이름 문자열 안에 있다.

## 임계값도 0.60 으로 올렸다

```python
retrieval_threshold: float = Field(default=0.60, ge=0.0, le=1.0)
```

[[74_기법을_더했는데_떨어졌다]]에서 쓸 수 있는 폭이 0.2 라고 했고,
[[65_측정값_뜯어보기]]에서 0.55 는 관측치 두 개로 그은 선이라고 했다. 0.05 올렸다.

## 다섯 설정

```text
문항 30개. 임계값 벡터 0.6. 크로스 인코더 0.2. 상위 3건

 기본 검색             90.0% (27/30)
 + Multi-Query     86.7% (26/30)
 + 하이브리드           80.0% (24/30)
 + 리랭킹             93.3% (28/30)
 + 크로스 인코더         90.0% (27/30)
```

유형별로 보면 무엇이 움직였는지가 나온다.

| 유형 | 기본 | +MQ | +하이브리드 | +리랭킹 | +크로스 |
| --- | --- | --- | --- | --- | --- |
| 단일 조항 | 90.0 | 80.0 | 80.0 | 90.0 | 80.0 |
| 표 안의 조건 조합 | 83.3 | 83.3 | 66.7 | **100.0** | **100.0** |
| 개정 전후 비교 | 100.0 | 100.0 | 75.0 | 100.0 | 100.0 |
| 타 부서 문서 참조 | **100.0** | 100.0 | 100.0 | 100.0 | 100.0 |
| 규정에 없는 사항 | 83.3 | 83.3 | 83.3 | 83.3 | 83.3 |

읽을 것이 셋이다.

**「타 부서 문서 참조」가 50% 에서 100% 가 됐다.** 골든셋 두 문항을 고친 효과이고
검색은 한 줄도 바뀌지 않았다. [[65_측정값_뜯어보기]]에서 "검색 1위가 정답이었다"고
적은 그 두 문항이다.

**「표 안의 조건 조합」이 리랭킹에서 100% 가 됐다.** [[75_리랭킹_두_가지]]의 표 가산점이
한 일이다. 하이브리드에서 66.7% 로 떨어졌던 것을 되돌리고 그 위로 올라갔다.

**「개정 전후 비교」가 하이브리드에서만 75% 다.** 정책 필터를 되돌렸는데도 그렇다.
BM25 가 만료본을 글자로 끌어올리고([[73_키워드_검색과_RRF]]) 리랭킹이 없으면 그 순서가
그대로 남는다. 리랭킹을 켜면 100% 로 돌아온다.

## 남은 둘

```text
기본 검색        틀림 3개  ['G07', 'G16', 'G26']
+ Multi-Query  틀림 4개  ['G04', 'G07', 'G16', 'G26']
+ 하이브리드       틀림 6개  ['G04', 'G07', 'G11', 'G16', 'G19', 'G26']
+ 리랭킹         틀림 2개  ['G07', 'G26']
+ 크로스 인코더     틀림 3개  ['G04', 'G07', 'G26']
```

가장 좋은 설정에서 남은 둘이 **G07 과 G26** 이다. [[74_기법을_더했는데_떨어졌다]]의
고장 표에서 「검색 쪽이 아니다」로 분류한 것과 「검색 설계를 바꿔야 풀린다」로 분류한 것
하나씩이다.

| 문항 | 고장 | 어디서 고치나 |
| --- | --- | --- |
| G07 | `DOC-FI-009` 가 색인되지 않았다 | 재색인 — 검색 밖 |
| G26 | 임베딩이 「국내」와 「해외」를 못 가른다 | 크로스 인코더가 후보를 다시 읽어도 못 고쳤다 |

**검색 기법으로 고칠 수 있는 것은 다 고쳐졌다.** 리랭킹까지 붙인 93.3% 가 지금 재료에서
나오는 상한에 가깝고, 남은 6.7% 는 적재 한 건과 임베딩의 성질 한 건이다.

G26 이 크로스 인코더에서도 안 고쳐진 것은 짚어 둘 만하다. 질문과 조각을 함께 읽는
모델도 「해외 체류비」 질문에 「국내출장 일비 30,000원」이 걸린 것을 걸러내지 못했다.
후보 안에 해외 조항이 아예 없으니 다시 읽어도 고를 것이 없다. 리랭킹은 순서를 바꾸는
일이고 **없는 것을 만들지는 못한다.**
