# 검색 평가와 답변 평가

[[64_골든셋과_채점기]]부터 [[67_오답_목록과_약한_유형]]까지 잰 것은 전부 한 가지다.
**정답 청크를 가져왔는가.** 모델이 그 근거로 어떻게 답했는지는 재지 않았다.

평가가 두 층이다.

| | 재는 것 | 채점하는 쪽 | 지표 |
| --- | --- | --- | --- |
| 검색 평가 | 정답 청크를 가져왔는가 | 규칙(코드) | Hit@k · Recall@k · MRR · nDCG |
| 답변 평가 | 그 근거에 맞게 답했는가, 질문에 답했는가 | 사람 또는 LLM 채점기 | 근거 충실도 · 답변 적합도 |

위층은 코드로 채점되므로 싸고 되풀이할 수 있다. 아래층은 사람이나 모델이 읽어야 해서
비싸다. 그래서 위를 먼저 세운다. **근거가 안 올라왔으면 답변을 평가할 이유가 없다.**

## 지금 채점기는 Hit@3 의 엄격한 변형이다

```python
for h in hits:            # hits 는 상위 3건
    ...
    return True, f"{h['doc_id']} {h['version']} {h['locator']}"
return False, "정답 문서가 상위에 없음"
```

상위 3건에 정답이 있으면 1, 없으면 0 이다. 그게 Hit@k 다.

다만 보통의 Hit@k 보다 좁다. 문서·판·종류·키워드를 모두 채워야 인정한다.
"정답 문서를 가져왔다"가 아니라 "정답 조각을 가져왔다"를 본다.

### k 를 바꿔 가며 재 봤다

답이 있는 24문항에서 정답 청크가 몇 위에 오는지 세어 봤다.

```text
  Hit@1   14/24   58.3%
  Hit@3   20/24   83.3%     ← 지금 쓰는 값
  Hit@5   21/24   87.5%
  Hit@10  21/24   87.5%
  Hit@12  21/24   87.5%

  MRR     0.7028
  찾은 것들의 평균 순위  1.57
```

읽을 것이 세 가지 있다.

**Hit@1 이 58.3% 다.** 24문항 중 10개는 1위가 정답이 아니다. 답은 상위 3건 안에
있지만 첫 줄은 다른 것이다. [[65_측정값_뜯어보기]]에서 본 목차·표지 조각이 여기에서도
자리를 먹고 있을 가능성이 크다.

**Hit@3 에서 Hit@5 로 가면 하나 늘고 거기서 멈춘다.** 그 하나가 G16(5위)이다.
`k` 를 5로 올리면 이번 측정은 한 문항 더 맞는다. 그런데 그건 LLM 에게 근거를
다섯 줄 넘기겠다는 결정이고, 검색이 좋아진 것은 아니다.

**Hit@12 가 87.5% 에서 멈춘다.** 12건을 다 뒤져도 3문항은 못 찾는다.
G07·G23·G24 — 기대한 문서가 DB 에 없는 문항이다([[69_골든셋_점검기]]).
**이 골든셋에서 검색이 닿을 수 있는 상한이 87.5% 다.**

깨진 셋을 빼고 21문항으로 보면 숫자가 달라진다.

```text
  Hit@3  20/21 = 95.2%
  MRR    0.8032
```

## 왜 Hit@k 하나로는 부족한가

Hit@3 은 정답이 1위인 것과 3위인 것을 똑같이 1 로 센다. 버리는 정보가 있다.

`MRR` 은 정답 순위의 역수를 평균한다. 1위면 1, 2위면 0.5, 5위면 0.2 다.
G16 이 5위라는 사실이 `0.2` 로 남는다. 목차 조각을 색인에서 빼서 G16 이 3위로
올라오면 Hit@3 은 1 이 되고 MRR 은 0.2 에서 0.33 으로 움직인다.

순위를 조금 끌어올린 개선이 Hit@3 에서는 0 으로 보이고 MRR 에서는 보인다.
재순위를 붙일 때 효과를 확인할 지표가 MRR 쪽이다.

`Recall@k` 는 정답 청크가 여러 개일 때 그중 몇 개를 가져왔는지 본다.
지금 골든셋은 정답을 조각 하나로 적으므로 Hit@k 와 같아진다. 「표 안의 조건 조합」처럼
조항과 별표를 함께 봐야 답이 되는 문항은 정답을 둘로 적어야 Recall 이 뜻을 갖는다.

`nDCG` 는 순위에 가중치를 주고 여러 정답의 중요도까지 반영한다. 정답을 등급으로
적어야(이 조각은 꼭 필요, 저 조각은 있으면 좋음) 쓸 수 있다. 지금 골든셋에는 그 칸이 없다.

지표를 바꾸려면 골든셋의 모양이 먼저 바뀌어야 한다. **지표는 시험지가 허용하는 만큼만
정밀해진다.**

## 아래층 — 답변 평가

근거가 올라온 다음을 본다. 두 가지를 따로 묻는다.

- 근거 충실도 — 답이 넘겨준 근거 안에 있는 말로만 되어 있는가. 근거에 없는 숫자나
  조문을 끌어왔으면 지어낸 것이다.
- 답변 적합도 — 사용자가 물은 것에 답했는가. 근거에 충실하면서 질문을 비껴갈 수 있다.

둘을 나누는 이유는 고칠 곳이 다르기 때문이다. 충실도가 낮으면 프롬프트와 가드가,
적합도가 낮으면 검색이나 질문 이해가 문제다.

[[65_측정값_뜯어보기]]의 G26 이 아래층에서 어떻게 보이는지가 이 구분을 설명한다.
해외 체류비를 물었는데 국내 일비 30,000원이 근거로 올라온다. 모델이 "국내출장 일비는
30,000원입니다"라고 답하면 **충실도는 만점이고 적합도는 0 이다.** 근거에 충실하게
답했는데 틀린 답이 나온다.

규칙으로 채점할 수 없는 자리다. 사람이 읽거나 LLM 채점기를 세워야 한다.
그리고 LLM 채점기도 틀리므로 [[64_골든셋과_채점기]]에서 `judge()` 를 먼저 눌러 본 것처럼
채점기 자체를 검증하는 단계가 또 필요하다.

## 순서

```text
①골든셋 점검     모델 없음    1초     기대값이 데이터와 맞는가
②검색 평가       임베딩만     1분     정답 청크를 가져왔는가
③답변 평가       LLM 또는 사람 비쌈   그 근거로 제대로 답했는가
```

위에서 걸리면 아래로 내려가지 않는다. ①에서 오류가 3건 나온 골든셋으로 ③을 돌리면
비싼 채점을 하고도 "시험지가 틀렸다"는 결론이 나온다.

참고: evals/run_eval.py, evals/check_golden.py, evals/golden_set.yaml
