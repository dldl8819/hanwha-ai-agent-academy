# 관측과 실행 기록 — LangFuse 를 붙이고 runs 에 남기기

[[30_LLM_프레임워크_개요]]에서 본 `trace` / `observation` / `score` 를 실제 코드에 붙인다. 핵심 원칙은 하나다.

> **관측이 실패해도 답변은 나가야 한다.**

기록을 남기려다 사용자 요청을 깨뜨리면 관측 도구를 붙인 것이 손해가 된다. 이 노트의 거의 모든 설계 판단이 이 한 줄에서 나온다.

## 설정 — 기본값은 꺼짐

### `backend/app/core/config.py`

```python
# --- 관측 langfuse ---
langfuse_enabled: bool = False
langfuse_host: str = "http://localhost:3000"
langfuse_public_key: str | None = None
langfuse_secret_key: SecretStr | None = None
```

| 판단 | 이유 |
| --- | --- |
| `langfuse_enabled` 기본값 `False` | 키를 안 넣은 사람도, 패키지를 설치하지 않은 사람도 앱이 그대로 돈다 |
| `public_key` 는 `str`, `secret_key` 는 `SecretStr` | public 은 화면에서 다시 볼 수 있고, secret 은 로그·`print` 에 실수로 찍히면 안 된다 |

`.env` 에 같은 이름으로 넣는다. `.env` 값이 클래스 기본값을 덮는다([[03_Pydantic]]).

```text
LANGFUSE_ENABLED=false
LANGFUSE_HOST=http://localhost:3000
LANGFUSE_PUBLIC_KEY=
LANGFUSE_SECRET_KEY=
```

## 클라우드냐 셀프 호스팅이냐

| | 클라우드 | 셀프 호스팅 |
| --- | --- | --- |
| 준비 | 가입 → Org·Project 생성 → 키 발급 | 컨테이너 띄우기 |
| 비용 | 일정 사용량까지 무료 | 내 PC 자원 |
| 데이터 | 서비스 서버에 남는다 | 내 PC 에만 남는다 |

**리전 주소와 키가 짝이 맞아야 한다.** 일본 리전에서 발급한 키를 `cloud.langfuse.com` 으로 보내면 인증이 실패한다. 이게 실습에서 가장 흔한 막힘이라, 어댑터에도 노트북에도 확인 절차를 넣었다.

### 셀프 호스팅 — 순서를 바꾸면 안 된다

```bash
# 1) 3000 번 포트가 비었는지 먼저 본다 (쓰고 있으면 컨테이너가 조용히 안 뜬다)
netstat -ano | findstr :3000

# 2) docker-compose.yml 에 langfuse 블럭 추가 (아래)

# 3) langfuse 전용 데이터베이스를 손으로 만든다
docker compose exec postgres psql -U agent -d agent -c "CREATE DATABASE langfuse OWNER agent;"

# 4) 그 다음에 컨테이너를 올린다
docker compose --profile langfuse up -d
docker compose logs -f langfuse        # 안 뜨면 로그부터 본다
```

3번을 먼저 하지 않으면 4번이 실패한다. LangFuse 는 뜨면서 바로 자기 DB 에 붙어 마이그레이션을 돌리는데, **compose 는 `DATABASE_URL` 에 적힌 데이터베이스를 만들어 주지 않는다.** 없으면 그대로 죽는다.

### `docker-compose.yml`

```yaml
  langfuse:
    image: langfuse/langfuse:2
    container_name: agent-langfuse
    profiles: ["langfuse"]
    depends_on:
      postgres:
        condition: service_healthy
    environment:
      DATABASE_URL: postgresql://agent:agent@postgres:5432/langfuse
      NEXTAUTH_URL: http://localhost:3000
      NEXTAUTH_SECRET: hanhwa-lecture-local-only
      SALT: hanhwa-lecture-local-only
      ENCRYPTION_KEY: "0000...0000"
      TELEMETRY_ENABLED: "false"
    ports:
      - "3000:3000"
```

읽을 점 셋.

- **`profiles: ["langfuse"]`** — 그냥 `docker compose up -d` 로는 뜨지 않는다. 필요한 날만 `--profile langfuse` 로 올린다
- **`DATABASE_URL` 의 호스트가 `localhost` 가 아니라 `postgres`** — 컨테이너끼리는 compose 가 붙여준 서비스 이름으로 서로를 찾는다([[20_Docker와_PostgreSQL]])
- **`condition: service_healthy`** — 단순히 "먼저 시작"이 아니라 `pg_isready` 가 통과할 때까지 기다린다

컨테이너를 내릴 때 주의할 것이 하나 있다.

```bash
docker compose stop langfuse       # langfuse 만 멈춤
docker compose down langfuse       # 서비스 이름을 빼면 postgres 까지 같이 지워진다
```

## 어댑터 — 실패를 삼키는 자리

### `backend/app/integrations/langfuse_client.py`

```python
_client = None
_tried = False

def get_client():
    global _client, _tried
    if _tried:
        return _client          # 실패도 기억한다
    _tried = True

    settings = get_settings()
    if not settings.langfuse_enabled:
        return None
    if not settings.langfuse_public_key or settings.langfuse_secret_key is None:
        log.warning("LANGFUSE_ENABLED=true 인데 키가 비어 있습니다. 관측을 건너뜁니다.")
        return None
    try:
        from langfuse import Langfuse
        _client = Langfuse(...)
    except Exception as e:
        log.warning("Langfuse 클라이언트를 만들지 못하였습니다 (무시하고 계속) : %s", e)
        _client = None
    return _client
```

`factory` 처럼 `@lru_cache` 를 쓰지 않고 전역 변수 두 개를 쓴 이유가 있다. **실패도 캐시해야 한다.** `@lru_cache` 는 예외를 캐시하지 않아서, 만들기에 실패하면 요청마다 다시 시도하며 같은 경고를 쏟는다. `_tried` 를 따로 두면 첫 번째 시도의 결과(`None` 포함)가 그대로 재사용된다.

`from langfuse import Langfuse` 도 함수 안에 있다. 관측을 끄고 쓰는 사람은 `langfuse` 를 설치하지 않아도 된다([[23_포트와_어댑터]]의 지연 import 와 같은 이유).

```python
except Exception as e:      # 종류를 나누지 않는다
```

평소에는 나쁜 습관이지만 여기서는 의도한 것이다. 패키지 미설치·주소 오타·키 형식 오류가 전부 여기로 오고, 무엇이 왔든 정답이 "관측만 포기"라서 나눌 이유가 없다.

### 같은 경고를 두 번 찍지 않기

```python
_warned = False

def _quiet(message: str, e: Exception) -> None:
    global _warned
    if not _warned:
        _warned = True
        log.warning("%s (무시하고 계속): %s", message, e)
    else:
        log.debug("%s: %s", message, e)
```

관측이 막혀 있으면 요청마다 같은 경고가 찍혀서, 로그가 **정작 봐야 할 것을 덮는다.** 첫 실패만 warning 으로 알리고 그 다음은 debug 로 내린다([[06_로깅]]).

### `trace()` — 꺼져 있어도 with 는 지나간다

```python
@contextmanager
def trace(name: str, *, run_id: str, user_id: str = "", metadata: dict | None = None):
    client = get_client()
    handle = None
    if client is not None:
        try:
            handle = client.trace(id=run_id, name=name, user_id=user_id, metadata=metadata or {})
        except Exception as e:
            _quiet("Langfuse 트레이스를 시작하지 못했습니다.", e)
    try:
        yield handle
    finally:
        pass
```

관측이 꺼져 있으면 `handle` 이 `None` 이다. 예외가 아니라 `None` 이라는 게 중요하다. **부르는 쪽은 `with` 블록을 그대로 쓰고, 안에서 `handle` 을 쓸 때만 `None` 을 확인하면 된다.**

```text
get_client() : None
trace() 의 handle : None
with 블록 안 계산 : 3 + 4 = 7
score() 호출 : 예외 없음
```

`client.trace(id=run_id, ...)` — 트레이스 id 를 **우리가 정한 번호로 넘긴다.** LangFuse 가 매긴 번호를 받아 오는 게 아니다. 그래서 화면과 DB 를 같은 값으로 찾아갈 수 있다.

## `run_id` — 다섯 군데에서 같은 값

| 어디 | 무엇으로 쓰나 |
| --- | --- |
| LangFuse | 트레이스 id |
| `runs` 테이블 | 기본키 PK |
| `usage_logs` 테이블 | 외래키 FK |
| `GET /api/v1/chat/runs/{run_id}` | 경로 파라미터 |
| 감사 로그 | 사람이 화면에서 눈으로 확인하는 값 |

그래서 **번호를 먼저 만들고 그 다음에 트레이스를 붙인다.** DB 의 자동 증가 PK 를 쓸 수 없는 이유가 여기 있다. INSERT 를 해야 번호가 나오는데, 우리는 호출을 시작하기 전에 이미 번호가 필요하다.

### `backend/app/services/ids.py`

```python
RUN_START = 8821

def next_run_id(session: Session) -> str:
    used = session.scalars(select(Run.id)).all()
    numbers = [RUN_START - 1]                 # 아무 행도 없을 때 max() 가 죽지 않게
    for run_id in used:
        tail = run_id.removeprefix("RUN-")
        if tail.isdigit():                    # "RUN-테스트" 같은 값에서 int() 가 터지지 않게
            numbers.append(int(tail))
    return f"RUN-{max(numbers) + 1:04d}"
```

`:04d` 는 21 을 `0021` 로 채운다. 문자열로 정렬해도 순서가 맞는다.

이 방식의 한계도 분명하다. **행을 전부 읽어서 최대값을 찾는다.** 기록이 쌓이면 느려지고, 두 요청이 동시에 들어오면 같은 번호를 받을 수 있다. 운영이라면 DB 시퀀스로 바꿀 자리다.

## 테이블 — trace 와 observation 을 그대로 옮긴다

### `backend/app/models/run.py`

```python
class Run(Base, TimestampMixin):
    __tablename__ = "runs"
    id: Mapped[str] = mapped_column(String(32), primary_key=True)     # "RUN-8821"
    user_id: Mapped[int] = mapped_column(ForeignKey("users.id"), nullable=False)
    question: Mapped[str] = mapped_column(Text, nullable=False)
    answer: Mapped[str | None] = mapped_column(Text, nullable=True)   # 나중에 채운다
    status: Mapped[str] = mapped_column(String(24), default="완료")
    latency_ms: Mapped[int] = mapped_column(Integer, default=0)
    mode: Mapped[str] = mapped_column(String(8), default="mock")
    sources: Mapped[list | None] = mapped_column(JSON, nullable=True)

class RunStep(Base):
    __tablename__ = "run_steps"
    id: Mapped[int] = mapped_column(primary_key=True)
    run_id: Mapped[str] = mapped_column(ForeignKey("runs.id"), nullable=False)
    ord: Mapped[int] = mapped_column(Integer, default=0)
    name: Mapped[str] = mapped_column(String(64))
    ok: Mapped[bool] = mapped_column(default=True)
    ms: Mapped[int] = mapped_column(Integer, default=0)
    detail: Mapped[str | None] = mapped_column(Text, nullable=True)
```

| 판단 | 이유 |
| --- | --- |
| 관측 도구에만 두지 않고 우리 DB 에도 남긴다 | 그 서비스가 죽거나 무료 한도를 넘으면 기록이 사라진다. 화면·감사 로그·통계는 우리 힘으로 만들어야 한다 |
| `answer` 가 `nullable` | 호출 **전에** 행을 먼저 넣기 때문에 그때는 답이 없다 |
| `mode` 를 남긴다 | 이 답이 mock 이었나 live 였나. 나중에 기록을 볼 때 이게 없으면 판단이 안 된다 |
| `sources` 를 JSON 통째로 | "그때 이렇게 답했다"는 스냅샷이다. 문서가 개정되어도 이 기록의 버전·위치는 그대로 남아야 한다 |
| `RunStep` 에 `ord` 를 따로 | `created_at` 으로 정렬하면 같은 밀리초에 끝난 단계들의 순서가 뒤집힌다 |
| `RunStep` 에 `TimestampMixin` 없음 | 단계는 `ord` 로 순서를, `ms` 로 시간을 재므로 등록일·수정일이 필요 없다 |

### `models/__init__.py` 에 등록하는 것을 잊으면

```python
from app.models.run import Run, RunStep
```

**Alembic 의 autogenerate 는 `Base.metadata` 에 등록된 테이블만 본다.** 모델 파일을 만들어도 여기서 import 하지 않으면 리비전 파일이 빈 채로 생성된다. 에러가 아니라 빈 파일이 나오는 조용한 실패다([[21_Alembic_마이그레이션]]).

## 서비스에 붙이기

### `backend/app/services/chat_service.py`

```python
def ask(*, question: str, run_id: str | None = None, user_id: int = 1) -> AskOut:
    q = check_question(question)
    llm = factory.get_llm()

    from app.integrations.langfuse_client import score, trace
    from app.integrations.llm_claude import _extract_json

    started = time.perf_counter()

    # 1) 호출 전에 먼저 기록을 만든다
    with session_scope() as session:
        if run_id is None:
            run_id = next_run_id(session)
        session.add(Run(id=run_id, user_id=user_id, question=q,
                        status="진행중", mode=get_settings().app_mode))

    # 2) 여기서부터가 한 건의 트레이스
    with trace("ask", run_id=run_id, user_id=str(user_id), metadata={"question_len": len(q)}):
        out = None
        hint = ""
        for attempt in range(1, MAX_ATTEMPTS + 1):
            ...
            out = AskOut(**data, run_id=run_id, attempts=attempt, fallback_used=False)
            break
        if out is None:
            out = _fallback(run_id, MAX_ATTEMPTS)
            score(run_id, "schema_ok", 0.0)

        # 3) 기록 마무리
        with session_scope() as session:
            run = session.get(Run, run_id)
            run.answer = out.answer
            run.status = "완료"
            run.latency_ms = int((time.perf_counter() - started) * 1000)
            run.sources = [s.model_dump() for s in out.sources]
        return out
```

바뀐 점을 하나씩.

**`status="진행중"` 으로 먼저 넣는다.** 답을 받은 다음에 남기면 호출 중에 서버가 죽은 요청은 흔적이 없다. 먼저 넣어두면 끝나지 않은 요청도 DB 에 보인다. 트레이스보다 이 `with` 블록을 먼저 닫아서, 행이 확실히 커밋된 뒤에 관측을 시작한다.

**`return` 이 `out = ...; break` 로 바뀌었다.** 전에는 검증을 통과하면 바로 `return` 했다. 이제는 트레이스 안에서 DB 마무리까지 해야 해서 변수에 담고 루프를 빠져나온다. `for` 를 끝까지 돌았다는 뜻이던 폴백 조건은 `if out is None` 으로 바뀌었다.

**`score(run_id, "schema_ok", 0.0)`.** 폴백으로 빠진 것을 점수로도 남긴다. 로그는 사람이 찾아 읽어야 하지만, 점수는 "폴백 비율"로 집계된다([[29_골든셋_회귀테스트]]의 통과율과 같은 성격이다).

### 계층 규칙을 어떻게 지켰나

`test_layers.py` 에는 "services 는 `app.integrations.factory` 만 본다"는 규칙이 있다([[23_포트와_어댑터]]). `langfuse_client` 는 factory 를 거치지 않으니 최상단에서 import 하면 이 규칙에 걸린다. 그래서 **함수 안에서 import 한다.**

```python
def test_services_reach_integrations_only_through_factory() -> None:
    offenders = _violations("services", forbidden=("app.integrations",),
                            allowed=("app.integrations.factory",))
```

그 검사는 `ast` 로 파일 최상단(`tree.body`)만 읽으므로 함수 안 import 는 걸러지지 않는다. **검사를 피한 셈이지만, 규칙을 우회한 것과 판단이 다른 것은 구별해야 한다.** factory 를 거치라는 규칙의 목적은 "공급자 SDK 가 서비스 코드에 박히지 않게" 하는 것이다. 관측은 계층을 타고 흐르는 의존이 아니라 어디서든 껐다 켤 수 있는 부수 기능이고, 껐을 때 `None` 만 돌아오면 되므로 Protocol 로 감쌀 대상이 아니다.

```bash

```

## 조회 API

### `backend/app/services/chat_service.py`

```python
def get_run(*, run_id: str) -> dict:
    with session_scope() as session:
        run = session.get(Run, run_id)
        if run is None:
            raise NotFound(f"실행 기록을 찾을 수 없습니다: {run_id}")
        return {
            "run_id": run_id, "user_id": run.user_id, "question": run.question,
            "answer": run.answer, "status": run.status, "latency_ms": run.latency_ms,
            "mode": run.mode,
            "sources": run.sources or [],
            "created_at": run.created_at.isoformat(),
        }
```

모델 객체를 그대로 돌려주지 않고 `dict` 를 만든다.

- 세션이 닫힌 뒤에 속성을 읽으면 `DetachedInstanceError` 가 난다([[11_SQLAlchemy]])
- 테이블 컬럼이 늘어날 때 응답이 **조용히 같이 늘어난다**
