# EC2 서버 준비

과목 7 의 첫 시간. 지금까지 만든 앱을 내 컴퓨터 밖의 서버에 올리기 위한 준비다. 이날은 서버를 만들고 Docker 까지 깔았다.
앱은 아직 올리지 않았다.

## AWS

| 이름 | 뜻 |
| --- | --- |
| AWS 관리 콘솔 | 웹에서 AWS 자원을 만들고 관리하는 화면 |
| IAM | 계정 안의 사용자·권한. 수업 계정은 IAM 사용자 전용 로그인 주소(계정 별칭이 들어간 `…signin.aws.amazon.com`)로 들어간다 |
| EC2 | 클라우드에 만드는 가상 서버 |

접속은 SSH 다. 터미널의 `ssh` 나 Termius 같은 전용 프로그램을 쓴다. 인스턴스를 만들 때 받은 키 파일로 들어간다.

## 리눅스 기본 설정 (Ubuntu)

```bash
sudo passwd root          # root 비밀번호. 입력이 화면에 안 보이는 게 정상
su - root / exit          # 관리자로 전환 · 복귀
sudo apt update           # 패키지 목록 갱신
sudo apt upgrade -y       # 설치된 것들 올리기
sudo apt install curl vim tree
timedatectl set-timezone Asia/Seoul
```

`apt` 는 패키지 관리자다. [[01_개발환경설정]]의 `pip` 이 파이썬 패키지를 깐다면 `apt` 는 운영체제 프로그램을 깐다.
`update` 는 「무엇이 있는지 목록만 받기」, `upgrade` 는 「실제로 올리기」다. 순서가 바뀌면 옛 목록으로 올린다.

시간대가 중요한 이유는 우리 앱 쪽에 있다. 실행 기록·감사 로그·체크포인트가 모두 `datetime.now` 로 시각을 남긴다
([[94_HITL_승인]]). 서버 시간대가 UTC 면 승인함의 「오늘 승인」([[96_반려_루프와_승인함]])이 한국 날짜와 9시간 어긋난다.

## 스왑 2GB

```bash
sudo fallocate -l 2G /swapfile     # 2GB 파일을 잡는다
sudo chmod 600 /swapfile           # root 만 읽고 쓰게
sudo mkswap /swapfile              # 스왑 형식으로
sudo swapon /swapfile              # 켠다
free -h                            # Swap 줄 확인
```

메모리가 모자랄 때 디스크를 메모리처럼 쓴다. 우리 앱에서는 꼭 필요하다. [[82_수업_코드_고친_것_일곱]]에서 서버가 뜰 때
임베딩 모델(bge-m3)과 리랭커를 미리 열게 했다. 메모리가 작은 인스턴스는 이 순간 OOM(메모리 부족)으로 프로세스가 죽는다.
느려지는 것이 죽는 것보다 낫다.

**재부팅하면 스왑이 꺼진다.** `swapon` 은 지금만 켠다. 그런데 수업 순서는 스왑 → Docker 권한 → **재부팅**이다.
계속 켜 두려면 부팅 때 읽는 `/etc/fstab` 에 적는다.

```bash
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

재부팅 뒤 `free -h` 의 Swap 줄이 0 이 아닌지 확인한다.

## Docker 설치

1. Docker 공식 apt 저장소 등록 — GPG 키를 `/etc/apt/keyrings/docker.asc` 에 받고, 저장소를 `/etc/apt/sources.list.d/docker.sources` 에 적는다
2. `docker-ce` · `docker-ce-cli` · `containerd.io` · `docker-buildx-plugin` · `docker-compose-plugin` 설치
3. `sudo systemctl status docker` 로 확인
4. `sudo usermod -aG docker $USER` 후 재부팅 — sudo 없이 docker 쓰기

Ubuntu 기본 저장소에도 docker 가 있지만 공식 저장소를 따로 등록한다. 최신판과 compose 플러그인을 받기 위해서다.
GPG 키는 「이 저장소에서 받은 파일이 Docker 가 만든 것이 맞는지」를 apt 가 확인하는 데 쓴다.

`docker-compose-plugin` 이 들어가므로 [[20_Docker와_PostgreSQL]]에서 쓰던 `docker compose up -d` 를 서버에서도 같은 명령으로 쓴다.

## 짚어 둘 것

| 항목 | 이유 |
| --- | --- |
| root 비밀번호는 없어도 된다 | EC2 Ubuntu 는 root 를 잠가 두고 sudo 로 쓰는 구성이 기본이다. 시간대도 `sudo timedatectl ...` 로 된다. 설정했다면 추측하기 어려운 값으로 |
| docker 그룹은 사실상 root | sudo 없이 docker 를 쓴다는 것은 컨테이너로 서버 전체에 닿을 수 있다는 뜻이다. 이 계정의 SSH 키를 잘 지킨다 |
| 그룹 반영에 재부팅까지는 필요 없다 | 다시 접속하거나 `newgrp docker` 로도 된다. 다만 재부팅하면 스왑이 꺼지니 fstab 을 먼저 |
| `-y` 없는 `apt install` | 설치 중에 계속할지 묻는다 |
| 보안 그룹 | SSH(22)는 내 IP 에서만. 앱 포트(8000, 8501)는 배포할 때 정한다 |
| 공개 글 | IAM 로그인 주소에는 계정 별칭이 들어 있다. 블로그·저장소에는 쓰지 않는다 |

참고: 수업 자료 (서버 설정 명령). 저장소 코드는 바뀌지 않았다.
