# 레이어드 아키텍처

## main.py 하나에 다 몰아넣으면 안 되는 이유

로그인 확인, 권한 확인, 업무 규칙 처리, DB 조회/저장, 외부 API(LLM) 호출, 로그 기록, 응답 생성까지 한 요청 안에서 처리할 일이 많다. 이걸 `main.py` 한 파일에 순서대로 다 적으면, 코드가 길어질수록 어디를 고쳐야 할지 찾기 어렵고, 같은 로직(예: 권한 확인)을 다른 요청에서 재사용하기도 힘들다. 그래서 역할별로 파일/폴더를 나눈다.

## MVC 패턴

| 요소 | 역할 | hanwha-agent에서의 위치 |
| --- | --- | --- |
| Model | 데이터와 비즈니스 로직 | `backend/`, `models/`, `services/`, `repositories/` |
| View | 사용자에게 보여주는 화면 | `frontend/` |
| Controller | 요청을 받아 Model과 View를 연결 | `api/` |

## Layered Architecture (MVC를 더 세분화)

hanwha-agent의 폴더 구조는 MVC의 Model 부분을 역할별로 더 잘게 쪼갠 계층형(Layered) 구조다. 요청이 위에서 아래로 흐른다.

```text
frontend        Streamlit 화면
    | HTTP 요청
API             FastAPI Router — 요청을 받고 분배
    |
Schema          Pydantic — 요청/응답 데이터 형태 검증
    |
Service         비즈니스 로직 처리 (AI 기능도 여기)
    |
Repository      DB 접근
    |
Model           DB 테이블 정의
    |
PostgreSQL
```

각 계층은 자기 바로 아래 계층만 호출한다 (API가 DB를 직접 건드리지 않고 Service를 거치는 식). 계층을 나눠두면 예를 들어 DB를 SQLite에서 PostgreSQL로 바꿀 때 Repository 계층만 손보면 되고, 나머지 계층은 그대로 둘 수 있다.

## 계층 규칙을 테스트로 강제하기

"각 계층은 자기 바로 아래만 호출한다"는 규칙은 지키지 않아도 **기능은 잘 돈다.** 라우터가 급할 때 리포지토리를 직접 부르면 화면은 정상으로 보인다. 그래서 사람이 코드 리뷰로만 막으면 시간이 지나며 새어 나간다.

`backend/tests/test_layers.py`는 이 규칙을 테스트로 만들어 둔 것이다. 코드를 실행하지 않고 `ast`로 각 파일의 최상단 import 문만 읽어서, 금지된 방향으로 부르는 자리를 모은다.

```python
import ast

def _top_level_imports(path: Path) -> list[str]:
    tree = ast.parse(path.read_text(encoding="utf-8"))
    names: list[str] = []
    for node in tree.body:
        if isinstance(node, ast.Import):          # import app.models
            names += [alias.name for alias in node.names]
        elif isinstance(node, ast.ImportFrom):    # from app.models import User
            if node.module:
                names.append(node.module)
    return names
```

검사하는 규칙은 다섯 가지다.

| 테스트 | 막는 것 | 어기면 생기는 일 |
| --- | --- | --- |
| `test_models_import_nothing_but_models` | 모델이 다른 계층을 import | 맨 아래층이 위를 올려다보면 순환 구조가 된다 |
| `test_api_does_not_import_repositories_or_models` | 라우터가 한 단계 건너뛰기 | 트랜잭션 경계와 업무 규칙이 라우터로 샌다 |
| `test_services_do_not_import_api` | 서비스가 라우터를 import | 의존이 거꾸로 서고 순환 import 가 난다 |
| `test_repositories_do_not_import_services_or_api` | 리포지토리가 위층을 import | 판단이 DB 계층으로 내려온다 |
| `test_services_reach_integrations_only_through_factory` | 서비스가 어댑터를 직접 import | 공급자 SDK 가 서비스 코드에 박힌다 ([[23_포트와_어댑터]]) |

실패 메시지에 **어느 파일이 무엇을 불렀는지**와 **어떻게 고치면 되는지**를 같이 담아둔 것이 요령이다.

```python
assert not offenders, (
    "라우터가 repositories/models 를 직접 import 합니다. 그 호출을 services 의 "
    "함수로 옮기고 라우터는 그 함수만 부르세요:\n  " + "\n  ".join(offenders)
)
```

한계도 분명하다. `tree.body`만 보기 때문에 **함수 안에서 하는 지연 import는 걸리지 않는다.** 규칙을 우회하려면 얼마든지 우회할 수 있고, 이 테스트는 실수로 무너지는 것을 막는 용도다.
