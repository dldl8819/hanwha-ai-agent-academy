# API 토큰과 과금

## 과금 단위는 요청 수가 아니라 토큰 수

호출을 몇 번 했는지가 아니라 **얼마나 많은 글자를 주고받았는지**로 돈이 나간다. 같은 1회 호출이라도 문서를 통째로 붙여 보내면 비용이 몇 배가 된다. [[22_AI_Native_애플리케이션]]에서 "호출 한 번에 돈과 시간이라는 비용이 발생한다"고 한 것이 이 구조다.

## 토큰

모델이 글을 세는 단위다. **글자도 단어도 아니다.**

| 대상 | 대략 |
| --- | --- |
| 영어 | 단어 하나가 대체로 1~2 토큰 |
| 한글 | 글자 하나가 대체로 1토큰 이상 — 영어보다 많이 든다 |
| 공백·줄바꿈·문장부호 | 이것도 전부 토큰 |

프롬프트에 불필요한 공백과 줄바꿈을 잔뜩 넣으면 그만큼 돈이 나간다.

**정확한 수는 응답에 오는 `usage` 로만 알 수 있다.** 진짜 토큰 수는 모델이 세는 방식에 달려 있어서, 우리가 미리 계산하는 값은 어디까지나 어림이다.

### 어림 계산해보기

```python
import math

def estimate_tokens(text: str) -> int:
    korean = 0
    other = 0
    for ch in text:
        if "가" <= ch <= "힣":      # 완성형 한글 범위
            korean += 1
        elif ch.isascii():          # 영문·숫자·공백·문장부호
            other += 1
        else:
            korean += 1             # 그 밖(한자, 이모지 등)은 한글과 같게 잡는다
    return math.ceil(korean * 1.0 + other * 0.25)
```

같은 뜻의 질문을 한국어와 영어로 넣어보면 차이가 드러난다.

```text
한국어 · 글자  19자 · 어림 토큰  16 · 글자당 0.84 토큰
영어   · 글자  46자 · 어림 토큰  12 · 글자당 0.26 토큰
```

**글자 수는 영어가 2배 이상 많은데 토큰은 더 적다.** 한국어가 토큰을 많이 먹는다는 뜻이고, 프롬프트를 한국어로 길게 쓰면 비용이 빨리 올라간다.

## 비용 계산

가격은 **100만 토큰당 달러**로 매겨진다. 실습에서 쓴 값(`claude-haiku-4-5` 기준)이다. 모델마다 다르고 바뀌므로 실제 값은 공식 가격표에서 확인해야 한다.

```python
PRICE = {
    "input": 1.0,         # 입력 100만 토큰당 $1
    "cache_write": 1.25,  # 캐시에 써 둘 때 (조금 비싸다)
    "cache_read": 0.10,   # 캐시에서 읽을 때 (1/10 값)
    "output": 5.0,        # 출력 100만 토큰당 $5
}
USD_KRW = 1400
IN_TOK, OUT_TOK = 800, 400
DAILY_CALL_LIMIT = 200

def cost_usd(input_tok: int, output_tok: int, cache_read_tok: int = 0) -> float:
    billed_input = input_tok - cache_read_tok       # 캐시로 읽은 몫은 입력에서 뺀다
    total = (
        billed_input * PRICE["input"]
        + cache_read_tok * PRICE["cache_read"]
        + output_tok * PRICE["output"]
    ) / 1_000_000                                    # 가격이 100만 토큰 기준이라 나눈다
    return total
```

**출력이 입력보다 5배 비싸다.** 답을 길게 쓰게 만드는 프롬프트가 비용에 더 크게 작용한다.

실행 결과다.

```text
1회 질의 :  3.92 원
하루 요청 횟수를 모두 사용하면 : 784.0원
600이 캐시 읽기 :  3.16 원
절감 :  19.39 %
```

한 번에 4원이 안 되지만, `DAILY_CALL_LIMIT`인 200회를 다 쓰면 하루 784원이다. 사용자가 늘어나면 이 값이 그대로 곱해진다.

### 프롬프트 캐싱

매번 똑같이 들어가는 부분(시스템 프롬프트, 사내 규정 문서 등)을 캐시에 올려두면, 다음 호출부터 그 몫은 **1/10 값**으로 계산된다. 위 예시에서 800토큰 중 600을 캐시로 읽으니 19% 정도 줄었다.

`cache_write`는 값만 정의해두고 계산식에는 아직 넣지 않았다. 캐시에 처음 써 넣을 때는 오히려 조금 비싸서, 실제로 이득인지 보려면 그 비용까지 넣어야 한다.

## 한도 — 두 가지를 구분한다

| | spend limit | rate limit |
| --- | --- | --- |
| 무엇 | 누적 금액(월 단위) | 분당 속도 |
| 걸리면 | 다 쓰면 멈춘다 | 잠깐 막았다가 다시 받는다 |
| 성격 | 돈을 막는다 | 돈을 막지는 않는다 |

한도에 걸린 요청은 **HTTP `429`**(rate limit error)로 돌아온다. [[05_예외_계층_설계]]에 `RateLimited`(429)를 미리 만들어 둔 자리가 여기다.

`.env`의 `DAILY_CALL_LIMIT`, `MAX_INPUT_CHARS`는 공급자가 아니라 **우리가 먼저 거는 상한**이다. 공급자 한도에 부딪히기 전에 우리 쪽에서 선제적으로 멈추기 위한 값이고, 사고로 비용이 폭증하는 것을 막는 1차 방어선이다.
