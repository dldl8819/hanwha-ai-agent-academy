        print("잘못된 메뉴 번호입니다.")

## 1. 클래스 메서드 종류와 property, 던더 메서드

클래스 안에 정의하는 메서드는 크게 세 종류로 나뉩니다.

```python
class Student:
    school: str = "HeiFam"

    def __init__(self, name: str, score: int):
        self.name: str = name
        self.score: int = score

    # 인스턴스 메서드
    def is_passed(self) -> bool:
        return self.score >= 60

    # 클래스 메서드 : self 대신 cls(클래스 자신)를 받음
    @classmethod
    def show_school(cls):
        print(f"우리는 모두 {cls.school} 멤버 입니다.")

    # 정적 메서드 : self, cls 둘 다 받지 않음
    @staticmethod
    def study_sum(a, b):
        return a + b
```

`@property`를 활용하면 값을 조회·수정할 때 검증 로직을 끼워 넣을 수 있습니다. 이때 getter 안에서 `self.age`라고 쓰면 자기 자신을 무한히 다시 호출하는 재귀가 발생하기 때문에, 관례적으로 실제 값은 `_age`처럼 언더바를 붙인 이름에 저장합니다.

```python
class Person:
    def __init__(self, age):
        self.age = age

    @property
    def age(self):
        return self._age    # self.age라고 쓰면 무한 재귀 발생

    @age.setter
    def age(self, val):
        self._age = val
```

`__repr__`, `__eq__` 같은 이름 앞뒤에 밑줄 두 개가 붙은 메서드는 "던더(dunder, Double UNDERscore) 메서드" 또는 "매직 메서드"라고 부릅니다. `==` 연산자를 쓰면 파이썬이 내부적으로 `__eq__`를 자동 호출해주는 식이라, 개발자가 직접 부르지 않아도 알아서 동작한다는 의미에서 매직이라는 별명이 붙었습니다.

## 2. 상속과 오버라이딩

부모 클래스의 속성과 메서드를 자식 클래스가 그대로 물려받는 것이 상속입니다. 자식이 부모와 같은 이름의 메서드를 새로 정의하면 오버라이딩이 되어 자식의 것이 우선 실행됩니다.

```python
class Person:
    def __init__(self, name):
        self.name = name

    def work(self):
        print(f"{self.name}이/가 일을 한다.")

class Postman(Person):
    def __init__(self, name, postman_id):
        super().__init__(name)   # 부모 생성자를 명시적으로 호출해야 name이 초기화됨
        self.postman_id = postman_id

    def work(self):
        print(f"{self.name}이/가 우편물을 배달한다.")
```

여기서 중요한 포인트는, 자식이 `__init__`을 직접 정의하면 부모의 `__init__`은 자동으로 실행되지 않는다는 점입니다. 부모의 초기화 로직도 함께 쓰고 싶다면 `super().__init__(...)`으로 명시적으로 불러와야 합니다.

## 3. 다중 상속과 MRO

파이썬은 하나의 클래스가 여러 부모를 동시에 상속받는 다중 상속도 지원합니다. 다만 같은 이름의 메서드를 여러 부모가 갖고 있으면 어떤 부모의 것이 실행되는지 헷갈릴 수 있는데, 이 순서를 결정하는 규칙이 MRO(Method Resolution Order)입니다.

```python
class A:
    def hello(self):
        print("hello A")

class B(A):
    def hello(self):
        print("hello B")

class C(A):
    def hello(self):
        print("hello C")

class D(B, C):
    pass   # hello 없음

d = D()
d.hello()          # "hello B" 출력
print(D.mro())      # [D, B, C, A, object]
```

MRO를 따라가다가 메서드가 정의된 첫 번째 클래스를 만나면 그 자리에서 멈추기 때문에, `D`는 `B`의 `hello`만 실행하고 `C`나 `A`는 확인하지 않습니다. `super(클래스, self)`처럼 기준 클래스를 직접 지정하면 MRO 상의 원하는 지점부터 다시 탐색을 시작할 수도 있습니다. 상속 구조가 너무 복잡해지면 어느 부모의 메서드가 실행되는지 추적하기 어려워지므로, 상속 관계는 최소한으로 단순하게 유지하는 것이 유지보수에 유리하다는 점도 함께 배웠습니다.

## 4. 추상 클래스

추상 클래스는 내용물 없이 "이런 메서드가 반드시 있어야 한다"는 설계만 정의해두는 클래스입니다. 표준 라이브러리 `abc` 모듈의 `ABC`와 `@abstractmethod`로 만듭니다.

```python
from abc import ABC, abstractmethod

class Animal(ABC):
    @abstractmethod
    def sound(self):
        pass

class Cat(Animal):
    def sound(self):
        print("야옹~~")

class Dog(Animal):
    def sound(self):
        print("멍멍!!")
```

`@abstractmethod`가 붙은 메서드를 자식 클래스가 구현하지 않고 인스턴스를 만들려고 하면 `TypeError`가 발생합니다. 즉 "이 기능은 자식이 반드시 채워야 한다"는 규칙을 파이썬 문법 차원에서 강제하는 장치입니다.

## 5. 모듈과 패키지

`.py` 파일 하나가 모듈이고, 여러 모듈을 폴더로 묶어 `__init__.py`를 넣으면 패키지가 됩니다.

```python
# math_utils.py (모듈)
def add(a, b):
    return a + b

# 사용하는 쪽
import math_utils
print(math_utils.add(1, 2))   # 3
```

`import module`(전체), `import module as m`(별명), `from module import func`(필요한 함수만) 등 상황에 맞는 import 방식을 골라 쓸 수 있습니다.

## 6. 파일 입출력

`open(경로, 모드)`로 파일을 열고, `with-open` 구문을 쓰면 블록이 끝날 때 자동으로 파일이 닫힙니다.

```python
with open("Heifam.txt", "w", encoding="utf-8") as f:
    f.write("안녕하세요.\n")

with open("Heifam.txt", "r", encoding="utf-8") as f:
    for line in f:
        print(line.strip())
```

`'w'` 모드는 기존 내용을 삭제하기 때문에, 이어서 쓰고 싶을 땐 `'a'` 모드를 사용해야 합니다. 또한 파일이 없는 상태에서 `open(..., 'r')`을 바로 호출하면 `FileNotFoundError`가 발생하기 때문에, `os.path.exists()`로 먼저 존재 여부를 확인하는 방어적 습관도 함께 배웠습니다. 경로는 OS마다 구분자(`\` vs `/`)가 달라서, `pathlib.Path`를 쓰면 운영체제에 상관없이 안전하게 처리할 수 있다는 점도 인상 깊었습니다.

```python
from pathlib import Path

ROOT = Path(__file__).resolve().parent.parent
print(ROOT)
```

## 7. 예외 처리

코드 실행 중 발생하는 오류를 프로그램이 강제 종료되지 않도록 처리하는 문법이 `try-except`입니다.

```python
try:
    num = int(input("정수 : "))
except ValueError:
    print("정수를 입력하십시오.")
except ZeroDivisionError:
    print("0으로는 나눌 수 없습니다.")
else:
    print("정상 실행되었습니다.")   # 예외 없이 성공했을 때만 실행
finally:
    print("항상 실행되는 코드")      # 예외 발생 여부와 무관하게 항상 실행
```

`ValueError`, `TypeError`, `KeyError`, `FileNotFoundError`처럼 자주 만나는 예외 클래스들은 전부 `Exception`이라는 공통 부모를 갖기 때문에, 세세하게 나누지 않고 `except Exception as e:`로 한 번에 처리할 수도 있습니다. 필요하면 `Exception`을 상속받아 직접 예외 클래스를 만드는 것도 가능합니다.

```python
class MyException(Exception):
    pass

try:
    raise MyException("경고!! 예외가 발생했습니다!")
except MyException as e:
    print("예외 처리가 필요합니다. : ", e)
```

## 8. 내장 함수

파이썬 내장(built-in) 함수는 모듈과 달리 `import` 없이 바로 쓸 수 있는 함수들입니다. "이미 있는 것을 다시 만들지 말라"는 원칙대로, 자주 필요한 동작은 이미 언어 차원에서 제공된다는 점이 인상 깊었습니다.

오늘 배운 함수 중 앞으로 자주 쓸 것 같은 것들만 추려서 정리해봤습니다.

```python
# 참/거짓 판단
all([1, 2, 3])          # True  -- 요소가 모두 참이어야 True
any([0, "", None])       # False -- 하나라도 참이면 True

# 컬렉션 다루기
list(enumerate(['a', 'b']))     # [(0, 'a'), (1, 'b')] -- 인덱스 + 값
list(zip([1, 2], [3, 4]))        # [(1, 3), (2, 4)] -- 여러 데이터를 짝지어 묶음
sorted([3, 1, 2])                # [1, 2, 3]
max([1, 2, 3]), min([1, 2, 3])   # 3, 1
sum([1, 2, 3])                   # 6

# 함수형 도구
list(map(lambda x: x * 2, [1, 2, 3]))       # [2, 4, 6]
list(filter(lambda x: x > 0, [1, -3, 2]))   # [1, 2]

# 자료형 변환/확인
type("abc")              # <class 'str'>
isinstance(3, int)        # True
```

`map`과 `filter`는 각각 for문과 조건문으로 짤 수 있는 로직을 한 줄로 줄여주는 함수라, 앞서 배운 리스트 컴프리헨션과 비슷한 역할을 합니다. `enumerate`와 `zip`은 반복문에서 인덱스나 여러 리스트를 동시에 다뤄야 할 때 자주 쓰일 것 같습니다.

여기서 함께 나온 `lambda`도 짚고 넘어가야 할 것 같습니다. `lambda`는 이름 없는 함수를 한 줄로 만드는 문법으로, `def`로 함수를 따로 정의하지 않고 그 자리에서 바로 간단한 함수를 만들어 쓸 수 있게 해줍니다.

```python
# def로 만든 함수
def two_times(x):
    return x * 2

# lambda로 만든 같은 함수
two_times = lambda x: x * 2
```

매번 이름을 짓고 `def`로 정의하기엔 아까운, 한 번만 쓰고 버릴 간단한 함수를 `map`이나 `filter`, `sorted(key=...)` 안에 바로 넣을 때 특히 유용하다는 걸 오늘 실습을 통해 체감했습니다.
