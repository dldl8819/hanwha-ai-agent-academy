# 예외 처리 (Exception Handling)

## 예외 (Exception)

- 예외는 코드 실행 중 발생하는 오류.
- 프로그램을 강제 종료시키지 않고 처리할 수 있는 것들.

## 예외 처리 문법

```python
try:
    # 예외가 발생할 수 있는 코드들
except 예외클래스:
    # 예외 발생 시 처리할 코드들
```

## 자주 사용하는 예외 클래스

| 예외 클래스 | 발생 예시 |
| --- | --- |
| `ValueError` | `int("abc")` |
| `TypeError` | `"a" + 1` |
| `KeyError` | `mydict["없는키값"]` |
| `IndexError` | 인덱스 번호 에러 |
| `AttributeError` | 속성이 없는 것을 부를 때 `None.age` |
| `FileNotFoundError` | 없는 파일 열 때 |
| `ZeroDivisionError` | 0으로 나눌 때 |
| `UnicodeDecodeError` | 인코딩 불일치 |

관련 예시: [day03/ex24.py](../day03/ex24.py)의 `os.path.exists()`로 미리 확인해서 `FileNotFoundError`를 방지하는 방식도, 결국 예외가 나기 전에 조건으로 걸러내는 방어적 처리의 한 예시다. `try-except`는 그 대안으로, 조건으로 미리 막기 어려운 상황(예: 실행 도중에만 알 수 있는 오류)에서 사용한다.

### 예외 클래스 계층 구조

- 모든 예외는 `BaseException`을 최상위로 하는 클래스 계층을 이룬다.
- `Exception`은 프로그램에서 다루는 대부분의 예외의 부모 클래스이자, **모든 예외를 한 번에 처리하고 싶을 때 사용할 수 있는 클래스**다.

```
BaseException
    Exception
        ValueError
        OSError   # FileNotFoundError, ...
        ...
```

- `except Exception as e:`처럼 잡으면 위 계층에 속한 거의 모든 예외를 한 번에 처리할 수 있다. 다만 어떤 예외인지 구분해서 다르게 처리하고 싶다면, `ValueError`처럼 더 구체적인 예외 클래스를 먼저 잡고, 마지막에 `Exception`으로 나머지를 잡는 순서로 작성한다.

### 여러 개의 오류 처리하기

- `except`를 여러 번 써서 오류별로 각각 다르게 처리할 수 있다.

```python
try:
    a = [1, 2]
    print(a[3])
    4 / 0
except ZeroDivisionError:
    print("0으로 나눌 수 없습니다.")
except IndexError:
    print("인덱싱할 수 없습니다.")
```

- 여러 오류를 **동일하게** 처리하고 싶다면, 괄호로 묶어서 하나의 `except`에서 함께 잡을 수 있다.

```python
try:
    a = [1, 2]
    print(a[3])
    4 / 0
except (ZeroDivisionError, IndexError) as e:
    print(e)
```

### 오류 회피하기

- 특정 오류가 발생해도 별다른 처리 없이 그냥 넘어가고 싶을 때는 `except` 블록에 `pass`를 쓴다.

```python
try:
    f = open("나없는파일", 'r')
except FileNotFoundError:
    pass   # 파일이 없더라도 오류를 발생시키지 않고 그냥 통과
```

### `else` - `finally`

```python
try:
    # 예외가 발생할 수 있는 코드들
except 예외클래스:
    # 예외 발생 시 처리할 코드들
else:
    # 예외 없이 성공했을 때 실행
finally:
    # 예외 발생 여부와 상관없이 항상 실행
```

- `else`: try 블록이 예외 없이 성공했을 때만 실행.
- `finally`: 예외가 발생하든 안 하든 **항상** 실행 (파일 닫기, 리소스 정리 등에 사용).
- `finally`는 `except` 없이 `try-finally`만으로도 쓸 수 있다. 이 경우 예외가 발생하면 `finally` 실행 후 예외가 그대로 위로 전파된다.

```python
try:
    f = open("foo.txt", "w")
    # 무언가를 수행
    ...
finally:
    f.close()   # 중간에 오류가 발생하더라도 무조건 실행되어 파일이 닫힘
```

### 예외 발생시키기 (`raise`)

```python
raise 예외클래스(메시지)
```

- 특정 조건에서 강제로 예외를 발생시키고 싶을 때 사용한다.

```python
class Person:
    def __init__(self):
        self.age = 0

    def set_age(self, v):
        if not isinstance(v, int):
            raise TypeError("입력하신 데이터 타입을 확인해주십시오.")
        if v < 0:
            raise ValueError("나이는 음수가 될 수 없습니다.")
        self.age = v
```

- `except` 블록 안에서 인자 없이 `raise`만 쓰면, 잡았던 예외를 그대로 다시 발생시킨다(원래 예외를 상위로 전파하고 싶을 때 사용).

```python
try:
    p.set_age(-10)
except TypeError as e:
    print(f"예외 발생!! {e}")
    raise   # 잡은 예외를 그대로 다시 던짐
except ValueError as e:
    print(f"예외 발생!! {e}")
```

관련 예시: [day03/ex25.py](../day03/ex25.py) (`try-except-else-finally`, 예외별 개별 처리 vs `Exception`으로 한 번에 처리), [day03/ex26.py](../day03/ex26.py) (`raise`로 예외 발생시키기, `except` 안에서 `raise`로 재발생)

### 사용자 정의 예외 만들기

- 내장 예외 클래스만으로 표현하기 애매한 상황은 `Exception`을 상속받아 직접 예외 클래스를 만들 수 있다.

```python
class MyException(Exception):
    pass
```

```python
raise MyException("이런저런 예외가 발생했습니다.")
```

```python
try:
    ...
except MyException as e:
    # 예외 처리 메시지 : "이런저런 예외가 발생했습니다."
    print("예외 처리: ", e)
    ...
```

### 예시 (day03/ex26.py)

```python
class MyException(Exception):
    pass

try:
    print("사용자 정의 예외 만들기")
    raise MyException("경고!!예외가 발생했습니다!")
except MyException as e:
    print("예외 처리가 필요합니다. : ", e)
```

- 사용자 정의 예외도 `Exception`을 상속받은 클래스이므로, 지금까지 다룬 `try-except`, `raise`, `except Exception`으로 한 번에 잡기 같은 규칙이 모두 동일하게 적용된다.

### `__str__`로 사용자 정의 예외 메시지 지정하기

- 사용자 정의 예외 클래스에 `__str__` 메서드를 구현하면, `print(e)`처럼 예외 객체를 출력할 때 그 메시지가 표시된다.

```python
class MyError(Exception):
    def __str__(self):
        return "허용되지 않는 별명입니다."

def say_nick(nick):
    if nick == "바보":
        raise MyError()
    print(nick)

try:
    say_nick("천사")
    say_nick("바보")
except MyError as e:
    print(e)   # 허용되지 않는 별명입니다.
```

### 참고: `raise`로 자식 클래스의 메서드 구현 강제하기

- [10_추상클래스](10_추상클래스.md)에서 다룬 `abc.ABC` + `@abstractmethod` 외에, 파이썬 내장 예외 `NotImplementedError`와 `raise`만으로도 비슷한 효과를 낼 수 있다.

```python
class Bird:
    def fly(self):
        raise NotImplementedError

class Eagle(Bird):
    pass   # fly()를 구현하지 않음

eagle = Eagle()
eagle.fly()   # NotImplementedError 발생
```

```python
class Eagle(Bird):
    def fly(self):
        print("very fast")

eagle = Eagle()
eagle.fly()   # "very fast" — 정상 실행
```

- 차이점: `@abstractmethod`는 **미구현 상태로 인스턴스를 생성하는 시점**에 바로 `TypeError`가 발생하지만, `raise NotImplementedError` 방식은 인스턴스 생성은 되고 **그 메서드를 실제로 호출하는 시점**에야 오류가 발생한다.
