# 상속 (Inheritance)

- 부모 클래스의 속성과 메서드를 자식 클래스가 물려받아 사용한다.
- 메서드 오버라이딩이 가능하다.

## 구조

```python
class 자식클래스명(부모클래스명):
    pass
```

## 예시 (day03/ex20.py)

```python
class Person:
    def __init__(self, name):
        self.name = name

    def study(self):
        print(f"{self.name}님은 공부를 한다.")

class Heifam(Person):   # self.name, study() 물려받음
    def __init__(self, name, email):
        super().__init__(name)  # 부모 생성자를 호출하여 name 속성 초기화
        self.email = email

    # 오버라이딩
    # 부모로부터 물려받은 기능을 수정하는 것
    # 기존 def study(self): 선언부는 동일해야 한다.
    def study(self):
        print(f"{self.name}님은 Python 공부를 한다.")

member = Heifam("소울", "test@example.com")
print(f"{member.name}님의 이메일 주소는 {member.email}입니다.")
member.study()
member.name = "민식"    # 물려받은 변수의 값 수정
member.study()
```

- `study()`는 자식 클래스에서 새로 정의(오버라이딩)했기 때문에, `Heifam` 객체는 자신의 `study()`가 호출된다.
- `Heifam`이 `__init__`을 직접 정의했기 때문에, 부모 `Person`의 초기화(`self.name = name`)를 그대로 쓰고 싶으면 `super().__init__(name)`으로 **명시적으로** 호출해줘야 한다.

## Q. 상속받은 클래스로 객체를 생성하면 생성자는 어떤 것이 호출될까?

- **자식이 `__init__`을 정의하지 않은 경우**: 부모의 `__init__`을 그대로 물려받아 그게 호출된다.
- **자식이 `__init__`을 정의한 경우**: 자식의 `__init__`만 호출되고, 부모의 `__init__`은 **자동으로 호출되지 않는다.** 부모의 초기화 로직도 실행하고 싶다면 자식 생성자 안에서 `super().__init__(...)`을 직접 호출해야 한다. (위 `Heifam` 예시)

이건 "오버라이딩"과 동일한 원리다 — 자식이 같은 이름의 메서드(`__init__`도 결국 메서드)를 정의하면 부모 것을 덮어쓰기 때문에, 부모 것도 쓰고 싶으면 `super()`로 명시적으로 불러와야 한다.

## 다중 상속 (Multiple Inheritance)

- 파이썬은 여러 개의 부모 클래스를 동시에 상속받을 수 있다.
- `class 자식클래스(부모클래스1, 부모클래스2, ...)` 형태로 작성한다.

### 구조

```python
class D(A, B, C):
    pass
```

### 예시 (day03/ex20.py)

```python
class A:
    def __init__(self):
        print("A 생성자")

    def a(self):
        pass

class B:
    def __init__(self):
        print("B 생성자")

    def b(self):
        pass

class C:
    def __init__(self):
        print("C 생성자")

    def c(self):
        pass

class D(A, B, C):
    def __init__(self):
        print("D 생성자")

    def d(self):
        pass

a1 = A()
b1 = B()
c1 = C()
d1 = D()   # "D 생성자"만 출력됨 (A/B/C 생성자는 호출 안 됨)

d1.a()  # A의 메서드도 사용 가능
d1.b()  # B의 메서드도 사용 가능
d1.c()  # C의 메서드도 사용 가능
d1.d()
```

### 핵심 포인트

- `D`가 `A, B, C`를 모두 상속받아도, **`D`가 자기 `__init__`을 정의하면 자기 생성자만 실행된다.** `d1 = D()`를 해도 콘솔에는 "D 생성자"만 찍히고, "A 생성자"/"B 생성자"/"C 생성자"는 찍히지 않는다.
- 반대로 메서드(`a()`, `b()`, `c()`)는 `D`가 따로 정의하지 않았기 때문에, 상속받은 그대로 부모의 것을 사용할 수 있다.
- 즉 생성자(`__init__`)도 결국 메서드이기 때문에, 위 오버라이딩 규칙을 그대로 따른다 — 자식이 재정의하면 자식 것만 실행되고, 부모 것을 같이 실행하려면 `super().__init__()`을 명시적으로 호출해야 한다.
- 만약 `D`가 `__init__`을 아예 정의하지 않았다면, 파이썬은 MRO(Method Resolution Order)에 따라 상속 순서상 **가장 먼저 적힌 부모(`A`)의 `__init__`**을 찾아 호출한다. (B, C의 생성자는 여전히 자동 호출되지 않는다.)

### MRO (Method Resolution Order)

- 같은 이름의 메서드를 여러 부모가 갖고 있을 때, 파이썬이 "어느 클래스의 메서드를 쓸지" 탐색하는 순서.
- 사용하는 알고리즘 이름은 **C3 선형화(C3 linearization)**.
- 기본 원칙: 자기 자신 → 왼쪽 부모부터 → 오른쪽 부모 → ... → `object` 순으로 검색.
- `클래스.mro()` 또는 `클래스.__mro__`로 실제 탐색 순서를 직접 확인할 수 있다.

```python
class A:
    def greet(self): print("A")

class B(A):
    def greet(self): print("B")

class C(A):
    def greet(self): print("C")

class D(B, C):   # 다이아몬드 상속: B, C가 둘 다 A를 상속
    pass

d = D()
d.greet()          # "B" — 왼쪽(B)이 오른쪽(C)보다 우선
print(D.mro())      # [D, B, C, A, object] — A는 중복 없이 한 번만 탐색됨
```

- 다이아몬드 상속(B, C가 둘 다 A를 상속하고, D가 B와 C를 모두 상속하는 구조) 같은 경우에도 C3 선형화 덕분에 A가 중복 탐색되지 않고 MRO 안에 한 번만 들어간다.
- `D(B, C)`처럼 D가 B, C만 직접 나열해도, B와 C가 각각 A를 상속하고 있으므로 D도 **전이(transitive) 상속**으로 A를 물려받는다 (`isinstance(D(), A)`는 `True`).

### 탐색은 "첫 매치"에서 멈춘다

- MRO를 따라가다가 **메서드가 정의된 첫 번째 클래스를 만나면 그 자리에서 멈춘다.** 뒤에 같은 이름의 메서드가 더 있어도 확인하지 않는다.

```python
class A:
    def hello(self): print("hello A")

class B(A):
    def hello(self): print("hello B")

class C(A):
    def hello(self): print("hello C")

class D(B, C):
    pass   # hello 없음

d = D()
d.hello()   # "hello B" — MRO [D, B, C, A, object]에서 B가 첫 매치, C/A는 확인 안 함
```

### `super(클래스, self)`로 MRO 특정 지점부터 탐색하기

- `super()`(인자 없이)는 사실 `super(정의된클래스, self)`와 같다. 즉 "그 메서드가 정의된 클래스 **바로 다음부터** `self`의 MRO를 탐색해라"라는 뜻.
- 두 번째 인자는 항상 고정이 아니라, **`self`의 실제 타입(가장 아래 자식)의 MRO를 기준으로** 첫 번째 인자로 준 클래스 다음 지점을 찾는다. 그래서 `super(B, self)`, `super(C, self)`처럼 기준 클래스를 바꿔가며 명시적으로 호출하면, MRO 상의 여러 지점을 자식 하나에서 전부 순서대로 불러올 수 있다.

```python
class D(B, C):
    def hello(self):
        print("hello D")
        super(D, self).hello()   # D 다음(MRO 기준) → B
        super(B, self).hello()   # B 다음(MRO 기준) → C
        super(C, self).hello()   # C 다음(MRO 기준) → A

d = D()
d.hello()
# hello D
# hello B
# hello C
# hello A
```

| 호출 | MRO `[D, B, C, A, object]`에서 시작 위치 | 결과 |
| --- | --- | --- |
| `super(D, self)` | D 다음부터 | B |
| `super(B, self)` | B 다음부터 | C |
| `super(C, self)` | C 다음부터 | A |

- 다만 실전에서는 자식이 이렇게 부모들을 일일이 지정해서 부르기보다, **각 클래스가 자기 메서드 안에서 `super().메서드()`를 호출**해 체인처럼 자동으로 이어지게 하는 협력적 다중 상속(cooperative multiple inheritance) 패턴이 더 흔하다.

## 다단계 상속 (Multi-level Inheritance)

- 상속이 한 줄로 여러 세대에 걸쳐 이어지는 구조. `A → B → C → D`처럼 부모의 부모의 부모...로 이어진다.
- 위 다중 상속(같은 세대에 부모가 여러 명, 가로 방향)과 다른 개념이다. 다단계 상속은 세로 방향으로 여러 층이 쌓인다.

### 구조

```python
class B(A):
    pass

class C(B):
    pass

class D(C):
    pass
```

### 예시

```python
class A:
    def a(self): pass

class B(A):   # B는 A의 자식
    def b(self): pass

class C(B):   # C는 B의 자식 (= A의 손자)
    def c(self): pass

class D(C):   # D는 C의 자식 (= B의 손자, A의 증손자)
    def d(self): pass

d = D()
d.a()  # A에게서 물려받음
d.b()  # B에게서 물려받음
d.c()  # C에게서 물려받음
d.d()  # 자기 것

print(isinstance(d, A))  # True
print(isinstance(d, B))  # True
print(isinstance(d, C))  # True
print(D.__mro__)         # (D, C, B, A, object) — 메서드/속성 조회 순서
```

### 핵심 포인트

- D는 C의 자식이지만, 상속은 전이(transitive)되기 때문에 결과적으로 A, B, C 모두의 후손이 되고 세 클래스의 속성·메서드를 전부 물려받는다.
- 가족 관계로 비유하면: D 입장에서 C는 부모, B는 조부모, A는 증조부모. 조상들이 가진 재산(속성)과 기술(메서드)을 대를 이어 전부 물려받는 것과 같다.
- [[08_클래스_기초]]의 생성자 규칙도 동일하게 적용된다 — 중간에 있는 클래스가 `__init__`을 재정의하면 그 아래 자손은 명시적으로 `super().__init__()`을 호출하지 않는 한 더 위 조상의 생성자를 자동으로 타지 않는다.

### 다중 상속과의 비교

| 구분 | 관계 | 부모 개수 |
| --- | --- | --- |
| 다중 상속 (Multiple) | D가 A, B, C를 **동시에** 직접 상속 | 한 세대에 부모가 여러 명 |
| 다단계 상속 (Multi-level) | A→B→C→D로 **한 줄로 이어서** 상속 | 각 세대마다 부모는 1명, 대신 세대가 여러 층 |
